# 檢視顯著計劃

本文件詳細列出如何完整檢視、確認與說明 InterSubMod 專案中顯著性分析流程的操作計劃。

## 1. Read 與 甲基數值矩陣實作確認

### 檢視目標
確認 Read 標籤 (Label) 與甲基化矩陣 (Methylation Matrix) 的程式碼是否已完整實作，並且整合在預設的主運行流程中。

### 程式碼現況分析
經過對 `src/core` 原始碼的檢視，確認以下實作狀態：

- **Read 標籤 (Tags) 解析**:
    - **實作位置**: `MethylationParser.cpp` (解析 MM/ML), `RegionProcessor.cpp` (解析 HP, proper_pair, is_tumor 等)。
    - **完整性**:
        - `MethylationParser::parse_read` 已完整實作 `MM` (位置) 與 `ML` (機率) 標籤的解析。
        - **關鍵細節**: 已包含對 **Reverse Strand** 的特殊處理邏輯 (反向迭代 SEQ 以匹配 5'->3' 的 MM deltas)，這是正確的。
        - `RegionProcessor` 在讀取 BAM 時，會將 `HP` (Haplotype), `PS` (Phase Set), `is_tumor` 等資訊存入 `ReadInfo` 結構。
    - **預設流程**: 是。在 `RegionProcessor::process_single_region` 中，預設會對每個 read 呼叫 parser 並收集這些資訊。

- **甲基化矩陣 (Matrix) 建構**:
    - **實作位置**: `MatrixBuilder.cpp`, `RegionProcessor.cpp`。
    - **完整性**:
        - 系統會收集區域內所有 reads 的 CpG 位點，建立統一的 Column 索引。
        - 矩陣數值包含 Raw Probability (0.0-1.0) 與 Binary (-1/0/1)。
        - `RegionProcessor` 會將此矩陣轉換為 `Eigen::MatrixXd` 供後續距離計算使用。
    - **預設流程**: 是。`matrix_builder.finalize()` 與後續的 `DistanceCalculator` 呼叫皆在主流程中。

### 後續檢視操作計劃
1.  **執行測試**: 執行 `./scripts/run_vcf_all_snv.sh` (或使用單一位點模式)。
2.  **檢查輸出**: 查看 `output/.../debug/reads.jsonl` 與 `matrix_binary.csv`。
    - 確認 `reads.jsonl` 中有 `hp`, `alt_support` 等欄位且有值。
    - 確認 `matrix_binary.csv` 的數值分佈合理 (非全 NaN)。

## 2. 顯著關係判讀方法合理性

### 檢視目標
確認將「標籤對應矩陣的群內群外方法 (Label-First)」與「矩陣分多群後對應標籤 (Cluster-First)」整合的判讀流程是否合理。

### 方法論分析
目前的 `SignificanceAnalyzer` 採用了 **雙向驗證 (Bidirectional Verification)** 策略，這是非常嚴謹且合理的做法：

1.  **Cluster-First (分群優先)**:
    - **邏輯**: 先不看標籤，純粹根據甲基化距離矩陣進行階層聚類 (Hierarchical Clustering)，切出 K 個群。
    - **檢定**: 使用 Fisher's Exact Test 檢定這 K 個群的分佈是否與 HP/Allele 標籤有顯著關聯。
    - **意義**: 驗證「甲基化特徵是否自然形成了與遺傳標籤一致的結構」。

2.  **Label-First (標籤優先)**:
    - **邏輯**: 直接根據 HP 或 Allele 標籤將 reads 分組。
    - **檢定**: 使用 **PERMANOVA (Permutational MANOVA in Distances)** 計算群內距離 (Within-group) 與群間距離 (Between-group) 的差異 (Pseudo-F statistic)。
    - **意義**: 驗證「已知標籤是否能解釋甲基化的變異」。code 中已實作 `LabelTest::test_hp_multigroup_permanova`，可處理多個單倍型 (HP1, HP2, HP1-1 等)，比單純比較兩群更完整。

3.  **整合判讀**:
    - 系統根據兩者的結果定義了 `Verification Class`:
        - **Strong**: 兩者皆顯著 (最強證據)。
        - **Subclone**: 僅 Cluster 顯著 (可能存在與 HP 無關的甲基化亞群，具生物意義)。
        - **Weak**: 僅 Label 顯著 (訊號微弱，不足以形成明顯分群)。
        - **Noise**: 皆不顯著。

### 結論
此流程**符合研究目標**。它不僅檢測標籤關聯性，還能發現標籤未標記的異質性 (Subclones)，這對於癌症研究中的腫瘤異質性探索至關重要。

## 3. 科學驗證方法與文獻查證

### 檢視目標
確認方法是否符合生物資訊與癌症研究標準。

### 驗證重點
- **PERMANOVA**: 在微生物體學 (Microbiome) 與表觀遺傳學中常用於距離矩陣的差異分析。
- **Allele-Specific Methylation (ASM)**: 這是本研究的核心現象。
- **Tumor Heterogeneity**: 腫瘤異質性分析常依賴非監督式分群 (Unsupervised Clustering)。

### 查詢關鍵詞 (Search Queries)
建議使用 Google Scholar 或 PubMed 查詢以下組合：
1.  `"PERMANOVA" methylation distance matrix cancer`
2.  `"Allele-specific methylation" detection methods "clustering"`
3.  `"haplotype-dependent methylation" sequencing analysis`
4.  `"epigenetic heterogeneity" "distance matrix" clustering`

### 查詢與驗證計劃
1.  **查找論文**: 尋找是否有工具使用類似 "Distance-based analysis" 來偵測 ASM (例如 `MethHaplo`, `Long-read based ASM tools`)。
2.  **對比方法**: 確認其他工具是否也比較 "Within-haplotype variance" vs "Between-haplotype variance"。
3.  **引用支持**: 在報告中引用支持使用 PERMANOVA 處理高維度甲基化資料的文獻。

## 4. 程式碼影響因子列表

以下列出詳細的程式碼參數與邏輯，依據運作流程順序列出，標註其對顯著性結果的影響。

### A. 資料過濾階段 (Data Filtering)
這些參數決定了「哪些 Reads 進入分析」，直接影響統計檢定的樣本數 (N)。
1.  **`min_mapq` (預設 20)**: [中] 影響讀段品質，過低會引入錯誤 mapping 導致假訊號。
2.  **`min_read_length` (預設 1000)**: [高] 長讀段才能跨越足夠 CpG 形成有效距離，過短會導致矩陣稀疏。
3.  **`require_mm_ml`**: [絕對] 必須有甲基化標籤。
4.  **`AltSupport` 判定**: [極高]
    - `MethylationParser.cpp` 中的 CIGAR 解析邏輯。
    - **影響**: 錯誤的 ALT/REF 判定會直接導致 Label-First 檢定失效 (垃圾進，垃圾出)。

### B. 矩陣建構階段 (Matrix Construction)
5.  **`min_base_quality`**: [低] 影響單個 CpG 的採納。
6.  **Binary Threshold (0.2/0.8)**: [高]
    - 將機率轉為 0/1/-1。
    - **影響**: 若閾值太嚴格，`-1` (Uncertain) 會變多，導致距離計算的有效位點減少。

### C. 距離計算階段 (Distance Calculation)
7.  **`min_common_coverage` (C_min)**: [極高]
    - 兩條 reads 必須至少共有 C 個有效 CpG 才計算距離。
    - **影響**: 設定過高會導致距離矩陣出現大量 `NaN`，使 Clustering 或 PERMANOVA 無法計算 (Insufficient overlap)。
8.  **`DistanceMetric` (NHD/Jaccard)**: [中] 不同度量對稀疏資料的敏感度不同。

### D. 顯著性判讀階段 (Significance Analysis)
9.  **`clustering_min_reads`**: [中] 少於此數不進行分群。
10. **`optimal_k` 選擇 (TreeCutter)**: [高]
    - 決定分群數量 (2, 3, ...)。
    - **影響**: 若 K 選錯 (例如應分 2 群卻分 3 群)，Fisher Test 的 p-value 會被稀釋。
11. **`p_value` 閾值 (Alpha, 0.05)**: [絕對] 決定是否顯著的切截點。
12. **`gating_p_threshold`**: [高] 粗篩門檻，決定是否進入更細部的 Local Test。

## 5. 結果正確性與錯誤判讀檢視計劃

### 檢視目標
偵測兩種錯誤：
- **Type I Error (FP)**: 不顯著判為顯著 (False Positive)。
- **Type II Error (FN)**: 顯著判為不顯著 (False Negative)。

### 後續操作計劃
1.  **檢視 "Weak" Class (潛在 FN)**:
    - 篩選出 `verification_class == "Weak"` 的位點。
    - **檢查重點**: 這些位點 Label Test 顯著但 Cluster 不顯著。可能有強烈背景雜訊干擾分群。
    - **行動**: 檢查 `heuristic_score` 是否偏低，人工查看 Heatmap 確認是否有肉眼可見的分群趨勢。

2.  **檢視 "Subclone" Class (潛在 FP)**:
    - 篩選 `verification_class == "Subclone"`。
    - **檢查重點**: 分群顯著但與 Label 無關。
    - **行動**: 確認是否為真實的「非遺傳性表觀異質性」 (Valid Discovery)，還是因為 Artifact (如 PCR duplicates 未濾除乾淨) 導致的分群。

3.  **人工審閱 Heatmap**:
    - 對於 p-value 在臨界值 (e.g., 0.04 - 0.06) 附近的案例，強制生成 Heatmap。
    - 確認 `leaf_order` 是否正確將相似 reads 排在一起。

## 6. TP/FP 與特徵關聯分析計劃

### 檢視目標
分析 True Positive (顯著) 與 False Positive (誤判) 是否與特定的生物特徵或數據特徵有關。

### 具體分析計劃
1.  **資料量相關性**:
    - 繪製 Scatter Plot: X軸 = Read Depth, Y軸 = P-value。
    - **預期**: Depth 過低時 P-value 分佈應較隨機；深度高時顯著性應較穩定。若低深度大量顯著，可能是偽陽性。

2.  **CpG 密度相關性**:
    - 統計每個 Region 的 CpG 數量。
    - 分析: 高 CpG 密度區域是否更容易出現顯著結果？(理論上資訊量多，檢定力較高)。

3.  **甲基化程度 (Beta Value) 相關性**:
    - 計算 Region 平均甲基化率。
    - 分析: 極端甲基化 (全0或全1) 通常不應顯著 (Variance = 0)。顯著位點應集中在中間甲基化程度 (0.3-0.7)。

4.  **序列特徵**:
    - 檢查顯著位點是否落在 Repetitive Regions 或 Homopolymer 區域 (可能導致測序錯誤)。

### 實行步驟
1. 收集所有位點的 `significance.json` 結果。
2. 匯總成 CSV 表格，包含 columns: `p_value`, `num_reads`, `num_cpg`, `avg_methylation`, `verification_class`.
3. 使用 Python (pandas/matplotlib) 進行上述關聯分析繪圖。
