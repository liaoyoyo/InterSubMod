為何要三個、不是一個

  • 只有 p 不夠：reads 一多，很小的差異也可顯著→ 加 Cramér's V 看關聯幅度。所以是雙門檻：p 表示與指定 null 的不相容性，V 表示關聯幅度；都不是「真假機率」。
  • Fisher/V 只看「分群 vs 標籤」：若候選結構對不上 ALT/HP 標籤會漏 → PERMANOVA 直接用距離矩陣檢驗標籤關聯的 centroid separation；不能略過 PERMDISP 或設計限制就升格為真實分群。
  • PERMANOVA 會被「某組比較散」騙（看似分開、其實只是離散度不同）→ PERMDISP 側檢標記這種假象。

三個你該知道的真相（已對原始碼核實）

① 舊閘 Significant 根本沒用 PERMANOVA。 verdict 只聽 Fisher 那張表（SignificanceAnalyzer.cpp:309-311）；「PERMANOVA 顯著但 Fisher p>0.05」的 region 會被打成 Weak/Noise — 即 06-16 FN1 audit 那件事。圖中以虛線表示 PERMANOVA「有算但未進舊閘」。
② Cramér's V 在表太稀疏時被強制歸 0。 Cochran：期望<5 的格子佔比>20% → 不可靠 → V=0（RegionProcessor.cpp:1745-1749）；因此 762 MISSED / 487 gate-to-0 只能稱「PERMANOVA-positive candidate structure missed by the V reliability gate」，不是真實關聯證明。
③ chi_square_p 是佔位符（直接 = Fisher p，GlobalTest.cpp:122-124），沒有獨立的卡方 p；卡方統計量只用來算 V。
補充（與工作站欄位有關）： memory/CURRENT_FOCUS 記的加權式 StrengthScore = 0.30·HP_AUC + 0.25·|Δβ| + 0.25·CramersV + 0.20·−log10 GlobalP 不在目前 checked-out branch 原始碼；它在 develop binary（inter_sub_mod_develop，即產生工作站資料那顆）。現 branch 的兩個合成分是 heuristic_score(−log10p + 2·V) 與 quality_score(100 − QC 罰分)。工作站數字無誤，但別把該公式當「現 branch 程式碼」引用。
