從零到第一個結果：公開步驟與內部 smoke test

本頁保存 2026-08-05/06 的內部機器執行收據；不是任何人 clone 公開 GitHub 後都能在 10 分鐘完成的承諾。 編譯與測試指令可從 repo 嘗試，但 Step 4 使用的 HCC1395 BAM、hg38 FASTA 與 VCF 未包含在公開 Git objects，因此目前公開讀者無法照原指令重現第一個分析結果。

公開重現狀態：BLOCKED（缺輸入 fixture） 要把本頁升級成可公開執行的教學，需補一組可合法散布的最小 fixture：區域化 tumor BAM + BAI、相符 reference FASTA + FAI、單位點 VCF、SHA-256、下載/建立指令，以及固定版本的預期輸出收據。補齊前，Step 4–5 只能視為內部環境 smoke test。
開始之前：先確認你自己的機器狀態 CPU、記憶體與磁碟餘量會隨主機與時間改變；不要沿用本頁的歷史環境數字。 跑全基因組分析前應實際檢查資源並保存 command receipt，大型輸出可能快速耗盡磁碟。

內部限定：單位點 smoke test

INTERNAL-ONLY 下列三個輸入路徑未隨公開 GitHub 發布；只有已取得內部資料與授權的環境才能執行。

# 準備一個只含單一突變的小 VCF
SP=/tmp/ism_demo && mkdir -p $SP
V=/big7_disk/liaoyoyo2001/InterSubMod/data/vcf/HCC1395/pileup/filtered_snv_tp.vcf

# internal preflight：公開 clone 目前會在這裡停止
test -r "$V" && \
test -r data/bam/HCC1395/tumor.bam && test -r data/bam/HCC1395/tumor.bam.bai && \
test -r data/ref/hg38.fa && test -r data/ref/hg38.fa.fai || {
  echo "Missing internal fixture; public smoke test is not yet reproducible" >&2
  exit 2
}

grep '^#' $V > $SP/one_snv.vcf
grep -P '^chr19\t29283968\t' $V >> $SP/one_snv.vcf

# 跑（只給三個必填參數）
./build/bin/inter_sub_mod \
  --tumor-bam  data/bam/HCC1395/tumor.bam \
  --reference  data/ref/hg38.fa \
  --vcf        $SP/one_snv.vcf \
  --output-dir $SP/out_min

08常見狀況排除

症狀原因與解法
程式直接停，說找不到參考基因組 參考 FASTA 缺 .fai 索引是硬性錯誤。跑 samtools faidx 建索引。
Python 腳本 import 就崩，錯誤指向 dataclass Python 版本問題，不是程式壞了。改用 /usr/bin/python3.10。
CI 判定 --help 失敗 --help 的退出碼是 1 不是 0（與參數錯誤共用同一路徑）。改寫檢查方式。
某支腳本跑了但什麼都沒發生 可能是函式庫不是入口（如 ism_heatmap_std.py）。看它有沒有 argparse。
讀 CSV 後整列變成一欄 linkage_matrix.csv 實際是 tab 分隔。加 sep='\t'。
跨 run 比較時欄位對不上 目前稽核版本的 significance_summary.csv 有 199 欄，並含 VerificationSchemaVersion=2 與 RegionStratificationSchemaVersion=1 兩個元件 schema；沒有單一 whole-file layout version。解析時須用欄名，並同時驗證必要欄位集合與兩個 component versions。
工作站 HTML 開很久／瀏覽器很卡 單檔可達 188 MB。示範時先開最小的那個（約 14.6 MB）。
LongLineage 說 KernelBlocked 這是預期行為不是故障。正式入口刻意 fail-closed，見 LongLineage 分冊。
