# Part A：固定個人風格（Core Identity，**不可動**）

此 Part 內所有條目均為跨簡報類型共用，定義廖子游的「簡報風格 DNA」。源頭：`20260311_個人PPT設計風格規範_01.md`（S2）§13 自我宣告。

## A.1　語言策略

來源：S2 §2、memory `feedback_pptx_bilingual_formatting.md`

| 維度 | 規則 |
|------|------|
| 主語言 | 台灣繁體中文 |
| 專有名詞 | 可用英文，但首次出現時以中文理解為主 |
| 英文出現場合 | 僅限：每頁標題下方副標、主要段落輔助說明、圖表註記層的欄位/單位 |
| 英文不強制 | 不逐條 bullet 雙語；若需逐條，**優先拆頁**而非擠壓 |
| 英文格式 | 縮排 `0.25"` + 字號為主字的 `60%` + `space_before=1pt`（緊貼中文）+ 色 `#5E6572` |
| Speaker Notes | **全中文**講稿；對外英文版另外另寫，不混寫 |

**為何**：中文是視覺重點、英文是輔助，不應搶注意力。

## A.2　字體家族

來源：S2 §3、memory `feedback_pptx_text_formatting_rules.md`

| 用途 | 字體 |
|------|------|
| 中文標題 | **Noto Sans TC Bold**（思源黑體粗體） |
| 中文內文 | **Noto Sans TC** |
| 英文標題 | **Arial Bold** |
| 英文內文 | **Arial** |
| 等寬/路徑 | **Consolas** |
| 備選中文 | Microsoft JhengHei |
| 備選英文 | Calibri |

**使用原則**：

1. 全檔無襯線
2. 標題固定粗體、適合標題可粗體；**禁止斜體**（僅保留給專有名詞如 *p-value*, *in vitro*）
3. 內文字型一致、同層級不隨頁切換
4. 每頁 ≤ 3 種字級
5. 避免底線、全大寫（以粗體取代）
6. 加粗後注意不溢出背景框

> **注意**：有歷史文件（SKILL.md 早期）曾用 Georgia + Calibri，現以 Arial + Noto Sans TC 為準。

## A.3　結構：一頁一重點 + 三層掃描

來源：S2 §5、memory `feedback_ppt_slide_design_rules.md`

### 三層規則

| 層 | 放什麼 |
|----|--------|
| 標題層 | 這頁在講什麼 |
| 內容層 | 3-5 個重點、流程、圖表或比較 |
| 註記層 | 資料來源、時間範圍、單位、必要說明 |

### 每頁硬約束

| 項目 | 值 |
|------|-----|
| 主題數 | 1 |
| 重點數 | 3-5 個為佳 |
| Bullets | **≤ 4 條**（行動頁 ≤ 3） |
| 視覺元素 | ≤ 6 個 |
| 字級種類 | ≤ 3 種/頁 |
| 6x6 Rule | ≤ 6 行 × ≤ 6 詞/行（中文 ≤ 12-15 字/行） |
| 中文標題 | **≤ 15 字 一行**，不換行 |
| 10 秒法則 | 觀眾應在 10 秒內抓到重點 |

### 結論頁特別規則

- 用**結論句**取代數字列表（例：「LOH 定義經 FDA 金標準認證」優於「Jaccard=0.928, Sensitivity=0.961」）
- 每 5-8 頁內容之間插入 **Section Divider**（深色過渡頁 + 段落名稱 + 一句話預告）

### 必須拆頁的 5 個信號

任一成立即拆頁：
1. 同一頁超過一張圖表
2. 一頁同時講背景+方法+結果+結論
3. 文字縮到 `16pt` 以下才放得下
4. 觀眾要花很久才找到重點
5. 需要指著多個區塊才能講清楚

## A.4　Speaker Notes 六段結構

來源：S2 §8、S4 §八、S5 §5.3

每頁 notes **至少包含六段**：

```
【本頁目的】：（一句話核心訊息）
【關鍵詞彙】：
  - 術語1：定義
  - 術語2：定義
【口頭講解重點】：
  （2-3 句銜接語與口頭說明）
【完整中文推論】：
  （這頁背後的完整論證）
【數據/圖表證據】：
  - 引用的數字、圖表
  - 來源路徑（絕對路徑）
【補充背景】：
  （可選，提供深度脈絡）
【報告人】：廖子游
```

**原則**：頁面正文只保留重點，完整句子與推導寫進 notes；對外英文版不與頁面正文混寫。

## A.5　圖片/圖表/表格規則

來源：S2 §7

### 圖片使用條件

只有能解釋下列之一時才使用：概念 / 流程 / 情境 / 比較 / 情感定位。**禁止純裝飾**。

### 圖表 6 必備元素

每張圖表必須回答一個明確問題（趨勢？差多少？佔比？轉折？）並包含：
1. 清楚的結論式標題（Assertion-Evidence，參 B.5）
2. 單位
3. 時間範圍
4. 標籤或直接標示數值
5. 資料來源（必要時）
6. 圖表結論導向文字

### 表格處理

只留最有用欄位。若表格變成「閱讀文件」→ 拆頁 / 轉圖表 / 細節入附錄或 notes。

## A.6　視覺優先哲學

來源：memory `feedback_pptx_visual_first_philosophy.md` + `feedback_pptx_term_explanation_rule.md`

核心原則：**視覺優先，文字最小化**。

| 場景 | 規則 |
|------|------|
| 概念/定義解釋 | 預設用**物件圖**（流程圖、對照表、annotated 圖片），不用 bullet list |
| 文字保留範圍 | 僅：標題（結論式）、關鍵數字、判決結果 |
| 教學頁 | 圖示佔 **60-70% 面積** |
| 專有名詞首次出現 | **必須配圖示化說明 + 同頁解釋區塊**（框/卡片），不假設讀者記得 |
| 數據結果頁 | 每張研究圖旁邊要有「此圖證明什麼」的結論框 |
| 無圖片頁 | 評估能否用 comparison diagram / flow steps / card layout 圖形化 |

## A.7　研究簡報頁型骨架

來源：S2 §9

| 頁 | 固定內容 |
|----|---------|
| P1 封面 | 左側文字區 + 右側重點圖留位 + 清楚標題 + 報告時間 + **報告人：廖子游** |
| P2 大綱 | 整體報告大綱、頁數、主題、順序 |
| P3 破題 | 重點 + 證明/重點圖 + 主架構/主題/核心結論 |
| P4+ | 依序：背景 → 定義/方法 → 目標/判斷/推論 → 完成事項 → 結果 → 如何驗證 → 數據圖證明 → 結論 → 未來目標/待確認 → 附錄與原始路徑 |

**封面佈局**：左側文字 + 右側**手動插圖留白**（自動生成只放 placeholder `[ 每週重點圖 — 手動插入 ]`，不自動插圖）。

# Part B：設計規範細節（有業界依據，可微調）

此 Part 的參數來源為業界最佳實踐（S3）與 WCAG 無障礙標準，在 Part A 固定身份的基礎上**按簡報類型微調**。

## B.1　字級制度

### B.1.1　Keynote 型（口頭報告 / 會議 / 學術簡報）

| 元素 | 絕對下限 | 建議 | 上限 |
|------|---------|------|------|
| 封面標題 | 36pt | 44-64pt | 72pt |
| 頁面標題 | 28pt | 32-36pt | 44pt |
| 副標題 | 20pt | 24-28pt | 32pt |
| 內文/Bullet | **20pt** | 24-28pt | 32pt |
| 圖表標籤 | 16pt | 18-20pt | 24pt |
| 腳注/來源 | 12pt | 14-16pt | 18pt |
| Section Divider | 36pt | 44-64pt | 72pt |

### B.1.2　Report 型（Send-ahead / 文件型）

| 元素 | 絕對下限 | 建議 |
|------|---------|------|
| 標題 | 20pt | 28pt |
| Headers | 16pt | 20pt |
| 內文 | 12pt | 14-16pt |
| 附錄/細節表格 | 10pt | 12pt |

### B.1.3　深色背景加成

深色背景 → 字號 **×1.15–1.20**，補償感知對比度損失：

| 元素 | 淺色 | 深色（+18%） |
|------|------|-------------|
| 頁面標題 | 32pt | **38pt** |
| 內文 | 24pt | **28pt** |
| 圖表標籤 | 18pt | **21pt** |

### B.1.4　個人規範硬約束

- 標題 **不得小於 16pt**
- 內文縮到 16pt 以下放不下 → **拆頁**
- 英文輔助最小 10pt
- 絕對下限 9pt（Consolas 路徑用）
- 中文標題 ≤ 15 字一行

## B.2　色彩系統（三層並列）

### B.2.1　第一層：週報主題色（淺色主）

| 角色 | HEX | 用途 |
|------|-----|------|
| Dark | `#1E2A44` | 深色頁背景 |
| BG | `#F7F3EC` | 主背景（暖米白） |
| BG Alt | `#EEE6DB` | 替代背景 |
| Accent（修正版）| `#A85540` | 強調色（原 `#C76B50` 對比度 3.5:1 不過 AA，已升 5.2:1） |
| Accent 2 | `#6E9D8A` | 輔助強調/裝飾（對比 2.8 → 建議加深 `#4A7D6A`） |
| Text | `#17202A` | 主文字 |
| Muted | `#5E6572` | 次要文字（含英文副標） |

### B.2.2　第二層：功能語義色

| 色名 | HEX | 用途 |
|------|-----|------|
| 綠 | `#009E73` | 正面 / TP / CONFIRMED |
| 紅 | `#D55E00` | 負面 / FP / REJECTED |
| 藍 | `#0072B2` | 主數據 |
| 青（Success） | `#00B0A0` | 正面結果 |
| 琥珀（Warning） | `#FFC000` | 注意 |
| 紅（Alert） | `#C00000` | 警告 |

### B.2.3　第三層：色盲安全色板（Okabe-Ito）

需 8+ 分類圖表時採用（Nature 期刊推薦）：

```
#E69F00 Orange    #56B4E9 Sky Blue    #009E73 Bluish Green
#F0E442 Yellow    #0072B2 Blue        #D55E00 Vermillion
#CC79A7 Reddish Purple               #000000 Black
```

### B.2.4　WCAG 對比度要求

| 文字類型 | AA | AAA |
|---------|-----|-----|
| 一般文字（≤24pt） | **4.5:1** | 7:1 |
| 大字（>24pt 或 Bold ≥19pt） | **3:1** | 4.5:1 |

**投影機補償**：投影時感知對比度降 ~30%，設計時預留。

### B.2.5　深色頁文字色（vs `#1E2A44`）

| 元素 | HEX | 對比度 |
|------|-----|--------|
| 主標題 | `#F5F5F5` Off-white | ~13.2:1 ✅ AAA |
| 內文 | `#D1D1D1` Light gray | ~9.3:1 ✅ AAA |
| 次要 | `#A0A0A0` Medium gray | ~5.0:1 ✅ AA |
| 弱化 | `#808080` | ~3.5:1 ⚠️ 僅大字 |

> **避免**：純白 `#FFFFFF` 在純黑 `#000000` 上（21:1 過高造成眼疲勞）。Off-white 搭 Charcoal 最佳。

## B.3　版面規則

### B.3.1　基本設定

| 項目 | 值 |
|------|-----|
| 比例 | 16:9 |
| 尺寸 | 13.333" × 7.5" |
| 安全邊距（左/右/上/下） | 0.75" / 0.75" / 1.0" / 0.5" |
| 安全內容區 | 11.833" × 6.0"（71% 面積） |

### B.3.2　間距

| 間距 | 建議 |
|------|------|
| 群組間距（大） | 0.4"-0.6" |
| 群組內元素（小） | 0.15"-0.25" |
| 標題與內容 | 0.3"-0.5" |
| 圖表與說明 | 0.15"-0.25" |

### B.3.3　行高與段落

| 元素 | 值 |
|------|-----|
| 行高 | 1.2-1.5 倍字號 |
| 段落間距 | 0.5-1.0 倍字號 |
| Bullet 間距 | 6-12pt space before |
| 深色頁行高 | **1.4-1.6**（補償可讀性） |

## B.4　圖表版面比例

| 類型 | 視覺 : 文字 | 適用 |
|------|------------|------|
| Chart-Dominant | **70-80 : 20-30** | 數據展示（**科學簡報最常用**） |
| Two-Column | 60 : 40 | 左文右圖（最通用） |
| Side-by-Side | 50 : 50 | Before/After |
| Full-Bleed | 90-100 : 0-10 | 純視覺衝擊 |
| Grid/Bento | 50 : 50 | 多指標儀表板 |
| Text-Heavy | 20-30 : 70-80 | 僅限 Report 型 |

科學簡報黃金比例：**圖表 60-70% / 文字 30-40%**。

## B.5　Assertion-Evidence 標題法

來源：Penn State 研究（Garner & Alley, 2013; ScienceDirect 2025 replication）

**舊式（描述性）**：「Results」「Data Analysis」「Figure 3」
**A-E 式（結論式）**：「LOH 區域 ISM 甲基化完全失效（7/7 AUC≈0.50）」

- 標題 ≤ 2 行，觀眾立即知道重點
- 頁面其餘用**圖表/視覺證據**支持結論
- **適用**：結果頁、驗證頁、結論頁
- **不適用**：封面、目錄、Section Divider

## B.6　頁型優先序（科學簡報）

| 優先 | 類型 | 視:文 | 適用 |

# Part E：技術陷阱與渲染排查

此 Part 處理 python-pptx 生成 PPTX 導致 PowerPoint 無法開啟/白頁/損壞的已知問題。來源：memory `reference_pptx_rendering_troubleshoot.md`。

## E.1　6 大已知問題

### 問題 1：Connector 零尺寸 → 後續白頁

- **症狀**：某張 slide 之後所有頁面白色
- **根因**：`add_connector()` 水平箭頭 `y1==y2` → cy=0 或極小
- **修復**：強制最小尺寸 `0.06" (54864 EMU)`

```python
min_dim = Emu(Inches(0.06))
if abs(cy2 - cy1) < min_dim:
    cy2 = cy1 + min_dim
```

閾值參考：`0.005"` 仍太小、`0.04"` 檢測閾值、`0.06"` **安全值**。

### 問題 2：RGBA PNG + dangling PIL handle → 白頁（**最常見**）

- **症狀**：含 RGBA 圖片的 slide 之後所有頁白
- **根因（複合）**：
  1. matplotlib/seaborn 預設輸出 RGBA
  2. **`Image.open()` 未關閉** → 兩個 handle 同時開啟同一檔案
  3. runtime 轉換（RGBA→RGB）產出不完整嵌入資料

**三層防護（缺一不可）**：

**Layer 1 — 預先轉換（最可靠）**：

```python
with Image.open(img_file) as img:
    if img.mode == "RGBA":
        rgb = Image.new("RGB", img.size, (255, 255, 255))
        rgb.paste(img, mask=img.split()[3])
        if rgb.size[0] > 1920:
            rgb = rgb.resize((1920, ...), Image.Resampling.LANCZOS)
        rgb.save(str(img_file), format="PNG", optimize=True)
```

**Layer 2 — 關閉所有 PIL handle**：

```python
# ❌ 錯誤（dangling）
img = Image.open(fig_path)
aspect = img.size[1] / img.size[0]

# ✅ 正確
with Image.open(fig_path) as _img:
    aspect = _img.size[1] / _img.size[0]
```

**Layer 3 — `_safe_add_picture()` 保底**：自動偵測 RGBA 並轉換。

**教訓**：
- `alpha min=255` 全不透明**不代表安全**
- **dangling `Image.open()` 是隱形殺手**：程式化檢查全 PASS 但 PPT 仍失敗
- matplotlib/seaborn 所有輸出都需轉換

### 問題 3：超大圖片 >1920px → 白頁

**修復**：預先轉換時同時降至 `1920px` 寬（LANCZOS）。`1920px @ 6" 顯示 = 320 DPI` 已充足。

### 問題 4：標題與圖片重疊

- 雙語標題底約 `y=2.05"`
- 下方元素**至少從 `y=2.15"` 起**

### 問題 5：元素超出 Footer

- Footer 安全線 `y=6.68"`
- 動態高度：`card_h = min(target_height, 6.68 - card_top)`

### 問題 6：缺失背景 → 白 slide

每 builder 開頭必呼叫 `set_bg(slide, theme["bg"])`。

## E.2　自動防護：`_verify_pptx_rendering_safety()`

儲存後自動執行，CRITICAL → `raise SystemExit(1)`：

| 檢查項 | 閾值 |
|--------|------|
| 背景 `<p:bg>` 存在 | 每 slide |
| Shape w/h = 0 | 任何 shape |
| 極小 connector | EMU < 36576 |
| RGBA 圖片 | mode == RGBA/PA |
| 超大圖片 | 寬 > 1920×1.1 px |
| 損壞圖片 | PIL verify 失敗 |
| ZIP 完整性 | testzip 失敗 |
| XML 解析 | parse 失敗 |
| rId 關聯 | slide rId → target 缺失 |

## E.3　`_safe_add_picture()`（保底層）

| 功能 | 處理 |
|------|------|
| RGBA/PA → RGB | 白色背景 paste + alpha mask |
| > 1920px | LANCZOS 降解析度 |
| ICC profile | 移除 |
| 嵌入方式 | tempfile（非 BytesIO） |
| 檔案不存在 | 警告跳過 |

## E.4　除錯流程（5 步）

1. **程式化檢查**：`_verify_pptx_rendering_safety()` 列 CRITICAL
2. **若程式化 PASS 但 PPT 仍失敗**：
   - 檢查 dangling `Image.open()`（**最常見隱形問題**）
   - 檢查 images/ 是否 RGBA：`python3 -c "from PIL import Image; print(Image.open('x.png').mode)"`
   - 預先轉換所有圖片為 RGB
3. **定位問題 slide**：PPT 中逐頁檢視找第一個白頁
4. **常見元兇排序**：
   1. dangling PIL + RGBA（問題 2）
   2. connector 零尺寸（問題 1）
   3. 超大圖片（問題 3）
   4. 背景缺失（問題 6）
5. **修復後**：確認 `RENDERING SAFETY: ✅ PASS` **且**實際 PPT 開啟確認
