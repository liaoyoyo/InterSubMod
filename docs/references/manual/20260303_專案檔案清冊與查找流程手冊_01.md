# 專案檔案清冊與查找流程手冊

## 1. 清冊檔案入口

1. 全專案檔案清冊（含大小與時間）  
   `docs/reports/validated/2026/03/assets/20260303_repository_full_file_inventory_01.tsv`
2. 全專案目錄清冊  
   `docs/reports/validated/2026/03/assets/20260303_repository_directory_inventory_01.txt`
3. docs 子樹清冊（含 category/state/year/month）  
   `docs/reports/validated/2026/03/assets/20260303_docs_file_inventory_01.tsv`

## 2. 欄位定義

### 2.1 `20260303_repository_full_file_inventory_01.tsv`

1. `path`：相對於 repo root 的檔案路徑
2. `top_dir`：第一層目錄
3. `ext`：副檔名（無副檔名為空字串）
4. `size_bytes`：檔案大小（bytes）
5. `mtime`：最後修改時間（local time）

### 2.2 `20260303_docs_file_inventory_01.tsv`

1. `path`：相對於 `docs/` 的路徑
2. `category`：docs 第一層類別
3. `state`：狀態（如 validated/finalized/in_progress）
4. `year` / `month`：日期分層（可空）
5. `ext` / `size_bytes` / `mtime`：檔案屬性

## 3. 常用查找流程

1. 找「最終結論」：優先查 `docs/reports/finalized/YYYY/MM/`
2. 找「可驗證方法」：查 `docs/reports/validated` 與 `docs/experiments/validated`
3. 找「執行規劃」：查 `docs/plans/YYYY/MM/`
4. 找「特定問題修復」：查 `docs/solutions/{topic}/YYYY/MM/`
5. 找「舊資料」：查 `docs/archive/YYYY/MM/`，最後才查 `docs/archive/deep/`

## 4. 盤點更新步驟（不刪檔）

1. 重新產生清冊檔（full/docs/directory）。
2. 重新統計 `docs` 類別數量與副檔名分佈。
3. 對非 Markdown 檔進行人工判斷：
   - 是附件：保留在對應主題目錄。
   - 是暫存/中介輸出：搬到 `docs/archive/YYYY/MM/...pending_review.../`。
4. 為每次搬移新增 `move_manifest`。
5. 更新 `docs/README.md` 與對應報告。
