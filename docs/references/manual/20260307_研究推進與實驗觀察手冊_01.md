# 研究推進與實驗觀察手冊

## 1. 每次啟動前必做

### 1.1 固定必讀

1. [docs/CURRENT_FOCUS.md](../../CURRENT_FOCUS.md)
2. [docs/experiments/INDEX.md](../../experiments/INDEX.md)
3. [docs/README.md](../../README.md)
4. [研究藍圖](../../research/methylation_methodology/2026/03/20260307_5kHz主實驗與方法學驗證藍圖_01.md)

### 1.2 啟動前要先寫清楚

1. 本次研究問題
2. 本次假設
3. 成功條件
4. 失敗條件
5. 主要評估指標
6. 預計輸出

## 2. 標準研究流程

### Step 1：完整理解問題與背景

必填：

- 為什麼這個問題重要
- 既有文獻或過去研究怎麼做
- repo 內已有什麼基礎
- 本次不打算做什麼

### Step 2：定義本次研究目標與驗證問題

必填：

- 本次目標
- 要驗證的假設
- 成功怎麼判定
- 失敗怎麼判定
- 要用哪些評估指標

### Step 3：盤點既有資源

必填：

- 相關資料
- 相關程式
- 相關文件
- 相關過去結論
- 缺少的元件

### Step 4：建立研究計畫與執行順序

至少區分：

- 現在必做
- 可以後做
- 有複利效果、值得先投資的腳本或工具

### Step 5：正式開始前確認重點

至少列出：

- 任務排序
- 主要風險
- 模糊點
- 需要特別觀察的數據

### Step 6：實作與分析設計

原則：

1. 先保持輸入輸出一致
2. 先小幅改動，避免一次改太多
3. 能自動化的盡量做成腳本

### Step 7：先檢查正確性，再檢查執行條件

必查：

1. 流程是否完整
2. 邏輯是否符合本次假設
3. 是否有 bug 或遺漏
4. CPU / RAM / disk / 執行時間是否足夠

### Step 8：先做小規模測試，再做正式實驗

規則：

1. 先做 minimal validation
2. 有問題先停在小規模修正
3. 大規模實驗只在流程確認後執行

### Step 9：完整記錄每次實驗

每次 round 至少記錄：

- 實驗時間
- 測試重點
- 使用資料與條件
- 改動內容
- 方法與參數
- 完成了哪些部分
- 主要結果
- 初步結論
- 特殊觀察
- 異常現象
- 下一步建議

### Step 10：驗證假設並分析異常

至少回答：

1. 結果是否支持假設
2. 哪些部分符合預期
3. 哪些部分不符合預期
4. 異常可能來自資料、參數、方法、實作還是環境

### Step 11：重排下一輪研究計畫

至少重排：

- 哪些假設要先驗
- 哪些任務要提前
- 哪些方向延後
- 哪些方向取消
- 下一輪最佳切入點

## 3. 實驗紀錄格式

### 3.1 Round summary 最少欄位

1. `created_at`
2. `sample`
3. `sample_set`
4. `test_focus`
5. `changes`
6. `data_inputs`
7. `benchmark_summary`
8. `methodology_findings`
9. `diagnostic_outputs`
10. `conclusion`
11. `next_step`

### 3.2 Benchmark 一律要寫的數字

每次都要列：

- `truth_total`
- `calls_total`
- `TP`
- `FP`
- `FN`
- `precision`
- `recall`
- `F1`

比較範例：

1. `ClairS vs SEQC2`
2. `LongPhase-S vs SEQC2`
3. `InterSubMod vs SEQC2`

## 4. 當結果不合假設時

不可只寫「效果不好」或「沒改善」。

至少要補：

1. 對應 region 或樣本的 diagnostics
2. 關聯數據表
3. 圖片輸出
4. 可能原因推理
5. 下一個可驗證修改點
