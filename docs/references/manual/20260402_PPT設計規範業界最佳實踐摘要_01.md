## 1. 文字規範

### 1.1 每頁最大文字量

| 規則 | 內容 | 來源 |
|------|------|------|
| 6x6 Rule | 每頁不超過 6 行，每行不超過 6 個詞 | 業界通用 |
| 10-20-30 Rule | 10 頁、20 分鐘、字體不小於 30pt | Guy Kawasaki / Microsoft 365 |
| 1 分鐘規則 | 每張投影片的討論時間應 ≤ 1 分鐘 | PMC 8638955 (Ten Simple Rules) |
| 認知負荷上限 | 每頁視覺元素 ≤ 6 個（超過此數認知負荷增加 500%） | PMC 8638955 |
| 中文建議 | 每頁 3-5 個重點，bullets ≤ 4 條 | 個人規範（已對齊） |

**建議常數**：

```
MAX_LINES_PER_SLIDE = 6
MAX_WORDS_PER_LINE = 6        # 英文；中文約 12-15 字
MAX_BULLETS_PER_SLIDE = 4     # 科學簡報建議更嚴格
MAX_VISUAL_ELEMENTS = 6       # 含圖、表、文字區塊、標籤
```

### 1.2 字體大小建議

#### 科學/學術簡報（Keynote / Conference Talk）

| 元素 | 最小 (pt) | 建議 (pt) | 上限 (pt) |
|------|-----------|-----------|-----------|
| 封面標題 | 36 | 44-64 | 72 |
| 頁面標題 | 28 | 32-36 | 44 |
| 副標題 | 20 | 24-28 | 32 |
| 內文/Bullet | 20 | 24-28 | 32 |
| 圖表標籤/圖例 | 16 | 18-20 | 24 |
| 腳注/來源 | 12 | 14-16 | 18 |
| Section Divider | 36 | 44-64 | 72 |

#### 文件型簡報（Send-ahead / Report Deck）

| 元素 | 最小 (pt) | 建議 (pt) | 上限 (pt) |
|------|-----------|-----------|-----------|
| 標題 | 20 | 28 | 36 |
| Headers | 16 | 20 | 24 |
| 內文 | 12 | 14-16 | 20 |
| Callout 標籤 | 12 | 14-18 | 20 |
| 附錄/細節表格 | 10 | 12 | 14 |

#### 深色背景加成

在深色背景上，字體大小應比淺色背景**增加 15-20%**，以補償感知對比度的損失。

### 1.3 字體選擇建議（科學簡報）

| 語言 | 推薦字體 | 備選 | 用途 |
|------|---------|------|------|
| 中文標題 | **Noto Sans TC Bold** (思源黑體) | 微軟正黑體 Bold | 無襯線、現代感、跨平台 |
| 中文內文 | **Noto Sans TC Regular** | 微軟正黑體 Regular | 清晰易讀 |
| 英文標題 | **Arial Bold** | Calibri Bold, Helvetica Bold | 無襯線標準 |
| 英文內文 | **Arial Regular** | Calibri, Helvetica | 無襯線標準 |
| 等寬/程式碼 | **Consolas** | Source Code Pro, Cascadia Code | 數據標籤、路徑 |

**原則**：
- 全檔無襯線字體（Sans-serif）
- 每頁不超過 3 種字級
- 避免斜體、底線、全大寫（無障礙考量）
- 粗體用於強調，取代底線與全大寫

### 1.4 行高與段落間距

| 元素 | 建議值 |
|------|--------|
| 行高 (line spacing) | 1.2-1.5x 字體大小 |
| 段落間距 (space after) | 0.5-1.0x 字體大小 |
| Bullet 間距 | 6-12 pt space before |

## 2. 視覺比例規範

### 2.1 圖片 vs 文字面積比

| 投影片類型 | 視覺 : 文字 | 說明 |
|-----------|------------|------|
| Chart-Dominant | **70-80% : 20-30%** | 圖表佔主導，僅標題+來源注 |
| Two-Column (Text + Visual) | **60% : 40%** 或 **50% : 50%** | 最通用的商務/學術版面 |
| Image + Text Side-by-Side | **50% : 50%** 或 **60% : 40%** | 產品展示、before/after |
| Full-Bleed Image | **90-100% : 0-10%** | 純視覺衝擊，文字以疊加方式 |
| Text-Heavy (Report) | **20-30% : 70-80%** | 文件型簡報限定 |

**科學簡報黃金比例**：圖表/視覺佔 **60-70%**，文字佔 **30-40%**。

### 2.2 留白比例

| 規則 | 說明 |
|------|------|
| 2/3 Rule | 約 2/3 的投影片面積應為留白（含邊距、元素間距） |
| 20-30% 文字區 | 文字佔投影片面積的 20-30%，其餘為視覺+留白 |
| 黃金比例 | 1:1.618 比例用於元素配置 |
| Rule of Thirds | 將畫布分為 3x3 九宮格，重點放在交叉點 |

### 2.3 安全邊距（Margins / Safe Zone）

**16:9 投影片 (13.333" x 7.5")**：

| 邊距類型 | 推薦值 (inches) | python-pptx EMU |
|----------|----------------|-----------------|
| 標準邊距（四邊） | 0.75" | 685,800 |
| 最小安全邊距 | 0.5" | 457,200 |
| 上方（標題區保留） | 1.0" | 914,400 |
| 底部（頁碼/來源區） | 0.5" | 457,200 |

**安全內容區域**（Safe Content Area）：

```
左邊界: 0.75"
右邊界: 13.333" - 0.75" = 12.583"
上邊界: 1.0"（標題下方）
下邊界: 7.5" - 0.5" = 7.0"

安全區域寬: 11.833"
安全區域高: 6.0"
安全區域面積: 71.0 sq in（佔投影片 71%）
```

### 2.4 元素間距

| 間距類型 | 建議值 |
|---------|--------|
| 群組間距（大間距） | 0.4"-0.6" |
| 群組內元素間距（小間距） | 0.15"-0.25" |
| 標題與內容間 | 0.3"-0.5" |
| 圖表與說明文字間 | 0.15"-0.25" |

## 3. One Slide One Message 原則

### 3.1 核心原則

每張投影片只傳遞**一個**核心訊息。觀眾應在 **10 秒內**就能理解該頁的重點。

| 原則 | 具體做法 |
|------|---------|
| 一頁一重點 | 每頁只回答一個問題或傳遞一個結論 |
| Assertion-Evidence | 標題寫結論（如「CTNND1 is central to metastasis」），而非描述（如「Results」） |
| 10 秒法則 | 觀眾應在 10 秒內抓到重點，否則需拆頁 |
| 1 分鐘法則 | 每頁討論時間 ≤ 1 分鐘；20 分鐘報告 ≈ 20 張投影片 |

### 3.2 如何拆分複雜內容

**必須拆頁的信號**：
1. 同一頁超過一張圖表
2. 一頁同時講背景、方法、結果、結論
3. 文字縮到 16pt 以下才放得下
4. 觀眾需要很長時間才找到重點
5. 需要指著多個區塊才能講清楚
6. 多面板圖（multipanel figure）在論文中是一張，但在簡報中應拆成每面板一頁

**拆分策略**：
- **時間序拆分**：背景 → 方法 → 結果 → 結論，各自一頁
- **層次拆分**：總覽 → 細節 → 結論，漸進式深入
- **對比拆分**：A 方案一頁 → B 方案一頁 → 比較一頁
- **證據鏈拆分**：假說 → 實驗設計 → 數據 → 結論

### 3.3 Transition Slides 的用法

Transition slides（過渡頁）的目的是提供**心理分隔**，讓觀眾在主題切換時有緩衝。

| 用途 | 設計建議 |
|------|---------|
| Section Divider | 大字標題（44-64pt）+ 5 個字以內 + 全版背景色或全版圖片 |
| Progress Indicator | 顯示「目前在哪」的大綱 highlight |
| Bridge Slide | 連結前後兩段的過渡語（「從 X 我們知道..., 接下來看 Y...」） |
| Recap/Breath | 重述前段結論再引出下段 |

**設計原則**：
- 所有 Section Divider 風格一致（同字體、同配色、同版面）
- 文字量極少，以視覺為主
- 強調當前章節名，弱化其他章節

### 3.4 Section Divider 的設計

```
┌──────────────────────────────────────────────┐
│                                              │
│          [深色背景或全版圖片]                  │
│                                              │
│       Section 02                             │
│       ────────────                           │
│       結果與驗證                              │
│       Results & Validation                   │
│                                              │
│       (44-64pt 主標 + 18-24pt 副標)           │
│                                              │
└──────────────────────────────────────────────┘
```

## 4. 科學/研究簡報特殊規範

### 4.1 數據圖表的展示方式

| 規則 | 說明 |
|------|------|
| 一圖一問 | 每張圖表必須回答一個明確的研究問題 |
| 圖佔 70-80% | Chart-Dominant layout，圖表佔投影片 70-80% |
| 軸標籤必備 | 所有軸必須有清楚標籤、單位、足夠大的字體（≥16pt） |
| 圖例必備 | 圖例字體 ≥16pt，位置不遮擋數據 |
| 結論式標題 | 標題寫數據的結論，而非「Figure 3」 |
| 來源注 | 圖表下方標注資料來源與時間範圍 |
| 去噪 | 移除不必要的格線、邊框、3D 效果 |
| 色盲友善 | 使用色盲安全色板（避免紅/綠並排） |
| 直接標注 | 在數據點旁直接標注數值，減少查閱圖例的需求 |

**多面板圖在簡報中的處理**：
- 論文中的 multi-panel figure 應拆成每面板一頁
- 每頁只展示一個 panel，配合口頭說明
- 如需完整全景，用一頁「總覽」後再逐頁深入

### 4.2 流程圖/機制圖的設計

| 原則 | 具體做法 |
|------|---------|
| 分組 ≤ 4 | 每張投影片的流程圖顯示 ≤ 4 個主要群組 |
| 一致符號 | 同一份簡報中，相同意義的變數/過程使用相同的形狀、大小、顏色 |
| 漸進色彩 | 使用顏色變化表示流程進展 |
| 標籤完整 | 每個節點至少包含：名稱標籤 + 解釋標籤 + 詳細圖例 |
| 方向一致 | 流程方向一致（左→右 或 上→下） |
| 對照組標記 | 實驗流程圖應一目了然地顯示實驗組 vs 對照組 |

### 4.3 假說驗證的視覺化表達

**推薦三頁結構**：

```
[頁 1: 假說]
┌──────────────────────────────────┐
│  假說：LOH enrichment 在 TP 中更高  │
│                                    │
│  ┌──────┐    ┌──────┐             │
│  │ NULL │→→→→│ ALT  │             │
│  │ H0   │    │ H1   │             │
│  └──────┘    └──────┘             │
│  預期：enrichment > 1.0            │
└──────────────────────────────────┘

[頁 2: 數據/證據]
┌──────────────────────────────────┐
│  結果：TO enrichment = 0.805x     │
│                                    │
│  [圖表：7 樣本 enrichment bar]      │
│  [統計：p-value, CI]               │
└──────────────────────────────────┘

[頁 3: 結論/判決]
┌──────────────────────────────────┐
│  ✗ H1 REJECTED                    │
│                                    │
│  原因：TO LOH 是 TP marker         │
│  影響：方向需反轉                    │
│  下一步：...                        │
└──────────────────────────────────┘
```

### 4.4 Before/After 對比展示

| 方法 | 適用情境 | 版面 |
|------|---------|------|
| 左右並列 | 修正前後的數值/圖表 | 50:50 或 40:60 分割 |
| 上下並列 | 同一圖表的兩版本 | 各佔 45%，中間留間距 |
| 疊加動畫 | 同一位置的漸變 | 先顯示 before，再疊加 after |
| Big Number | 關鍵指標的前後對比 | 大數字 + delta 標注 |
| Grouped Bar | 多組別的前後對比 | Chart-Dominant layout |

**Before/After 必備元素**：
- 明確的「修正前」/「修正後」標籤
- Delta 值（差異量）+ 方向箭頭
- 顏色區分（灰色=before, 強調色=after）
- 統計顯著性標注

## 5. 深色主題特殊考量

### 5.1 對比度要求

| 元素 | 最低對比度 | 推薦對比度 | WCAG 等級 |
|------|-----------|-----------|-----------|
| 內文（≤24pt） | 4.5:1 | 7:1 | AA / AAA |
| 大字（>24pt） | 3:1 | 4.5:1 | AA |
| 圖表標籤 | 4.5:1 | 7:1 | AA / AAA |
| 裝飾性元素 | 不適用 | 3:1 | - |

**投影機補償**：投影時感知對比度降低約 **30%**，設計時應預留此補償量。

### 5.2 深色背景色推薦

| 色名 | HEX | 用途 |
|------|-----|------|
| Charcoal Gray | `#1E1E1E` | 通用深色背景，減少眩光 |
| Midnight Blue | `#0A1929` | 現代企業感 |
| Deep Navy | `#1E2A44` | ISM 現用主色 |
| Pure Black | `#000000` | 最大對比，戲劇效果（慎用） |
| Gradient | `#1A1A1A` → `#0A0A0A` | 垂直漸層，10-15% 亮度差 |

### 5.3 深色背景文字色推薦

| 元素 | HEX | 對比度 vs #1E1E1E |
|------|-----|-------------------|
| 主標題 | `#F5F5F5` (Off-white) | ~15:1 |
| 內文 | `#D1D1D1` (Light gray) | ~10:1 |
| 次要資訊 | `#A0A0A0` (Medium gray) | ~5.5:1 |
| 弱化/隱性 | `#808080` (Gray) | ~3.5:1 |

**重要**：避免純白 `#FFFFFF` 在純黑 `#000000` 上（21:1 對比度過高，造成眼疲勞）。使用 Off-white 搭配 Charcoal 是最佳組合。

### 5.4 強調色使用

| 色名 | HEX | 用途 |
|------|-----|------|
| Cyan | `#00BCD4` | 主強調色、連結、正面指標 |
| Magenta | `#E91E63` | 警告、重要變化 |
| Lime | `#CDDC39` | 成功、增長 |
| Blue-gray | `#607D8B` | 中性強調 |
| Pale Orange | `#FFAB91` | 暖色調補充 |

**強調色原則**：
- 使用**去飽和色（desaturated / pastel）**，避免高飽和色在深色上造成視覺振動
- 強調色在色輪上應相距 **90-120 度**
- 亮色佔比 **< 15%**（避免喧賓奪主）
- 限制為 3 個主色 + 2 個強調色

### 5.5 陰影與層次

| 技法 | 做法 |
|------|------|
| 卡片層次 | 比背景亮 5-10% 的色塊作為卡片背景 |
| 微陰影 | 0-2px blur, 1-2px offset, 20-30% opacity 黑色 |
| 分隔線 | 比背景亮 10-15% 的細線（0.5-1pt） |
| 避免 | 不用 drop shadow、不用漸層邊框、不用發光效果 |

### 5.6 深色 vs 淺色的字體調整

在深色背景上：
- 字體大小增加 **15-20%**
- 使用 **Medium** 字重（Light 字體會消失，Extra-Bold 會模糊）
- 增加字間距（letter spacing / tracking）防止字元黏連
- 行高增加至 **1.4-1.6x**

### 6.2 科學簡報常用頁型優先序

1. **Chart-Dominant** (最常用)
2. **Two-Column (Text+Visual)**
3. **Side-by-Side Comparison** (before/after)
4. **Process Flow** (方法論)
5. **Big Number** (關鍵數據)

### 7.9 對比度檢查函數

```python
def relative_luminance(hex_color: str) -> float:
    """計算相對亮度 (WCAG 2.1 定義)"""
    hex_color = hex_color.replace("#", "")
    r, g, b = (int(hex_color[i:i+2], 16) / 255.0 for i in (0, 2, 4))

    def linearize(c):
        return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4

    r, g, b = linearize(r), linearize(g), linearize(b)
    return 0.2126 * r + 0.7152 * g + 0.0722 * b


def contrast_ratio(color1: str, color2: str) -> float:
    """計算兩色的對比度比值 (WCAG 2.1)"""
    l1 = relative_luminance(color1)
    l2 = relative_luminance(color2)
    lighter = max(l1, l2)
    darker = min(l1, l2)
    return (lighter + 0.05) / (darker + 0.05)


def check_wcag_aa(text_color: str, bg_color: str, is_large_text: bool = False) -> bool:
    """檢查是否符合 WCAG AA 標準"""
    ratio = contrast_ratio(text_color, bg_color)
    threshold = 3.0 if is_large_text else 4.5
    return ratio >= threshold


def check_wcag_aaa(text_color: str, bg_color: str, is_large_text: bool = False) -> bool:
    """檢查是否符合 WCAG AAA 標準"""
    ratio = contrast_ratio(text_color, bg_color)
    threshold = 4.5 if is_large_text else 7.0
    return ratio >= threshold


# === 驗證 ISM 深色主題 ===
# contrast_ratio("F5F5F5", "1E2A44")  → ~13.2:1 (AAA pass)
# contrast_ratio("D1D1D1", "1E2A44")  → ~9.3:1  (AAA pass)
# contrast_ratio("A0A0A0", "1E2A44")  → ~5.0:1  (AA pass)
```
