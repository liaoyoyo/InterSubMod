# HTML preview + 圖示生成 3-skill 設計規格

## TL;DR

建立 3 個互補的 Claude Code skill，分**三 Phase** 落地，整合到既有 myPPT 工作流：

| Skill | Phase | 職責 |
|-------|-------|------|
| `image-gen` | 1 | `prompts/*.txt` → `figures/*.png`（封裝既有 `image_gen_pipeline.sh` + `gpt-image-2`，4 類 prompt 模板） |
| `image-vision-check` | 1 | `figures/*.png` → 6 維 quality checklist（Claude `Read` 讀圖，自動重生 1 次） |
| `html-preview` | 2 | `foo.md` → 旁邊建主題資料夾 `foo/` 含 `index.html` + `ch{NN}.html` + `README.md` + `figures/` + `prompts/`（**主題資料夾化**） |
| **既有 6 個 Tier A skill 接入** | **3** | Tier A skill 結束時 opt-in / opt-out / myPPT 自動觸發 html-preview 產主題資料夾（**companion，不取代 .md**） |

**Phase 1 acceptance**：能跑通 `prompt → PNG → vision check pass → 嵌入示範 demo 主題資料夾顯示`（demo HTML，驗證閉環）。
**Phase 2 acceptance**：`/html-preview InterSubMod/docs/foo.md` 自動建 `InterSubMod/docs/foo/` 主題資料夾、產 `index.html` (主入口 + ToC) + 多章節 HTML + `README.md` (資料夾說明 + 連回 .md source)，遵循 Anthropic 設計禁忌，預設 L2-bake、偵測升級 L3。
**Phase 3 acceptance**：Tier A 6 個既有 skill (`structured-tech-report` / `weekly-report` / `results-report` / `feature-layered-observation` / `methodology-audit` / `conclude-research`) 結束時自動 invoke html-preview 產主題資料夾（companion 模式，**.md 永不取代**）。

## 1. 背景與動機

### 1.1 用戶痛點（PI 自述）

> 「之後的部分要介紹內容的話，可以先同時再撰寫使用 HTML 格式檢視與確認的文件格式，加速我確認細節與了解感覺，也同時保留 .md 當作重點與格式紀錄」

當前痛點：
- 寫 .md → 直接看 raw markdown 在 terminal 或 GitHub render，**無法快速看到「PI 視角」的版面感覺**
- 圖片需求散落各報告，**無統一 prompt 模板與品質檢核**
- 既有 `image_gen_pipeline.sh` 可生圖，但**沒有自動 vision check 回路**

### 1.2 業界趨勢印證（2026 May）

- **Anthropic 2026-05-08 改 Claude Code 預設**：`thariq` 推動「9 個 category 預設產 HTML 而非 markdown」
  ([Simon Willison May 8 報導](https://simonwillison.net/2026/May/8/unreasonable-effectiveness-of-html/))
- **官方 companion pattern**：MD 是「可編輯源 / git diff 友善 / LLM 消費」，HTML 是「視覺化交付物 / 多人閱讀」，**兩者同時 commit 進 PR**
- **設計禁忌**（明確列出）：no gradients、no 多種 indigo、no emoji-decorated headers、no glass morphism — 維持 print-friendly 與專業感
- **技術約束**：單檔、內聯 CSS/JS、圖片用 Base64 或 inline SVG、system-ui font、零網路呼叫
- 現成參考 skill：[dogum/html-artifacts](https://github.com/dogum/html-artifacts)
- 圖片 prompt 範例庫：[awesome-gpt-image](https://github.com/ZeroLu/awesome-gpt-image)（純 prompt 範例，**無 quality check 標準**，需自行定義）

### 1.3 與既有 skill 的邊界

| 既有 skill | 職責 | 不衝突原因 |
|-----------|------|---------|
| `pptx-build` | 產 PPTX deck | 圖示需求改委派 image-gen；HTML preview 不取代 PPTX |
| `weekly-report` | 產 W1–W7 母稿 | 母稿仍 markdown；html-preview 是 companion |
| `structured-tech-report` | 產 13 段技術報告 .md | 同上，html-preview companion |
| `myPPT` | 場景識別入口 | 擴充識別「需 HTML preview」「需補圖」分支 |
| `scripts/lib/image_gen_pipeline.sh` | OpenAI gpt-image-2 batch | image-gen skill 直接封裝它，不重做 |
| `scripts/lib/plot_setup.py` | matplotlib 真實數據圖 | 不變；image-gen 只負責「示意圖 / icon / 概念」 |

## 2. 14 項已決策摘要

| # | 項目 | 決策 |
|---|------|------|
| D1 | Skill 範圍切割 | 三個 skill：html-preview + image-gen + image-vision-check |
| D2 | 呼叫鏈整合 | 各 skill 獨立可觸發 + myPPT 可調度 + AI 在對話中主動判斷啟動 |
| D3 | HTML 互動深度 | 預設 L2-bake (Tailwind precompiled inline) + 偵測自動升 L3 (Alpine.js) |
| D4 | HTML 生命週期 | **主題資料夾 + companion + 進 git**：`foo.md` 旁建同名資料夾 `foo/`，內含 `index.html` (主入口) + `ch{NN}_{slug}.html` (分章節) + `README.md` (資料夾說明 + 連回 .md source)；資料夾與 `.md` 一起 commit |
| D5 | 圖片分類 | 4 類：concept_diagram / flow_diagram / data_mockup / icon |
| D6 | Vision check 維度 | 6 維度 + 4/6 通過閾值 |
| D7 | 圖檔儲存 | **主題資料夾內** `prompts/` 進 git（可重生）；**主題資料夾內** `figures/` `.gitignore` 不進；HTML inline base64 |
| D8 | 重生策略 | Vision fail 自動重生 1 次，再 fail → 上報 checklist 讓 PI 手動調 prompt |
| D9 | 首批實作範圍 | Phase 1: image-gen + image-vision-check + 端到端 demo 主題資料夾；Phase 2: html-preview 完整 skill；**Phase 3**: Tier A 6 個既有 skill 接入 |
| **D10** | **Tier A skill 接入範圍** | **6 個 skill 加 companion HTML**：`structured-tech-report` / `weekly-report` / `results-report` / `feature-layered-observation` / `methodology-audit` / `conclude-research`（依 Anthropic "Reports & Research / Diagrams" category） |
| **D11** | **取代 vs 並存** | **絕對 companion 不取代**。理由：(1) LLM 消費 (其他 AI agent 讀 .md)；(2) git diff 細粒度 review；(3) `grep` 全專案搜尋；(4) repo 內部索引 (`INDEX.md`/`MEMORY.md`/`evidence_ledger.jsonl`) 引用都靠 .md |
| **D12** | **資料夾命名規則** | 主題資料夾名 = `.md` basename（不含副檔名）；內部 HTML 命名 `index.html` / `ch{NN}_{slug}.html` / `appendix_{slug}.html`；圖檔 `fig{N}_{slug}.png`；`README.md` 自動生成資料夾說明 |
| **D13** | **AI 生圖後端** | **只走 codex CLI + ChatGPT OAuth**（已 login）。透過 `codex exec --image-dir <dir> "<prompt> $imagegen"` 呼叫內建 `$imagegen` skill (gpt-image-2)。**免 USD 帳單**，但吃 ChatGPT 訂閱 usage quota（~30k agent tokens/張 low quality，消耗 3-5×）。既有 `scripts/lib/image_gen_pipeline.sh`（OPENAI_API_KEY 路徑）標記 deprecated，可作 fallback 但 skill 不主動使用。 |
| **D14** | **生圖雙軌** | **AI 軌（codex $imagegen）+ 程式軌（cairo）分工**：concept_diagram / data_mockup → AI 軌；flow_diagram / icon → cairo 軌（pycairo 程式繪圖，**不會錯字、不吃 quota、可 batch、deterministic**）。**PIL（Pillow）統一後製**：所有產出 → resize / crop / Base64 encode 供 html-preview inline。 |

## 3. Phase 切分

### 3.1 Phase 1（本輪先做，預估 2-3 工作天）

**目標**：圖片生成與檢核閉環跑通，**端到端 demo 主題資料夾顯示驗證**。

交付物：
1. `InterSubMod/.claude/skills/image-gen/`（完整 skill）
2. `InterSubMod/.claude/skills/image-vision-check/`（完整 skill）
3. `InterSubMod/examples/phase1_demo/demo_topic/`（**主題資料夾 demo**，手寫 HTML，不是 skill，僅驗證閉環）：
   ```
   examples/phase1_demo/
   └── demo_topic/                      ← 主題資料夾 (示範 D4/D12)
       ├── README.md                    ← 資料夾說明 (手寫 demo)
       ├── demo_topic.md                ← 來源 .md (含 4 類圖示需求)
       ├── index.html                   ← 主入口 (極簡 HTML，無 Tailwind)
       ├── prompts/                     ← in git
       │   ├── fig1_concept_loh.txt
       │   ├── fig2_flow_pipeline.txt
       │   ├── fig3_data_mockup.txt
       │   └── fig4_icon_status.txt
       └── figures/                     ← .gitignore
           ├── fig1_concept_loh.png
           ├── fig2_flow_pipeline.png
           ├── fig3_data_mockup.png
           └── fig4_icon_status.png
   ```
   - `index.html` 規格：純 HTML5 + `<style>` ~50 行 CSS（system-ui font + 簡單排版，**不用 Tailwind**）
   - 4 張圖以 `<img src="data:image/png;base64,...">` inline
   - 每張圖下方顯示 vision check verdict + score
   - **目的單純**：驗證 base64 inline 顯示效果、PI 確認「圖能用、嵌入無問題、主題資料夾結構合理」
   - **不是 Phase 2 html-preview 的 design 預覽**（Phase 2 才用 Tailwind L2-bake）
4. `InterSubMod/.gitignore` 補規則：`examples/**/figures/*.png` + `docs/**/figures/*.png` + `**/figures/*.png`
4. `.gitignore` 補規則：`docs/**/figures/*.png` + `examples/**/figures/*.png`

### 3.3 Phase 3（Phase 2 ship + PI 確認後再啟動）

**目標**：Tier A 6 個既有 skill 自動產 companion 主題資料夾。

交付物：
1. 修改 6 個 Tier A skill 的 SKILL.md 與 playbook，在最後一步加「invoke html-preview」步驟
2. 觸發機制（依 D2 + 用戶後續確認決定）：
   - **opt-in flag**：每個 skill 加 `--with-html-preview`（預設關）
   - **opt-out flag**：預設開、加 `--no-html-preview` 跳過
   - **myPPT 智能路由**：myPPT 偵測「PI 要看 / 列印 / 給教授」場景時自動帶
3. 對既有產 .md 的回填：選定一批代表性既有 .md（5-10 份）回填產主題資料夾，作為 examples + style baseline

**Acceptance criteria**：
- [ ] Tier A 6 個 skill 各自跑一次，產生符合 D4/D12 主題資料夾結構
- [ ] 既有 .md 不受影響（可回滾、可刪除主題資料夾不影響 .md）
- [ ] PI 確認 6 個 skill 的 HTML 樣式一致、可讀性符合期待
- [ ] `INDEX.md`、`MEMORY.md`、`evidence_ledger.jsonl` 內 .md 路徑引用全部維持有效

## 5. Skill 細節規格

### 5.1 `image-gen` skill

**SKILL.md `description` 觸發詞**（需豐富，符合 D2「對話中主動判斷啟動」）：

> **Use when**：「需要示意圖」「畫個流程圖」「補個 icon」「LOH 概念圖怎麼示意」「報告補圖」「生成圖片」「生圖」「畫示意」「畫個概念圖」「補張圖」「需要圖」「插圖」、PI 寫報告時提到圖片需求。
>
> **Skip when**：matplotlib/seaborn 真實數據圖（用 `scripts/lib/plot_setup.py`）、UI 截圖（用瀏覽器開發工具）、文字流程（用 mermaid markdown）。

**4 類 prompt 模板共通結構**：

```yaml
type: concept_diagram | flow_diagram | data_mockup | icon
subject: <主體>
key_elements: [<元素1>, <元素2>, ...]
labels: {<位置>: "<label>"}
style:
  palette: [<顏色1>, <顏色2>]   # 限 2-3 色，no gradient
  font: system-ui (隱含)
  background: white | transparent
  composition: centered | flow_left_to_right | grid_2x2
constraints:
  - no gradient overuse
  - no glass morphism
  - colorblind-friendly (no red/green pair)
  - print-friendly contrast >= 4.5:1
output:
  size: 1024x1024 | 1024x1536
  quality: high
```

**呼叫鏈**（D13 + D14 雙軌）：

```bash
/image-gen <prompts_dir> <figures_dir> [--quality high|medium] [--max-retries 1]
  ↓
tools/dispatch.py 讀每個 prompt YAML 的 type 欄位
  ├─ type ∈ {concept_diagram, data_mockup} → AI 軌
  │     codex exec --image-dir <figures_dir> \
  │       "$(cat prompts/{slug}.txt) $imagegen"
  │     ↓
  │     codex 寫到 ~/.codex/generated_images/ 或 --image-dir 指定
  │     ↓
  │     tools/codex_output_collector.py 搬到 <figures_dir>/{slug}.png
  │
  └─ type ∈ {flow_diagram, icon} → 程式軌
        tools/cairo_render.py prompts/{slug}.txt → <figures_dir>/{slug}.png
        (pycairo: 讀 YAML 描述 → 計算節點/箭頭/文字座標 → PNG)
  ↓
tools/pil_postprocess.py（共用）
  - resize 統一規格（1024×1024 預設、icon 256/512）
  - 補加標題 watermark（可選）
  - 不做 base64 encode（留給 html-preview 階段）
  ↓
<figures_dir>/{slug}.png 最終輸出
```

**成本提示**（skill 啟動時一行告知）：
> `[image-gen] 偵測 N 個 prompts (AI×k, cairo×m)。AI 路徑吃 ChatGPT quota ~30k tokens/張；cairo 路徑零成本。啟動？`

**Pre-flight check**（skill 啟動時驗證）：
1. `codex login status` 含 "Logged in" → 否則錯誤訊息「請先 `codex login`」
2. `python3 -c "import cairo"` → 否則「請 `pip install pycairo`」
3. `python3 -c "import PIL"` → 否則「請 `pip install Pillow`」

### 5.2 `image-vision-check` skill

**SKILL.md `description` 觸發詞**：

> **Use when**：「圖夠不夠好」「圖達標了嗎」「檢核圖片」「這張圖能用嗎」「vision check」「品檢」「review 圖」、image-gen 產出後自動觸發。
>
> **Skip when**：真實數據圖（用人眼確認 + statistical test）、PPTX 內已 review 過的圖。

**6 維度 checklist**（D6）：

```markdown
## Vision Check Checklist (per image)

1. [ ] **Prompt fidelity** — 圖中可辨識描述的核心物件/概念
2. [ ] **可讀性** — 中英文無亂碼、字型統一、可閱讀
3. [ ] **重點突出** — 主體與背景對比、視覺層次清楚
4. [ ] **設計禁忌** — 無 gradient overuse / glass morphism / multi-indigo / emoji headers
5. [ ] **列印友善** — 對比 ≥ 4.5:1、不依賴顏色傳遞訊息（colorblind-friendly）
6. [ ] **跨圖風格一致** — 與同報告其他圖風格相近（首張定基調）

## Verdict
- 6/6 ✅ pass
- 4-5/6 ⚠️ partial → 自動重生 1 次 → 仍 fail 則上報
- ≤3/6 ❌ fail → 自動重生 1 次 → 仍 fail 則上報

## Output: quality.json
{
  "image": "fig1_loh_diagram.png",
  "version": 1,
  "checks": {
    "prompt_fidelity": true,
    "readability": true,
    "focal_clarity": false,
    "design_taboos_avoided": true,
    "print_friendly": true,
    "cross_figure_consistency": true
  },
  "score": "5/6",
  "verdict": "partial",
  "suggestions": [
    "focal_clarity: 主體與背景對比不夠，建議 prompt 加 'high contrast subject', dark background, dramatic lighting"
  ],
  "retry_history": [{"version": 1, "score": "3/6"}, {"version": 2, "score": "5/6"}]
}
```

**重生策略**（D8）：

```
v1 fail (≤3/6 OR 4-5/6 含 critical fail)
  ↓
讀 vision check suggestion → 自動 patch prompt
  ↓
重跑 image-gen → v2.png
  ↓
re-vision check
  ↓
v2 pass → 收工
v2 fail → 寫 quality.json verdict=needs_human + 列 checklist 給 PI
```

### 5.3 `html-preview` skill（Phase 2）

**SKILL.md `description` 觸發詞**：

> **Use when**：「想看看排版」「給 PI 看 preview」「快速確認感覺」「報告 HTML 預覽」「companion HTML」「preview html」「html preview」「.md 預覽」「給人看的版本」、寫完報告 .md 後 PI 提到「想先看看」。
>
> **Skip when**：README.md（GitHub 渲染即可）、Slack 片段、給其他 LLM 用的 .md、純個人筆記、CI 自動化文件。

**核心轉換流程**（**主題資料夾架構**）：

```
foo.md
  ↓
1. tools/topic_folder_builder.py
   - 在 foo.md 同層建 foo/ 主題資料夾
   - 建 prompts/ + figures/ 子目錄 (figures/ 含 .gitkeep)
   - 偵測 .md 內含 <!-- figure-needed: ... --> → 寫 prompts/*.txt 範本
  ↓
2. tools/interactivity_detect.py 掃 .md
   - 找 <!-- interactive: tab|filter|slider --> 標記
   - 偵測 weekly-report W7 多方案比較表
   → 決定 L2 or L3
  ↓
3. tools/md_to_html.py
   - pandoc .md → 中間 HTML
   - 依 H1/H2 切章節 → ch01_{slug}.html / ch02_{slug}.html / ...
   - beautifulsoup4 重組為 chapter_l2.html (套用 components/*)
   - 產 index.html (含 ToC + 章節連結 + 第一章內容預載入)
  ↓
4. tools/tailwind_precompile.sh
   - tailwindcss CLI scan 所有產出 HTML 的 utility class
   - 產 ~25 KB CSS → inline 進每個 .html 的 <style>
   - (避免重複: 共用 CSS 提取為 design_tokens.css inline)
  ↓
5. tools/inline_assets.py
   - 對每個 ch*.html 內 <img src="figures/*.png"> → Base64 inline
   - SVG → inline
   - (figures/*.png 仍保存於資料夾內供重生用)
  ↓
6. README.md 自動生成 (components/readme_template.html)
   - 列出 source .md 連結
   - 列出所有 HTML 入口
   - 圖檔 ↔ prompt 對應表
   - 重建指令
  ↓
7. design_taste_check.md (Claude 自審)
   - 對 index.html + 所有 ch*.html 確認無 gradient/glass morphism/multi-indigo/emoji headers
  ↓
foo/ 主題資料夾 (內含 README.md + index.html + ch*.html + figures/ + prompts/)
```

## 7. 技術 stack 細節

### 7.1 image-gen 依賴（D13 + D14）

**主路徑（必裝）**：
- `codex` CLI v0.125.0+ 已 `Logged in using ChatGPT`（透過 `codex login` 完成 OAuth）
- `python3` + `pycairo`（cairo 程式繪圖）→ `pip install pycairo` 或 `apt install python3-cairo`
- `python3` + `Pillow`（PIL fork，圖檔後製）→ `pip install Pillow`
- `pyyaml`（讀 prompt YAML）→ `pip install pyyaml`

**模型**：
- `gpt-image-2`（codex CLI 內建 default，2026-04-21 launched，透過 `$imagegen` 觸發）

**成本模型**：
- AI 軌：吃 ChatGPT 訂閱 usage quota，~30k agent tokens/張 low quality（消耗 3-5×）
- 程式軌：零成本（純本機運算）

**Deprecated（保留為 fallback，skill 不主動使用）**：
- `scripts/lib/image_gen_pipeline.sh`（OPENAI_API_KEY + Python SDK 路徑）
- 標記為 `# DEPRECATED 2026-05-10: 由 image-gen skill (codex OAuth) 取代` 但**不刪除**（既有 PPTX pipeline 可能還引用）

### 7.2 image-vision-check 依賴

- Claude `Read` tool（內建，PNG 直接讀）
- `python3` + `json` 標準庫
- 無需額外 API（用 Claude 自己看圖）
- 成本 ~$0.005/張（vision prompt ~500 tokens）

### 7.3 html-preview 依賴（Phase 2）

- `python3` + `pandoc`（系統需安裝）+ `beautifulsoup4` + `jinja2`
- `tailwindcss` v4 standalone CLI binary（首次下載 ~50 MB，之後本機 build）
- `Alpine.js` 3.x CDN minified inline（~15 KB，僅 L3 用）
- 無 Node.js 需求

**Tailwind v4 standalone 安裝**：
```bash
curl -sLO https://github.com/tailwindlabs/tailwindcss/releases/latest/download/tailwindcss-linux-x64
chmod +x tailwindcss-linux-x64
mv tailwindcss-linux-x64 tools/bin/tailwindcss
```

### 7.4 設計禁忌防護（Anthropic 風格）

**雙層防護**（image-gen 與 html-preview 各自負責一層）：

**Layer 1：image-gen prompt 端**（避免「生出」禁忌風格）
- 4 類 prompt 模板的 `constraints` 區段強制列出：
  - `no gradient overuse`（漸層僅用於極少數背景，不用於主體）
  - `no glass morphism`
  - `palette limit 2-3 顏色`，禁多種 indigo 堆疊
  - `colorblind-friendly`（避 red/green pair）
  - `print-friendly contrast >= 4.5:1`
- vision check 第 4 維「設計禁忌避免」會 audit 結果，fail 則自動重生

**Layer 2：html-preview 渲染端**（避免「渲染出」禁忌風格）
- `design_tokens.css` 強制：
  - 配色限 system grayscale + 1-2 強調色（避 multi-indigo）
  - `font-family: system-ui, -apple-system, "Noto Sans CJK TC", sans-serif`
  - 移除所有 `background: linear-gradient(...)` 用法
  - 移除 `backdrop-filter: blur(...)` (glass morphism)
  - header 不放 emoji（CJK heading 例外保留中文標題符號）
- `prompts/design_taste_check.md` 在輸出前讓 Claude 自審 final HTML

## 9. 風險與 open questions

### 9.1 風險

| 風險 | 影響 | 緩解 |
|------|------|------|
| `OPENAI_API_KEY` 未設定 | image-gen 直接失敗 | image_gen_pipeline.sh 已有 pre-flight check + 清楚 error message |
| 重生後仍 fail（gpt-image-2 隨機性） | PI 需手動調 prompt | quality.json 含 suggestion 引導；最多重生 1 次後上報，避免無限燒錢 |
| Tailwind precompile 首次 ~50 MB binary 下載 | Phase 2 setup 慢 | one-time cost；放在 `InterSubMod/tools/bin/` `.gitignore` |
| HTML inline base64 後檔案大小膨脹 | git repo size +25-200 KB/份 × 多章節 | 已在 D7 接受；plain MD 不受影響；多章節分檔避免單檔過大 |
| Phase 1 demo HTML 與 Phase 2 skill 不一致 | demo 的 design 細節可能與後續 skill 衝突 | demo 故意極簡（不用 Tailwind），純驗證 base64 inline + 主題資料夾結構，不定 design 標準 |
| **主題資料夾過多堆積 docs/** | docs/reports/validated/2026/05/ 變胖 | 緩解 1：`README.md` 自動生成讓 PI 一進資料夾就有導引；緩解 2：`tree -L 1` 仍可一覽；緩解 3：可在 INDEX.md 加 emoji 標記哪些有 HTML companion |
| **既有 .md 引用的相對路徑可能失效** | weekly-report W7 母稿等內部 link 變更時 | Phase 3 接入時必先掃 `docs/**/*.md` 找相對 link，產出影響清單給 PI 確認後再回填 |
| **Tier A skill 接入時可能影響既有自動化** | 跑 batch 時意外產主題資料夾 | D2 + 後續確認：opt-in flag 預設為 off（最保守），需 PI 顯式啟用 |
| **ChatGPT usage quota 月限耗盡** (D13) | image-gen AI 軌停擺（concept_diagram / data_mockup 無法生） | 緩解 1: cairo 軌不吃 quota，flow/icon 不受影響；緩解 2: vision check 用 Claude `Read` 不依賴 codex；緩解 3: skill 啟動時 echo quota 預估、月底前 PI 盤查；緩解 4: 緊急時改回 deprecated `scripts/lib/image_gen_pipeline.sh` (需設 OPENAI_API_KEY) |
| **`pycairo` 安裝困難** (D14) | image-gen 程式軌停擺 (flow_diagram / icon 無法生) | 緩解 1: skill pre-flight check 給清楚錯誤；緩解 2: 提供 `apt install python3-cairo` (Ubuntu) 與 `pip install pycairo` 兩條安裝路徑；緩解 3: 緊急時 flow/icon 改走 AI 軌（接受錯字風險） |
| **codex `--image-dir` 行為與預期不符** (D13) | 圖未存到指定目錄、需手動搬 | 緩解：`tools/codex_output_collector.py` 同時掃 `--image-dir` 與 `~/.codex/generated_images/` 兩處，找到最新時間戳的 PNG 移到目標路徑 |
