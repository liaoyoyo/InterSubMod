## 1. 建議工作流

### 1.1 使用哪些 Agent / Skills

本流程建議固定採以下組合：

1. `intersubmod-weekly-research-agent`
   - 作用：先確認週報主線、來源文件與本輪口徑
2. `intersubmod-weekly-report-writer`
   - 作用：先把 `.md` 週報整理成穩定結構
3. `liao-research-ppt`
   - 作用：套用廖子游的固定字體、雙語、notes、版面、QA 與版本管理規則
4. `pptx`
   - 作用：將週報轉為簡報，並執行 PPTX QA
5. `intersubmod-report-prompt-refiner`
   - 作用：把你對簡報的偏好整理成固定規則與下次可重用的要求

### 1.2 這次的實作流程

1. 讀入口文件：
   - [CURRENT_FOCUS.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/CURRENT_FOCUS.md)
   - [INDEX.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/experiments/INDEX.md)
   - [README.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/README.md)
2. 讀來源週報：
   - [20260311_研究主線週報_20260305_20260311_phase2_annotation整合_01.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/reports/validated/2026/03/20260311_研究主線週報_20260305_20260311_phase2_annotation整合_01.md)
3. 讀個人簡報規範與 profile：
   - [20260311_個人PPT設計風格規範_01.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/references/manual/20260311_個人PPT設計風格規範_01.md)
   - [20260311_liao_research_ppt_profile_01.json](/big8_disk/liaoyoyo2001/InterSubMod/docs/references/manual/assets/20260311_liao_research_ppt_profile_01.json)
4. 用設定檔控制：
   - deck 標題
   - 視覺風格
   - 章節內容
   - 路徑頁面
5. 用腳本生成 `.pptx`
6. 用 `markitdown` 與 slide render 做 QA

## 2. 如何重新生成 PPTX

```bash
python /big8_disk/liaoyoyo2001/InterSubMod/scripts/analysis/build_weekly_report_pptx.py \
  --config /big8_disk/liaoyoyo2001/InterSubMod/docs/references/manual/assets/20260311_weekly_report_pptx_config_01.json
```

重新生成後，輸出預設應採：

`docs/presentations/{validated|draft}/YYYY/MM/<deck_name>/`

也就是一次輸出一個資料夾，將：

1. `.pptx`
2. `.version.json`
3. `pdf/`
4. `assets/`

集中在同一個版本資料夾中，方便：

1. 並排比較 `v01 / v02 / v03`
2. 驗證同一版的資產與 QA 是否完整
3. 避免月目錄直接堆滿 deck 檔

## 3. 設定檔可以改哪些欄位

設定檔位置：
[20260311_weekly_report_pptx_config_01.json](/big8_disk/liaoyoyo2001/InterSubMod/docs/references/manual/assets/20260311_weekly_report_pptx_config_01.json)

### 3.1 最常改的欄位

| 欄位 | 位置 | 意義 | 建議何時修改 |
| --- | --- | --- | --- |
| `meta.deck_title` | `meta` | 簡報主標題 | 改報告名稱或用途時 |
| `meta.deck_subtitle` | `meta` | 副標題 / 日期範圍 | 改時間範圍時 |
| `meta.summary_line` | `meta` | 封面破題句 | 想改高層口徑時 |
| `meta.output_pptx` | `meta` | 輸出檔案路徑 | 想另存新版本時 |
| `theme.*` | `theme` | 色彩與字體 | 想改風格時 |
| `deck.key_findings` | `deck` | 第 2 頁四張結論卡 | 想改開場重點時 |
| `deck.goals` | `deck` | 主要目標與完成度表 | 想改任務摘要時 |
| `deck.timeline` | `deck` | 時間軸內容 | 想改時間順序敘事時 |
| `deck.to_rescue` | `deck` | TO rescue 頁數據與判讀 | 更新 TO 結論時 |
| `deck.feature_roles` | `deck` | 特徵定位表 | 特徵角色有新結論時 |
| `deck.annotation_policy` | `deck` | annotation layer 頁 | annotation 口徑更新時 |
| `deck.next_steps` | `deck` | 待補齊與下一步 | 每次 round 結束後 |
| `deck.source_paths` | `deck` | 附錄路徑頁 | 想換成別的來源時 |

### 3.2 若要改投影片結構

目前腳本固定產生 12 頁：

1. 封面
2. 重點結論
3. 背景、問題與四象限
4. 主要目標與完成度
5. 時間軸
6. paired pure rerun
7. TO rescue
8. phase 2 paired raw benchmark
9. 特徵定位
10. annotation layer 決策
11. 待補齊與下一步
12. 複查路徑與重生方式

若你要增減頁面，建議修改：

1. [build_weekly_report_pptx.py](/big8_disk/liaoyoyo2001/InterSubMod/scripts/analysis/build_weekly_report_pptx.py) 裡的 `slide_builders`
2. 對應 `deck.*` 區塊

## 4. 你可以怎麼客製化

### 4.1 視覺風格

你可以直接改：

- `theme.dark`
- `theme.bg`
- `theme.bg_alt`
- `theme.accent`
- `theme.accent2`
- `theme.font_title`
- `theme.font_body`

### 4.2 內容取向

你可以透過修改文字，把簡報偏向：

1. `研究內部深度版`
   - 多放方法、風險、限制、數據意義
2. `管理摘要版`
   - 縮短表格，強化 3–5 個結論與下一步
3. `混合版`
   - 前半高層結論，後半保留技術證據鏈

### 4.3 投影片濃度

可直接調整的方向：

- 減少 `deck.source_paths`
- 減少 `deck.goals`
- 把 `deck.feature_roles` 精簡成 3–4 個特徵
- 只保留 `5kHz` 或只保留 `TO`

## 5. 問答式客製化清單

下面這份 Q/A 可直接拿來告訴 Agent 你要怎麼改：

### Q1. 這份 PPTX 的主要讀者是誰？

- `研究內部同仁`
- `PI / 管理者`
- `對外簡報`

### Q2. 你要的是哪一種風格？

- `研究內部深度版`
- `混合版`
- `管理摘要版`

### Q3. 你要不要保留完整數據表？

- `保留完整表格`
- `只留 F1 / TP / FP 核心欄位`
- `改成圖表為主`

### Q4. 你要不要保留最後的絕對路徑頁？

- `要，方便追查`
- `不要，改放 speaker notes`

### Q5. 你希望未來簡報更偏哪一種？

- `更重視證據鏈`
- `更重視視覺說服`
- `更重視會議溝通速度`

### Q6. 哪些偏好應該升級成固定規則？

建議可升級的高影響偏好：

1. 封面一定先講高層結論
2. 表格一定保留 `TP / FP / FN / F1`
3. 最後一頁一定有絕對路徑
4. 每份簡報都保留「哪些不能現在就做」頁

## 6. 下次可直接使用的指令模板

### 6.1 簡短版

```text
把最新研究週報做成一份研究內部混合版 PPTX，保留高層結論、paired/TO 核心比較、annotation layer 決策與下一步，並用既有設定檔輸出。
```

### 6.2 完整版

```text
請先讀 CURRENT_FOCUS.md、experiments/INDEX.md、docs/README.md，再把指定的 validated 週報轉成一份 .pptx。簡報要先講重點結論，接著整理背景、主要目標、paired/TO 核心數據、phase 2 benchmark、annotation layer 決策、待補齊事項與下一步。請使用絕對路徑來源，並把簡報要求寫回客製化設定檔與手冊。
```

### 6.3 高精度版

```text
請使用 InterSubMod 研究文件 agent 流程與 pptx skill，將指定週報轉成研究內部混合版 PPTX。要求如下：
1. 封面先講高層結論。
2. 保留 paired / TO / phase 2 / annotation 的完整邏輯鏈。
3. 所有數據都要有意義解釋，不只列數字。
4. 最後一頁保留可複查的絕對路徑。
5. 另外輸出一份客製化設定文件，讓我之後可以自行修改簡報風格、頁數與重點。
```

## 7. 建議下次補強的地方

1. 讓設定檔支援「選擇 slide 模板」而不是固定 12 頁。
2. 把 speaker notes 也做成可自訂欄位。
3. 讓圖表輸出支援：
   - `只保留 5kHz`
   - `只保留 TO`
   - `強調 annotation`
4. 若你之後反覆要求同一種簡報風格三次以上，建議把它正式升級成一個 `PPTX 報告 skill`。
