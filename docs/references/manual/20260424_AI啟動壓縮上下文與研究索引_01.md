# AI 啟動壓縮上下文與研究索引

> 本文件是每次 InterSubMod 研究/分析前的高密度入口。它不取代 validated reports、Knowledge Base 或 data specs；它的用途是讓 agent 在數分鐘內掌握「現在專案在哪裡、哪些數據可信、哪些方向不能重踩、下一步有什麼先後順序、哪些問題需要使用者決策」。

## 0. 使用方式

### 最小啟動讀法

1. 讀本文件 §1-§6，先取得壓縮上下文。
2. 讀 [CURRENT_FOCUS](../../CURRENT_FOCUS.md)，確認最新 P0/P1。
3. 讀 [experiments/INDEX](../../experiments/INDEX.md)，避免重複已失敗方向。
4. 若涉及結論穩定性或論文主軸，讀 [research_landscape/00_INDEX](../../reports/research_landscape/00_INDEX.md) 與 [Research Chain Registry](../../reports/research_landscape/10_Research_Chain_Registry.md)。
5. 若涉及 benchmark、truth set、F1 或 sample path，讀 [truth set 與 F1 協議](../../data_specs/20260422_truth_sets_and_f1_protocol_01.md) 並查 Knowledge Base。

### Agent 上下文控制面分工

| 入口 | 角色 | 使用原則 |
|------|------|----------|
| `AGENTS.md` | repo 內硬規則、資料/輸出位置、Knowledge Base 查閱義務 | 先判斷任務屬於 code、docs、output、runbook 或 meeting，再選落點 |

### Agent 啟動 5 問

1. 本輪是否涉及 Thread D `LOH-constrained phasing` 或 Thread B 撤回範圍？
2. 使用的是 KDE-corrected master、stale-binary master，還是未標註 provenance 的資料？
3. 是否需要 VCF caller AF，而不是 ISM TSV 的 `AlleleDelta`？
4. 是否重踩已關閉 filter / rescue / pooled OLS 方向？
5. 是否觸及使用者決策矩陣、長計算、C++ 修改、搬移/刪除等 gate？

### 壓縮規則

壓縮對話或交接任務時，必保留：

1. 當前主軸：`LOH-constrained phasing` 是 TO 層主要發現；ISM 主要價值是 characterization，不是 production FP filter。
2. 最新結論變動：Thread D 強化；Thread B S3/S5 whitelist 跨樣本失敗，降級為 per-sample characterization。
3. 資料狀態：KDE-corrected master 與 stale-binary master 必須分開；所有 2026-04-19 前 cross-sample CovM 結論需標註前提。
4. 假說 ID、verdict、evidence tier、artifacts path、待驗證 gate。
5. 使用者限制：不刪檔；新正式輸出走 `output/canonical/` 或 `output/synthesis/`；`.md` 導航路徑給使用者時以 `InterSubMod/...` 呈現。

## 1. 一段話背景摘要

InterSubMod 是 ONT 長讀序列的 read-level epigenetic characterization 工具，核心是把 somatic SNV、haplotype tag、MM/ML methylation pattern、LOH/CN/AF 背景放在同一個 region-level 框架裡解讀。過去曾嘗試把 ISM 特徵用作 TP/FP filter，但 60+ 特徵、7 樣本、約 748K regions 的系統性探索已確認：純甲基化或一般 ISM 特徵無法穩定區分 TO 模式 TP/FP，F1 改進路線已不是主軸。

目前研究重心已轉為「機制與 annotation」。2026-04-22 至 2026-04-24 的最大發現是 `HPFineNGroups` 不是直接 methylation group count，而是 `{HP1, HP1-1, HP2, HP2-1}` 四個 phasing bucket 的 occupancy count。這把原本的 methylation bimodality 敘事修正為 `LOH-constrained phasing signatures`：LOH 區 somatic SNV 在單 haplotype 物理限制下產生 same-haplotype 分裂，非 LOH 區 germline het 與 somatic het 產生 cross-het pattern，TO caller 因缺 normal context 無法分辨。

因此目前最有價值的方向不是再找 production filter，而是整理 phasing signature、paired/TO negative controls、KDE-corrected data 的穩健性、以及外部 CN/SV 工具如何補足 TO 物理限制。

| 層級 | 角色 | 目前口徑 |

## 3. 重要術語表

| 術語 | 中文詞義 | 本輪角色 |
|------|----------|----------|
| Paired mode | 腫瘤-正常配對模式 | 有 matched normal，可排除 germline het；常作 TO 機制 negative control |
| Tumor-only / TO | 只有腫瘤樣本的 somatic calling | 主要困難來源；germline het 與 somatic het 在 phasing pattern 上可能同構 |
| `HPFineNGroups` | HP fine bucket occupancy count | 不是 methylation group count；目前重詮釋為 phasing signature |
| Same-hap split | 同一 haplotype 上 ref/somatic bucket 分裂 | LOH 區 somatic SNV 的物理預期，Thread D 主證據 |
| Cross-het pattern | HP1 與 HP2-side 的 heterozygous pattern | 非 LOH 區 germline het / somatic het 在 TO 下不可分，是 germline leak 物理根源 |
| `--germline-hp-only` | demote somatic HP tag 的 ReadParser flag | HCC1395 TO 下 NG>=3 collapse to 0，作為 Thread D 內部 negative control |
| KDE diploid coverage | per-sample 2x coverage baseline | 取代 hardcoded 75x；避免 cross-sample CovM artifact |
| `Diploid_Coverage_Used` | ISM TSV audit column | 判斷該 run 是否真的用 KDE baseline 的重要欄位 |
| S3/S5 scheme | LOH x AF x CN 分層白名單候選 | 2026-04-24 X6 後跨樣本失敗，不能當全域 whitelist |
| Characterization | 生物機制/annotation 解讀 | 目前 ISM 主要價值定位 |

## 5. 已知前提與不可重踩方向

### 已驗證成立

1. ISM 的主要定位是 read-level epigenetic characterization，不是 TO production FP filter。
2. TO 模式 Paired/TO 不能混用；`pileup` 與 `full model` 來源必須明確標示。
3. `HPFineNGroups` 的字面解讀不可靠，分析任何 feature 前必查 C++ 定義。
4. `AlleleDelta` 不是 caller AF；需要 VCF AF 時必須從 VCF merge。
5. KDE-corrected master 與 stale-binary master 的 CovM/CN 結論不可混寫。

### 不應重複投入的方向

| 方向 | 為何不再做 |
|------|------------|
| TO single-sample post-hoc germline FP filter | G1-G7、Beyond-AUC、Thread D 皆指向物理不可分或特徵不足 |
| 純 methylation TP/FP filter | 多輪 AUC <= 0.58，且 O11/O12/O13 已關閉 |
| LOH/CNV zone-aware exclusion filter | 10/10 LOH strategies fail；CNV zone-aware 跨樣本不穩 |
| FN methylation rescue | O9 顯示 FN 與 TP 在甲基化空間不可分 |
| S3 Diploid Het 全域 whitelist | X6 後跨樣本不成立，需撤回或降級 |
| 只看 pooled OLS/residualization 的 AUC 提升 | 已知 collider / data snooping 風險，必須 within-group 或 AF-bin 驗證 |

## 7. 小規模測試規則

任何新方向先做小規模觀察，通過後才升級：

1. 單樣本優先：HCC1395 作 benchmark；若涉及 outlier，另加 HCC1954。
2. 單 bucket 優先：先選已知高信號 bucket，如 Inner same-hap、Outer cross-het、S4 ambiguous。
3. 單檔 artifacts：每輪至少產生一個 TSV/JSON summary、一份短 md report、一條 evidence ledger 或 memory 更新建議。
4. Gate 必須可否證：例如 AUC >= 0.70、6/6 direction、Wilcoxon p < 0.05、bootstrap CI 不跨 0、或明確的 n/TP rate 門檻。
5. Confound guard 必須前置：AF、NR/NumReads、CN/CovM、LOH_Subtype、sample identity、chr/pos spatial autocorrelation。

## 8. 需要使用者釐清與決策的矩陣

| 決策問題 | 建議預設 | 影響 | 若選擇不同方向 |
|----------|----------|------|----------------|
| 論文/報告主軸是否正式轉為 `LOH-constrained phasing signatures` | 是，作為 TO 層主軸 | 會重排週報、簡報與 research_landscape 的敘事 | 若保留 methylation bimodality 主軸，需要額外 paired methylation-vs-phasing 證據，成本高且風險大 |
| Thread B S3/S5 是否撤回跨樣本 whitelist 宣稱 | 是，降級為 per-sample characterization | 避免 stale-binary / CN-tier-sensitive 過度宣稱 | 若重測，需先重建 v2 定義與 X6 差異，不可直接沿用 95.5% |
| AutoResearch 舊方向是否重寫 | 是，先重寫方向與 queue，不立即跑 | 避免 2026-03 TO rescue 方向誤導 agent | 若暫不重寫，任何 research-loop 前都要人工提醒其過時 |
| 下一個小規模實驗先做什麼 | HCC1954 Thread D outlier + case panel | 直接補主軸弱點 | 若做 Wakhan/SAVANA，需先確認外部工具與 input 成本 |
| KDE-corrected master 是否作為新預設 | 是，但所有舊結論保留 provenance 標籤 | 提升後續 CN/CovM 分析一致性 | 若保留舊 master，所有 CN/CovM 結論需加 stale warning |
| memory 是否立即 consolidation | 暫不自動合併，只更新必要 active hooks | memory 目前 88 行，未爆 200 行 | 若要整理，需另開 memory-consolidation，先列候選給使用者確認 |

1. 每次週報或重大結論變動後，更新本文件 §4、§6、§8。
