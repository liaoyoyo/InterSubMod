# 研究週報撰寫指令與 Skill 草案

## 1. 這份文件的用途

這份文件專門回答 3 件事：

1. 其他人如果要幫你整理 InterSubMod 研究週報，應該怎麼下指令。
2. 目前這類週報還缺哪些資訊，哪些地方最容易寫歪。
3. 你之後如果要持續修 prompt、skill 或 agent，應該優先確認哪些偏好。

這份文件不是取代 [研究報告 Agent 與 Skills 使用手冊](/big8_disk/liaoyoyo2001/InterSubMod/docs/references/manual/20260310_研究報告Agent與Skills使用手冊_01.md)，而是更聚焦在「研究週報」這個單一交付物。

## 2. 目前週報類任務仍需補齊的資訊

### 2.1 研究內容缺口

| 缺口 | 為什麼重要 |
|---|---|
| 是否需要固定的對外摘要版 | 目前預設是研究內部混合版，若要對外或對管理層簡報，密度可能過高 |
| 是否要固定列出所有圖片 | 本週主體多為 TSV/CSV 證據鏈，不是每次都值得大量嵌圖 |
| 是否要區分 `pileup` 與 `full model` 的專章 | TO 類結論容易因輸入不同而混淆，後續可能需要固定提醒 |

### 2.2 證據鏈缺口

| 缺口 | 目前狀態 |
|---|---|
| 某些跨樣本結論仍未有完整 validated report | 例如 `HCC1395_DORADO TO candidate-specific` 尚未完成 |
| 某些圖像 diagnostics 尚未全部有文字說明 | 本週已開始制度化，但ยัง未全部補完 |
| 某些規則僅有單一樣本成立 | 週報必須持續標明「單一樣本成立」與「跨樣本成立」的差異 |

### 2.3 指令規格缺口

| 缺口 | 風險 |
|---|---|
| 沒有指定讀者 | 容易導致背景過多或過少 |
| 沒有指定時間範圍 | 容易把舊結論與本週內容混在一起 |
| 沒有指定是否要表格 | 容易只剩敘述，缺 benchmark 對照 |
| 沒有指定是否需要問答 refinement | 容易寫完一次就無法持續改善 |

## 3. 其他人如何撰寫指令

### 3.1 簡短版

適用情境：你已經熟悉背景，只要快速整理本週進度。

```text
請使用 intersubmod-weekly-report-writer，整理 2026-03-05 到 2026-03-10 的研究週報。
請先講重點結論，再附主要 benchmark、規則比較、待補齊事項與下一步。
```

**優點**

1. 短
2. 啟動快

**缺點**

1. 若沒有再補充讀者與表格要求，輸出深度容易不一致

### 3.2 完整版

適用情境：希望有背景、時間序、主題整合與表格。

```text
請先閱讀 /big8_disk/liaoyoyo2001/InterSubMod/docs/CURRENT_FOCUS.md、
/big8_disk/liaoyoyo2001/InterSubMod/docs/experiments/INDEX.md、
/big8_disk/liaoyoyo2001/InterSubMod/docs/README.md，
再使用 intersubmod-context-synthesizer 和 intersubmod-weekly-report-writer，
整理 2026-03-05 到 2026-03-10 的研究主線週報。
請用台灣繁體中文，開頭先寫高密度重點結論，
補足必要背景知識，並用表格比較 benchmark、規則與完成度。
所有重要檔案請用絕對路徑 Markdown 連結。
```

**優點**

1. 背景、結論與表格通常都會比較完整
2. 較適合研究內部共享

**缺點**

1. 若沒有指定讀者深度，背景仍可能過多或過少

### 3.3 高精度版

適用情境：你要一份可以直接當 validated report 草稿的週報。

```text
請使用 intersubmod-weekly-research-agent。
時間範圍：2026-03-05 到 2026-03-10。
主題：pure paired、tumor-only、caller-first、methylation-support、artifact-veto、agent/skills 制度化。
讀者：已理解知識庫內容的研究同仁。
輸出：混合版週報。

要求：
1. 開頭先用一段高密度結論破題。
2. 先補本週必要背景知識，不要重抄整份 knowledge。
3. 每個主目標都列完成度與主要證據。
4. 依時間順序整理進展，再做主題式整合分析。
5. benchmark 一定列 truth_total、TP、FP、FN、precision、recall、F1。
6. 若引用圖，必須解釋 X 軸與 Y 軸。
7. 結尾要列待補齊事項、下一步，以及一組可直接重用的下次 prompt。
```

**優點**

1. 結構最穩
2. 最適合重複使用與後續收斂成 skill / agent

**缺點**

1. 撰寫成本較高
2. 若只是快速摘要，會顯得太重

## 4. 目前固定建議保留的偏好

以下偏好已建議固定保存，因為它們跨任務都有明顯價值：

1. 開頭先講重點結論
2. 使用台灣繁體中文
3. 專有名詞第一次補中文解釋
4. 所有 benchmark 都列 `truth_total / TP / FP / FN / precision / recall / F1`
5. 數據一定解釋意義
6. 若引用圖片，必須解釋 X/Y 軸
7. `.md` 內連結優先使用絕對路徑
8. 最後一定列待補齊事項與下一步

對應規格請看：

- [個人化研究寫作偏好設定規格](/big8_disk/liaoyoyo2001/InterSubMod/docs/references/manual/20260310_個人化研究寫作偏好設定規格_01.md)

## 5. 問答式 refinement 區

這一段是給你之後持續修正 prompt / skill / agent 用的。每次只要回答這些問題，就能讓下一版更準。

### Q1. 這次背景知識是太多、太少，還是剛好？

**你可以回答**

1. 太少，因為讀者看不懂 paired / TO / rescue 的差別
2. 太多，因為我只想看本週重點
3. 剛好，但術語表還可以更清楚

### Q2. 這次表格深度夠不夠？

**你可以回答**

1. 不夠，我要更多 TP/FP/FN 對照
2. 太多，我只要主要結論表
3. 剛好，但想再固定欄位

### Q3. 你要的是哪種讀者版本？

**你可以回答**

1. 研究內部深度版
2. 管理摘要版
3. 混合版

### Q4. 你要更多圖，還是更多推論？

**你可以回答**

1. 我需要更多圖，尤其 diagnostics
2. 我需要更多推論，不要只列數字
3. 我需要兩者平衡，但圖一定要解釋軸

### Q5. 哪些偏好應該升級成固定規則？

**你可以回答**

1. 每次都要先講結論
2. 每次都要有完成度表
3. 每次都要附 prompt 模板
4. 每次都要明確區分單一樣本與跨樣本結論

## 6. Skill / Agent 下一輪怎麼改會更有價值

### 6.1 最值得優先補的項目

1. **真實 eval prompts**
   - 讓每個 skill 都有 2 到 3 個固定測試案例
2. **週報輸出模板**
   - 建一個可直接複用的 Markdown 骨架
3. **refinement changelog**
   - 記錄每次使用者新增或修改的偏好

### 6.2 不急著先做的項目

1. 把所有任務都做成完全 rigid 的固定格式
2. 為每一種研究主題都拆成獨立 skill
3. 一開始就要求大量自動評分

原因是目前更重要的是先讓輸出穩定、可追溯、可修正，而不是過早把規則寫死。

## 7. 建議你下一輪直接這樣下指令

如果你下一輪要我繼續用這套 agent/skills，最實用的起手式是：

```text
請使用 intersubmod-weekly-research-agent。
先讀 CURRENT_FOCUS.md、experiments/INDEX.md、README.md，
再整理 [指定期間] 的研究週報。
請用混合版，開頭先講重點結論，
補必要背景知識，列主要目標與完成度，
用表格整理 benchmark、規則比較與待補齊事項，
最後再用問答方式告訴我這份報告還有哪些可修正的地方。
```

這個版本的優點是：

1. 已把閱讀入口固定住
2. 已把報告核心章節固定住
3. 已把 refinement 也包進同一次任務

## 8. 現在最需要你回覆的偏好

如果要把這套系統再往前推一版，你最值得先回答的是這 3 題：

1. 你之後的週報，預設想看「研究內部深度版」還是「混合版」？
2. 你要不要固定要求每次都至少嵌入 1 張圖，還是保持「有需要才放圖」？
3. 你要不要把每次 refinement 的結果寫成 changelog，累積成正式 skill 更新歷史？
