# AI 對話執行報告：ClairS 邊緣 FN 探勘與甲基化救援

## 對話目標

本輪針對「ClairS-TO 過濾但 truth set 包含」的 FN 位點（Pool B FN）進行甲基化補充分析，評估：
1. Pool B FN 的規模與可救援性
2. Caller 端規則（GQ、VariantCluster）的 F1 效益
3. 甲基化訊號是否能補充 Caller 信心，提升 rescue precision

**基線（HCC1395 5kHz TO）**：ClairS-TO F1=0.7127，TP=28,396，FP=11,843，FN=11,051，truth_total=39,447

---

## 關鍵決策

### 決策 1：使用 bcftools isec 而非 rtg vcfeval

計劃書原本列 rtg vcfeval，但 bcftools isec 更直接、無需 SDF reference，且適合小批次位點比對。
選用 `bcftools isec -c none` 進行精確 chrom:pos:ref:alt 匹配。

### 決策 2：Pool B 定義排除 NonSomatic

`bcftools view -e 'FILTER=="PASS" || FILTER~"NonSomatic"'`：
- PASS → 已進 callset，不是 FN 來源
- NonSomatic → germline 標籤完整，Pool B 聚焦於 LowQual 系列

### 決策 3：策略 B（補跑 InterSubMod）

初始甲基覆蓋率 0%（non-PASS 位點從未進入 InterSubMod）。
將 pool_b_fn.vcf.gz 與 pool_b_non_fn.vcf.gz 的 FILTER 全改為 PASS，對這兩組分別補跑 InterSubMod，達到：
- Pool B FN 覆蓋率：99.9%（839/840）
- Pool B non-FN 覆蓋率：98.8%（2609/2642）

### 決策 4：雙 sig CSV 修正（Bug fix）

初始版 `analyze_clairs_borderline_fn.py` 只載入一份 significance CSV（FN 組），
導致 non-FN 的 PairwiseDist/AlleleDelta 全部預設為 0.0，Combined 規則的 FP 數量嚴重低估。

修正：新增 `--significance-csv-non-fn` 參數，分別用 `sig_map`（FN）與 `sig_map_non_fn`（non-FN）
各自 enrich，才能正確評估 Combined 規則的 FP 代價。

## 實驗結果摘要

### Pool B 量化

| 指標 | 數值 |
|------|------|
| Pool B 候選（non-PASS, 非 NonSomatic） | 6,647 |
| BED scoping 後 | 3,482 |
| **Pool B FN（在 truth set）** | **840** |
| Pool B non-FN（不在 truth set） | 2,642 |

### 最佳 Caller-only 規則

| 規則 | TP+ | FP+ | Precision | F1 delta |
|------|-----|-----|-----------|---------|
| `no_varcluster` | 428 | 390 | 52.3% | **+0.003391** |
| `gq15_and_af015` | 448 | 547 | 45.0% | +0.002316 |
| `no_varcluster_and_gq15` | 115 | 45 | **71.9%** | +0.001452 |

### 最佳 Combined 規則（Caller + Methyl）

| 規則 | TP+ | FP+ | Precision | F1 delta |
|------|-----|-----|-----------|---------|
| `gq15_and_allele_delta_low` | 431 | 473 | 47.7% | +0.002702 |
| `gq15_and_pairwise_ge_015` | 340 | 448 | 43.2% | +0.001471 |

**核心差距**：最佳 Combined vs 最佳 Caller-only = +0.000386，甲基增益極小。

### 甲基化訊號深度分析（Standard 調整評估）

| 指標 | Pool B FN (840) | Pool B non-FN (2642) |
|------|----------------|---------------------|
| VerificationClass = Strong+Subclone | 30.8% | **44.7%** |
| Median AlleleDelta | 0.0097 | 0.0648 |
| AD < 0.10 比例 | 90% | 60% |

**關鍵洞察**：Pool B non-FN 含有大量 germline 變異（被 VariantCluster/cluster-aware 過濾但未標記 NonSomatic），
這批 germline 位點有強烈 HP 甲基訊號，導致 VerificationClass=Strong 在 non-FN 組反而更常見。
這是甲基唯一規則（`pairwise_ge_020`、`class_strong_or_subclone`）全數為負效益的根本原因。

**AlleleDelta 作為 Somatic 指標**：Pool B FN 的 AD 中位數 0.010（90% < 0.10），
而 non-FN 為 0.065（40% ≥ 0.10），具有統計區分力，
但 precision 仍只有 ~32%，不足以單獨作為救援條件。

---

## 標準調整結論

**問題**：甲基化標準是否需要調整？

**結論**：現行 VerificationClass 系統**正確地**偵測到 HP 結構化甲基訊號（germline 確實有強烈 HP 甲基），
問題不在標準本身，而在於**Pool B non-FN 混入了大量 germline 變異**（非 NonSomatic 標記的）。

這類 germline 的「High AlleleDelta」正是 HP 特異性甲基化的表現，而非 somatic artifact。
VerificationClass 無法單靠甲基訊號區分 somatic FN 與 germline 假性非 PASS。

**AlleleDelta < 0.10 可作為 somatic 富集的輔助訊號**（在 Pool B FN 中 enrichment 效果明顯），
但需搭配 GQ 才有正 F1 效益（`gq15_and_allele_delta_low` F1 delta=+0.002702）。

## 後續行動建議

1. **不推薦將 Pool B Combined 規則升為正式方法**：最大 F1 delta = +0.002702，precision 47.7%，未達 50%+ 門檻
2. **`no_varcluster_and_gq15` 值得在 HCC1395_DORADO TO 上交叉驗證**（precision=71.9%, F1 delta=+0.001452）
3. **研究重點維持 FP triage**：甲基訊號（低 VAF + 高 AlleleDelta）對 FP 識別已有明確正效益（見實驗 22/23）
4. **AlleleDelta < 0.10 可作為 somatic-aware rescue 輔助條件**，但需搭配 GQ >= 15 才有效
5. **Pool A-light 無需探索**：Pool B FN 已達 840 個且結論清晰
