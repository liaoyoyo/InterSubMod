# LOH 盤點執行規格

## 1. 文件定位

本文件不是 LOH 研究結論，而是 **LOH 盤點與觀察的固定執行規格**。

若某一輪已經完成實際範圍拍板，應另外建立 round 專用文件記錄本輪決策，而不要把所有 round-specific 細節直接寫死在本規格中。

首個依本規格正式啟動的 round 為：

1. [20260327_LOH_round1_cross_sample_audit啟動與決策紀錄_01.md](/big7_disk/liaoyoyo2001/InterSubMod/docs/experiments/in_progress/2026/03/20260327_LOH_round1_cross_sample_audit啟動與決策紀錄_01.md)

用途是確保之後每一輪 LOH 盤點都能：

1. 先講清楚研究問題與假設
2. 使用同一套定義
3. 固定輸出可追溯的數據與圖表
4. 固定記錄哪些判斷是事實、哪些是推論、哪些還待使用者確認
5. 讓之後任何人都可以從 summary 一路追回原始 table、figure、case 與來源路徑

---

## 2. 這份 LOH 盤點要回答什麼

LOH 盤點的角色不是直接證明某個方法有效，而是回答以下問題：

### 2.1 分佈問題

1. `Potential_LOH / LOH-like / HP family imbalance` 在 TP 與 FP 的占比如何？
2. 這些分佈在不同樣本、不同模式、不同工具來源下是否一致？
3. 單看 LOH-like 比例時，哪些現象是普遍、哪些是 sample-specific？

### 2.2 機制問題

1. paired 中看到的 LOH-like 訊號，較像真實 LOH、germline ASM、phase/QC 問題，還是其他 artifact？
2. TO 中看到的 LOH-like 訊號，是否只是「沒有 normal 對照時的不可分辨混合」？
3. LOH-like 區域的甲基特徵是完全失效，還是只在特定條件下有效？

### 2.3 工具與流程問題

1. LongPhase-S 與 LongPhase-TO 對同類問題輸出的 HP / LOH 線索有何差異？
2. 同一個樣本、同一個位點，在 paired 與 TO 中是否呈現一致的 LOH-like 行為？
3. 哪些結論會被 `PS / phase block` 邊界破壞？

### 2.4 後續研究價值問題

1. LOH 是否適合當下一輪方法改善的切入點？
2. 哪些 LOH case 應進 evidence panel？
3. 哪些 LOH case 只適合當風險提示，不適合當主證據？

---

## 3. 固定研究前提

每次執行 LOH 盤點前，摘要段落必須先寫清楚以下前提：

1. 本輪是 `distribution audit`、`mechanism audit`、`same-locus compare` 還是 `case panel build`
2. 本輪使用的 sample scope
3. 本輪使用的 mode scope
4. 本輪是否只做 summary，不做方法修改
5. 本輪不打算回答哪些問題

---

## 4. LOH 盤點的標準定義

## 4.1 名詞分層

所有輸出都必須把以下三層概念分開：

| 層級 | 典型欄位 | 正確意義 | 不可直接做的事 |
|---|---|---|---|
| read-level | `HP=1/2/1-1/2-1/3/0` | 單條 read 的 local haplotype 標記與 ALT-support 狀態 | 不能單靠某個 HP tag 宣稱 LOH |
| region-level proxy | `HP_Ratio`, `Potential_LOH`, `LOH_like`, `H flag`, `AF>=0.9` | 區域層的 haplotype imbalance 線索 | 不能把 proxy 當正式 LOH |
| region-level evidence | `LOH.bed`, phased genotype, CNV context | 正式 LOH / structural evidence | 不能和 read-level HP 混寫成同一層 |

## 4.2 HP family 定義

**固定採用**

1. `HP1_family = HP1 + HP1-1`
2. `HP2_family = HP2 + HP2-1`

理由：

1. 這與目前 `LabelTest` merged HP test 一致
2. 便於在 paired 中把 germline HP 與 ALT-support family 放在同一邊觀察

## 4.3 HP ratio 主定義

主要指標一律寫成：

```text
hp_ratio_core = HP1_family_reads / (HP1_family_reads + HP2_family_reads)
```

**注意**

1. 若 `HP1_family_reads + HP2_family_reads = 0`，不可把該值直接解釋成 balanced HP
2. 這類 case 必須同時看 `effective_hp_reads`

## 4.4 HP0 與 HP3 的處理

`HP0` 與 `HP3` 一律：

1. **不納入** `hp_ratio_core` 分母
2. 另外獨立輸出：
   - `hp0_reads`
   - `hp3_reads`
   - `hp0_ratio`
   - `hp3_ratio`
3. 定位為 `phase/QC annotation`

理由：

1. `HP0` 是 unphased / missing phase
2. `HP3` 是 LongPhase-S 中 ALT-supporting 但 germline HP 無法唯一解析
3. 兩者若併入主比例，會把 phase completeness 問題誤解成生物訊號

## 4.5 effective HP coverage 定義

每次都必須同時回報：

1. `HP1_family_reads`
2. `HP2_family_reads`
3. `effective_hp_reads = HP1_family_reads + HP2_family_reads`
4. `total_reads`
5. `hp_assign_rate = effective_hp_reads / total_reads`

這是為了避免：

1. `1 vs 0` 被誤讀成強 LOH
2. `50 vs 0` 和 `1 vs 0` 被當成同級訊號

## 4.6 LOH-like / Potential_LOH 定義

目前預設沿用現有系統：

```text
Potential_LOH = (hp_ratio_core < 0.1) OR (hp_ratio_core > 0.9)
```

但每輪 LOH 盤點都必須額外做 exploratory bins：

1. `<0.05`
2. `0.05–0.1`
3. `0.1–0.2`
4. `0.2–0.8`
5. `0.8–0.9`
6. `0.9–0.95`
7. `>0.95`

原因：

1. 避免把閾值本身當成不可質疑真理
2. 方便之後判斷是否需要調整 LOH-like 定義

## 4.7 PS / phase block 邊界

所有 LOH 報告都必須加註：

1. `HP1` 與 `HP2` 只有在**同一 PS / phase block** 內才可直接比較親緣意義
2. 不同 PS block 的 `HP1` 與 `HP2` 不可直接串成同一條親代敘事
3. 目前主輸出尚未正式匯出 `PS` 到 `reads.tsv`

因此目前的 HP-driven 結論，預設只能寫成：

1. `local haplotype imbalance`
2. `HP-driven pattern`
3. `phase-block-unresolved`

不可直接升級成：

1. `父系/母系`
2. `跨 block 一致等位差異`
3. `穩定 parent-of-origin narrative`

## 6. 固定分析問題清單

每次 LOH 盤點都必須至少回答以下問題。

## 6.1 Distribution layer

1. TP / FP 的 `Potential_LOH` 占比？
2. `LOH_Subtype` 在 `Strong / Weak / Subclone / Noise` 的分佈？
3. `hp_ratio_core` 的分佈形狀？
4. `effective_hp_reads` 是否足夠？
5. `hp0_ratio / hp3_ratio` 是否在某些樣本明顯偏高？

## 6.2 Mechanism layer

1. LOH-like TP 與 FP 的 `AlleleDelta`、`PairwiseMedianDist`、`Quality_Score` 是否方向一致？
2. paired 中的 LOH-like FP 是否更接近 germline ASM？
3. TO 中的 LOH-like TP / FP 是否真的不可分？

## 6.3 Cross-track layer

1. 同一樣本 paired 與 TO 的 LOH-like 比例是否一致？
2. paired 與 TO 對相同位點的 `VerificationClass` 是否一致？
3. 同位點若 paired 與 TO 結論不同，差異來自 caller、phasing、HP completeness、還是甲基訊號？

## 6.4 Tool-boundary layer

1. 哪些判斷來自 LongPhase-S 的 read-level HP？
2. 哪些判斷來自 LongPhase-TO 的 `LOH.bed` / phased VCF？
3. 哪些結論只是一個 proxy，不應升級成正式 LOH？

## 6.5 Case layer

1. 哪些 LOH-like case 最有代表性？
2. 哪些 case 需要 IGV + heatmap + phased context 才能判斷？
3. 哪些 case 因 `PS` 缺失只能先標記為 unresolved？

## 11. 每輪必填的判斷與決策

每輪 LOH 盤點都必須把以下判斷寫成 decision ledger。

## 11.1 定義型決策

1. 本輪 `LOH-like` 閾值是否沿用 `<0.1 or >0.9`
2. 本輪是否把 `HP1-1 / HP2-1` 併入 family
3. 本輪是否把 `HP0 / HP3` 僅作 QC annotation
4. 本輪是否允許在沒有 `PS` 的情況下做 HP-driven 解釋

## 11.2 範圍型決策

1. 本輪看哪些樣本
2. 本輪看哪些 mode
3. 本輪是否做 same-locus paired-vs-TO compare
4. 本輪是否做 case panel

## 11.3 結果型決策

1. LOH-like 在本輪是否真的能區分 TP/FP
2. 若不能，是普遍不能還是只在某 track 不能
3. 哪些特徵在 LOH-like case 中還有效
4. 哪些特徵在 LOH-like case 中會誤導

## 13. 本規格預設建議

若本輪未另外說明，預設採：

1. `HP1-1` 歸 `HP1 family`
2. `HP2-1` 歸 `HP2 family`
3. `HP0 / HP3` 不進主分母
4. `Potential_LOH` 先沿用 `<0.1 or >0.9`
5. `PS` 缺失視為高風險解釋缺口，不阻止 summary audit，但阻止強 allelic 敘事

7. paired 與 TO 分開下結論，不共用同一個「LOH 有效 / 無效」口徑

## 14. 需你確認的決策

以下是本規格已先幫你預設、但建議你明確確認的項目。

若某輪已拍板，應在該 round 的 `decision ledger` 或啟動文件中把最終版本寫死；本節保留為通用預設，不取代 round-specific 決策紀錄。

### Decision A：Round 1 樣本範圍

**建議**

1. 先做 `HCC1395 5kHz paired/TO`
2. 再做 `HCC1395_DORADO paired/TO`
3. 第二輪再擴 `H1437 / H2009`

**你要確認的點**

1. 你要先做最小閉環，還是第一輪就同時看異質性？

### Decision B：LOH-like 閾值策略

**建議**

1. 主判斷沿用現有 `<0.1 / >0.9`
2. 但 summary 一律補 exploratory bins

**你要確認的點**

1. 你是否接受「主閾值固定、探索分箱另外報」這種雙層策略？

### Decision C：PS 缺口的處理方式

**建議**

1. Round 1 不先改 C++
2. 先在報告中把 `phase-block-unresolved` 標記清楚
3. 若 LOH / HP 解釋真的卡住，再開 `PS export` 任務

**你要確認的點**

1. 你要先 summary audit，再決定是否補 `PS`，還是現在就把 `PS` 當 blocking item？

### Decision D：case panel 強度

**建議**

1. Round 1 case panel 只做 4–8 個代表案例
2. 不先把所有 LOH-like case 都做圖

**你要確認的點**

1. 你偏好先廣盤 summary，還是先深做 case？

### Decision E：same-locus compare 的優先度

**建議**

1. Round 1 summary 先做
2. same-locus paired-vs-TO compare 放在 Round 1.5 或 Round 2

**你要確認的點**

## 15. 本規格的完成條件

當一輪 LOH 盤點至少做到以下條件，才可視為完整：

3. 有固定 figures

## 16. 本規格不直接承諾的事

本文件只規範「怎麼盤點與記錄」，不直接承諾：

1. LOH 一定能提升 F1
2. LOH 一定能解 second hit
3. TO 的 LOH 問題一定能被 paired 類比解決
