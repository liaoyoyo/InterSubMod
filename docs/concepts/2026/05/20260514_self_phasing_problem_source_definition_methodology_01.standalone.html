0.TL;DR — 5 層方法論

當有人問你「self-phasing pipeline 的問題源頭在哪？」— 單一句答案（「HP tag 偏」或「getVote bug」）幾乎一定錯。正確答案是一條由淺到深的 5 層敘事鏈。每往下一層，都要有外部可驗證的證據（不是「我覺得」），且不能跳層。

17.3 : 1
現象 — HP1:HP2 全基因組偏移（baseline）
1 : 1.275
獨立性對照 — Paired binary 同樣本
34,855
個案 — Read-level priority bug victims
2 × 機制
疊乘 — 生物 × 演算法 = 17.3:1
4 軌
證據鏈 — 統計 / 跨樣本 / 機制 / 正交
核心原則：問題源頭的「源頭」不是單一點，而是一條因果鏈。本方法論的目的是把這條鏈拆到「每一層都可被獨立驗證 / 反駁 / 取代」的程度。如果有人能在任一層舉反例，整個敘事必須修正 — 這才是「清楚定義」的真正意涵。

1.為何需要 5 層 — 常見認知偏誤陷阱

不分層就解釋 pipeline 問題，會掉入以下陷阱（self-phasing 案例都實際發生過，已留下 5 條 errata 紀錄）：

陷阱典型錯誤敘述為何錯對應 Layer 修正
定性化 「HP tag 方向偏」「somatic 投票異常」 沒給量化值；無法被反駁 — 不滿足科學陳述最低要求 Layer 1 強制量化（17.3:1 而非「偏」）
單因論 「getVote 有 bug 所以偏 HP1」 忽略 17.3 倍量級需要疊乘解釋；單 bug 通常只造成 1.x 倍 Layer 4 機制疊乘（A × B 才到 17.3:1）
單樣本歸納 「HCC1395 chr19 觀察到 113:0」 無法排除「樣本性質」或「region 性質」假設 Layer 2 獨立性對照（paired binary + 全 chr 分佈）
統計層停止 「BAM 統計顯示偏移」 不知是哪些 read、修正方向是否一致 — 修補後無法驗證 Layer 3 個案級逐條 trace（34,855 victims）
機制懸空 「somatic 票被誤用」 沒指到 file:line — 同事 / 未來自己無法接手 patch Layer 5 機制證據（HaplotagProcess.cpp:506-530）
過度宣告 「V6 修對 self-phasing 所有問題」 混淆 tagging layer vs phasing layer；混淆 caller F1 vs tag ratio 「不可宣告事項」誠實揭露

5 層方法論就是針對這 6 個陷阱設計的，每一層都對應反制特定陷阱。

2.方法論流程圖

L1
現象量化 — 把「偏」變成數字
回答：偏離預期多少？單位是什麼？基準是什麼？

核心動作

把問題敘述中所有定性詞（「方向偏」「票數異常」「分佈不平均」）替換成帶單位的比值或差值，並標明「預期值」與「實測值」。

Self-phasing 案例對照

定性敘述（壞）量化敘述（好）來源
「HP tag 方向偏 HP1」 — 無從驗證
— HP1 系列 reads : HP2 系列 reads = 17.3 : 1（全基因組）；HP1 占比 94.6%（vs 預期 50%） samtools view -F 256 tagged.bam | grep -oE "HP:i:[0-9]+" | sort | uniq -c
「somatic 投票異常」 — 無從驗證
— baseline somatic ALT 偏 HP1 比例 = 94.6%；對齊 17.3/(17.3+1) ≈ 0.9454 算術自洽 整合報告 §2.1

具體要求

  • 每個數字必須有單位（read 數、比值、百分比、bp 距離）。
  • 每個數字必須有預期值對照（隨機應為 50%、無 bug 應為 1:1）— 否則「偏」沒意義。
  • 每個數字必須有可重現命令（samtools / awk / 一行 Python）— 否則不能審查。
  • 避免「大量」「明顯」「顯著」這類無單位形容詞，除非後面緊跟 p-value 或 effect size。
常見錯誤：止步於 chr19 局部觀察（如 SP1 位點 113:0），未量化全基因組。Self-phasing 早期報告就掉過這坑，5/8 整合報告補上全基因組 17.3:1 才完整。
L2
獨立性測試 — 排除替代解釋
回答：這偏移是 sample 的、binary 的、region 的，還是真的 bug？

核心動作

對 L1 觀察到的偏移，逐項排除「不是 bug 的可能解釋」。每個解釋都用一個獨立對照組驗證：

  • 排除 sample 性質：用同 sample 跑獨立 binary — 若獨立 binary 不偏，則排除「sample 天生偏」。
  • 排除 binary 性質：用同 binary 跑獨立 sample — 若多 sample 都偏，則是 binary 的問題。
  • 排除 region 性質：檢查偏移在全基因組分佈是否一致 — 若僅某 chr 偏，則可能是 region 屬性而非全域 bug。
  • 排除上游 caller 性質：對照caller F1 vs SEQC2 truth是否變動 — 若 F1 不變但 tag 偏，則 bug 在 tagging 而非 calling。

Self-phasing 案例對照

替代假設對照組結果判定
「HCC1395 sample 天生 HP1 偏」 HCC1395 paired binary (longphase-s) 同 BAM HP1:HP2 = 1 : 1.275 排除 ✓ 是 binary-specific
「TO mode 7 樣本都偏因 caller 偏」 caller F1 vs SEQC2（baseline / V3F / V5 / V6 四版） F1 = 0.7166 / 0.6273 四版皆同 排除 ✓ caller 不變，bug 在 tagging
「chr19 局部偏因 region 性質」 全基因組 24 chr 分佈一致性 chr19 占全基因組 priority bug 僅 2.16%（rank 19） 排除 ✓ 全域均勻發生
「paired mode 也有同 bug 只是沒測到」 paired binary 原始碼閱讀 SomaticHaplotagProcess.cpp 不 ordered + 無 break 排除 ✓ paired binary 邏輯獨立，無 priority bug

4 個對照組設計原則

  • 正交性：每個對照組只變動一個維度（binary / sample / region / 上游 caller），否則無法歸因。
  • 同口徑：對照組統計方法完全相同（同 samtools 指令、同篩選條件）— 否則差異可能來自方法而非物件。
  • 對照組必須能輸出「無偏」結果：若所有對照都偏，就無法定位 bug — 至少要有一組「應該無偏的對照」（例：paired binary）。
哲學備註：L2 是科學方法的核心 — Karl Popper 的 falsifiability。觀察到偏移不等於發現 bug；只有當「不是 bug 的所有解釋」都被獨立對照組推翻，才能下一步進入 L3 個案 trace。
L3
個案級 trace — 從統計到逐條 read
回答：具體是哪些 read 被影響？修正方向是否一致？反向案例有多少？

核心動作

L1/L2 是宏觀層；L3 必須潛入微觀層。對 baseline / 修補版本 / 對照版本三組，dump 每個 read 經關鍵函式後的 intermediate state，merge 後檢查：

  • 受影響 read 數量（被誤判方向的 read 數）
  • 修正率（修補版本將多少受影響 read 改對）
  • 反向案例數（修補版本意外改錯的 read 數）— 此項必須接近 0，否則修補有 regression

Self-phasing 案例對照

對 baseline / V3F / V6 三版加 --debug-vote-dump flag，dump 每條 read 經 getVote() 後的 5-vote countMap + hpResult。

# Dump command (per version)
./longphase haplotag --debug-vote-dump out.tsv -s in.vcf -b in.bam ...

# Merge & analyze
awk -v OFS='\t' '...' out.baseline.tsv out.v3f.tsv out.v6.tsv > merged.tsv
# Filter priority bug victims (baseline somatic dir != v6 corrected dir)
python3 priority_bug_victims.py merged.tsv
統計數量意義
chr19 dump rows（三版各） 549,206 三版相同 — 確保 dump 完整一致
三版 merged events 1,069,832 覆蓋無漏 — 後續統計基於完整 events
chr19 priority bug victims 752 baseline 標 somatic 方向且 V6 反向 — 即 bug 受害者
全基因組 victims 34,855 chr19 占 2.16% — 全域分佈，非局部
V6 修正率 100% (34,855/34,855) 修補完全覆蓋 — 無遺漏
反向案例（baseline=21 → V6=11） 0 無 regression — 修補單向改善

為何 L3 不可省略

  • L1 只看 aggregate ratio — 修補可能把 A 改對但把 B 改錯，aggregate 仍變好但個案層面有 regression。
  • L3 的「反向案例 = 0」是修補正確性的最強證據。若反向案例 > 0%，修補有未列出的副作用。
  • L3 也提供修正率上限：若修補只覆蓋 80% victims，剩下 20% 需要 follow-up 或承認限制。
常見錯誤：只 dump baseline 不 dump 修補版本，無法驗證「修對」。三版 dump 是最小集合（baseline + 修補 + 對照）。
L4
5 Whys + 機制疊乘 — 量級必須有解釋
回答：為何放大到 17.3 倍？單一機制能解釋嗎？若不能，哪些機制疊加？

核心動作 A — 5 Whys 拆到 file:line

每個 Why 必須指到具體位置（file:line / 函式 / 上游模組），不能停在「設計選擇」「歷史原因」。

Why #問題答（必須帶 file:line）
1為什麼 HP1:HP2 = 17.3:1？大量 reads 被誤標 HP1 系列（HP:i:1 / HP:i:11）
2為什麼那些 reads 被誤標？getVote() 在 countMap 有 ≥1 票 somatic 時直接決定方向
3為什麼 ≥1 票 somatic 就能決定？HaplotagProcess.cpp:506-530 把 somatic pair 排第一 + break 跳出
4為什麼 pair 順序 somatic-first？原始設計假設 somatic 優先（commit 歷史無記載原因）— 設計缺陷
5為什麼 somatic 票偏 HP1？上游：tumor sub-clone lineage 同源 + phasing 把 somatic 當投票員 → VCF GT2 偏 1\|.

核心動作 B — 機制疊乘量化

單一機制通常只造成 1.x 倍偏移。17.3 倍量級必須有 ≥2 個機制疊乘解釋，否則敘事不完整。

為何「機制 A × 機制 B」很重要

知道是疊乘而非單一機制，決定了修補策略：

  • 若敘事只說「somatic 偏 HP1」（單機制 A），修補方向會錯（會嘗試修 caller，但 caller F1 不變）。
  • 若敘事只說「getVote bug」（單機制 B），無法解釋為何修補後仍有 V5 Layer 1.5 在 germline-absent 區4.19:1 殘餘偏移。
  • 正解：「機制 A 永遠存在（生物現象），修機制 B 就足以解 bug」— V6 patch 設計依此判斷，germline-absent 區保守標 hp=33 而非嘗試從 somatic 推方向（避免 Layer 1.5 復現機制 A 偏移）。
算術自洽檢查：機制疊乘的好處是可以做數字驗證。17.3 / (17.3 + 1) ≈ 94.6%（HP1 占比），與整合報告 §2.1 全基因組 94.6% somatic ALT 偏 HP1 完全一致 — 雙重來源算術閉合，敘事可信。
L5
4 軌證據鏈 — 每軌可獨立推翻整個敘事
回答：若有人質疑，4 個獨立證據來源都站得住嗎？

核心動作

把 L1-L4 的證據組織成4 條獨立軌道，每條都來自不同來源，任一條失敗則整個敘事必須修正。這是 InterSubMod 專案 /structured-tech-report skill 的 evidence layer 設計。

軌類型Self-phasing 案例證據來源
軌 1 統計證據（BAM stats） HP1:HP2 = 17.3:1 全基因組 整合報告 §2.1
軌 2 跨樣本證據（4-sample expansion） V6 修補後 4 樣本 hp ratio 0.611-1.243（中性） paired_priority_bug_audit/08_phaseD_v6_cross_sample_findings.md
軌 3 機制證據（C++ 原始碼 file:line） HaplotagProcess.cpp:506-530 baseline getVote;:512-559 V6 patch /big8_disk/.../longphase-to/ + /big7_disk/.../longphase-to-mod/
軌 4 正交證據（獨立 binary 對照） paired binary SomaticHaplotagProcess.cpp 同樣本 1:1.275 無偏 paired_priority_bug_audit/00_audit_report.md

4 軌的「獨立」意涵

  • 軌 1 來自 baseline BAM — 即使後續所有分析都錯，原始 BAM 統計仍存在。
  • 軌 2 來自不同樣本 — 排除「HCC1395 特殊」可能性。
  • 軌 3 來自原始碼閱讀 — 完全不依賴 BAM 統計，是純語法 / 邏輯層證據。
  • 軌 4 來自獨立 binary — 完全不依賴 longphase-to 任何行為，是純對照組證據。

若有人能在任一軌舉反例（例：發現某個樣本 paired binary 也有 17.3 偏移），整個敘事必須重新檢視 — 但 4 軌獨立性使這種反例非常難找。這是敘事「可被反駁」的具體實現。

4 軌完整性自我檢核（4 軌全綠才能宣告解決）

  • ✓軌 1（統計）—— 有量化數字 + 預期值對照 + 可重現命令L1 強化
  • ✓軌 2（跨樣本）—— ≥3 樣本一致；單樣本不可宣告L2 + L1 跨樣本
  • ✓軌 3（機制）—— file:line 指到具體函式 + diff 對照L4 + 原始碼
  • ✓軌 4（正交）—— 對照組來源完全獨立（不同 binary / 不同 pipeline）L2 強化

3.不可宣告事項 — 誠實揭露的負面清單

5 層方法論定義的是正面證據鏈。但敘事完整性也需要負面清單 — 明確列出「即使所有證據都成立，仍不能宣告的事」。這是 self-phasing 系列 5 條 errata 的根本起因（過度宣告 → 後續發現邊界 → 撤回 / 修正）。

✓ 可以宣告

  • 「baseline longphase-to 在 tagging layer 有 priority bug」
  • 「V6 patch 在 4 樣本 hp ratio 接近中性」
  • 「機制 A × B 疊乘解釋 17.3:1 量級」
  • 「caller-level F1 不變（本專案口徑）」
  • 「paired binary 不受同 bug 影響」

✗ 不可宣告

  • 「V6 解決 longphase 所有 priority bug」（只解 tagging layer，phasing layer 另有「球員兼裁判」by PON-only flag）
  • 「ISM downstream F1 因 V6 改善」（V6 不改 caller；ISM feature 影響未量化）
  • 「longphase 論文 F1 == 本專案 F1」（不同口徑 — 論文用 V_H/V_L post-filter，本專案用 caller-level；詳見 KB query 規則）
  • 「Paired 與 TO 同 bug 已解」（Paired 從沒這 bug）
  • 「17.3:1 = 完全 bug；無生物學成分」（機制 A 是 self-phasing 生物現象，無法 0 化）
負面清單規則：每寫一條正面宣告，同時思考它的 boundary — 在什麼條件下這條會失效？把那條失效寫入負面清單。這就是 InterSubMod 「2026-05-13 outside-claim 必先查 KB」教訓的具體實現（slide 14 F1 雙口徑事件直接源自此類過度宣告）。

4.Pre-publish 6 點檢核（每份報告必跑）

寫完問題源頭定義後，用以下 6 點自我檢核。任一項打 ✗ 不發布。

  • ☐ L1 量化檢核 — 所有「偏」「異常」「不平均」是否都已替換成帶單位的數字 + 預期值對照？ Layer 1
  • ☐ L2 獨立性檢核 — 「不是 bug 的 4 個假設」（sample / binary / region / 上游 caller）是否都有對照組排除？ Layer 2
  • ☐ L3 個案檢核 — 修正率 = 100%？反向案例 = 0？若否，是否誠實說明殘留？ Layer 3
  • ☐ L4 機制檢核 — 偏移量級是否需要疊乘解釋？若 >5 倍偏移卻只給單機制，補機制 A 或拒絕單一敘事。 Layer 4
  • ☐ L5 證據鏈檢核 — 4 軌（統計 / 跨樣本 / 機制 / 正交）都有獨立證據？任一軌缺失 → 敘事降級為「假設」而非「結論」。 Layer 5
  • ☐ 負面清單檢核 — 每條正面宣告是否有對應的 boundary 敘述？外部工具 claim 是否已查 KB？ Honesty

5.問題定義範本（可複製套用）

新 pipeline 問題出現時，填入以下範本（建議放在報告 §0 或 §1）：

# Self-Phasing Pipeline Bug 問題源頭 — 5 層敘事

## L1 現象（量化）
- 觀察值: HP1:HP2 = 17.3 : 1 (全基因組)
- 預期值: 1 : 1 (假設無偏 phasing)
- 偏離: HP1 占 94.6% vs 預期 50%
- 可重現命令: `samtools view -F 256 tagged.bam | grep -oE "HP:i:[0-9]+" | sort | uniq -c`

## L2 獨立性（排除替代解釋）
- 排除 sample 性質: paired binary 同樣本 1:1.275 → 排除
- 排除 region 性質: 全基因組分佈均勻, chr19 占 2.16% → 排除
- 排除 caller 性質: F1 vs SEQC2 baseline/V3F/V5/V6 四版皆 0.7166 → 排除
- 殘留假設: binary-specific tagging bug

## L3 個案 trace（逐條 read）
- 三版 dump (baseline / V3F / V6) chr19 各 549,206 rows
- Priority bug victims: chr19 752, 全基因組 34,855
- V6 修正率: 100% (34,855/34,855)
- 反向案例: 0

## L4 5 Whys + 機制疊乘
- Why 1-5: ... (見上文)
- 機制 A: 生物 + 上游 phasing (P ≈ 1.0)
- 機制 B: getVote 1 票觸發 + break (放大係數 ≈ 17×)
- 疊乘 ≈ 17.3 : 1 (與 L1 算術自洽)

## L5 4 軌證據鏈
- 軌 1 統計: 整合報告 §2.1
- 軌 2 跨樣本: paired_priority_bug_audit/08_phaseD_v6_cross_sample_findings.md
- 軌 3 機制: HaplotagProcess.cpp:506-530 (baseline) / :512-559 (V6)
- 軌 4 正交: SomaticHaplotagProcess.cpp 同樣本 1:1.275
