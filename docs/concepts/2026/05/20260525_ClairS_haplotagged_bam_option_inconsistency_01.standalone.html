ClairS --haplotagged_tumor_bam_provided_so_skip_intermediate_phasing_and_haplotagging Option
Help Text 與實際行為矛盾分析

Bug-like behavior in ClairS pipeline — EXPERIMENTAL option 行為與文件描述不符

TL;DR

ClairS 的 --haplotagged_tumor_bam_provided... option 的 help text 承諾「haplotype information will be acquired from haplotagged tumor BAM」，但實際 code 在 line 691 將 phase_tumor=False，導致下游 mpileup 不抽 HP tag。最終行為與 --disable_phasing 等同 — user 提供的 HP tag 完全不會進入 model。

對 InterSubMod Phase 2 Cycle 2 計劃的意涵：不能依賴此 option 把 longphase-s 結果注入 ClairS，必須走 post-filter framing。

§1 問題陳述

BUG-LIKE Argparse help 與 runtime behavior 矛盾

ClairS 提供 --haplotagged_tumor_bam_provided_so_skip_intermediate_phasing_and_haplotagging option，文件描述為「使用 user-provided haplotagged BAM，跳過 intermediate phasing，HP info 從 BAM 取得」。但實際程式碼將 phase_tumor flag 設為 False，造成下游 samtools mpileup 不輸出 HP tag，最終 phase channel 全為 untag。

結果：此 option 等同 --disable_phasing，user 提供的 HP tag 完全 invisible to model。

§2 Background — Option 的設計意圖

ClairS 預設流程在 STEP 1 之前會跑兩個 pre-phasing step（NVTB mode 預設）：

  • Pre-D: longphase phase — 用 normal Clair3 het SNP + tumor BAM evidence 推 phasing
  • Pre-E: longphase haplotag — 把 HP:i:1/2 寫入 tumor BAM

這兩個 step 在 ONT 30× tumor BAM 上約耗 30-60 分鐘。當 user 已有 phased BAM（如先前已跑過 LongPhase 或 WhatsHap），重跑是浪費。

設計初衷（合理）：

  1. 節省 wall time：跳過 Pre-D/E 約 30-50% pipeline 時間
  2. 支援 multi-tool integration：user 已有 phased BAM 不需重跑
  3. 靈活性：對 CI/CD 或 batch pipeline 有用

關鍵承諾：「the haplotype information will be acquired from haplotagged tumor BAM」

實際 runtime 行為（line 690-691）

// run_clairs:690-691
if args.disable_phasing or args.haplotagged_tumor_bam_provided_so_skip_intermediate_phasing_and_haplotagging:
    args.phase_tumor = False   # ← 把 phase_tumor 直接設為 False

關鍵觀察：兩個語意完全不同的 option（--disable_phasing = 完全不要 phasing；--haplotagged_tumor_bam_provided... = 已 phase 好直接用）走完全相同分支，都把 phase_tumor=False。

§5 下游影響鏈（flow diagram）

展開：每一步驟詳細解釋
  1. User 提供 phased BAM：假設 user 已用 LongPhase 跑過 germline phasing，BAM 含 HP:i:1/2 tag
  2. 啟用 EXPERIMENTAL flag：CLI 加 --haplotagged_tumor_bam_provided_so_skip_intermediate_phasing_and_haplotagging
  3. line 690-691 分支：phase_tumor 被設為 False
  4. STEP 3 BAM 路由（綠色 ✓）：phase_tumor=False → 不切到 phased_output/tumor_*.bam → 直接傳 user-provided BAM（這部分符合 help text）
  5. mpileup HP flag（紅色 ✗）：phase_tumor=False → 不加 --output-extra HP → mpileup 不輸出 HP 欄位
  6. 結果：即使 user-provided BAM 有完整 HP tag，ClairS 也讀不到 → phase channel 全填 untag → 等同 disable_phasing

§6 三種 BAM 餵法對照

輸入 BAM 啟用 flag 實際 phase 訊號可用？ Result
原始 BAM（無 HP） 不啟用 YES ClairS 自己跑 longphase phase + haplotag → HP 進 model 預設 path — works as expected
LongPhase germline tagged BAM (HP:i:1/2) 啟用 NO phase_tumor=False → mpileup 不抽 HP HP 完全浪費 — 行為 = --disable_phasing
LongPhase-S somatic tagged BAM (HP:z:1-1/2-1/3) 啟用 NO 同上 + 字串編碼亦不相容 HP 完全浪費 + 即使能讀也會 silently drop

§7 即使 Layer 1 被繞過，Layer 2 仍 block

有人可能想 hack：手動強制 --phase_tumor True + --haplotagged_tumor_bam_provided... 同時開啟，繞過 line 691 的 disable。即使這樣，餵 longphase-s tagged BAM 仍會撞 Layer 2 阻礙：

// src/create_pair_tensor_pileup.py
for b, hap in zip(base_list, phasing_info):
    if hap in '12' and base in 'ACGTacgt':   # ← Python substring check
        pileup_tensor[channel_size + base_index[base + "HP" + hap]] += 1

對 longphase-s 寫的 HP:z: 字串 tag，substring check 結果：

longphase-s tagmpileup 輸出hap in '12'結果
HP:z:1"1"True計入 HP1 ✓
HP:z:2"2"True計入 HP2 ✓
HP:z:1-1"1-1"Falsesilently dropped ✗
HP:z:2-1"2-1"Falsesilently dropped ✗
HP:z:3"3"Falsesilently dropped ✗

含義：longphase-s 的 somatic-aware tag (1-1/2-1/3) 從來不可能進入 ClairS model — 即使 Layer 1 被 fix，Layer 2 仍 silently drop。要支援 somatic-aware HP 必須改 create_pair_tensor.py 的 parsing 邏輯 + retrain model with extended HAP_TYPE encoding。

§8 修正建議

建議修正 line 690-691（decoupling fix）

把兩個語意不同的 option 分開：

// Proposed fix for run_clairs:690-691

# Original (problematic):
if args.disable_phasing or args.haplotagged_tumor_bam_provided_so_skip_intermediate_phasing_and_haplotagging:
    args.phase_tumor = False

# Proposed:
if args.disable_phasing:
    args.phase_tumor = False
elif args.haplotagged_tumor_bam_provided_so_skip_intermediate_phasing_and_haplotagging:
    # Keep phase_tumor=True so HP info is read from user BAM via mpileup
    if args.phase_tumor is None:
        args.phase_tumor = True if args.platform != 'ilmn' else False
    # But skip the Pre-D/Pre-E longphase steps (separate flag)
    args.skip_intermediate_phasing_steps = True

同時調整 Pre-D/E 條件：

// Add condition guard at run_clairs:1064 and 1103
if not args.skip_intermediate_phasing_steps:
    echo_list.append("[INFO] Phase the Tumor BAM")
    ...
    echo_list.append("[INFO] Haplotag the Tumor BAM")
    ...

這樣才能達到 help text 承諾的「skip intermediate phasing AND acquire HP from user BAM」。

建議：Help text 重寫

若上游不修 code，至少修 help text 反映實際行為：

help="EXPERIMENTAL: Skip intermediate phasing and haplotagging steps to save runtime.
NOTE: This currently also DISABLES HP tag reading from the input BAM (behavior is equivalent to
--disable_phasing). To use HP tags from a pre-phased BAM, do NOT enable this flag — let ClairS
run its own haplotag step (which will overwrite existing HP tags). Default: disabled."
建議：上報 HKU-BAL GitHub issue

建議 issue 內容：

Title: --haplotagged_tumor_bam_provided_so_skip_intermediate_phasing_and_haplotagging behavior conflicts with help text

The argparse help (run_clairs:1818) states "the haplotype information will be acquired from haplotagged tumor BAM", but line 690-691 sets phase_tumor=False, which propagates to create_pair_tensor.py:661 and disables --output-extra HP in samtools mpileup. As a result, HP tags from the user-provided BAM are never read, and the phase channel is filled with untag values — equivalent to --disable_phasing.

Suggested fix: decouple "skip intermediate phasing steps" from "disable HP reading" by introducing a separate internal flag, or update the help text to reflect the current behavior.
