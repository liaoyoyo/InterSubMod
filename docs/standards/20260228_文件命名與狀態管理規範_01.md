# 文件命名與狀態管理規範

- 生效日期：2026-02-28
- 適用範圍：`docs/`（`archive/deep/` 歷史快照除外）

## 1. 命名規範

1. 一般文件：`YYYYMMDD_主題_流水號.md`
2. 固定文件：`README.md`、`CURRENT_FOCUS.md`、`INDEX.md`
3. 長期架構文件：`snake_case.md`（例如 `system_overview.md`）
4. 禁止格式：
- 含空格
- `YYYY-MM-DD_...` 混用日期
- 無日期且無固定名稱

## 2. 狀態分層規範

### 實驗文件 (`docs/experiments/`)

1. `in_progress/YYYY/MM/`：草稿、探索中、尚未驗證
2. `validated/YYYY/MM/`：已重跑驗證，可內部引用
3. `finalized/YYYY/MM/`：最終結論，可作正式對外口徑

### 報告文件 (`docs/reports/`)

1. `validated/YYYY/MM/`：分析報告與診斷報告
2. `finalized/YYYY/MM/`：總結、決策、整體盤點

## 3. Metadata 規範

新文件建議包含開頭 metadata：

```markdown
<!--
建立時間: YYYY-MM-DD HH:MM
狀態: draft|validated|finalized|archived
資料來源: ...
驗證命令: ...
關聯文件: ...
-->
```

## 4. 歷史文件處理規範

1. 2026-02-28 後新增/更新文件必須遵守本規範。
2. `archive/deep/` 視為歷史快照，不強制回溯改名。
3. 舊路徑若仍被引用，需在重整報告中附映射表。
