# 文件盤點分類與歸檔流程規範

## 1. 目的

建立一致且可追溯的文件治理流程，確保：

1. 可以快速找到任何文件或輸出。
2. 可以區分草稿、驗證稿、定稿與歷史檔。
3. 重整時只搬移不刪除，保留人工確認空間。

## 2. 分類標準（docs 目錄）

| 類別 | 路徑 | 定義 |
|---|---|---|
| 架構 | `docs/architecture/` | 長期設計，不綁定單次實驗 |
| 計畫 | `docs/plans/YYYY/MM/` | 里程碑、任務規劃、執行前設計 |
| 報告 | `docs/reports/{validated\|finalized}/YYYY/MM/` | 驗證報告與定稿總結 |
| 簡報 | `docs/presentations/{draft\|validated\|finalized}/YYYY/MM/` | deck、PDF、版本檔與簡報資產 |
| 實驗 | `docs/experiments/{in_progress\|validated\|finalized}/YYYY/MM/` | 實驗流程、結果、草稿 |
| 解法 | `docs/solutions/{topic}/YYYY/MM/` | 問題追查、修復方案、優化分析 |
| 研究 | `docs/research/{topic}/` | 專題研究與其附件 |
| 參考手冊 | `docs/references/manual/` | 操作手冊、agent/skill 規格、設定檔 |
| 外部參考 | `docs/references/external/YYYY/MM/` | 文獻綜述、第三方指南、外部方法整理 |
| Provenance | `docs/provenance/ai_sessions/YYYY/MM/` | AI 對話執行報告、工作過程 provenance |
| 規範 | `docs/standards/` | 命名、流程、操作政策 |
| 歸檔 | `docs/archive/YYYY/MM/` | 待保留或待清理文件（不刪除） |

## 3. 文件狀態與生命週期

1. `in_progress`：探索中，允許不完整內容。
2. `validated`：可重現、可驗證，提供內部引用。
3. `finalized`：對外或專案決策口徑，避免頻繁更動。
4. `archive`：歷史保留或待人工確認之文件。

建議流程：`in_progress -> validated -> finalized -> archive`。

## 4. 命名規範

### 4.1 標準命名

```text
YYYYMMDD_主題_流水號.md
```

### 4.2 例外

1. 導航檔：`README.md`、`CURRENT_FOCUS.md`、`INDEX.md`。
2. 長期架構文件：`snake_case.md`（如 `system_overview.md`）。
3. 歷史快照：`docs/archive/deep/` 保持原檔名，不回寫。

## 5. 盤點流程（全專案）

1. 建立完整清冊：輸出 `path/top_dir/ext/size/mtime`。
2. 建立目錄清冊：輸出所有目錄路徑。
3. 生成 docs 子清冊：補齊 `category/state/year/month` 欄位。
4. 審閱非 Markdown 檔案，判斷是否屬於附件或待歸檔。
5. 輸出盤點報告到 `docs/reports/finalized/...`。

### 5.1 資產歸屬規則

1. `docs/reports/` 以 Markdown 報告為主；若需資產，僅保留報告本身直接引用的 `assets/`。
2. `docs/presentations/` 承接 `.pptx`、`.pdf`、`.version.json` 與 deck 專屬 QA/圖像資產；`validated/` 僅放已完成 QA 的 deck，草稿與 superseded deck 退出到 `draft/`。
3. `docs/references/external/` 只承接外部文獻、第三方指南、方法整理；內部手冊與 agent/skill 規格不得放在此處。
4. `docs/research/` 以文檔與其最小必要資產為主；腳本與大量結果圖原則上應退出到 `scripts/` 或明確的 `assets/` 邊界，不再把研究工作區直接混入主導航。
5. `docs/provenance/` 只承接 provenance 類文件，不作正式結論主入口。

## 6. 查找流程（給人與 Agent）

1. 從 `docs/README.md` 進入。
2. 先依目的選類別：`plans`、`reports`、`experiments`、`solutions`。
3. 再依狀態篩選：`in_progress`、`validated`、`finalized`。
4. 最後依日期與主題關鍵字定位檔案。
5. 找不到時先查 `docs/archive/YYYY/MM/`，再查 `docs/archive/deep/`。

## 7. 歸檔與清理政策（強制）

1. 不允許直接刪除檔案。
2. 清理動作一律採「搬移到 archive 待審」。
3. 每次搬移必須附 `move_manifest`，至少包含：
   - 搬移原因
   - 原路徑
   - 新路徑
   - 執行時間
   - 狀態（`pending_manual_review`）
4. 真正刪除由使用者手動執行。

## 8. 實作檢查清單

1. 新增文件前，先確認分類與狀態路徑。
2. 新增後，更新 `docs/README.md` 導航（必要時）。
3. 重整後，更新盤點報告與清冊檔。
4. 若有搬移，更新 archive 的 `move_manifest`。
