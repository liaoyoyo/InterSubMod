§3 你的 5 個問題 — 逐一回答（含數據）

#1 再次檢查 MM+ML 是否多餘？

守門4（ReadParser:56-65）過濾須 MM+ML；MethylationParser:23 又 check。數據：此 BAM 守門4 篩 0 read（全有 MM/ML），MethylationParser 的 check 實務上 never triggers。結論：冗餘但無害（defense-in-depth）——parser 是 public/thread-safe，可能被獨立調用，保留為 safety net。建議加註解標明 defensive。

#2 read 長度 ≥ 1000 合理嗎？順序放 G3 適合嗎？

🔑 read 層（守門1-4）是同時累積所有 reason（:67 keep=全 NONE），無內部順序——「放 G3 順位」不適用。✅ 你的洞察對：read 長度可 bam_cigar2qlen(:50) 直接從 CIGAR 讀、不需解析甲基，現狀已在甲基解析前早篩。數據：1000bp 篩掉 8.1%（實質但溫和，非激進）。

#3 ±5000 下每層篩掉多少？

✅ 見 §2。每位點經過 252 read、保留率 47.5%；守門5（SNV）40.7% 最大、守門3（len）8.1%、FLAG ~5%、MAPQ 2%、MM/ML 0%。

#4 dedup 合理嗎？保留更有用？

去重（同 qname）避免重複膨脹，合理。⚠ 注意：dedup 不在 filtered_reads 記錄（ReadAggregator 另階段），故此處無數字。🔑 你的洞察值得記錄為 future 研究：保留重複 read 可看 (a) copy 狀況 (b) 摺疊 read 主/附判別 (c) 重複 read 甲基一致性驗證分群 (d) 分群先後順序。結論：dedup 保留為預設，重複 read 的分群驗證價值列 future。

#5 無交集/共同CpG<3 設 MAX_DIST=1.0 好嗎？會模糊影響？

U1 全量對比已驗：🔴 SKIP（不計入的替代）目前 segfault（NaN 矩陣讓 clustering/PERMANOVA 崩）= 新 bug，不可用。✅ MAX_DIST BERNOULLI±5000 下 Noise 僅 9.4%（vs NHD±1000 的 26.4%）→ 不支持「大量模糊誤判」。結論：MAX_DIST 目前合理且唯一可用；要嚴格驗證 SKIP 是否更優、是否反而缺 read（你的疑慮），必須先修 SKIP segfault bug 才能對比。
