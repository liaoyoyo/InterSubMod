SKIP segfault 修復 —— 改動步驟、數字、案例差異圖

這幾天修了一個讓 ISM 在 --nan-distance-strategy SKIP 下一開跑就崩潰（SIGSEGV）的 bug。這頁把根因 → 修法 → 三層驗證 → 解鎖的 U1 比對 → 4 個案例熱圖攤出來，讓你確認改動有效、無副作用、且符合你的判斷。

L0 一眼看懂

Bug：SKIP 策略把覆蓋不足的 read pair 距離設成 NaN，UPGMA 永遠選不到 NaN（NaN<x 恆假）→ 建出有環的樹 → 下游 collect_internal_nodes 沿環無限遞迴 → 堆疊溢位崩在第一個 region（exit 139）。

修法：A（治本）＝clustering 前先 filter 掉 NaN，讓 clustering 與 PERMANOVA 用同一份乾淨 read 子集；C（安全網）＝遞迴加 cycle guard，再有環也不崩。

驗證：✅ ctest 221/221、✅ MAX_DIST 結果 bit-identical（零副作用）、✅ 原本崩的 input 現在 exit 139 → exit 0。

解鎖效果：SKIP 路徑現可用 → 完成 U1（MAX_DIST vs SKIP 分群品質比對），發現 MAX_DIST 的 1.0 假距離一直在稀釋甲基分群訊號。範圍：HCC1395 單樣本（chr1 + 全基因組）。

🔴 一句話判斷：這是個真 crash bug（不是調參），修法 A 治本 + C 安全網雙保險，且 MAX_DIST 預設路徑經 regression 證實逐位元不變 → 對既有結果零風險，純粹「修掉崩潰 + 解鎖一條本來跑不了的路」。

① bug 根因鏈（gdb 重現確認）

為什麼只有 SKIP 崩、MAX_DIST 不崩？關鍵在「NaN 距離」這顆地雷一路滾到 clustering。

② 修法：A 治本 + C 安全網

兩層防護。A 解決「NaN 為什麼會害死 clustering」，C 是「就算還有環也不准崩」的兜底。

修法在哪做什麼關鍵保證
A 治本RegionProcessor
新 extract_complete_submatrix_indices()		clustering 前先剔除「非-NaN 鄰居最少」的 read 直到子矩陣無 NaN；與 StructureTest::filter_reads_for_complete_matrix 同演算法 → clustering 與 PERMANOVA 用同一份 valid read 子集MAX_DIST（無 NaN）→ 子集＝全部 → zero-copy → bit-identical
C 安全網TreeStructure
collect_internal_nodes/leaves		加 std::set<TreeNode*> visited，節點第二次被訪問即 return遞迴深度 ≤ 不同節點數 ≤ 2N−1 → 永不爆 stack，且不誤傷正常深樹
設計要點 A 把 SKIP 的語意做對了 ——「共同 CpG 不足的 read 本來就無法可靠分群，剔除它」正是 SKIP 的設計意圖；而且讓 clustering 與顯著性檢定看同一份 read（先前不一致）。C 是與 bug 機制無關的通用防護，未來任何畸形樹都擋得住。

⚠ 本質判別（誠實天花板） 浮現的訊號主導是 germline-HP（DominantLabel hp 85%），不是 somatic subclone —— 與主軸「甲基＝germline-haplotype 層級」一致。所以 SKIP 是「更正確的 NaN 處理」，但對somatic subclone 偵測力的淨增益尚未確立（需 normal 對照，見 gap2）。

⑤ 案例差異圖：4 個 region 的 MAX_DIST vs SKIP 熱圖

⑥ gap1 補強：NReadsValid 欄（剔除量可追溯）

U1 發現一個記錄缺口：SKIP 每個 region 到底剔掉多少 read，從 summary 看不到。e154934 補了這欄。

策略NReadsValid（用於 clustering 的 read 數）剔除量 = NumReads − NReadsValid
MAX_DIST== NumReads（filter 是 no-op，無 NaN）0
SKIP≤ NumReads（例：98→68、92→50）剔除比例對得上 NaN 佔比

驗證：ctest 221/221；MAX_DIST regression 仍 bit-identical（新欄是附加，golden 9 欄按名抽取不受影響）。gap2（germline vs somatic-subclone 分離，需 normal-only HP 對照）尚未補 → 列入下一步。
