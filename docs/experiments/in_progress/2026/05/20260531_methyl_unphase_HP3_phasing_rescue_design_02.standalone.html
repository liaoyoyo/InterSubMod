0.一句話結論：longphase-S 已救一半 H3，但完全放棄 unphase — 甲基來補這塊

paired 模式下，phasing 工具 longphase-S 已內建把「卡住的 somatic read（H3）」往 haplotype 救（H1-1 / H2-1）的機制，且已救掉 42%。但它對 unphase read 完全不處理 （inheritance 前後一條都沒動）。本任務 = 對 longphase-S 放棄的 unphase + 救不動的 H3，用甲基分群再救一層相位歸屬，並量化能不能做、做得多好。

2.關鍵發現：inheritance 救 42% H3、untag 一條不動 — 守恆已驗證

下圖比較 longphase-S inheritance 執行前 vs 後各類 read 的數量（HCC1395，120,834 somatic 位點，read-instance 口徑）。這是用它既有輸出檔親自重算、守恆檢查通過的權威基線。

為什麼這對設計是好消息：本任務不是從零建重指派，而是站在 longphase-S 已做好的基礎上補最後一塊。unphase 是它主動放棄、無既有方法競爭的乾淨空間 — 甲基若有訊號，這裡最容易看出來。

4.方案：先純 Python 旁路驗證判別力，過門檻才動 C++

你已拍板的策略（MD1=C）：先在零改碼的 Python 旁路驗證甲基有沒有判別力，只有過 GO 門檻才投入不可逆的 longphase-S C++ 工程。這把最貴、最不可逆的步驟延後到證據充足之後。

5.GO / NO-GO 用量化門檻判定，不靠感覺

判定量化條件後續動作
GO ✓unphase 或卡住 H3 子集的甲基 affinity AUC > 0.58 且顯著超過 germline-het null（過 /auc-confound-guard 三關）升級評估 Phase B C++ 增強（另開 spec）
NO-GO ✗AUC ≤ 0.58，或 AUC>0.58 但被 germline-het null 解釋（=baseline 甲基 confound 非 somatic 訊號）兩路皆停，不投入任何 C++
PROBE ⚠AUC>0.58 僅特定子集（如 non-LOH 區）成立限定 scope 重評
為什麼這個門檻嚴格：本 repo 已多次確認「純甲基特徵的 TP/FP 判別 AUC ≤ 0.58 天花板」。本任務目標雖不同（救相位非判別 TP/FP），但沒理由假設甲基訊號會因換目標就突破天花板 — 所以 Phase A 先驗證，是誠實的前置擋點。

8.兩條紅線：防止滑回已死的「甲基當 FP filter」死路

紅線 1 — metric 鎖死在 read tag / phasing 層級。 success = 被救回 read 與 ground-truth haplotype 一致率 + 對 LOH-phasing 活軸的增益。 絕不可回頭包裝成「改善 variant TP/FP F1」— 那是已 concluded 的死路（⭐2 L4，100% sample-level circularity）。
紅線 2 — HP-axis 為主證據軸。 你提的 Ref-Alt vs Alt-Ref（ALLELE-axis）會被 germline-het 基線甲基化 confound（TP 11.1% < het null 15.2%）。 只有 HP-axis（HP1 vs HP1-1）是 somatic-controlled；ALLELE-axis 僅作描述且強制 germline-het negative control。
