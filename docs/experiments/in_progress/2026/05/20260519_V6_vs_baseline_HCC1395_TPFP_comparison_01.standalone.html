1.為何做這個實驗

V6 production tag Tier 1.2 Day 2 supporting evidence。V6 doc §4-§7 已比 V3F vs V5 vs V6（三向，不含 baseline）。本實驗加入 baseline 第 4 個 BAM 完成 4-way head-to-head，提供 V6 production sign-off 所需的「對照 upstream baseline 之直接 quantification」。

同時作為 regression test：4-way 管線 reproduce V6 doc 三向發表數字（V3F/V5/V6 marker count / rate / h11_h21 ratio 全部逐位元相同）— 證實管線無 drift。

Commit d0bcd8c + 938f0df (2026-04-30)。Marker rate 0.8937 反低於 baseline 0.8967（差 -0.0030 pp）— 本實驗的最關鍵發現之一：V5 Layer 1.5 somatic fallback 在 germline-absent 區做了 priority bug 的「feature 化」，增加 marker 候選但 TP 純度沒保持。

Marker count 18,382 > baseline 15,738 但 < V6 23,980。HP1:HP2 ratio 1.690 與 baseline 1.696 接近 — V5 phasing 不解決 ratio bias。V5 → V6 的設計動機在本實驗 cross-validated。

V6 V6 patch — V5 phasing + V3F-style hp=3 hybrid，最佳整體 WINNER

V6 patch (HaplotagProcess.cpp:537-548 移除 Layer 1.5 else if 分支)。Marker count 23,980 (全 4 BAM 最高，+9% over V3F, +52% over baseline)；marker rate 0.9093（< V3F 0.9175 -0.9pp 但 > baseline + V5）；LOH-positive marker rate 0.9801 全 4 BAM 最高；hp=3 ambig 138,317（甚至略多於 V3F 132,060）。

V6 trade-off：相比 V3F 多捕 +1,983 marker regions（其中 TP 占 81.9%）。V6 = V3F-style 保守 + V5 phasing 紅利 hybrid 此實驗直接驗證 V6 doc §8.2 「best of both」敘事。

NG_on=2 purity V6 = V5 = 0.8285（因 V6 重用 V5 phased VCF — caller F1 不變的另一面證據）。

Fix 3 Source-code dual bug 鐵證 (5/20 對話澄清新加) DUAL BUG

User Q (5/20)：「baseline 因 priority bug 不會輸出 hp=33，但數據顯示 baseline hp=3=10,440，矛盾嗎？」
解答：沒矛盾。baseline 同時有兩個獨立 source-code-level bug，V3F 同時修補。

Util.h enum 鐵證（line 19-26）

enum Haplotype {
    HAPLOTYPE_UNDEFINED = -1,
    HAPLOTYPE1   = 0,  HAPLOTYPE2 = 1,  HAPLOTYPE3 = 2,
    HAPLOTYPE1_1 = 3,  HAPLOTYPE2_1 = 4,
};

而 hpResult 實際被 getVote 設成 mapped integer (haplotypeBase map)：可能值 {0, 1, 2, 11, 21, 33}，從不會是 3 或 4。

🔴 Bug 1: getVote priority order (line 510-513)

std::vector<std::pair<int, int>> variantKeys = {
    {HAPLOTYPE1_1, HAPLOTYPE2_1},   // 1st priority: somatic pair ← BUG (順序倒置)
    {HAPLOTYPE3,   HAPLOTYPE2_1},   // 2nd
    {HAPLOTYPE1,   HAPLOTYPE2} };   // 3rd: germline pair

somatic 優先於 germline。任一 somatic vote (HP1_1 > 0) 即 break。Effect：全基因組 ALT-only HP1:HP2 = 17.3:1 (PI 4-29)；germline-strong-evidence reads 被 somatic vote preempt。

🔴 Bug 2: judgeHaplotype dead code branch (line 697-701)

if (max == 0 || max/(max+min) < percentageThreshold) {
    if(hpResult != HAPLOTYPE1_1 && hpResult != HAPLOTYPE2_1){
    //  比 enum value (3,4) vs hpResult mapped integer (0,1,2,11,21,33)
    //  6 個可能值都 ≠ 3 AND ≠ 4 → 條件恆 TRUE
        hpResult = 0;   // ← 永遠執行
    } else {
        hpResult = 33;  // ← 9 年 dead code，從未執行
    }
}

enum-vs-integer type mismatch bug。低信心 fallback 永遠走 hpResult=0，never 33。baseline 的 hp=33 output 完全不來自此 fallback。

baseline hp=3 = 10,440 唯一 source（澄清矛盾）

baseline hp=3 output 唯一路徑 = getVote 第 2 priority pair {HAPLOTYPE3, HAPLOTYPE2_1} 中 HAPLOTYPE3 winning：

  • 1st pair skip: countMap[HP1_1]=0 && countMap[HP2_1]=0 (read 無 somatic-traceable vote)
  • 2nd pair enter: countMap[HP3] > 0 (cover 到 HAPLOTYPE3-annotated variant)
  • HP3 wins → hpResult = 33 → BAM HP:i:33

10,440 是「自己沒 somatic-traceable vote、cover 到 HAPLOTYPE3 annotated variant」的小邊界 case（佔全 reads 0.42%）。

7.Limitations & Caveats

7.1 HP1:HP2 ratio all-reads 層級 vs PI 報告 ALT-only 層級

V6 doc §8.5 引用 PI 4-29 baseline 17.3:1 是 ALT-supporting reads only (alt_support='ALT' 過濾後)。本實驗的 1.696 是 all reads in ISM window（含 ALT + REF supporting + 跨 phase 邊界 reads）。ALT-only 限定 reads 反映 priority bug 的「somatic 偏 HP1」最尖銳信號；all-reads 層級則 dilute 此 signal。兩個指標都有效但口徑不同。本實驗的 marker rate + count 是 ALT/REF 都納入的整合指標，更代表「下游 marker filter 在 ISM 後的實用差異」。未來可加 alt_support='ALT' filter 重跑 (~2 hr) 完整重現 PI 17.3:1 敘事。

7.2 V6 LOH BED 共用 V5

V6 patch 只改 haplotag stage 不動 phasing。V6 ISM 跑時用的 LOH BED 是 V5 tumor_phased_LOH.bed (4 BAM 共用，非循環依賴)。對 marker rate 沒影響 — LOH BED 只影響 LOH 區域標註，不影響 NG 計算。

7.3 LOH zone 只有 2 categories

LOH_Bed_Annotation 在 master.tsv 只有「set」或「NA」二值。要做更細緻的 zone（如 LOH × CN × AF 32-cell）需用 V6 doc §3-§4 的完整 grid（step2 / step3 已做，本實驗不重複）。

7.4 Scope: 單樣本 HCC1395

本實驗只跑 HCC1395。Phase D 已驗證 V6 在 H1437/H2009/HCC1954/HCC1937 4 樣本 cross-sample marker rate ≥ 0.85（HCC1937 0.817 BRCA1 edge case），但未測 baseline 在 4 個樣本。本輪 V6 production tag scope 5/7 樣本（V6 already validated），baseline 4-sample comparison 留待 Phase 2。

10.F1 Analysis — 能否打敗 caller-alone？

User 問題：「可以做到比 baseline 還有 caller 更好的 F1 結果嗎？」本節從 ISM marker filter 套用後對 canonical caller F1 vs SEQC2 truth 的影響回答。

10.1 F1 公式與 canonical 對齊

TP = caller PASS ∩ truth_positive ∩ filter_kept
FP = caller PASS ∩ ~truth_positive ∩ filter_kept
FN = FN_CALLER_PILEUP (=19,288, caller missed) + (TP_TOTAL - TP_filter_kept)
F1 = 2 × TP / (2 × TP + FP + FN)
Caller-alone F1 sanity check：2 × 30,490 / (2 × 30,490 + 4,842 + 19,288) = 0.7165 ✓ 與 V6 doc §8.6 published canonical F1 = 0.7166 對齊到 0.0001 容差。

11.2 驚人發現 — LR 機制 NOT V6-specific

baseline LR ΔF1 = +0.02302 略勝 V6 LR +0.02236（差 +0.00066）。意味：
  1. +0.02236 ΔF1 的價值主要來自 BAM-independent features（caller_af / LOH / Cov / methylation 5 feature），NG 只是 10-feature 中一個
  2. NG 分布差被 LR 自動 compensate：baseline NG 較低，LR 自動 shift τ 從 0.39 → 0.48 補償 — 達到相當（甚至略高）F1
  3. Cycle 2 H_C1_6 已證 V3F/V5/V6 cross-binary max variance 0.00073；本實驗擴展 baseline 加入 cross-binary invariance set

11.3 對 V6 production tag 的影響

層級V6 是否優於 baseline？
Filter-level (marker count + rate)✅ 是（+52.4% count, +1.26pp rate）
F1-level (hard NG threshold sweep)✅ 是（ΔF1 +0.001 至 +0.197 跨 T=1-5）
F1-level (multi-axis LR)⚠️ 否 — baseline LR +0.02302 反而略勝 V6 +0.02236
核心 verdict：V6 production tag 升級的價值在 filter-level + hard threshold F1 level（marker filter 用途）。對於 multi-axis LR-based F1 提升用途，V6 / baseline / V3F / V5 都能達 ≈ +0.023 ΔF1（cross-binary invariant）— LR 機制不挑 BAM，主要 leverage BAM-independent features。
