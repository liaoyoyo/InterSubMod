這幾天的幾次改動驗證 —— 聚焦「skip 問題」

回顧 06-09～06-11 對「甲基救 unphase / 矯正 longphase-S tag」做的四次迭代修正（V11 → V11b → V11c → V12），把每一步的前後數字差異攤出來，特別是你問的 skip 問題（絕大多數 unphase read 其實無法救、被跳過）。所有數字都標了來源 JSON。

L0 一眼看懂這幾次改動在修什麼

原本的好消息是「甲基能把 unphase read 救回正確 haplotype，正確率 88.5%」。這幾天的修正把這句話收斂到誠實版本：

① 88.5% 只在「可嘗試」的那 ~6% read 上成立，其餘 94% 的 unphase read 根本沒有本地參考、必須跳過（skip）；② 之前 T3「亞群有獨特甲基（+0.022）」是沒做同窗配對的假象，正確配對後 p=0.924（與噪音無異）；③ 但 T3 用「位點 ALT/REF」重做，存在性窄翻案 POSITIVE（可用性仍 NEGATIVE）。

範圍誠實標註：全部 = HCC1395 單樣本、longphase-S 單一 pipeline、skip 清點只實掃 chr15/19/20/22（4 條）。tier 上限 ⭐3。

「skip 問題」到底指什麼？ 一條 unphase read 要能被甲基救援，必須同時滿足：(a) 自己有 ≥5 個 CpG 甲基訊號、(b) 它所在的 2kb 區段裡有足夠的 HP1 與 HP2 read（各 ≥8 條）當「本地參考」可比對。不滿足 (b) 的 read 沒有可比的對象 → 無法區分 → 被跳過（cannot_distinguish）。V12 的清點發現：滿足兩者的只有 ~6%。

② 配對校正：T3「亞群有獨特甲基」是假象 V11b · 已撤回

這是另一個「skip/配對」相關的修正 —— 比較亞群 vs 噪音時，原本沒把同一個窗的數據配對起來，造成虛假的正向差異。下面兩張圖就是改動前後。

口徑亞群 vs 噪音 Δβ統計判定
改動前 unmatched（池化噪音 0.088）亞群 0.110 − 噪音 0.088 = +0.0224無配對檢定看似有訊號
改動後 matched 同窗配對（真噪音 0.0997）同窗配對差 median −0.0043Wilcoxon p=0.924（dz=0.07）與噪音無異
正控（不同 haplotype H1 vs H2）median +0.0425p=1.77e-49配對法有效

+0.0224 → −0.0043（p=0.924） ：差異整個消失。正控 p=2e-49 證明「不是配對法把所有訊號都殺光」，而是亞群本來就沒有獨特甲基。

Takeaway · 配對 教訓：比較兩組「差異」時，噪音地板必須在同一個窗內配對抽樣，不能用全體池化平均當對照 —— 否則窗與窗之間的甲基差會被誤算成「亞群訊號」。修正後 T3「亞群有獨特甲基」撤回。

為什麼之前 ②會是 NEGATIVE？（標籤污染）

HP1 read 約 20kb 長、somatic 突變稀疏 → 多數真亞群 read 根本沒蓋到那個突變位點 → 被 longphase 標成普通「1」（母本）→ 混進母本組把訊號沖淡。改用「位點 ALT/REF 鹼基」直接看誰帶突變，就避開了這個污染。→ 你當初「亞群應該有差異」的直覺，在存在性層級成立。

Takeaway · T3 亞群甲基差異存在（窄、單樣本、⭐3 未達 reopen 門檻），但不能用來實際判別/指派。存在 ≠ 可用 —— 與全專案 ASM 結論一致。

三個需要你拍板的點

  • ① skip 問題的定性對嗎？ 我把「94% skip」歸因為缺本地 HP1/HP2 錨點（不是甲基訊號不夠）。這符合你對機制的理解嗎？還是你認為瓶頸在別處？
