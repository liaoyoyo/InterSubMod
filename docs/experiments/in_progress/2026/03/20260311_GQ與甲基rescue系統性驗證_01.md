# GQ 與甲基 rescue 系統性驗證

## 重點結論

這輪結果把 `caller-first` 與 `methylation-support` 的分工講得更清楚了。`GQ` 目前仍是最穩定的第一層救援訊號，但它**不能直接被理解成 ClairS-TO 一開始就該全域放寬的閾值**，因為在 `HCC1395 5kHz TO` 中，被後段排除的 `FP` 共有 `2,720,008` 筆，而真正進入 rescue-eligible 候選池的只有 `298` 筆；若不先經過 caller 的候選池收斂，而是直接全域放寬 `GQ`，會把大量 `NonSomatic / PON` 噪音一起放回來。甲基資料方面，`5kHz TO` 上確實存在有效的 support 訊號，例如 `PairwiseMedianDist`、`Quality_Score`、`agreement_positive`，但目前都**沒有超過同一 caller gate 的 `GQ only`**；`5kHz paired` 與 `HCC1395_DORADO paired` 則更明確支持 caller-first，甲基 rescue 不是穩定跨樣本規則。最合理的結論仍是：第一層用 caller `GQ / QUAL / candidate_eligible` 定義可救集合，第二層才讓甲基特徵做 support 或 artifact triage，而不是反過來。

## 1. 背景與名詞說明

### 1.1 `GQ` 是什麼

根據 [ClairS-TO VCF 詳細規格](/big8_disk/liaoyoyo2001/knowledge/03_file_formats/vcf_clairs_to.md)，`GQ` 是 `Genotype Quality`，中文可譯為**基因型品質分數**。它是 caller 對該位點最終 genotype / variant 判定信心的摘要分數；在 ClairS-TO 的規格中，`GQ >= 20` 被列為建議的高信心閾值。

`GQ` 的意義不是「越高越一定是真 TP」，而是：

1. caller 對該位點整體判讀的信心較高；
2. 若要從 final VCF 中做 borderline rescue，`GQ` 通常是最直接的第一層排序依據；
3. 但在 tumor-only 問題上，若沒有再配合 `FILTER / PON / verdict / 候選池條件`，單獨放寬 `GQ` 很容易把大量非 somatic 噪音一起救回來。

### 1.2 為什麼 ClairS-TO 不一開始就放寬 `GQ`

根據 [Variant Callers](/big8_disk/liaoyoyo2001/knowledge/05_tools/variant_callers.md) 與 [ClairS-TO VCF 詳細規格](/big8_disk/liaoyoyo2001/knowledge/03_file_formats/vcf_clairs_to.md)，ClairS-TO 在 tumor-only 模式下本來就要同時對抗：

1. `PON` 命中的 germline / recurrent artifact，
2. `NonSomatic` 與 `LowQual` 類型的低信心位點，
3. `VariantCluster / StrandBias / ReadStartEnd / LowAltBQ` 等結構性錯誤。

因此它的預設策略是先用保守的 high-confidence 邏輯維持 precision，再把少量可能值得重看的位點留給 downstream rescue。這也正是本輪分析想驗證的核心：**是否能在 candidate pool 內進一步放寬，而不是在整個 call set 上直接放寬。**

### 1.3 這輪數據如何解讀

本報告所有 rescue 表格都固定使用以下欄位：

| 欄位 | 意義 |
| --- | --- |
| `TP_rescued` | 原本落在 `caller_lost_tp` 的真陽性，被規則救回的數量 |
| `FP_reintroduced` | 原本落在 `caller_removed_fp` 的偽陽性，被規則一起放回的數量 |
| `delta F1 vs baseline` | 相對原始 baseline kept set 的 F1 變化 |
| `delta F1 vs gate` | 相對同一 caller gate 的 F1 變化，用來判斷甲基是否真的有額外資訊 |

其中 `delta F1 vs gate` 特別重要，因為它可以避免把「只是把 caller gate 變窄」誤判成「甲基特徵真的有增量」。

## 3. 問題一：為什麼 ClairS-TO 不一開始就放寬 `GQ`

### 3.1 候選池母數

| 資料集 | 狀態 | 總數 | candidate_eligible | 比例 | 排除後但 `GQ>=10` |
| --- | --- | ---: | ---: | ---: | ---: |
| `HCC1395 5kHz TO` | `caller_lost_tp` | 2,108 | 773 | 36.67% | 1,220 |
| `HCC1395 5kHz TO` | `caller_removed_fp` | 2,720,008 | 298 | 0.011% | 2,631,739 |
| `HCC1395 5kHz paired` | `caller_removed_fp` | 12,974 | 5,266 | 40.59% | 154 |
| `HCC1395_DORADO paired` | `caller_removed_fp` | 2,533 | 1,658 | 65.46% | 15 |

資料來源：
- [pool_eligibility_summary.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260311_gq_methylation_rescue_matrix/pool_eligibility_summary.tsv)

### 3.2 5kHz TO 被排除 FP 的主要原因

| 排除原因 | 數量 | 比例 |
| --- | ---: | ---: |
| `NonSomatic` | 2,688,427 | 98.85% |
| `NonSomatic;low_dp` | 25,000 | 0.92% |
| `NonSomatic;low_alt_count` | 3,530 | 0.13% |
| `VariantCluster` | 1,969 | 0.07% |

資料來源：
- [exclusion_reason_summary.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260311_gq_methylation_rescue_matrix/exclusion_reason_summary.tsv)

### 3.3 結論

這裡的關鍵不是「`gq>=10` 有沒有用」，而是**`gq>=10` 只能在 candidate-eligible pool 裡談**。在 `HCC1395 5kHz TO`：

1. 真正進入 rescue 候選池的 `FP` 只有 `298` 筆；
2. 被排除的 `FP` 中，高達 `2,631,739` 筆仍有 `GQ>=10`；
3. 而且其中 `98.85%` 的主因就是 `NonSomatic`。

因此 `ClairS-TO` 不一開始就全面放寬 `GQ` 是合理的。若不先用 `candidate_eligible / FILTER / PON / verdict` 收斂母體，而直接放寬 `GQ`，就等於把大量明確被判為非 somatic 的位點一併放回來。

- 甲基資料是有訊號的第二層 support；

## 5. 問題三：這些特徵在 `HCC1395 5kHz tumor/normal` 與 `HCC1395_DORADO paired` 是否也有用

### 5.1 `HCC1395 5kHz paired`

| 規則 | TP rescued | FP reintroduced | F1 | delta F1 vs baseline |
| --- | ---: | ---: | ---: | ---: |
| `gq>=10` | 183 | 616 | 0.847749 | -0.004459 |
| `gq>=15` | 106 | 75 | 0.853033 | +0.000825 |
| `gq>=20` | 59 | 8 | 0.853080 | +0.000871 |
| `PairwiseMedianDist>=0.20` | 57 | 222 | 0.850443 | -0.001765 |

結論：

1. `gq>=10` 在 paired 5kHz 上反而是負增益。
2. paired 問題上較合理的是 `gq>=15` 或 `gq>=20`。
3. 甲基單獨在這個資料集目前沒有形成正向 rescue。

### 5.2 `HCC1395_DORADO paired`

| 規則 | TP rescued | FP reintroduced | F1 | delta F1 vs baseline |
| --- | ---: | ---: | ---: | ---: |
| `gq>=10` | 173 | 344 | 0.857775 | -0.001401 |

| `gq>=20` | 51 | 7 | 0.859925 | +0.000749 |
| `hp_assign_rate>=0.99` | 68 | 87 | 0.859216 | +0.000041 |
| `Strong/Subclone` | 29 | 56 | 0.858960 | -0.000216 |
| `PairwiseMedianDist>=0.20` | 13 | 58 | 0.858673 | -0.000503 |

結論：

1. `DORADO paired` 同樣不支持 `gq>=10` 當作穩定第一層 gate。
2. caller-first 仍是 `gq>=15 / gq>=20`。
3. 甲基訊號在 `DORADO paired` 的方向和 `5kHz TO` 不同；這裡真正較有價值的是 `hp_assign_rate`，不是高 pairwise。

### 5.3 跨樣本總結

| 規則 | `5kHz TO` | `5kHz paired` | `DORADO paired` | 解讀 |
| --- | --- | --- | --- | --- |
| `gq>=10` | 正增益 | 負增益 | 負增益 | 只在 TO candidate pool 適合 |
| `gq>=15` | 正增益 | 正增益 | 正增益 | 目前最穩定的 caller-first 閾值 |
| `gq>=20` | 正增益 | 正增益 | 正增益 | 最保守且跨樣本穩定 |

| `hp_assign_rate>=0.99` | 有訊號但非必要 | 幾乎無訊號 | 輕微正增量 | 偏 `DORADO paired` 支援特徵 |

### 6.2 與既有結論合併解讀

這輪的 early rescue 分析，加上前面已驗證的後段 triage 結論，可得到比較完整的定位：

1. 在 `5kHz TO` 的 post-InterSubMod triage 上，`low VAF + high AlleleDelta + low CramersV` 可以移除 `36 FP`、僅誤傷 `2 TP`，見 [20260308_TO特徵回查與label_upgrade_conflict分析_01.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/experiments/in_progress/2026/03/20260308_TO特徵回查與label_upgrade_conflict分析_01.md)。
2. 但在這輪 candidate-specific early rescue 上，把它拿來當主 rescue 或 veto 規則，並沒有形成正增量。

因此目前最合理的定位仍是：

- `low VAF + high AlleleDelta (+ low CramersV)` 比較適合作為**後段 artifact triage / FP suspect annotation**；
- 不適合作為「一開始就用來多救 TP」的主規則。

## 8. 回答原始研究問題

### 8.1 `gq>=10 + 甲基特徵` 有效嗎

有條件有效，但必須精確表述：

1. 在 `5kHz TO`，`gq>=10` 單獨就已經有效；
2. `gq>=10 + 甲基特徵` 仍能維持正向 rescue；
3. 但到目前為止，`甲基特徵` **沒有超過同一 gate 的 `gq>=10 only`**。

因此更準確的說法是：

- `gq>=10 + 甲基特徵` 是**可用的 caller-first + support**；
- 但目前還不是必要條件，也不是比 caller-only 更好的主規則。

### 8.2 單獨甲基特徵有沒有用

有訊號，但目前不能單獨取代 caller。

1. `5kHz TO` 上，`Quality_Score>=60`、`Pairwise>=0.15/0.20`、`agreement_positive` 都能從 baseline 救回 TP。
2. 但在 `5kHz paired` 與 `DORADO paired` 上，甲基單獨規則不是負增益，就是只有非常小的增益。

### 8.3 這些特徵能不能在一開始就多救回 TP

目前最可靠的答案是：

1. 一開始就多救回 TP 的主軸仍應放在 caller `GQ / QUAL / candidate_eligible`。
2. 甲基特徵目前更適合：
   - 做 second-layer support
   - 排序 candidate
   - 做 artifact suspect annotation
3. `low VAF + high AlleleDelta` 適合做**後段 triage**，不適合直接升級成 early rescue 主規則。

## 9. 結論與下一步

### 9.1 本輪正式結論

1. `GQ` 的確是目前最穩定的 caller-first rescue 訊號。
2. `ClairS-TO` 不一開始全域放寬 `GQ` 是合理的，因為 `TO` 被排除的 FP 幾乎都不是 rescue-eligible 候選。
3. `5kHz TO` 上甲基訊號有用，但目前最好定位為 support，不是必要條件。
4. `5kHz paired` 與 `DORADO paired` 目前不支持把 `gq>=10 + 高 pairwise` 升級成跨樣本規則。
5. `PairwiseMedianDist`、`Quality_Score`、`agreement_positive` 都呈現區間性或子集合訊號，不應再用單一全域硬閾值思考。

### 9.2 最值得直接延續的分析

1. 先對 `HCC1395_DORADO TO` 補做同型 candidate-specific InterSubMod，確認 TO 下是否仍是 `gq>=10` 有效但甲基僅為 support。
2. 在 `5kHz TO` 上把 `Quality_Score / Pairwise / agreement_positive` 做更細的 per-region diagnostics，確認它們各自對應的 read-level 現象是否不同。
3. 若要進到流程層，優先做 annotation：
   - `RescueCandidate_GQ`
   - `RescueSupport_Pairwise`
   - `RescueSupport_Agreement`
   - `ArtifactSuspect_LowVAF_HighADelta`

### 9.3 目前不建議做的事

1. 不要把 `gq>=10` 直接視為 ClairS-TO 的全域放寬閾值。
2. 不要把 `PairwiseMedianDist>=0.20` 當成跨樣本 rescue 規則。
3. 不要把 `low VAF + high AlleleDelta` 直接拿來當早期 TP rescue 主規則。
4. 不要把 `allele_assign_rate>=0.99` 這種技術 proxy 升級成正式甲基特徵。
