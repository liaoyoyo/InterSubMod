💡 V3F 同時修兩個獨立缺陷 — 機制敘述

[缺陷 1] 型別錯位 (enum vs integer literal mismatch)

原問題：baseline 比較 hpResult != HAPLOTYPE1_1，而 HAPLOTYPE1_1 是 enum=3；但 getVote 上游已透過 haplotypeBase map 把 hpResult 設為 integer 11/21/33。比較跨型別永遠不等 → 條件恆 true。

V3F 改法：commit 41ff147 改用 integer literal 直接比較 hpResult == 11 || == 21 || == 33，避開 enum 值。

為何有效：消除型別歧義，比較目標與 HP tag 實際寫入值對齊，hp=33 分支才有可能命中。

[缺陷 2] 判定方向反 (logic inversion)

原問題：baseline 寫 != 分支設 hp=0、== 分支設 hp=33 — 即使型別對齊，方向也是反的：somatic 有票時被丟回 0，純弱 germline 反而給 33。

V3F 改法：翻轉條件 — ==（somatic 11/21/33 命中）→ hp=33；!=（純 germline 弱信號）→ hp=0。

為何有效：somatic 有訊號時保留為 ambiguous tag (33) 供下游使用，純弱信號才丟棄；語意與 hp=33 設計初衷對齊。

合併結果差異 — 同一條 somatic read：baseline → hp=0（no tag，被丟棄）❌　/　V3F → hp=33（somatic ambiguous，下游可用）✅　兩缺陷疊加讓 hp=33 設計意圖完全失效，else 分支死碼 9 年；V3F 同 commit 一次修正型別與方向。
