getVote priority bug：1 票 somatic 蓋 5 票 germline

Vector-ordered + break-early loop ignores germline majority — by design, by mistake

// countMap reset per-read

for (auto v : votes) {            // vector 順序 ❶ somatic ❷ mixed ❸ germline

      hp = somatic_to_hp(v);
      break;                    // ❌ 1 票即 break-early
  }
  if (v.type == MIXED)    { ... }
  if (v.type == GERMLINE) { ... }  // 永遠到不了
}
return hp;

🎤 Speaker Note
2 分鐘
[開場] 這張投影片揭露 tagging 層 priority bug 的程式碼層級機制。 [主軸] baseline 的 getVote 函式 line 533 有兩個 bug： 1. vector 順序錯：somatic 優先於 germline； 2. break-early：1 票 somatic 就跳出迴圈，5 票 germline 永遠到不了。 [範例] 真實 read 案例：germline HP2 有 5 票、somatic HP1 只 1 票。 按多數決應 hp=21，但 baseline 標 hp=11 — 1 票把 5 票蓋掉。 [因果] tumor sub-clone 的 somatic 100% 同方向 → 所有 reads 都被標到 HP1 系列 → 這就是 17.3:1 偏移在 tag layer 形成的方式。 [結論] 下張投影片會看兩層 bug（phasing + tagging）對應兩層修補。
Tier 3 (口頭可選): enum 差異 — HAPLOTYPE1_1=2 是內部 enum，HP tag=11 是 BAM 寫出值。 兩者經 somatic_to_hp() 映射，bug 在映射前的 break-early 邏輯，不在 enum 本身。
