## 3. 🔴 三個必須先知道的結構性事實

### 事實 A：兩支 C++ 都**完全沒有寫 BAM 的能力**

- ISM：`sam_write1` / `bam_write1` / `sam_hdr_write` 全 repo 出現 **0 次**，所有 `sam_open` 都是 `"r"` 模式。
- LL：`src/io/` 8 個 .cpp 全為唯讀 API。
- 現存 tagged BAM 全部由**外部工具 LongPhase-S** 產生
  （`SomaticHaplotagProcess.cpp:533` 的 `bam_aux_append(aln,"HP",'Z',...)`）。

而且**現行架構刻意反對落地 BAM**：第二代 producer 用 `mkfifo` 把 tagged BAM 導進 pipe，
由 pysam 抽成 sidecar 後，**跑完還斷言目錄內不得存在任何 `*.bam`**。
authority 記錄 7/7 皆 `"persisted_tagged_bam": false`。

第一代確實落地過 —— 磁碟上仍有 **14 個 tagged BAM**（7 樣本 × 2 模式），
95 GB–452 GB 不等（HCC1395 paired_full = 278,270,281,041 bytes）。

**但 `/big7_disk` 目前只剩 617 GB（99% 已用）。**

> ✅ **好消息**：寫回 BAM **技術上完全可行**。
> sidecar 的 QNAME 是**明文 UUID**（實測 `ec1d98d5-5fcf-45fc-9691-7641e8731385`），
> 而 LL 的 `read_id = lowercase SHA-256(QNAME)`（`site_reads.record.json:56`）是**確定性正向計算**。
> 讀 BAM 時對每條 QNAME 重算 SHA-256 即可 join，**不需要任何反查表**。

### 事實 B：兩套系統對「甲基能不能進重建」的立場**直接衝突**

| | InterSubMod（論文既有結論） | LongLineage（現行程式碼） |
|---|---|---|
| 甲基角色 | **bounded-auxiliary，絕不進重建 likelihood**（cis-ASM 循環） | **M1 甲基分群是 topology unit 的必要 gate** |
| 機制 | 甲基只做負篩 + L3 旗標 | `m2_eligible` 前置 = M1 `stable_null_multigroup`（甲基分出 ≥2 群且穩定） |

⇒ **在 LL 裡，甲基沒分出群的位點永遠不會有拓撲解**。這是選擇性偏誤來源。
任何跨系統比較都必須明說這一點，否則會產生與論文既有結論矛盾的敘述。

### 事實 C：LL 的「拓撲」不是一棵樹

`topology_unit` 的 unit = **1 focal + ≤3 partner = 最多 4 個位點**。
所以 LL 產出的是**數萬個彼此獨立的 4-locus 局部 hypercube 解**，不是全域 subclonal tree。
LL 自己承認缺「跨 unit 組裝層」。全域組裝在 ISM 的 layered per-HP-family solver
（位於 `InterSubMod/docs/methodology/_assets/20260627_subclone_4axis_teaching/scripts/`）。

另外 ISM 的 `tree.nwk` 是 **read×read 甲基距離的階層分群樹**（葉 = read_name），
**不是 clone/subclone 譜系樹** —— 容易誤讀。

## 5. 建議的可行架構

核心判斷：**串接點選 sidecar TSV**（唯一 byte-level 一致的介面），
並沿用同一格式向外擴充「輸出側標籤」，避免發明新契約。

```
【輸入層】8 角色（7 樣本實體已齊）
  raw BAM + .bai │ PASS biallelic sSNV VCF + index
  HP/PS sidecar + .tbi │ reference FASTA + .fai
        │
        ├──────────────────────┬──────────────────────────┐
        ▼                      ▼                          │
 [A] inter_sub_mod       [B] longlineage dataset-gate     │
     per-region 統計          9 個 artifact               │
     (193 欄) + 甲基矩陣      site_reads / methyl_calls    │
                             m1_* / cooccurrence_*         │
                             topology_units / summary      │
        │                      │                           │
        │   read_id = SHA-256(QNAME) 為共同 join key        │
        └──────────┬───────────┘                           │
                   ▼                                       │
        ★新建1  label-sidecar writer ────────────────────────┘
                 輸出側 sidecar（沿用 9 欄 + 擴充欄）
                 #CHROM START0 END0 QNAME FLAG MAPQ CIGAR_B2 HP PS
                                    + CLUSTER + FAMILY + LINEAGE + METHYL_GROUP
                   │
                   ├──→ ★新建2  bam-tagger（選用）
                   │           raw BAM + label sidecar → tagged BAM
                   │           重算 SHA-256(QNAME) 對齊，--regions 限子集省磁碟
                   │
                   └──→ ★新建3  spec builder
                               artifact → workstation_spec.json
                               → build_workstation.py → standalone HTML
```

### 需新建的 3 個元件

| # | 元件 | 為什麼是它 | 規模估計 |
|---|---|---|---|
| ★1 | **label-sidecar writer** | 解 G4 的**根本問題**（per-read 標籤無持久化）。用 sidecar 而非 BAM 可同時避開磁碟與 fail-closed policy 衝突。ISM 的 cluster id 目前**完全不落檔**，這步把它救回來。 | 中 |
| ★2 | **bam-tagger** | 真正產出「帶標籤的 BAM」給 IGV/samtools。技術可行（事實 A）。需先定 aux tag 命名空間（**避開 SAM 保留 tag**）。 | 中 |
| ★3 | **spec builder** | 補 G7/G8 的空洞：「從資料到 `workstation_spec.json`」之間現在是**完全空的**，這是 `build_workstation.py` 只有 1 個複用者的根因。 | 中 |

### 必須先做的 2 個決策

1. **科學裁決（事實 B）**：LL 用甲基當 topology gate，與論文既有「甲基絕不進重建」結論衝突。
   要嘛接受並在所有輸出標註選擇性偏誤，要嘛改 LL 的 gate 邏輯（會撞 C++ Hard Gate + parity 重驗）。
2. **資源決策（事實 A）**：`/big7_disk` 只剩 617 GB。落地 tagged BAM 需先清理，
   或只做「子集 tagged BAM」（`--regions` 限定），或維持 sidecar-only。

### 已可直接複用、不必重寫的資產

- `InterSubMod/scripts/ism_heatmap_std.py` — 甲基 × read 標籤熱圖的 SoT（含側欄規格 + drift 稽核）
- `.claude/skills/verify-workstation/tools/build_workstation.py` — §13-A refuse-on-missing 的 HTML generator
