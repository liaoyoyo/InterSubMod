# bip7／bip8 操作與驗證

用 Step→Verify：**每台主機都必須從同一immutable commit建立fresh clone，依該主機profile完成doctor、plan、build/test、synthetic smoke與real-data read-only preflight；缺任一receipt就標BLOCKED。**

## 1. 目前機器 verdict

| Host | 真正在該host執行？ | 現況 | Verdict |
|---|---|---|---|
| bip7 | 是；receipt `hostname=bip7` | 目錄/本體/index皆存在；samtools、bcftools hash MATCH；4個local checksum locator缺失 | `BIP7_DATA_PREFLIGHT_BLOCKED` |
| bip8 | 否 | bip7可看到`/big8_disk` NFS，但這不證明bip8本機clone/build/runtime | `BIP8_DATA_PREFLIGHT_BLOCKED` |

bip7的四個精確blocker：reference FASTA、tumor BAM、normal BAM、somatic VCF各自宣告的`.sha256` locator不存在。修法是從可信上游取得既有checksum，或經批准後以bounded one-time hash建立checksum receipt；不可把`SIZE_ONLY/PRESENT`改寫成identity verified。

包內`machine_profiles/bip7.path-preflight.json`是**path-preflight evidence profile**，不是可直接執行的acceptance profile：它只覆蓋一個dataset、InterSubMod binary曾為size/existence observation、LongPhase-S只提供KB locator。完整執行前必須由fresh clone產生新profile並通過doctor的identity與role-completeness gates。

該profile的operator-facing object key為`HCC1395_ONT_5kHz`，但record內canonical `technical_dataset_id`是`HCC1395`；跨registry join必須用record欄位，不可用object key。映射見[dataset alias registry](registries/dataset_alias_registry.json)。

## 3. 建立本機site profile

```bash
scripts/site/bootstrap \
  --template config/site-profile.example.json \
  --output config/site-profile.local.json \
  --site-id "$(hostname)-handoff" \
  --expected-hostname "$(hostname)" \
  --project-root "$PWD"
```

→ 預期輸出：

```text
[RESULT] profile_created=true; edit checksums and machine-specific paths before doctor
```

`config/site-profile.local.json`已被Git ignore。建立後必須人工/機械更新：

- `data_roots.primary/output/knowledge`
- `schema_version=1.1.0`，reference `genome_build`、chr1–22 contig contract、FASTA與index
- samtools/bcftools/LongPhase-S/InterSubMod路徑及checksum policy
- 每個technical dataset的BAM/index、random-access VCF/index、truth VCF/BED與checksum locator

example中的64個`0`是假值，刻意讓doctor fail；不可當真實hash。

## 4. Doctor：先synthetic，再real-data

```bash
scripts/site/doctor \
  --profile config/site-profile.local.json \
  --mode synthetic \
  --receipt /absolute/receipt/root/site_doctor.synthetic.json

scripts/site/doctor \
  --profile config/site-profile.local.json \
  --mode real-preflight \
  --receipt /absolute/receipt/root/site_doctor.real.json
```

→ 驗證：

- `hostname_match=true`
- project/data roots存在且mount可解析
- required tools可執行；所有tool均記錄actual SHA-256，EXPECTED_SHA256均`MATCH`
- FASTA/BAM/VCF/index存在
- local checksum locator本身存在；不存在即`CHECKSUM_LOCATOR_MISSING`
- receipt `pass=true`

本輪bip7實際輸出：

```text
tally={CHECKSUM_LOCATOR_MISSING:4, CHECKSUM_LOCATOR_PRESENT:1,
       EXTERNAL_CHECKSUM_LOCATOR_DECLARED:2, MATCH:2, PRESENT:8}
pass=false
exit=5
```

Receipt：[包內bip7 real-data preflight receipt](evidence/bip7_real_data_preflight_receipt.json)。

## 5. Side-effect-free plan

```bash

  --site-profile config/site-profile.local.json \
  --sample HCC1395 \
  --mode s-pure \
  --output-root /absolute/planned/output \
  --plan
```

→ 驗證：列出project、profile SHA、FASTA、tumor/normal BAM、VCF、tools、output、override provenance與stages；exit 0；**不得建立output或log**。`--plan`只做schema/path/provenance解析；實際run會在建立output前強制real-data preflight PASS。

本輪在bip7以handoff profile實跑：

```text
[PLAN] stages=LongPhase-S,InterSubMod,filter-analysis
[RESULT] plan_only=true side_effects=none
[PASS] plan_side_effects=none output_absent=/tmp/ism-handoff-plan-no-side-effects-20260813
```

Portable profile模式強制skip現行stage 04 cleanup；該stage會直接刪除intermediate，因此固定為`REPRODUCIBLE_LEGACY`，直到archive-first replacement有單獨receipt contract。若用`--skip-longphase`，必須明確綁定tagged BAM、TP VCF、FP VCF及三個expected SHA-256；不會猜測latest folder。

## 11. Full benchmark的啟動gate

只有下列全通過才可移除`--plan`：

1. 該host doctor real receipt PASS。
2. input artifacts為current且license/redistribution已記錄。
3. disk/RAM/thread預算與stop rule核准。
4. command receipt與output root預先建立；不寫舊archive root。
5. task scope若為comprehensive，不可只跑subset。
6. 加`--skip-cleanup`；`scripts/pipeline/steps/04_cleanup.sh`含直接刪除，固定為`REPRODUCIBLE_LEGACY`，須等archive-first replacement驗證後才可重新評估。

本handoff不授權TiB級full science重跑。
