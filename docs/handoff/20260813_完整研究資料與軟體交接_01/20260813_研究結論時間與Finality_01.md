## 4. Finality 決策規則

```text
檔案存在
  └─ 不代表 current
      └─ 有 producer/commit/input/command/schema/scope/hash
          └─ 才能評估 evidence_status
              └─ AUTHORITY + FULL + FINAL_FOR_SCOPE
                  └─ 仍只在 claim_ceiling 內可引用
```

### 4.1 Final artifact的必要條件

- `artifact_id` 唯一。
- producer與producer commit明確；若commit不可證明，必須醒目標示。
- input、derived_from、schema、scope、hash與location有記錄。
- 有 `claim_ceiling` 與 `known_limits`。
- `FINAL_FOR_SCOPE` 必須有SHA-256；大型intermediate或BAM若本輪未hash，必須是`NON_FINAL`。
- superseded artifact不得被current index當成主入口。

本registry目前20筆`FINAL_FOR_SCOPE`分為：19筆`AUTHORITY`（frozen science/source bytes）與1筆`VALIDATED_DERIVED`（append-only source adjudication）。只有前19筆可在其各自claim ceiling內作frozen authority引用；provenance-only final不新增science結論。

### 4.2 14個paired tagged BAM

2026-06-01 targeted `stat`與本輪重查都確認current canonical下有14個paired tagged BAM，總計`3,709,322,840,333` bytes。這修正舊manifest全部標`tagged_bam_ready=false`的stale狀態，但**不**將BAM升格為production authority：

- 它們是歷史paired baseline與live read-level研究輸入。
- 完整hash本輪不讀TiB payload；registry記exact path、bytes、mtime與重生責任。
- 歷史tagging曾涉及truth-aware設定；只適合作research/engineering baseline。
- 狀態固定為`PARTIAL + NON_FINAL + LOCAL_CANONICAL`。

## 5. 時間欄位的語意

| 欄位 | 定義 | 可否由mtime取代？ |
|---|---|---|
| `source_created_at` | 上游來源首次建立／發布時間 | 否；未知就null |
| `run_started_at` | receipt/log明示的執行起點 | 否 |
| `run_completed_at` | producer成功完成並關閉輸出的時間 | 否 |
| `created_at` | artifact本身首次建立時間 | mtime只可fallback並標明 |
| `generated_at` | producer產出該bytes的時間 | mtime只可fallback並標明 |
| `verified_at` | 本輪實際重查時間 | 必須是驗證動作時間 |
| `published_at` | 上傳Git/GitHub Release/Pages後可取得的時間 | 未發布就null |
| `last_seen_at` | 在某machine path最後看到的時間 | 可由本輪stat填寫；不代表建立時間 |

任何無receipt的mtime只能回答「最遲/最後看到」，不能重建真實run時序。

## 7. Authority與後續更正

2026-08-01 authority檔保持immutable；本輪不覆寫。若後續source-origin adjudication發現某source snapshot的角色／來源commit需更正，採append-only crosswalk：

- frozen artifact仍可回答「當時登記的bytes是什麼」。
- adjudication回答「這些bytes實際源自哪個commit／是否能對應binary」。
- 兩者不得互相偷換；registry的`supersedes/derived_from/known_limits`明列關係。
