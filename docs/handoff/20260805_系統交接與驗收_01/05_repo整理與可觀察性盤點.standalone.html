二、這套程式在做什麼（給新讀者的背景）

一句話：把「同一條 ONT 長讀」上同時觀測到的體細胞變異與甲基化，整理成 read × 位點的矩陣， 再算 read 之間的距離、分群、檢定，最後嘗試組出區域內的突變狀態關係。 它不是變異偵測器（那是上游的 ClairS），也不是定相工具（那是 LongPhase）—— 它是接在那兩者之後的讀取層整合分析器。

三、怎麼用（28 個參數的分組意義）

CLI 由 include/utils/ArgParser.hpp 定義，共 28 個選項，可分成六組。 理解分組比背參數重要 —— 每一組控制流程中的一個環節。

標準執行方式

# 整合腳本（推薦，會自動接 Python 繪圖）
./scripts/run_vcf_all_snv.sh --mode all-with-w5000

# 快速驗證（chr19，< 30 秒）
./scripts/run_vcf_all_snv.sh --mode chr19-verification

# 直接呼叫 C++ 核心（只產數據，不繪圖）
./build/bin/inter_sub_mod \
    --tumor-bam <tumor.bam> --reference <ref.fa> --vcf <somatic.vcf> \
    --output-dir <results> --threads 32 --window-size 1000 --log-level debug

七、C++ 程式品質：其實比預期健康

好消息：程式本體不需要大整理

從零 clean build exit 0、258 個測試全過、 排除 vendored 依賴後只有 7 個編譯警告（3 個 unused-parameter、1 個 unused-variable、1 個 unused-function 等）。 以 27,653 行的專案來說，這是相當乾淨的狀態。

發現 那 1,501 行未 commit 的改動，正好就是在做「輸出結構化」 方向一致

從 diff 抽出的新增函式顯示，未提交的改動集中在三件事：

  • 原子寫入與發布狀態：write_atomic_text、atomic_temp_path、 write_region_stratification_artifacts_atomic、write_region_stratification_status_atomic、 mark_published、ensure_output_parent
  • 輸出驗證：validate_region_status_record、 is_region_stratification_eligible、valid_stratum
  • 統計與分類：StructureTest::permute_labels、 validate_permutation_options、determine_loh_subtype_legacy_vc

而且對應測試已經存在並通過 —— C++ 測試輸出中可看到 RegionStratificationArtifactsTest 的 5 個測試（含「狀態與內容矛盾時應在發布前失敗」、 「rename 失敗時應清掉自己的暫存檔」）。

意義：你現在想要的「輸出可觀察、可驗證」，程式裡已經開了頭，只是還沒 commit， 也還沒延伸到 log 與參數層。
