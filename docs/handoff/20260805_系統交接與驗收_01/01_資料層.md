# 交接分冊 01：資料層

## 0. 一句話

**資料不隨交接包走。** 光是 `paired_full` 一種模式的 7 個 tagged BAM 就 **1.67 TiB**，
而 `/big7_disk` 只剩 617 GB。交接的是**路徑 + 規模 + 信任度 + 重生方法**，不是檔案本身。

## 4. 信任度分級（引用前必查）

| 等級 | 定義 | 處置 |
|---|---|---|
| **CURRENT** | 最新方法產出，結論可信 | 直接使用 |
| **PRE-FIX** | Self-phasing 修正前產出，HP tag 可能受循環依賴影響 | 非 HP 欄位（AF/GQ/DP/甲基統計）可用；HP 相關結論需重跑 |
| **SUPERSEDED** | 已被後續版本取代 | 僅供回溯，不引用於新分析 |
| **DEPRECATED** | 已知錯誤或方法有缺陷 | **禁止使用** |

### 已知的資料層缺口

| 缺口 | 說明 | 影響 |
|---|---|---|
| **19 canonical runs 全為 `partial`** | `master_run_manifest.tsv` 的 `completeness_state=partial`、`blocking_reason=missing_tagged_bam`，此狀態自 2026-04 未更新 | 與現況矛盾（tagged BAM 明明存在且已被 2026-07 的分析使用）。**接手者必須重新核對此表**，否則會誤判資料不完整 |
| `archive-only`（5 樣本的 to_pileup） | 在 `research_rounds/archive/202603_early_pilots/` 有 post-HP-fix 輸出，但**缺 LOH/CN/KDE 欄位** | 需重跑 ISM 才能進 master |
| `pilot-empty`（COLO829 to_pileup） | `step05_intersubmod/` 為空 | 需從 step01 重跑 |
| HCC1395 ONT_5khz **normal** BAM 每 read 重複兩份 | 已確認的資料錯誤（比值 1.99 / fastq doubling） | 甲基分析用 tumor BAM 不受影響；**深度/count 型統計必須先去重** |

## 5. 交接規則（資料）

1. **絕不把 BAM／大型 JSONL 複製進交接包或 git。** 只保存 identity、path、scope、checksum。
   （這條也寫在 20260801 handoff README §6.5。）
2. 任何數字先查 machine-readable output（JSON/TSV），再查報告的文字解釋。
3. `technical_all_pass=true` **不等於** `validation_evidence_eligible=true`。
4. 引用任何 output 前先在 `OUTPUT_INDEX.md` 查它的信任度等級。
5. 歷史資料（`bip8_output_archive/`、`big8_output_archive/`）只用於理解演進，
   **不可覆蓋** canonical 數字。
