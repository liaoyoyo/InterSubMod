# 5kHz 主實驗與方法學驗證藍圖

## 1. 研究主軸

InterSubMod 下一階段的主線，不再以 `purity-aware` 或 subsample 作為第一證據，而是先完成：

1. 純樣本 `tumor/normal paired` 的完整方法學驗證。
2. `label-first` 與 `cluster-first` 的設計合理性驗證。
3. 甲基資訊與 phase / caller 整合後，是否能：
   - 提升突變位點判斷準確度
   - 找出具生物意義的 `Strong / Subclone / Weak / Noise`
   - 解釋哪些位點是甲基差異位點，以及它們和哪些特徵有關

## 2. 主樣本與驗證順序

### 2.1 第一主實驗

- 樣本：`HCC1395 5kHz`
- 原因：
  - 具 `MM/ML`，可直接做甲基分析
  - 錯誤與 FP 相對較多，較適合觀察方法改動是否真的改善判斷
  - truth set 為 `SEQC2 v1.2.1`，根據 Knowledge/02_samples/HCC1395.md 與 Knowledge/06_workflows/benchmark_workflow.md，這是目前最可靠的 benchmark 主樣本

### 2.2 第一交叉驗證

- 樣本：`HCC1395 ONT_Dorado + HCC1395BL`
- 角色：
  - 與 `HCC1395 5kHz` 為同一 biological sample、不同定序/資料來源
  - 用來驗證 5kHz 上的觀察是否可跨平台重現

### 2.3 後續順序

1. `HCC1395 5kHz` paired pure
2. `HCC1395 ONT_Dorado + HCC1395BL` paired pure
3. 其他 pure paired samples
4. pure tumor-only
5. mixed purity / subsample

> 根據 Knowledge/02_samples/HCC1395.md，現有 ONT subsample 並不含 `MM/ML`，而從 tumor/normal 混和產生的 purity 樣本又容易受組織甲基差異混淆，因此不適合作為此階段主證據。

## 3. 核心研究問題

### 3.1 方法學設計問題

1. `label-first` 是否真的在設計上合理：
   - 標籤足夠嗎
   - 統計檢定適用嗎
   - 標籤缺失時該如何判讀
2. `cluster-first` 是否真的在設計上合理：
   - 分群結果是否穩定
   - cluster 數與結構是否受資料量或距離方法強烈影響
3. 兩者何時可互補、何時不應混用

### 3.2 生物與分析問題

1. 加入 HP/Allele 後，哪些 region 會從 `Weak` 升級為 `Strong` 或 `Subclone`
2. 甲基差異位點與哪些特徵有關：
   - caller 訊號
   - read 數量
   - VAF
   - allele support
   - HP 標籤完整度
3. 在 paired tumor/normal 下成立的規則，哪些值得搬到 tumor-only

## 4. 重大流程節點與推理框架

本研究不只要列出可能影響結果的節點，還要在結果不符假設時，能系統化追查原因。

### 4.1 目前優先觀察的節點

1. 資料量是否足夠：
   - read 數
   - CpG 數
   - HP/Allele 標籤覆蓋率
   - 是否需要後續加入 read 數、VAF、SNV、SV 等更多共同資料
2. 單位點區域視角是否足夠：
   - window 太小可能抓不到穩定訊號
   - window 太大可能混入雜訊
3. read filter 是否過嚴：
   - 現有穩定 read 規則是否比 IGV 可觀察範圍更保守
4. 甲基資料表示方式：
   - 先保留完整 analog methylation 訊號
   - 二值化與更細緻轉換作為後續驗證項
5. 距離方法：
   - `NHD` 現為工作預設，但不是已定論最佳
6. 統計與分群方法：
   - 檢定是否與資料條件相容
   - 多重校正、dispersion、群數設定是否影響結論

### 4.2 當結果不好時的推理順序

1. 先確認資料層是否足夠：
   - read 太少
   - HP 指派率太低
   - allele 標記不足
2. 再確認方法層是否適用：
   - 距離法不合適
   - window 設定不合適
   - filter 太嚴或太鬆
   - label-first / cluster-first 其一根本不適用
3. 最後才判斷研究假說是否被否定：
   - 該 region 可能本來就沒有可觀察甲基差異
   - caller 特徵本來已足夠，甲基訊號只是弱補充

## 5. 證據與報告原則

### 5.1 F1 比較原則

每次 benchmark 都必須同時列出：

- `truth_total`
- `calls_total`
- `TP`
- `FP`
- `FN`
- `precision`
- `recall`
- `F1`

比較口徑至少要能回答：

1. `ClairS` 相對 `SEQC2`
2. `LongPhase-S` 相對 `SEQC2`
3. `InterSubMod` 相對 `SEQC2`

不可只寫「F1 提升多少」，而不附實際母數。

### 5.2 異常與不合假設時的輸出

若研究結論不合預期，必須至少輸出：

1. 相關聯數據表
2. region diagnostics 圖
3. 本輪改動與假說對照
4. 對可能原因的推理
