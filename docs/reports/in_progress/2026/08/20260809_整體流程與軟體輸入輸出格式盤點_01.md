# 2026-08-09 整體流程與軟體輸入輸出格式盤點

> **TL;DR：確認目前最新實際鏈已完成到「HCC1395 lineage BAM v2 → InterSubMod v3」，但全 7 資料集只完成 exact-PS/topology，lineage-tag、lineage methylation 與最新 drilldown 尚未全樣本化；舊 TP/FP→F1 腳本及名義上的 TO wrapper 不能視為現行 canonical pipeline。（影響：高，信心：高）**

## 0. 結論先行

### Situation

目前 repo 同時保留三種不同目的、不同世代的流程：

1. paired／tumor-only 的 variant calling、phasing、TP/FP benchmark；
2. 2026-07～08 的 exact-PS 遺傳 read-linkage、拓撲、lineage-tag、甲基關聯新鏈；
3. LongLineage formal production entrypoint 的 fail-closed 工程鏈。

### Complication

三者尚未統一為一個 production driver，而且 README、`pipeline/README.md`、8/8 interface contract、目前原始碼與 8/9 實際產物存在時間差。若只照文件執行，會遇到缺參數、假 TO、多軸實際只跑一軸、輸出欄數漂移及 provenance 不足。

### Question

「現在真正完成到哪裡？每個軟體吃什麼、吐什麼？哪些格式可以直接串、哪些必須先驗？」

### Answer

現況可簡化成以下四句：

- **全 7 資料集已驗證的是 exact-PS/topology 的 derived observation，不是全 7 lineage-tagged BAM。**
- **HCC1395 已有修正版單一 merged lineage BAM v2，且 InterSubMod v3 已跑完 chr1–22。**
- **目前最新 drilldown 仍綁舊 ISM v2，且 HCC1395 ISM v3 使用 dirty binary，尚非可發布 production bundle。**
- **Formal `longlineage run/probe` 仍 fail-closed；新 `lineage_paths/read_assign/tag_bam` 是獨立 experimental/export toolchain。**

## 2. 現在的整體流程

```mermaid
flowchart LR
    A[POD5] --> B[Dorado basecall<br/>MM/ML/MN]
    B --> C[align + sort + index<br/>BAM/BAI]
    C --> D1[Clair3 normal germline VCF]
    D1 --> E1[LongPhase germline phase<br/>GT|PS]
    C --> D2[ClairS paired<br/>somatic VCF]
    E1 --> F1[LongPhase-S<br/>latest HP/PS sidecar or tagged BAM]
    D2 --> F1
    F1 --> G[Exact-PS strict linkage<br/>partition + MLHP + topology JSONL]
    G --> H1[lineage_paths TSV.gz]
    G --> H2[read_assign TSV.gz]
    F1 --> H3[HP/PS sidecar TSV.bgz]
    C --> H4[MM/ML BAM]
    H1 --> I[LongLineage tag_bam]
    H2 --> I
    H3 --> I
    H4 --> I
    I --> J[lineage-tagged BAM/BAI<br/>HP PS lc lu lv lp lo ls]
    J --> K[InterSubMod<br/>read×CpG / distance / association]
    K --> L[drilldown HTML<br/>尚未以 ISM v3 重建]

    C -. tumor-only alternative .-> T1[ClairS-TO]
    T1 --> T2[LongPhase-TO<br/>phased VCF + LOH.bed + HP:i]
    T2 -. lineage bridge 尚未正式驗證 .-> K

    G -. 不等同 .-> P[formal longlineage run/probe<br/>目前 fail-closed]
```

### 2.1 現行新式 science/export 鏈

```text
ClairS paired PASS sSNV
+ LongPhase-S same-run latest HP/PS sidecar
+ MM/ML BAM
    → exact nonmissing PS × HP1/HP2 strict read linkage
    → k≤12 partition / MLHP
    → exact topology + family-specific read-AF
    → lineage_paths + read_assign + tag_bam
    → lineage-tagged BAM
    → InterSubMod lineage/methylation association
    → drilldown observation layer
```

這條鏈的遺傳層先固定，甲基只在其後做 association／characterization，不可移動拓撲 edge。canonical science ceiling 仍是：

- `confirmed cellular subclone = 0`
- `linear ancestry = 0`
- CN/LOH 未整合進 read-AF 排序
- `tree.nwk`／methylation cluster 不是 clone tree

### 2.2 舊式 paired benchmark 鏈

`InterSubMod/scripts/pipeline/run_benchmark.sh` 的真實流程是：

```text
LongPhase-S
→ bcftools isec 切 TP/FP/FN
→ InterSubMod 分別跑 TP/FP
→ 03_filter_analysis.py 算 hard-filter/F1
→ metrics.json
→ cleanup
```

此流程可作歷史 benchmark 或 regression comparison，但不應冒充新式 lineage canonical 流程。其 cleanup 會直接移除大型中間檔，也不符合目前「先 Archive、不直接刪除」治理。

### 2.3 Formal LongLineage production 鏈

`longlineage preflight/dataset-gate/run/probe` 是另一套正式 schema/fail-closed 工程入口；`run/probe` 目前仍明示被 P3/P4/P5 gate 阻擋。8/9 新增的三支 utility：

- `longlineage-lineage-paths`
- `longlineage-read-assign`
- `longlineage-tag-bam`

是 current experimental/export toolchain，不代表 formal `longlineage run` 已解除阻擋，也尚未登記進 formal 9-artifact catalog。

## 4. 軟體角色與輸入／輸出／格式矩陣

### 4.1 上游 calling 與 phasing

| 軟體 | 現在角色 | 主要輸入 | 主要輸出／格式 | 重要邊界 |
|---|---|---|---|---|
| Dorado basecaller | 上游資料來源 | POD5、完整 simplex model、mod model | unaligned BAM/FASTQ；BAM 可含 `MM:Z`、`ML:B:C`、`MN:i` | 必須 pin 完整 model/runtime；只有 `sup/hac/fast` 不足以重現 |
| Dorado aligner | 優先的 modBAM 對齊路徑 | unaligned BAM＋FASTA | coordinate-aligned BAM | 需驗 MM/ML/MN 逐 read 保留 |
| minimap2 | 對齊替代；通常經 tag-aware FASTQ bridge | FASTQ＋FASTA | SAM/BAM | `map-ont` 與 Dorado preset 不是同一契約；`-y`／tag bridge 需實測 |
| samtools | 核心格式處理 | SAM/BAM/CRAM | sort/index/merge/view/quickcheck/stats | transformation 可改 header/tag；本輪已發生 RG loss |
| Clair3 | paired germline 支線 | normal BAM＋FASTA＋model | germline SNP VCF | germline candidates 不是 somatic truth |
| LongPhase germline | normal phasing | germline VCF＋normal BAM＋FASTA | phased VCF；`GT=0|1/1|0`、`FORMAT/PS` | PS 只在同 dataset×chromosome 有意義 |
| ClairS v0.4.1 | **目前 paired somatic 骨幹** | tumor＋normal BAM、FASTA、model | SNV/INDEL VCF.gz＋index | `PASS` 不是 truth；project pin v0.4.1，不可偷套新版行為 |
| ClairS-TO | tumor-only caller | tumor BAM、FASTA、PON/resources | `snv.vcf.gz`、`indel.vcf.gz` | PON／Verdict 是 evidence label，不是 truth；不直接產正式 LOH |
| LongPhase-S | **paired active core** | phased germline VCF、normal/tumor BAM、somatic VCF、FASTA | HP-tagged BAM/CRAM、可選 recalibrated `_sc.vcf`、tumor DNA fraction/log | recalibration 可 PASS↔LowQual；HP 共九態 |
| LongPhase-TO | tumor-only phasing/haplotag | tumor VCF、tumor BAM、FASTA、caller enum、PON | phased VCF (`GT/GT2/GT3/PS`)、可選 `LOH.bed`、HP:i BAM | 與 LongPhase-S HP encoding 不可直接混用 |

## 5. 現行核心程式的可執行介面

以下命令為介面範本；`<...>` 必須換成新 output root 與已驗證輸入。這些範本不是本輪重跑紀錄。

### 5.1 Clair3 normal germline

```bash
run_clair3.sh \
  --bam_fn=<NORMAL.bam> \
  --ref_fn=<REFERENCE.fa> \
  --output=<NEW_CLAIR3_DIR> \
  --threads=64 \
  --platform=ont \
  --model_path=<PINNED_MODEL> \
  --sample_name=<NORMAL_ID>
```

### 5.2 LongPhase germline

```bash
longphase phase \
  -s <GERMLINE.vcf.gz> \
  -b <NORMAL.bam> \
  -r <REFERENCE.fa> \
  --ont -t 64 -o <NEW_PHASED_PREFIX>
```

### 5.3 ClairS paired

```bash
run_clairs \
  --tumor_bam_fn <TUMOR.bam> \
  --normal_bam_fn <NORMAL.bam> \
  --ref_fn <REFERENCE.fa> \
  --output_dir <NEW_CLAIRS_DIR> \
  --threads 64 \
  --platform ont_r10_dorado_sup_5khz_ssrs \
  --enable_indel_calling
```

### 5.4 LongPhase-S paired haplotag

```bash
longphase-s somatic_haplotag \
  -s <PHASED_GERMLINE.vcf> \
  -b <NORMAL.bam> \
  --tumor-snv-file <SOMATIC.vcf> \
  --tumor-bam-file <TUMOR.bam> \
  -r <REFERENCE.fa> \
  -t 64 -o <NEW_PREFIX> \
  --output-somatic-vcf
```

`--truth-vcf/--truth-bed` 是 benchmark-only 參數；production tagging 不應把 truth 餵入推論本身。

### 5.5 ClairS-TO＋LongPhase-TO

```bash
run_clairs_to \
  --tumor_bam_fn <TUMOR.bam> \
  --ref_fn <REFERENCE.fa> \
  --output_dir <NEW_TO_DIR> \
  --threads 64 \
  --platform ont_r10_dorado_sup_5khz_ssrs

longphase-to phase \
  -s <TO_SNV.vcf.gz> \
  -b <TUMOR.bam> \
  -r <REFERENCE.fa> \
  --ont --loh --caller clairs_to_ssrs \
  --pon-file <PON.vcf.gz> \
  --strict-pon-file <STRICT_PON.vcf.gz> \
  -t 64 -o <NEW_PHASED_PREFIX>

longphase-to haplotag \
  -s <PHASED_TO.vcf> \
  -b <TUMOR.bam> \
  -r <REFERENCE.fa> \
  -t 64 -o <NEW_TAGGED_PREFIX>
```

### 5.6 Exact-PS all-7 runner

```bash
python3 InterSubMod/research/20260724_exact_ps_cpp_topology_af_all_samples/scripts/run_exact_ps_cpp_topology_all7.py \
```

### 5.8 InterSubMod paired

```bash
./build/bin/inter_sub_mod \
  --tumor-bam <LINEAGE_TAGGED.bam> \
  --normal-bam <NORMAL_MM_ML.bam> \
  --reference <REFERENCE.fa> \
  --vcf <PASS_BIALLELIC_SNV.vcf.gz> \
  --output-dir <NEW_OUTPUT_DIR> \
  --group-by-tag lv \
  --require-tag-status UM \
  --distance-metric BERNOULLI \
  --nan-distance-strategy SKIP \
  --window-size 5000 \
  --threads 24
```

在 current source 修正前，`lc`、`lu`、`lv` 要分三個 output root各跑一次，不能以 `--group-by-tag lc,lu,lv` 宣稱一次完成三軸。

### 5.9 InterSubMod native tumor-only

真正 native tumor-only 是**省略** `--normal-bam`：

```bash
./build/bin/inter_sub_mod \
  --tumor-bam <TO_TAGGED.bam> \
  --reference <REFERENCE.fa> \
  --vcf <TO_PASS_SNV.vcf.gz> \
  --output-dir <NEW_OUTPUT_DIR> \
  --germline-hp-only \
  --distance-metric NHD \
  --nan-distance-strategy SKIP
```

`scripts/run_vcf_all_snv.sh --caller-mode to` 仍固定傳 `--normal-bam`；`scripts/pipeline/run_benchmark.sh --mode to-*` 也仍跑 LongPhase-S＋normal。兩者都不是可靠的 native TO wrapper。

## 6. 主要資料格式契約

### 6.1 BAM／CRAM

#### Canonical BAM 條件

- coordinate sorted
- `.bai` 可載入
- reference contig 與 FASTA／VCF 一致
- retained reads 必須有 `MM`、`ML`
- `MN` 若存在應驗證與當時 SEQ length 一致
- paired normal若提供，也必須符合相同甲基格式條件

InterSubMod 沒有完整 CRAM-reference 綁定契約，因此目前 BAM 才是 canonical。LongLineage `tag_bam --out-format cram` 是 export 能力，不等於 formal production input 接受 CRAM。

#### 甲基與 phasing tags

| Tag | SAM 型別 | 語意／現況 |
|---|---|---|
| `MM` | Z | base-mod delta encoding；InterSubMod current parser重點處理 `C+m?`，5hmC不是正式輸出軸 |
| `ML` | B:C | uint8 probability；InterSubMod 用 `N/255`，LongLineage/SAM schema 用 bin `[N/256,(N+1)/256)`，跨軟體比較前須統一 |
| `MN` | i | optional original SEQ length；InterSubMod目前不驗 |
| `HP` | Z 或 i | LongPhase-S常用 Z；TO可用 i；InterSubMod可正規化 1/2/11/21/33 |
| `PS` | i | phase set；不可跨 dataset/chrom直接按整數 join |
| `RG` | Z | read group；current merged HCC1395 v2 已遺失 |

#### Lineage tags

| Tag | 型別 | 內容 |
|---|---|---|
| `lc` | Z | unit/component id |
| `lu` | Z | block id |
| `lv` | Z | hierarchical path，如 `HP2-1-1`；`+` 表 subtree／後代集合 |
| `lp` | Z | observed `R/A/X` pattern |
| `lo` | Z | mutation order，例如 `98311>113820` |
| `ls` | A | `U` unique／`M` tied／`P` partial／`A` abstain |

同一 read 可落多個 block；writer 會把 `lc/lu/lv/lp/lo` 以逗號串接。InterSubMod current `LabelTest` 把整串當一個 atomic category，尚未拆成獨立 block/path。

### 6.2 HP/PS sidecar

固定 9 欄、BGZF＋Tabix：

```text
#CHROM	START0	END0	QNAME	FLAG	MAPQ	CIGAR_B2	HP	PS
```

- `CIGAR_B2`：16 位小寫 BLAKE2b hex
- HP vocabulary：`.`、`1`、`2`、`3`、`4`、`1-1`、`2-1`、`1-2`、`2-2`
- PS：非負整數或 `.`

目前 `tag_bam` 雖讀這 9 欄，實際 map 是 `side[QNAME] → (HP,PS)`；FLAG/MAPQ/CIGAR_B2 未參與 join。這低於 sidecar 的 exact alignment identity contract。

### 6.3 VCF／BCF

InterSubMod consumer：

- HTSlib 可開 VCF/BCF
- 只保留明確 `FILTER=PASS`
- 只保留 biallelic SNP
- `FORMAT/AF` 只讀第一個 sample 的第一個值
- AF 缺失目前會與真 AF=0.0混在一起
- GQ／DP／AD／INFO不參與 core gate；QUAL只被存下

LongLineage formal production contract更嚴：BGZF text VCF、Tabix/CSI、排序、無重複、單一 PASS biallelic A/C/G/T sSNV；BCF不接受。因此跨工具 handoff 應以較嚴規格為準。

`FILTER=PASS` 只表示未觸發 caller/pipeline filter，不等於 truth。

### 6.4 FASTA／BED

| 格式 | 契約 |
|---|---|
| FASTA | 必須有 `.fai`；contig名稱/長度須與 BAM、VCF 一致 |
| BED/LOH | 前三欄 `chrom start end`，0-based half-open；ISM 把 1-based SNV position轉為0-based查詢 |
| callable BED | benchmark分母的一部分；不可缺省後仍把 whole-genome結果稱正式 F1 |

### 6.5 Exact-PS／LongLineage 中間格式

#### topology JSONL

每列一個 JSON object，schema：

`intersubmod.exact_ps_cpp_topology_af.unit/1.0.0`

重要 keys：

```text
region_id, chrom, hp_family, phase_set, unit_id, block_id,
active_positions, active_original_indices, family_status,
best_tree_unique, representative_best_vertices,
representative_best_edges, read-AF coverage/census
```

`MLHP.groups[].positions` 是完整 sSNV集合；`topology.active_positions` 是active subset，兩者不可按 array index直接混用。

#### `unit_lineage_paths.tsv.gz`（18 欄）

```text
region_id chrom hp_family phase_set unit_id block_id vertex vertex_label
is_hidden depth lineage_path parent_vertex acquired_position mutation_order
edge_score_fraction n_children best_tree_unique family_status
```

#### `read_lineage_assignments.tsv.gz`（15 欄）

```text
dataset chrom molecule_id qname_sha256 hp_family phase_set unit_id block_id
block_index region_id pattern_vector k n_fixed_ra_in_block is_full_cov tree_supported
```

## 7. Paired 與 tumor-only 的真正差異

| 面向 | Paired | Native tumor-only |
|---|---|---|
| caller | ClairS | ClairS-TO／其他 TO model |
| normal BAM | caller與 LongPhase-S需要 | 不提供 |
| phasing | LongPhase-S＋normal germline anchor | LongPhase-TO＋PON／caller evidence |
| LOH | 可用 paired evidence／外部 BED | LongPhase-TO `--loh` 才輸出 `LOH.bed` |
| InterSubMod | 提供 `--normal-bam` | 省略 `--normal-bam` |
| matched-normal evidence | 有 | 無；不能因程式跑通而聲稱取得 normal evidence |
| lineage bridge | HCC1395 paired已實測 | 尚未正式驗證 |

`--germline-hp-only` 會忽略 somatic HP 11/21/33，只保留 germline HP 1/2，適合做 TO self-phasing敏感度／characterization；它不是把 TO變成 paired。
