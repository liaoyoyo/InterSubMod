# 甲基化顯著性分析：深入診斷與多層驗證策略報告

## 摘要

本報告針對 InterSubMod 專案的甲基化顯著性分析結果進行深入診斷，分析 TP/FP 判定不準確的根本原因，並提出多層驗證策略。主要發現包括：

1. **47.8% TP 可能是 LOH**（HP 極度不平衡），導致 HP 比較無意義
2. **低 Coverage (0.3-0.5x) 區域 LOH 率高達 88.5%**，暗示可能與 CNV 相關
3. **僅 3.8% TP 符合理想條件**（顯著 + HP 平衡 + 正常 Coverage）
4. **染色體間 Coverage 差異顯著**：chr7 平均 1.39x，chr5 僅 0.93x

---

## 1. 問題背景

### 1.1 原始討論起點

用戶發現 `significance_statistics.txt` 在程式碼改動後結果完全相同，質疑為何改動無效。

**根本原因**：
- 程式碼改動（多階段 HP 驗證）僅影響 `VerificationClass` 和 `DominantLabel` 分布
- `Significant` 欄位的判定邏輯未被修改：`passed_gating && p<=0.05 && V>=0.1 && reads>=20`
- 因此 `significance_statistics.txt` 統計結果保持不變

### 1.2 核心問題

| 指標 | AUC | 說明 |
|:---|:---:|:---|
| Cramér's V | 0.519 | 接近隨機 (0.5) |
| Heuristic Score | 0.444 | 低於隨機 |
| -log10(P-value) | 0.439 | 無區分能力 |

**結論**：現有甲基化顯著性指標無法有效區分 TP/FP。

## 2. 深入分析結果

### 2.1 資料概況

### 2.2 LOH 與 Coverage 的關係

| Coverage 倍數 | TP 數量 | LOH 率 | Subclone 率 | 顯著率 |
|:---|:---:|:---:|:---:|:---:|
| **0.3-0.5x** | 2,393 | **88.5%** | 9.4% | 3.0% |

| 0.8-1.0x | 7,604 | 39.9% | 3.5% | 7.4% |

| 1.5-2.0x | 2,327 | 28.4% | 2.1% | 5.4% |
| 2.0-4.0x | 599 | 29.7% | 1.2% | 6.8% |

**關鍵發現**：
- 低 Coverage 區域 LOH 率極高，可能是因為 **LOH 導致拷貝數減少**
- 正常 Coverage (1.0-1.5x) 區域 LOH 率最低，是最可靠的分析區域
- Subclone 率在低 Coverage 區域更高，可能反映真正的腫瘤異質性

### 2.3 LOH 區域的分類分布

| 分類 | 數量 | 比例 |
|:---|:---:|:---:|
| Noise | 6,825 | 46.9% |
| Weak | 3,745 | 25.7% |
| Strong | 2,728 | 18.7% |
| Subclone | 1,265 | 8.7% |

**LOH + Subclone (1,265 個)** 是特別值得關注的案例：
- 在 LOH 情況下仍然有多聚類結構
- 可能代表真正的亞克隆甲基化差異
- 也可能是技術假象（phasing 錯誤）

### 2.4 染色體層級 Coverage 分析

## 4. LOH 進階處理策略

### 4.1 不只是排除：分類與分析

LOH 不應該只是「排除」，而應該進一步分類：

| LOH 子類型 | 特徵 | 處理建議 |
|:---|:---|:---|
| **LOH + Noise** | 無結構，HP 不平衡 | 排除或降低權重 |
| **LOH + Weak** | 有弱結構 | 標記為低信心 |
| **LOH + Strong** | 有強結構 | 可能是單親等位基因的真實訊號 |
| **LOH + Subclone** | 有多聚類 | 可能是真亞克隆或 phasing 錯誤 |

### 4.2 Coverage 異常處理

| Coverage 類型 | 特徵 | 可能原因 | 處理建議 |
|:---|:---|:---|:---|
| **極低 (<0.5x)** | LOH 率 88.5% | 拷貝數缺失 (Deletion) | 標記為 "CNV_Loss" |
| **正常 (0.8-1.2x)** | LOH 率 ~35% | 正常二倍體 | 正常分析 |
| **偏高 (1.5-2x)** | - | 拷貝數增加 (Gain) | 標記為 "CNV_Gain" |
| **極高 (>2x)** | FP 顯著率 27.7% | 重複區或多拷貝 | 標記為 "High_Copy" |

### 4.3 建議的分類決策樹

## 5. 多層驗證策略建議

### 5.1 五層篩選架構（更新版）

```
Layer 1: 基本品質過濾
  - NumReads >= 30
  - NumCpGs >= 20
  - 排除已知問題區域 (chr9:41-42Mb)

Layer 2: Coverage 合理性檢查
  - 標記 Coverage_Multiple < 0.5 為 "CNV_Loss_Candidate"
  - 標記 Coverage_Multiple > 1.5 為 "CNV_Gain_Candidate"
  - 對異常 Coverage 區域降低信心分數

Layer 3: HP 平衡性檢查
  - HP_Ratio 在 0.2-0.8 為 "HP_Balanced"
  - HP_Ratio < 0.1 或 > 0.9 標記為 "Potential_LOH"
  - HP1 或 HP2 完全缺失標記為 "HP_Missing"

Layer 4: 多階段驗證一致性
  - HPMergedSig == AlleleSig = "Label_Consistent"
  - HPMergedSig == True AND DominantLabel == 'hp' = "HP_Driven"
  - AlleleSig == True AND DominantLabel == 'allele' = "Allele_Driven"

Layer 5: 綜合信心評分
  - 根據以上各層結果計算 Quality_Score (0-100)
  - Quality_Score >= 70: High Confidence
  - Quality_Score 40-70: Medium Confidence
  - Quality_Score < 40: Low Confidence
```

### 5.2 建議新增的輸出欄位

```cpp
// 新增到 RegionResult 結構
struct QualityFlags {
    bool cnv_loss_candidate;        // Coverage < 0.5x
    bool cnv_gain_candidate;        // Coverage > 1.5x
    bool potential_loh;             // HP Ratio 極端
    bool hp_balanced;               // HP Ratio 在合理範圍
    bool hp_missing;                // 某個 HP 完全缺失
    bool label_consistent;          // HP 與 Allele 一致
    float quality_score;            // 綜合信心分數 (0-100)
    std::string quality_tier;       // "High", "Medium", "Low"
};
```

## 7. 結論

### 7.1 主要發現

1. **LOH 是 TP 不顯著的主要原因之一**：47.8% TP 可能是 LOH
2. **Coverage 與 LOH 高度相關**：低 Coverage 區域 LOH 率達 88.5%
3. **LOH 不應只是排除**：LOH + Subclone (1,265 個) 可能代表真正的亞克隆
4. **Coverage 可作為 CNV 指標**：異常 Coverage 區域需要特別處理

### 7.2 核心建議

1. **不要直接排除 LOH**，而是分層處理
2. **使用 Coverage 倍數作為 CNV 指標**
3. **建立多層驗證機制**，計算綜合信心分數
4. **針對異常區域（如 chr9:41-42Mb）建立黑名單**
