SCQA：問題到底修了什麼？

Situation

per-region raw metrics與 legacy four-state provenance已存在，但 final Strong混合 label-first + cluster-first與 cluster-first-only兩條路徑。

Complication

current／legacy／truth／clone語意可能被 consumer混讀；舊 artifact與 destination race也可能讓失敗看似成功。

Question

能否不改 raw metrics與 binary Significant，拆清 evidence、統一 assignment，並保證 frozen rows逐列不漂移？

Answer

可以。C++、Python contract、74 consumers與 offline migration已完成；formal output與獨立 validator皆使用 fail-closed判斷。

Live evidence

LabelFirstSupport、ClusterFirstSupport、WithinHPSupport、DispersionWarning都是 typed boolean；EvidenceDerivation=LIVE。

Offline evidence

前兩欄可由 legacy推得；後兩欄固定 NA，不可由 class猜；EvidenceDerivation=LEGACY_CLASS。

禁止線：VerificationClass不是 truth；ClusterFirstOnly不是 cellular subclone。任何 consumer都不得用裸 class名稱補出 truth或 clone。
LOH provenance 的最小判斷
  1. potential_loh=false 固定為 None。
  2. potential_loh=true 只依 legacy四態映射 LOH_Noise/Weak/Strong/Subclone。
  3. canonical欄是 LOH_Subtype_LegacyVC；舊 LOH_Subtype只能是逐列 exact alias。
  4. unknown/missing不得歸 None，也不建立語意不明的 current subtype。

4. Fail-closed publication 與 stale artifact

Commit marker

  1. 先原子寫 FAILED/RUN_IN_PROGRESS。
  2. 寫三個 owned artifacts。
  3. 寫 significance CSV/statistics。
  4. 最後才寫 terminal status。

失敗路徑

  1. 任何矛盾零部分 write-back。
  2. 三個 owned artifacts覆寫成 empty/FAILED內容。
  3. status assignment/occupied固定0。
  4. 丟出 machine-readable error。
ArtifactVALID非 VALID
region_stratification.tsvheader + assignmentscanonical header only
region_stratification_summary.txtoccupied sectionsstatus/reason，無 sections
subclone_structure.txt固定 deprecation stub；不含 biological clone wording
Root-review hardening：TempFileGuard只在 rename成功後解除；writer/flush/close/rename失敗會呼叫std::remove()清本輪 owned temp。新增 rename-collision test後 C++為251/251；destructor不回報remove自身失敗，外部權限／namespace競爭另列為hostile-race限制。
讀者責任：三檔不是跨檔 filesystem transaction；一致性依賴 status-first protocol。若 consumer跳過 status，就主動放棄 fail-closed保證。

6. Frozen migration：byte-preserving、staging、no-replace

  1. Preflight 14個 input SHA-256與row count；任何不符立即停止。
  2. 以bytes解析CSV grammar，保留每個原token、quote、NA、newline與row order。
  3. 只授權替換既有 VerificationClass；原token exact複製到v1 deprecated欄。
  4. 逐 stable key核對唯一與順序；Significant比較raw token。
  5. 每檔temp fsync、讀回audit後才進staging canonical filename。
  6. 全檔與reports完成才用Linux renameat2(RENAME_NOREPLACE)發布整個目錄。
沒有 lossy fallback：destination race的EEXIST/ENOTEMPTY拒絕；kernel/filesystem不支援no-replace也拒絕。dangling destination symlink視為已存在。

Production 最小讀取步驟

  1. 先驗schema/status/provenance；production禁用unversioned fallback。
  2. current taxonomy讀C2；historical four-state明確讀L4。
  3. support path讀E，不由class字串反推boolean。
  4. Region artifact先接受R1 terminal VALID；非VALID不讀assignment。
  5. LOH讀canonical LegacyVC；alias存在就逐列驗equal。
  6. Pass-through保留P的完整欄位；不完整或mixed provenance拒絕。
  7. truth/clone/CCF/tree必須有各自明示來源。

9. 限制、風險與不能說的話

工程限制

  • 跨檔一致性依賴status protocol。
  • P2 cleanup不是dirfd-based hostile same-UID防護。
  • C++ TempFileGuard的remove是destructor best-effort，不回報remove自身失敗。
  • repo外precompiled ABI consumer未知。
  • aliases尚無machine-readable removal version。

科學 claim ceiling

  • 沒有BAM/read-matrix/statistics rerun。
  • 沒有F1/AUC caller benchmark。
  • 不證明upstream v1 biology。
  • 不證明class/stratum是clone或tree。
關鍵區分：本次 formal「全量」是 manifest中14個完整 frozen outputs，不是新的BAM pipeline run。權威規格明定此階段不需重跑BAM、distance、clustering或statistics。
