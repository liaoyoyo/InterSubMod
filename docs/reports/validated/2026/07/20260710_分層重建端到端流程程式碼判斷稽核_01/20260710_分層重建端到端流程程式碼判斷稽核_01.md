## 1. 研究背景、目的與閱讀方式

### 1.1 這條流程要解什麼問題？

InterSubMod 的長期目標是把 ONT 長讀長的 germline phase、somatic variant 與 read-level epigenetic evidence 結合。這次稽核的 active flow 不是傳統「用甲基化提高 caller F1」；它要從同一分子上多個 somatic SNV 的共現型態，重建區域性的 mutation-state candidate trees，之後才加入 CN 註記，甲基化則保持 bounded auxiliary。

- 主要服務 **G2/G3**：LongPhase-S 與 read-level evidence 的協同、保留 epigenetic 接口但不 overclaim。
- 工程上服務 **G4/G5**：7 datasets 一致 schema、可重跑、可外部稽核。
- `[F-L1]` Thread D 相關：核心證據是 read-level co-occurrence／HP family。
- `[F-L1]` 不重啟 Thread B 已撤回範圍：L3 明訂不得用甲基化 ranking 或 confirmation candidate trees。
- `[F-L1]` KDE 不在 active Python 主鏈；KDE 只屬 InterSubMod C++ CovM 平行支線。
- `[F-L1]` active 主鏈不讀 VCF caller AF 作 tree decision；它直接由 BAM 逐位點計 REF/ALT reads。VCF NAF 只存在 provenance/header，不進判斷。

### 3.2 `somatic_pass.vcf.gz` 不是 LongPhase-S `_sc.vcf` 的同義詞

### 4.2 SNV scope 與 grouping

`sm_multilocus_combinations.py:28-43` 用 tabix 讀 manifest VCF 的單鹼基 SNV；只檢查 REF/ALT 長度，不重讀 FILTER，因 preflight 已要求全部 PASS。讀取例外會回空 list，而不是立即報錯；final verifier 理論上可透過 VCF count 與 funnel mismatch 抓到，但 stage-local log 不會直接指出哪個 contig fetch 失敗。

Grouping 規則是：對已排序座標 `p1...pn`，只要

```text
p[i] - p[i-1] <= TIER_R
```

就留在同一 connected component。因為是 chain rule，總 span 可以遠大於 50 kb。例如每段 gap 40 kb 的 4 個 SNV，component span 可達 120 kb。文件與 UI 都必須寫「adjacent-gap component」，不能寫「50 kb region」。

當 component 超過 8 個 SNV，程式選擇讓 `p[i+7]-p[i]` 最小的連續 8 個；其餘全部列 `n_sSNV_cap_excluded`，不建立重疊第二視窗。因此 `MAX_SNV=8` 同時是計算上限與資訊選擇規則，不只是 UI cap。

### 4.3 Pileup 與單分子呼叫

`sm_linkage_genomewide.py:83-114` 對整個 component 做一次 `pysam.AlignmentFile.pileup`：

1. `truncate=True`，只看 component span。
2. `stepper="samtools"`；default filter 排除 unmapped、secondary、QC-fail、duplicate，但不排 supplementary。
3. `min_base_quality=0`；再由程式要求 MAPQ≥20。
4. deletion、reference skip、沒有 query position 的 observation 跳過。
5. base 等於 REF→`REF`；等於 ALT→`ALT`；其他 base→`OTHER`。
6. dictionary key 是 `query_name`；同名的 supplementary/多重 alignment 可覆寫同一 read 的 base、HP、PS。

`[F-L1]` PS 值會在這一步被讀入，但後續 vector/family/unit/solver 都沒有使用 PS 來分離 phase block 或作衝突檢查；同 query name 的 HP/PS 亦沒有 conflict counter。因此 PS 目前只是被攜帶的觀察欄位，不是 tree decision input。

`[O-L2]` HCC1395 chr1:10–11 Mb 的抽查有 524 supplementary alignments；9,234 個 unique query names 中有 1,767 個在此窗重複，最多同名 4 筆。這不能直接量化 topology impact，但足以證明「一個 query name=一個無歧義 molecule record」不是總是成立。上游又使用 `--tagSupplementary`，因此應明確選擇：排除 supplementary、或依 alignment segment/SA 一致性合併，而不是由最後一次 dictionary overwrite 決定。

此外，pysam pileup 的 `max_depth` 未顯式設定，沿用 8,000 default。極高深度區可能被截斷；目前 preflight/verifier 沒記錄或檢查這個隱含設定。

### 4.4 R/A/X vector 與 support

對 component 的 k 個位置，每個 read 轉為：

```text
R = clean REF observation
A = clean ALT observation
X = 未覆蓋、OTHER、deletion/refskip，或該 query name 沒有該位置
```

程式同時計算：

- pooled full vector：不含 X；
- pooled `subread_groups`：實作上包含所有 vector，**也包含 full R/A vector**；
- per-HP-family `populations_by_hp` 與 `subread_groups_by_hp`；
- 每 locus 的 `[nREF,nALT]` coverage。

這裡有兩個需要說清楚的語意：

1. `subread_groups` 名稱暗示 partial，但程式在判斷 full 前就把所有 vector 加入，因此 full vector 會同時出現在 full 與 subread 結構。它通常只重複同一 coverage constraint，不必然改樹，但會讓 `n_partial`、UI 與方法敘述膨脹。
2. component 的 retention 先看 pooled `nfull>=3` 或 pooled 某 pattern≥3；進 solver 前再按 family 與每個 pattern≥3 過濾。可能發生「pooled retained，但沒有任何 family/pattern 達 3」；該 SNV 會算在 retained funnel，卻沒有 tree unit。現行 verifier沒有檢查 retained groups 與 produced units 的 coverage mapping。

### 4.5 HP family 對應

KB 與 LongPhase-S 定義的 HP 可能是 `. / 1 / 2 / 3 / 4 / 1-1 / 2-1 / 1-2 / 2-2`。目前 `germ_family()` 的規則是：

| Raw HP | Python family | 保留／丟失的語意 |
|---|---|---|
| `1`, `1-1`, `1-2` | `1` | 保留第一 germline family；丟失 somatic suffix |
| `2`, `2-1`, `2-2` | `2` | 保留第二 germline family；丟失 somatic suffix |
| `3` | `3` | unresolved somatic-integrated auxiliary |
| `4` | `none` | 「both germline haplotypes」與 missing/unphased 被合併 |
| missing/other | `none` | unphased auxiliary |

Family-first 是已明示的建模選擇；真正模糊處在於 HP4 被混到 none、suffix 被丟失後不再能分辨 LongPhase-S somatic state，且上述 truth-BED selection 可能使各 sample 的 suffix availability 不一致。

### 4.6 六層 funnel

在 chr1-22 內，producer 檢查：

```text
n_sSNV_scope_input
  = n_positional_singleton
  + n_sSNV_cap_excluded
  + n_sSNV_read_unsupported
  + n_sSNV_retained
```

Region view 再加入 out-of-scope，檢查 VCF SNV total 與 autosomal count。這能證明分類加總守恆，不能證明每個 branch 的 biological label 正確，也不能證明 retained SNV 全部進入 primary tree。

## 5. Tree solver：模型、搜尋與分類細節

### 5.1 Solver 真正最佳化的是什麼？

對 k≤8 個 loci，把每個 genotype 表示成 ALT bit set；`RR...R` 是 root。Full observation 必須是 node；每個含 X 的 pattern 定義一個相容 subcube，樹至少要選一個 node 覆蓋它。

Solver 依序搜尋 extra hidden nodes 數 `e=0..4`，找第一個同時滿足：

- 所有 full nodes 都存在；
- 每個 partial subcube 至少被一個 node 命中；
- 每個非 root node 至少有一個「移除一個 ALT bit」後仍在 node set 的 predecessor。

因此目標是**最少 hidden-node count**。Read support 大小一旦通過 MINREAD，後續 solver 不加權 3 reads 與 300 reads；`full_counts` 被讀入但沒有進 objective。這不是 maximum-likelihood tree，也不是 CCF tree。

### 5.2 搜尋上限與 capped

| 限制 | Default | 後果 |
|---|---:|---|
| `k` | 由 MAX_SNV 限至 8 | state space 最多 256 bitsets |
| `extra_cap` | 4 | e≤4 找不到解便 fallback |
| `per_level_budget` | 150,000 combinations | 任一 e 層超過即 fast-cap |
| analysis tree cap | active driver 傳 0 | non-capped 分析嘗試生成全部 trees |
| display cap | 32 | 只影響輸出展示，理論上不改 exact summaries |

當超出 budget/extra cap，solver 用 greedy closure 生一棵 fallback tree 並標 `capped=true`。這棵樹只是一個 fallback witness，不能支持「所有最小樹已枚舉」「determined」或 exact shape。

`[O-L1]` 另有一個 capped accounting bug：若 full observations 已含 root genotype，fallback top-level `n_hidden=len(N)-len(full)-1` 會把 root 扣兩次。合成 `full={RR,AA}` 且強制 cap 的 probe 得到 top-level `n_hidden=0`、stored tree `n_hidden=1`。正確公式應統一為 `len(N - ({ROOT} ∪ full))`。

### 5.3 為何樹數可以分析式計算？

對固定 feasible node set `N`，每個非 root node `x` 可從所有 `x-{j}` 且仍在 `N` 的 predecessor 選一個 parent。因 edge 只增加一個 ALT bit，自然無環並回到 root：

```text
n_trees(N) = product over x != root of n_valid_predecessors(x)
total n_trees = sum over all minimal feasible N of n_trees(N)
```

這個模型只允許沿 edge 增加 mutation bit；所謂 recurrence 是同一 bit 在不同 branch 被引入至少兩次，不包含 explicit back-mutation/loss edge。

### 5.4 Class 判斷

| Class | 程式條件 | 正確說法 |
|---|---|---|
| determined | non-capped、存在 recurrence-free minimal N、`n_trees=1` | 模型內唯一最小 candidate tree |
| ambiguous | non-capped、存在 recurrence-free minimal N、`n_trees>1` | 有多個最小 candidate trees |
| recurrence_required | non-capped、無 recurrence-free minimal N、存在 recurrent N | 在 Model A 下所有最小解需 recurrence |
| underdetermined | 無上述可辨識狀態 | 輸入／模型不足 |
| capped | 搜尋未完成 | 必須另列 not-applicable，不得包成上述 exact class |

Layered driver 再把 ambiguous 分成：只有一個 feasible node-set 的 `ambiguous_order`，以及多個 node-set 的 `ambiguous_structure`。這仍是 model-defined identifiability，不是 biological truth。

### 5.5 Tree order 與 digest 可重現性

候選生成中多處從 `set/frozenset` 建 list；tree digest 會排序每棵樹內的 edges，但沒有排序整個 tree list。未固定 `PYTHONHASHSEED` 時，candidate prefix、display first-32 與 digest 可能跨 Python process 改變順序，即使候選集合相同。若 display 或 downstream heuristic 使用 prefix，這是實質可重現性風險；應 canonical sort complete tree set 後再 digest/截取。

此外，若使用者把 `SM_ANALYSIS_TREE_CAP` 設為正值，unit 仍可能因 V1–V7 對 stored prefix 全過而被標 `verification_status=full_pass`；`analysis_candidate_set_complete=false` 只會在 final H6 gate另行擋下。中間 JSON 的「full_pass」因此沒有同時保證 exhaustiveness，建議把 structural checks 與 candidate completeness 拆成兩軸，或讓 full_pass 同時要求 `analysis_complete=true`。

## 6. L0–L3 分層判斷

### 6.1 L0：family role

每個 region×family 產一個 unit。角色依序判斷：

1. family 1/2 且有 MINREAD-supported ALT pattern → `primary_mutation_lineage`。
2. family 1/2/3 但沒有 ALT → `reference_only_control`。
3. family 3 且有 ALT → `unresolved_H3_auxiliary`。
4. 其他 → `unphased_auxiliary`。

Primary denominator 只含第 1 類。`legacy_is_lineage` 仍保存舊語意，但新 consumer 必須讀 `is_primary_lineage`；region view 的 fallback `get("is_primary_lineage", get("is_lineage"))` 會在 schema 混用時悄悄恢復 legacy denominator，因此 final verifier必須拒絕缺新欄位的 artifact，而不能依 fallback 繼續。

### 6.2 L1：sSNV + Model A

L1 只看 full/partial genotype constraints 與 HP family，不讀 CN、methylation、VCF AF、purity 或 truth label。每個 unit 輸出候選數、hidden nodes、class、display trees、exact shape、digest 與 V1-V7 status。

### 6.3 L2：建樹後的 CN annotation

只有 mutation-bearing、non-capped、base class=`recurrence_required` 的 unit 送入 CN m-channel：

| CN evidence | 判斷 | 注意 |
|---|---|---|
| CN missing/unknown/unavailable | `unavailable` | 不得當 neutral |
| integer gain CN≥3 | `artifact_drop` | 只在有 integer gain BED 時可用 |
| integer loss CN=0 | `artifact_drop` | 只在有 integer loss BED 時可用 |
| categorical gain/loss | confounded | 不直接保留為 biological recurrence |
| categorical neutral | `candidate_keep` | 仍只是 candidate，不是 confirmed convergence |
| LOH | max read AF>0.7→likely artifact；否則 likely recurrence | heuristic；threshold 未做 sensitivity |

`max_vaf` 由同一 family 的 BAM `[ALT/(REF+ALT)]` 取最大值，不是 caller AF，也未做 purity/CN correction。

CN 目前有四個額外風險：

- **兩個 stage 實際使用不同 anchor**：Stage 1 `sm_multilocus_combinations.py:165` 用 sorted positions 的右中央 SNV；Stage 2 `layered_tree_reconstruction.py:119` 用 `(first_position + last_position)//2` 的算術 midpoint。對舊 HCC1395 snapshot 的只讀 probe 中，7,928 groups 有 12（0.151%）在兩種 anchor 得到不同 categorical state（例 `chr2:10178748-10256938 loss→loh`）。這是舊 snapshot 的風險量化，不是 v2 full-run result。
- group 只在單一 anchor 查 CN，即使 chain component span>50 kb；跨 segment component 可能被單點誤代表。
- lookup 用 `s <= POS <= e`；SEQC2 BED 已在其他腳本定義為 0-based half-open，應轉為 `s < POS <= e`，現行起點有 1 bp off-by-one。
- SEQC2 660 intervals 中有 239 個排序後與前一 interval overlap；程式回第一個命中 label，未定義重疊優先級或複合 state。
- manifest 的 `cn_semantics` 文字不被 producer/validator enforce；SAVANA 未列區域是否能視為 neutral 仍是 contract 假設。

### 6.4 L3：甲基化

Active driver 沒有 join per-unit methylation evidence，固定輸出：

```text
status = not_evaluated
role = bounded_auxiliary
allowed = negative_screen, residual_flag
prohibited = tree_ranking, lineage_confirmation, clone_confirmation
```

這個限制是合理且必要的：它保留 Thread D 的未來接口，同時不把已知 methylation-filter NEGATIVE 歷史重新包裝成 positive tree evidence。

## 7. V1–V7 到底驗了什麼？

| Check | 實際檢查 | 能抓到 | 不能證明 |
|---|---|---|---|
| V1 | stored tree edge 是 unit-flip；每 node 一父；root-connected；無 cycle | 結構格式錯誤 | 未儲存候選是否正確 |
| V2 | full node 在樹上；每 partial subcube 至少命中一 node | coverage invariant | read→vector 是否正確 |
| V3 | full observations 是 node subset | 基本一致性 | 與 V2 高度重疊，非獨立資料 oracle |
| V4 | 用同一 candidate pool/helper 重搜 `e_min-1` 不可行 | 部分 minimality bug | 不共用實作的 formal oracle；capped 跳過 |
| V5 | 用同一定義重算 analytical `n_trees` 並比 reported count | count formula/report mismatch | **不比較輸出 tree set，不能叫 complete enumeration oracle** |
| V6 | class flags 與 recurrence/refree flags 自洽 | 旗標矛盾 | 模型本身是否符合生物真相 |
| V7 | determined 必須 1 tree、refree、non-capped | 最直接 overclaim | `n_trees` 的外部正確性 |

固定 adversarial case 顯示：`n_trees=1,119,744`、只 stored 32、`trees_complete=false` 時，V5 仍回 `true`，overall 也 true。因此安全名稱應是 `implementation invariant suite`；V5 應更名 `count_consistency`，除非另有不共用 solver helper 的 canonical tree-set implementation。

Legacy `full_v4v5_verification.py` 還有第二個問題：stress case 一旦 capped，就不跑 V4/V5但直接 `stress_pass += 1`。固定 seed 前100案實測為 98 checked、2 capped-not-tested、0 checked failures；正確報法是 `98/98 checked pass, 2 skipped`，不是 `100/100 pass`。

## 14. Tutorial：一個最小例子如何走完整條鏈

假設同一 HP1 family、兩個 SNV，MINREAD=3：

```text
AR × 5 reads
AA × 4 reads
```

1. 兩個 pattern 都達 support 3。
2. `AR` 代表只帶第1個 mutation；`AA` 帶兩個。
3. root 是 `RR`；unit-flip tree 只能是 `RR → AR → AA`。
4. hidden nodes=0，candidate trees=1，class=`determined`。
5. 這個「determined」只在 Model A 與這些 observations 下成立。

若再觀察：

```text
RA × 4 reads
```

node set包含 `AR, RA, AA`。`AA` 可以掛在 AR或RA，且同一 mutation bit會在兩個 branch被引入；solver會得到 recurrence-required candidate set。只有到這時 L2 才查 CN：

- CN gain/loss→confounded/artifact annotation；
- CN neutral→`candidate_keep`；
- CN unavailable→不能裁決；
- 即使 candidate_keep，仍不能寫「真實 convergent clone已確認」。

如果 `AA` 只有2 reads，它不達MINREAD，不進constraint；結果可能從 recurrence-required變成單純 siblings。這說明基本門檻直接影響 topology，為何 sensitivity 不是選配。
