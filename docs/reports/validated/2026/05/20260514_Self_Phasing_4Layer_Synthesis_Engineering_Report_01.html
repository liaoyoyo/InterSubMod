§1Problem Statement

§1.1Self-Phasing Pipeline 定義

InterSubMod 使用 longphase-to（fork from upstream longphase）對 TO mode（tumor-only，無 matched normal）VCF 執行 read-level phasing：

  • 輸入：tumor BAM + ClairS-TO 的 somatic + germline VCF（無 PoN 預過濾 germline）
  • 輸出：phased VCF (PS/GT/GT2) + haplotagged BAM (HP tag)
  • 關鍵概念：因無 matched normal，germline het + somatic 共同進入 phasing graph → 形成 self-phasing。
為何 self-phasing 是設計問題：somatic 變異既是 phasing graph 的 node（與 germline 共構 haplotype block），也是後續 ISM/LOH/Subclone 分析的評估對象。球員兼裁判：somatic 的 phasing assignment 受其自身 read 支持決定，再回過頭用此 assignment 做 LOH/subclone 判定 → 循環依賴 (circular dependency)。

§4.1L0 — Self-Phasing Circular Dependency（球員兼裁判）

L0 設計層：somatic 進 phasing graph 形成循環依賴 IN SCOPE

機制

在 TO mode（無 matched normal）下，longphase 必須對 ClairS-TO 輸出的 somatic + germline VCF 同時做 phasing。baseline 行為：

  1. 把 germline het + somatic 全部加入 phasing graph 的 node set
  2. 用 read evidence 推出 phase block（PS）+ assignment（GT/GT2）
  3. 結果：somatic 的 phase 推定 受其自身 read evidence 影響
  4. 後續下游用此 phase 結果做 LOH / ISM / Subclone 分析

循環依賴問題：

somatic VCF ──→ phasing graph ──→ phase assignment ──→ LOH/ISM/Subclone 分析 ↑ │ └────────── 評估對象 ─────────┘ (球員又是裁判)

Symptom（baseline HCC1395 5kHz）

  • Phase block N50 = 4,061 bp（短碎片 — 因 somatic 引入錯誤連結，phase block 被斷開）
  • Phased rate = 54.9%（變異被 phased 的比例，相對 paired mode ~80% 偏低）
  • LOH detection = 31.2% — 為 self-phasing artifact（不是真實 LOH）

修補：--pon-only-phasing mode（commit 8b8c1fd）

核心想法：把 phasing 分兩 pass：

  1. Pass 1：用 PoN（panel of normal）篩出的 germline het only 進 graph，產出 germline-only phase block
  2. Pass 2 syncOrigins：把 somatic 投影到 Pass 1 germline phase block 上（不影響 phase block 結構），標 GT2 表示 somatic 對應 haplotype

效果：

  • Phase block N50 從 4,061 → ~20,000+（germline-only phasing 不受 somatic noise 干擾）
  • Phased rate ↑（更多 germline 進 phase block）
  • LOH detection 重新 valid（不再 artifact dominated）
L0 修對 ≠ 全部問題消失：PON-only 切斷 somatic 進 phasing graph 的反向影響，但 haplotag 階段（將 read 分配給 HP1/HP2）仍受 L2 priority bug 影響。L0 + L2 必須都修才完整。

§4.2L1(a) — Phasing 結構：Pass 2 後 ploidyRatio

L1(a) Pass 2 syncOrigins 後的 ploidy 重算 IN SCOPE

背景

longphase 在 phasing 過程估計 ploidy（基因組 region 的 copy number ploidy ratio），用於 GT 編碼（diploid / triploid 等）。原本流程：

  1. read alignment → phasing graph → ploidy estimate
  2. ploidy estimate 用於 GT phasing assignment

L0 mode 切換引入的問題

--pon-only-phasing 切兩 pass 後，ploidy 在 Pass 1 估完，Pass 2 syncOrigins 把 somatic 投影回 graph。但原本 code path 沒有在 Pass 2 後重算 ploidy → somatic 投影後 ploidy 與實際 graph 不同步。

修補：d0bcd8c — ploidyRatio after Pass 2 syncOrigins

  • 在 Pass 2 syncOrigins 完成後重新計算 ploidyRatio
  • 用新 ploidyRatio 重新 encode GT field（diploid vs triploid 分支）
  • 確保 phased VCF 內部 GT/PS/GT2 結構與 Pass 2 後 graph 一致
L1(a) ≠ assignment bias：L1(a) 解決的是「Pass 2 後內部結構同步」，不解決 altHaplotype 偏 HP1 的 1.77:1 ratio（那是 L1(b)）。L1(a) 是 cleanup patch，量化影響小（GT 編碼正確性），但不修則 V5 phased VCF 結構不一致。

baseline getVote() 完整 source

Haplotype HaplotagProcess::getVote(std::map<Haplotype,int> &countMap){
    // vector 順序：HAPLOTYPE1 在前，HAPLOTYPE1_1 在 HAPLOTYPE2 之後
    std::vector<Haplotype> vec = {HAPLOTYPE1, HAPLOTYPE2, HAPLOTYPE1_1, HAPLOTYPE2_1, HAPLOTYPE3};

    int maxVote = 0;
    Haplotype result = HAPLOTYPE_UNDEFINED;
    for( auto h : vec ){              // ← vector order 決定 break-early 優先序
        if( countMap[h] > maxVote ){
            maxVote = countMap[h];
            result = h;
        }
        // tie 情況不更新 result → 先進入 maxVote 的 haplotype 勝出
    }
    return result;
}

Bug 機制（per-read trace）

對一條 read：

  1. read 跨越 N 個 phased variant 位點 → countMap 紀錄每 Haplotype 的 vote 數
  2. 例：read 跨 5 個 germline het + 2 個 somatic → countMap = {HAP1: 3, HAP2: 2, HAP1_1: 2, HAP2_1: 0, HAP3: 0}
  3. getVote 走 vector 順序：HAP1 vote=3 → maxVote=3, result=HAP1（之後 HAP2 vote=2 不超過，被擱置）
  4. 結果：read 被分到 HP1（合理）

但另一例（tie 情況）：

  1. read 跨某 region → countMap = {HAP1: 2, HAP2: 2, HAP1_1: 0, HAP2_1: 0, HAP3: 0}
  2. vector 順序：HAP1 vote=2 → maxVote=2, result=HAP1
  3. HAP2 vote=2 不 > maxVote → result 不變
  4. 結果：read 被分到 HP1（tie 永選 HP1，無 random tie-break）

「9.8× 放大」的數學機制

對 N=34,855 條 read，假設每 read 的 countMap 為兩 family vote 數 X (HP1) vs Y (HP2)：

  • 若 X > Y：read 分到 HP1 family（HAP1 或 HAP1_1 先 maxVote）
  • 若 X < Y：read 分到 HP2 family
  • 若 X = Y（tie）：vector 順序使 HAP1 / HAP1_1 永遠優先 → read 分到 HP1

L1(b) 階段每 variant 的 altHaplotype 分佈是 1.77:1 偏 HP1。但每 read 的 vote 是 Σ（read 跨的 variants），這個 sum 過程進一步放大 bias：

  1. read 跨多 variants（typical 5-20 個 phased variants）
  2. 每 variant 獨立 1.77:1 偏 HP1 → 多 variants sum 後，HP1 family 累積優勢顯著（binomial-like 累積偏置）
  3. 加上 tie-break 永遠選 HP1 → 邊界 case 全推 HP1
  4. 累積：~17.3:1 / 1.77 ≈ 9.8× 放大
