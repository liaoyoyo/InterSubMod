# AI 自動化 F1 研究主線與 PPT 藍圖整合報告

## 重點結論

最近這一輪研究的核心，不是再手動試幾條規則，而是開始用 AI / agent 把「讀文件、找資料、跑流程、比規則、寫結論、回寫索引」制度化，目標是以 **提升 F1-score** 為中心，逐步拆解各個參數與其組合在不同母體中的效果。  
目前最穩定的高層結論已可收斂成三層：

1. **第一層：caller-first**
   - 目前最穩定的主規則仍來自 caller 端，尤其是 `GQ`、`QUAL` 與 `FILTER`。
2. **第二層：LongPhase + methylation-support**
   - 甲基特徵不是全負效果，但目前大多只能作 support / ranking / annotation，尚未穩定超過最佳 caller-only。
3. **第三層：haplotype / SNV / 甲基共分析**
   - 用來驗證標籤是否合理、哪些位點可能是 subclone、哪些結果更像 artifact 或 dataset-specific 偏差。

現階段最重要的具體結論有 5 個：

1. `HCC1395_HKU_5kHz` 在 `paired` 經過 `LongPhase-S`、在 `TO` 經過 `LongPhase-TO` 後，都能再篩掉一部分 FP，整體 F1 有小幅上升。
2. `HCC1395_DORADO` 在相同方向上大多只有持平或些微下降，說明這些甲基特徵目前**不具跨平台穩定性**，更可能是 dataset-specific 或對較 noisy 樣本更有幫助。
3. `TO` 的 TP rescue 問題上，`5kHz` 確實有兩類有效訊號：
   - caller-first：`gq>=10` 或 `qual>=10 or gq>=20`
   - methylation-support：`PairwiseMedianDist>=0.20`、`agreement_positive`
   但它們目前仍**沒有超過最佳 caller-only**。
4. `DORADO TO` 的 support 方向改成：
   - `gq>=10`
   - `Quality_Score>=60`
   - `PairwiseMedianDist<=0.20`
   這再次支持 `PairwiseMedianDist` 具明顯 dataset-dependence，不能全域化。
5. mixed sample 目前只能講到初步觀察：`tumor < normal < mixed`。合理推論是組織來源差異可能大於 haplotype 與癌症趨同的效應，但這一點尚未正式完成全基因組與純樣本後的校正驗證。

## 1. 為什麼最近改用 AI / agent 自動化

最近的研究策略有一個明確轉變：

從：
- 手動觀察少數位點
- 手動試少量規則
- 手動記錄零散結論

轉成：
- 讓 AI / agent 在固定限制下自動讀文件、抓數據、跑流程、彙整規則、寫出每次實驗報告
- 再把每輪實驗濃縮成主線結論與索引
- 讓下一次專案開啟時，AI 可以沿著已驗證的主軸繼續研究，而不是重複踩舊方向

目前這套自動化主要依賴：

1. `docs/CURRENT_FOCUS.md`
2. `docs/experiments/INDEX.md`
3. `docs/README.md`
4. `/big8_disk/liaoyoyo2001/knowledge/`
5. LongPhase-S / LongPhase-TO 的 tagged BAM workflow
6. Python 分析腳本與固定輸出表格
7. 每輪實驗後的 `.md` 報告與索引回寫

這樣做的研究價值是：

1. 每個方向都會留下可複查的數據與結論
2. 可以快速知道哪些規則只在單一樣本成立
3. 可以把「有用但不夠穩定」的特徵先降階成 annotation，而不是過早硬接進主流程

## 2. 這輪 AI 被限制只做哪兩類問題

這一輪我刻意限制 AI 只先做兩類驗證，避免把問題一次放太大。

### 2.1 問題 A：最後輸出後，能不能再刪 FP 而不刪太多 TP

也就是：

- 先看 caller / LongPhase / InterSubMod 最終輸出
- 再分析是否可用某些參數或甲基特徵，進一步刪掉 FP
- 在不明顯增加 FN 的情況下提升 F1-score

這一類問題對應的是：

- `5kHz paired`
- `5kHz TO`
- `DORADO paired`
- `DORADO TO`

的後段 `FP triage` 與 `support feature` 分析。

### 2.2 問題 B：一開始被 caller 移掉的 TP，能不能被救回

也就是：

- 找出 caller 一開始非 PASS、或後段被移除掉的 truth-like 位點
- 觀察能不能透過放寬某個 caller 條件，再配合甲基結果，把 TP 救回來而不帶回太多 FP

這一類問題對應的是：

- `caller_lost_tp`
- `Pool B FN`
- `candidate-specific rescue`

的設計與驗證。

### 2.3 這兩條線的差別

這兩類問題不能混成同一套規則，因為母體不同：

1. **後段刪 FP**
   - 母體是 caller 已經保留的 call set
2. **前段救 TP**
   - 母體是 caller 已經刷掉的 non-PASS 或 lost TP 候選

因此像 `AlleleDelta` 這類特徵，在兩種母體中的方向可能相反，不能全域化。

## 3. 自動化研究流程與 tagged BAM 的角色

目前 AI 自動化研究會依序做這些事：

1. 讀 `docs` 與 `knowledge`，先對齊目前主線與已驗證結論
2. 找到對應樣本的 caller output、benchmark 結果與 truth set
3. 執行 `LongPhase-S` 或 `LongPhase-TO`
4. 產生 InterSubMod 需要的 `tagged.bam`
5. 跑 candidate-specific rescue、feature sweep、interval / orthogonality 分析
6. 將每輪結果寫成研究報告
7. 回寫 `CURRENT_FOCUS`、`INDEX`、主線整合報告

這裡的 tagged BAM 很重要，因為：

1. `InterSubMod` 需要 `haplotagged BAM`
2. `LongPhase-S` 對 `paired` 使用
3. `LongPhase-TO` 對 `TO` 使用
4. 如果沒有 tagged BAM，就不能做真正的 HP / label-first 驗證

目前空間策略也因此被迫收斂：

- `big8_disk` 空間有限
- 先以 `HCC1395_HKU_5kHz` 為主驗證
- `HCC1395_DORADO` 為交叉驗證
- 其他樣本後續在 `big7_disk` 接著做

## 4. 樣本策略與目前的研究邏輯

### 4.1 為什麼先做 5kHz，再用 DORADO 驗證

目前的樣本策略很明確：

1. `HCC1395_HKU_5kHz` 是主實驗樣本
2. `HCC1395_DORADO` 是同樣本、不同定序流程的交叉驗證

理由是：

1. `5kHz` 比較 noisy，FP 較多，較適合找「能不能刪 FP」與「能不能救 TP」這類規則
2. `DORADO` 比較乾淨，可以用來檢查這些規則是否只是平台特異性

### 4.2 目前已看到的高層方向

| 樣本 | paired 後甲基/phase 是否有幫助 | TO 下 rescue/support 是否有幫助 | 目前判讀 |
| --- | --- | --- | --- |
| `HCC1395_HKU_5kHz` | 有，小幅提升 F1 | 有，caller 與甲基都能救回 TP / 刪除 FP | 最適合當主實驗樣本 |
| `HCC1395_DORADO` | 大多持平或些微下降 | support 有訊號，但不超過 caller-only | 證明目前規則不具跨平台穩定性 |

### 4.3 現在最合理的解釋

目前最合理的推論是：

1. `5kHz` 上較大的 FP 空間，讓某些甲基特徵更有機會顯現正增益
2. `DORADO` 本來就比較乾淨，因此同樣規則帶來的增益縮小甚至轉負
3. 這代表這些特徵目前比較像：
   - dataset-specific
   - platform-specific
   - 對 noisy sample 比較有效

但不能直接下定論說：

- `DORADO` 無效，所以甲基沒用

正確口徑應是：

- 目前這批甲基特徵對 `5kHz` 有用，但尚未跨平台穩定成立

## 5. 現有主結果：paired

### 5.1 paired 的 benchmark 主表

| Dataset | Method | TP | FP | FN | F1 |
| --- | ---: | ---: | ---: | ---: | ---: |
| `HCC1395_HKU_5kHz paired` | `ClairS` | `29,865` | `1,430` | `9,582` | `0.8443` |
| `HCC1395_HKU_5kHz paired` | `LongPhase-S` | `29,754` | `627` | `9,693` | `0.8522` |
| `HCC1395_HKU_5kHz paired` | `InterSubMod` | `29,752` | `544` | `9,695` | `0.8532` |
| `HCC1395_DORADO paired` | `ClairS` | `29,986` | `588` | `9,461` | `0.8565` |
| `HCC1395_DORADO paired` | `LongPhase-S` | `29,889` | `240` | `9,558` | `0.8592` |
| `HCC1395_DORADO paired` | `InterSubMod` | `29,877` | `238` | `9,570` | `0.8590` |

來源：

- [docs/reports/validated/2026/03/20260311_研究主線週報_20260305_20260311_phase2_annotation整合_01.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/reports/validated/2026/03/20260311_研究主線週報_20260305_20260311_phase2_annotation整合_01.md)
- [docs/reports/validated/2026/03/20260311_週報驗證分析報告_01.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/reports/validated/2026/03/20260311_週報驗證分析報告_01.md)

### 5.2 這些 paired 數據真正表示什麼

1. `5kHz paired`
   - `InterSubMod` 比 `LongPhase-S` 多出來的主要增益，**不是大量救回 TP**
   - 而是再少掉了 `83` 個 FP（`627 -> 544`）
   - TP 反而少 `2` 個（`29,754 -> 29,752`）
   - 所以這裡正確的說法是：
     - 甲基與 phase 的整合在最 noisy 的主樣本上，能再小幅改善 precision
2. `DORADO paired`
   - `InterSubMod` 與 `LongPhase-S` 幾乎持平略負
   - 代表這個方向不具穩定跨平台性

### 5.3 paired 的主結論

paired 目前最合理的口徑是：

1. caller 與 LongPhase 已經把大部分主要改善做掉
2. InterSubMod 在 `5kHz` 可再做少量 FP 精修
3. 這個精修在 `DORADO` 不穩定，因此現階段不能升級成全域規則

## 6. 現有主結果：tumor-only

### 6.1 TO 的 caller-first 與甲基 support 必須分開寫

#### `HCC1395_HKU_5kHz TO`

| 規則 | TP rescued | FP reintroduced | F1 delta | 口徑 |
| --- | ---: | ---: | ---: | --- |
| `gq>=10` | `499` | `119` | `+0.006943` | caller-first，有效 |
| `qual>=10 or gq>=20` | `491` | `118` | `+0.006824` | caller-first，有效，但與 `gq>=10` 不是同一規則 |
| `PairwiseMedianDist>=0.20` | `300` | `68` | `+0.004219` | 甲基 support，有效 |
| `agreement_positive` | `148` | `25` | `+0.002163` | label-aware support，有效 |

#### `HCC1395_DORADO TO`

| 規則 | TP rescued | FP reintroduced | F1 delta | 口徑 |
| --- | ---: | ---: | ---: | --- |
| `gq>=10` | `40` | `11` | `+0.000540` | caller-first，最穩定 |
| `Quality_Score>=60` | `208` | `77` | `+0.002620` | baseline 上有正訊號 |
| `PairwiseMedianDist<=0.20` | `173` | `60` | `+0.002217` | baseline 上有正訊號 |
| `hp_assign_rate>=0.99` | `122` | `41` | `+0.001577` | baseline 上有正訊號 |

### 6.2 TO 最重要的正確結論

1. `5kHz TO`
   - caller-first 與甲基 support **都能單獨救回 TP 並提升 baseline F1**
   - 但固定到同一 caller gate 後，甲基仍**沒有超過最佳 caller-only**
2. `DORADO TO`
   - 甲基 support 也不是負的
   - 但同樣只是在 baseline 上有正向訊號，尚未超過固定 caller gate

### 6.3 為什麼這一點很重要

這代表現在最準確的高層口徑不是：

- 甲基規則已能取代 caller

而是：

- **caller-first 穩定成立**
- **甲基規則在 TO 有 support 價值**
- **但還沒有證據讓它升級成第一層主規則**

## 7. Pool B FN：前段 TP rescue 問題的正式收尾

`Pool B FN` 已在：

- [docs/reports/validated/2026/03/20260312_PoolB_FN_integration_closeout_01.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/reports/validated/2026/03/20260312_PoolB_FN_integration_closeout_01.md)

正式 closeout。

### 7.1 Pool B 的主結果

| 項目 | 數值 |
| --- | ---: |
| `Pool B FN` | `840` |
| caller-only 最佳 `no_varcluster` | `428 TP / 390 FP`, `F1 +0.003391` |
| caller-only 最乾淨 `no_varcluster_and_gq15` | `115 TP / 45 FP`, `precision=71.9%` |
| 最佳 combined `gq15_and_allele_delta_low` | `431 TP / 473 FP`, `F1 +0.002702` |

### 7.2 這裡最重要的口徑

1. Pool B 再次證明 caller-side rescue 空間存在
2. 甲基只提供弱補強，沒有超過 caller-only 最佳規則
3. `AlleleDelta` 在 Pool B 與 TO kept-set / artifact triage 的方向不同，不能混成一條全域規則

因此這一節在 PPT 裡應作為：

- **「前段救 TP 與後段刪 FP 是不同母體」**

的說明頁，而不是再獨立開一條新主線。

## 8. 目前最重要的特徵與分工

| 特徵 | 目前定位 | 哪裡有效 | 可否升級 | 不能怎麼用 |
| --- | --- | --- | --- | --- |
| `GQ` | `caller-first` 主規則 | 四象限中最穩 | 可，已是主規則 | 不能直接解讀成 caller 一開始就該全面放寬 |
| `QUAL>=10 or GQ>=20` | `5kHz TO` caller-first 規則 | `5kHz TO` | 僅可作 dataset-specific caller gate | 不能寫成所有 TO 都該用的通則 |
| `Quality_Score` | support annotation | 兩個 TO 都有正訊號 | 可升 annotation | 不可直接 hard keep |
| `PairwiseMedianDist` | dataset-aware support annotation | `5kHz TO` 偏高、`DORADO` 偏低 | 可升 dataset-aware annotation | 不可全域固定方向 |
| `agreement_positive` | label-aware support | `5kHz TO` 較有價值 | 可保留為 support annotation | 不可當所有 dataset 的主 rescue |
| `Strong/Subclone` | support 子集 | 在部分情境可解讀 | 不可升級成 hard keep | FP 也可能很高 |
| `hp_assign_rate` | phase / QC annotation | `DORADO` 相關性較高 | 可升 QC | 不可當 truth-discriminative 主規則 |
| `low VAF + high AlleleDelta + low CramersV` | artifact triage | `5kHz` 對刪 FP 有用 | 可保留在 artifact 旁路 | 不可當 TP rescue 主規則 |

### 8.1 這張表要帶出的重點

1. 有用的特徵不一定能升級成主規則
2. 有些特徵的價值是在 support / ranking / annotation
3. 甲基特徵現在最常見的正確位置，不是第一層，而是第二層或第三層

## 9. mixed sample 的目前位置：假說，不是定論

目前 mixed sample 這條線，最合理的敘述是：

1. 快速觀察支持：
   - `tumor < normal < mixed`
2. 初步推論：
   - tumor 可能因癌症趨同而甲基更相似
   - normal 原本就有 haplotype 差異
   - mixed 的差異更大，可能是因為 tumor 為癌組織、normal 為血液，組織來源差異超過 haplotype 與癌症趨同的影響
3. 這條線目前還不是 closeout 結論
4. 正確策略是：
   - **先把純樣本做完**
   - 再回來分析 mixed，並加入更特殊的校正與去噪方法

因此在 PPT 中，mixed sample 應放在：

- 主線後段的一頁 hypothesis

而不是：

- 前段主證據頁

## 10. 現在最合理的三層分析架構

### 第一層：caller-first

目的：
- 先放寬或重排 caller 的條件
- 不要太早把可能的 TP 全刷掉

代表：
- `GQ`
- `QUAL`
- `FILTER`
- 若未來可行，再考慮 `pileup / full` 合併 candidate

### 第二層：LongPhase + methylation-support

目的：
- 用 `LongPhase-S / LongPhase-TO` 產生 tagged BAM
- 用甲基資訊輔助篩選、排序與保留

代表：
- `Quality_Score`
- `PairwiseMedianDist`
- `agreement_positive`
- `artifact triage`

### 第三層：haplotype / SNV / 甲基共分析

目的：
- 驗證 label 是否合理
- 研究哪些位點是 subclone
- 分析最終的共狀態與共結構

代表：
- haplotype
- SNV
- methylation
- label-first / cluster-first
- annotation / QC / diagnostics

### 10.1 這三層的實際意義

這個三層架構不是抽象概念，而是目前最適合繼續研究的方式：

1. 第一層盡量避免漏掉太多 TP
2. 第二層避免帶回太多 FP
3. 第三層則負責驗證整個結果是否合理、有沒有更深層的生物學或技術結構

## 13. 製作這份 PPT 時必須遵守的口徑

### 可以講

1. `5kHz` 上某些甲基特徵確實有用

### 不可以講

3. 不可說 `PairwiseMedianDist` 是穩定全域生物學訊號
4. 不可說 mixed sample 已經完成驗證
5. 不可把 `gq>=10` 與 `qual>=10 or gq>=20` 當成同一條規則
