# 甲基候選研究框架與觀察資產盤點

## 一句結論

目前最清楚的結論不是「甲基能不能全面提升 F1」，而是三段式：

1. `HCC1395 5kHz paired` 的甲基資訊**最有用在 FP triage 與 subclone 候選整理**，不是 caller 邊界 TP rescue。
2. `HCC1395 5kHz TO` 的甲基資訊**最有用在 caller-first 之後的 soft support / ranking**，特別是 `Quality_Score`、`agreement_positive`、`cluster_plus_weak_label`。
3. 真正要把這些訊號變成下一輪可驗證策略，必須先把資料觀察層級固定：`summary table -> per-region matrix -> external plot -> samtools read truth`，而不是直接把某一個欄位升級成全域規則。

本輪新增可重跑腳本 [analyze_methylation_research_framework.py](/big8_disk/liaoyoyo2001/InterSubMod/scripts/analysis/analyze_methylation_research_framework.py)，主輸出在 [/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework)。

根據 [asset_inventory.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework/asset_inventory.tsv)：

   - `cluster_heatmap.png` / `distance_heatmap.png` 與 `significance.json` 也各有 `30K+ / 4.8K+` 份，足夠支撐大量 per-region 回查
2. `methylartist` 已有大量既有圖資：
   - 根目錄總檔案數 `141,407`
   - `SVG = 70,666`
   - 已確認存在 `HCC1395` 專屬 phased methylation 輸出
3. `modbamtools` 的 HCC1395 輸出量也夠大：
   - `HCC1395 html = 35,332`
   - `HCC1395BL html = 34,615`
   - 適合做單位點 read-level / HP / strand / cluster 檢視
4. `TO diagnostics` 已有現成代表位點與圖：
   - `tsv = 107`
   - `png = 102`
   - `md = 36`
   - 可直接作為 `TO pilot` 的 read-level deep-dive 入口

### 1.2 這些資料應該怎麼看

本輪把觀察層級整理在 [observation_layers.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework/observation_layers.tsv)：

1. `InterSubMod 舊輸出`
   - 最適合回答：某個 SNV 周邊是否真的存在局部甲基結構差異
   - 優先看：`cluster_heatmap.png`、`distance_heatmap.png`、`methylation.csv`、`cpg_sites.tsv`
2. `paired rescue_joined_features.tsv`
   - 最適合回答：caller 邊界錯誤是哪一型，甲基摘要欄位是否有機會幫助
3. `TO diagnostics`
   - 最適合回答：既有支持特徵在 read-level 長什麼樣子
4. `modbamtools`
   - 最適合回答：差異是否集中在 ALT-supporting reads、某個 HP、某個 strand、某個 cluster
5. `methylartist`
   - 最適合回答：這是局部 SNV 周邊改變，還是整段 region 都有不同甲基背景
6. `samtools`
   - 最適合回答：當圖像與 summary 不一致時，到底是哪一批 reads 在支撐這個位點

換句話說：

- `InterSubMod` 是主證據層
- `modbamtools` 是單 read 驗證層
- `methylartist` 是 locus 背景層
- `samtools` 是最後的 truth inspection

## 2. 哪一類候選、哪個 dataset、哪種 caller 邊界錯誤，甲基最有幫助

### 2.1 最有幫助的 dataset：`HCC1395 5kHz TO`

在 `TO candidate-eligible` pool 中，甲基最清楚表現為 `caller-first` 之後的 support 訊號。  
根據 [candidate_taxonomy.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework/candidate_taxonomy.tsv)：

1. `Quality_Score >= 60`
   - `556 TP / 162 FP`
   - `TP fraction = 77.44%`
   - 在 candidate-eligible `TP` pool 中覆蓋 `71.93%`
2. `agreement_positive`
   - `319 TP / 85 FP`
   - `TP fraction = 78.96%`
3. `cluster_plus_weak_label`
   - `106 TP / 23 FP`
   - `TP fraction = 82.17%`

這代表：

1. `TO` 中真正值得投資的不是全域甲基過濾，而是**caller-first 後的 soft support**
2. 最有價值的不是單一數值，而是：
   - `Quality_Score`
   - `agreement_positive`
   - `cluster_plus_weak_label`
3. 這些群組很適合拿來做下一輪 `TO F1` 假設驗證與代表位點清單

對應代表位點已整理在：

- [to_pilot_manifest.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework/to_pilot_manifest.tsv)
- [to_diagnostic_manifest.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework/to_diagnostic_manifest.tsv)

### 2.2 最典型的 caller 邊界錯誤：`HCC1395 5kHz paired` 的 sparse / low-quality boundary

`paired` 的主問題不是甲基方向錯，而是**大多數 caller 邊界位點根本沒有足夠甲基摘要可用**。

根據 [candidate_taxonomy.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework/candidate_taxonomy.tsv)：

1. `paired_sparse_no_methylation`
   - `13,113` rows
   - 其中 `941 TP / 12,172 FP`
   - 佔 `caller_lost_tp` 的 `89.45%`
   - 佔 `caller_removed_fp` 的 `93.82%`

這表示：

1. `paired caller_lost_tp / caller_removed_fp` 的大多數位點，甲基不是「效果不好」，而是**沒有可用摘要**
2. 這批位點首先該看的是 `GQ / QUAL / filter / AF / AD`，不是期待甲基直接 rescue
3. 若之後要研究 paired rescue，前提是要先補 `candidate-specific region export` 與圖像層輸出

### 2.3 paired 裡甲基有局部訊號，但目前不適合作主規則

在 `paired` 少量有甲基摘要的 caller 邊界位點中：

1. `Quality_Score >= 60 + PairwiseMedianDist >= 0.20`
   - `42 TP / 182 FP`
   - 整體 `TP fraction = 18.75%`
   - 但若看各自母體命中率：
     - `caller_lost_tp` 命中率 `3.99%`
     - `caller_removed_fp` 命中率 `1.40%`

這代表它**有 TP enrichment，但仍不安全**。  
所以它的正確角色是：

- 人工檢查優先順序
- ranking
- paired 邊界位點的 support 註解

而不是：

- 直接拿來替代 `GQ`
- 直接拿來做 hard rescue

代表位點清單在 [paired_boundary_manifest.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework/paired_boundary_manifest.tsv)。

## 3. 甲基有用 / 甲基沒用 / 甲基目前最適合做什麼

### 3.1 甲基有用

1. `HCC1395 5kHz TO`
   - 在 `candidate-eligible` 邊界位點中當 soft support 很有用
   - 代表訊號：`Quality_Score`、`agreement_positive`、`cluster_plus_weak_label`
2. `HCC1395 5kHz paired` 的舊 global output
   - 對 `FP triage` 有用
   - 最強訊號是 `SuggestFilter=True`
     - `233 FP / 346 total`
     - `FP fraction = 67.34%`
   - `Noise + allele-dominant + 高 AlleleDelta` 也偏向 `FP triage`
     - `102 FP / 180 total`
     - `FP fraction = 56.67%`

這些結果整理在 [paired_old_output_signal_summary.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework/paired_old_output_signal_summary.tsv)。

### 3.2 甲基沒用

1. `HCC1395 5kHz paired` 的 caller 邊界 TP rescue
   - 主要原因不是甲基方向相反，而是多數位點沒有可用甲基摘要
2. paired 邊界上即使看到 `Quality_Score` / `Pairwise` 正向訊號
   - 目前也只到「局部有 enrichment」
   - 還不夠安全變成 hard rule

所以 paired 目前不能講「甲基 rescue 失敗」，更準確的說法是：

- paired caller 邊界的主要瓶頸是**摘要覆蓋不足與證據層不完整**

### 3.3 甲基目前最適合做什麼

目前最合理的角色分工是：

1. `paired`
   - `FP triage`
   - `suspect strong` / `artifact suspect` 分解
   - `subclone candidate prioritization`
2. `TO`
   - `caller-first` 後的 `soft support / ranking`
   - 代表位點優先清單
   - read-level diagnostics 入口
3. `跨資料共通`
   - 不直接替代 caller
   - 先當 annotation / triage / prioritization，再決定哪些訊號值得進下一輪 rule sweep

## 4. 哪些 SNV 附近甲基最值得先看，哪些可作 subclone 種子

### 4.1 paired 舊輸出最值得先看的 FP / artifact 群

目前最值得先 deep-dive 的 paired suspect group：

1. `SuggestFilter=True`
2. `Noise + allele-dominant + 高 AlleleDelta`
3. `Strong + allele-dominant + 高 HeuristicScore`

其中第一組最乾淨，第三組則更像「需要拆成 suspect strong 與真正 strong」的候選。

可直接回查的 paired representative manifest 在：

- [paired_representative_manifest.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_methylation_research_framework/paired_representative_manifest.tsv)

### 4.2 subclone 種子

最乾淨的 subclone 種子是：

1. `VerificationClass = Subclone`
2. `Significant = True`

在舊 paired 輸出中這群是：

- `22 TP / 0 FP`

這是本輪最明確可以承接到「多位點整理 subclone 線索」的候選群。  
也就是說，如果下一輪要回答「是否能分析與繪製 subclone 資訊」，最好的起點不是全域所有 Strong，而是這批 `Subclone + Significant` loci。

3. `TO` 的強訊號目前仍是 `caller-first` 後的 support，不代表已可直接變成跨樣本 hard rule。
