# GQ 救回 TP 與 FP 差異機制分析

## 一句結論

`GQ` 之所以能救回不少 `TP` 又不至於放回太多 `FP`，核心不是「單獨靠一個分數就能完美分辨 TP/FP」，而是**兩段式機制**：

1. caller 先用 `FILTER / PON / verdict / candidate_eligible` 把大部分明顯噪音排掉；
2. `GQ` 再在這個已大幅收斂的候選母體裡，優先挑出較像真 somatic 的位點。

在 paired 資料集裡，第二段的 `GQ` 本身確實還帶有明顯的 caller-level 區辨力；在 TO 資料集裡，低 FP 更大的原因是 **eligible FP pool 本來就已經極小**，`GQ` 主要負責在這個小母體內做排序，而不是單獨扛下 TP/FP 分離。

## 背景與定義

根據 [Knowledge/03_file_formats/vcf_clairs_to.md](/big8_disk/liaoyoyo2001/knowledge/03_file_formats/vcf_clairs_to.md)，`GQ` 是 `Genotype Quality`，也就是 caller 對最終 genotype 判定的信心分數；文件中把 `GQ >= 20` 列為建議的高信心閾值。  
同一份規格也明確指出：

- `PASS` 代表通過所有 caller 過濾。
- `NonSomatic` 主要反映 PON 或群體資料庫命中。
- `LowQual`、`VariantCluster`、`NoAncestry`、`MultiHap` 等旗標本身都可能帶有 error / 結構性複雜度訊號。

因此這一題不能只問「高 GQ 是不是 TP」，而要分成：

1. 高 `GQ` 是在什麼母體裡被使用？
2. 被 `GQ` 救回的 `TP` 與一起被放回的 `FP`，在 caller-level、甲基、LOH/CNV proxy 上有沒有穩定差異？

## 主要結果

### 1. 為什麼 TO 不能直接全域放寬 GQ

這一點是本題最重要的前提。

#### 1.1 candidate-eligible 母體極小

| Dataset | downstream status | 原始母體 | candidate-eligible | 比例 |
| --- | --- | ---: | ---: | ---: |
| `HCC1395 5kHz TO` | `caller_lost_tp` | `2108` | `773` | `36.67%` |
| `HCC1395 5kHz TO` | `caller_removed_fp` | `2720008` | `298` | `0.011%` |
| `HCC1395_DORADO TO` | `caller_lost_tp` | `1721` | `247` | `14.35%` |
| `HCC1395_DORADO TO` | `caller_removed_fp` | `2713328` | `94` | `0.0035%` |

解讀：

1. `TO` 下真正能被討論的 `FP rescue` 候選不到萬分之一。
2. 因此 `gq>=10` 看起來乾淨，不是因為它能從兩百多萬個 `FP` 裡直接挑出真 somatic，而是因為 caller 先把幾乎全部的 `FP` 排除掉了。

#### 1.2 被排除的 FP 幾乎都是 `NonSomatic`

`caller_removed_fp` 且 `candidate_eligible=False` 的主要原因：

| Dataset | 排除 FP 數 | `NonSomatic` | `NonSomatic;low_dp` | `VariantCluster` |
| --- | ---: | ---: | ---: | ---: |
| `HCC1395 5kHz TO` | `2719710` | `2688427 (98.85%)` | `25000 (0.92%)` | `1969 (0.07%)` |
| `HCC1395_DORADO TO` | `2713234` | `2691589 (99.20%)` | `19189 (0.71%)` | `1428 (0.05%)` |

這代表 `PON / NonSomatic` 過濾才是 TO precision 的第一道主防線。  
`GQ` 是在這道防線後才有意義。

### 2. 四象限的實際 rescue 效果

| Dataset | Primary gate | TP rescued | FP reintroduced | delta F1 | 補充 |
| --- | --- | ---: | ---: | ---: | --- |
| `HCC1395 5kHz TO` | `gq>=10` | `499` | `119` | `+0.006940` | 增益最大，但前提是 FP 母體先被 caller 壓到 `298` |
| `HCC1395 5kHz paired` | `gq>=15` | `106` | `75` | `+0.000833` | `gq>=20` 更乾淨，`59/8`，`+0.000880` |
| `HCC1395_DORADO paired` | `gq>=15` | `97` | `88` | `+0.000478` | `gq>=20` 更乾淨，`51/7`，`+0.000725` |
| `HCC1395_DORADO TO` | `gq>=10` | `40` | `11` | `+0.000540` | 增益小但方向一致 |

高層解讀：

1. paired 下 `GQ` 的作用比較像真正的 caller-side rescue。
2. TO 下 `GQ` 也有效，但不能誤讀成「ClairS-TO 應全域放寬 GQ」。
3. paired 一旦拉到 `gq>=20`，`FP/TP` 比明顯變乾淨，說明 paired 的第二層排序更像典型 caller confidence。

### 3. 被救回的 TP 與 FP 差在哪裡

## 3.1 HCC1395 5kHz TO

`gq>=10` 下：

| 特徵中位數 | rescued TP | rescued FP |
| --- | ---: | ---: |
| `GQ` | `17` | `16` |
| `QUAL` | `17.37` | `16.62` |
| `DP` | `84` | `70` |
| `AF` | `0.230` | `0.260` |
| `AD_ref` | `59` | `38` |
| `AD_alt` | `21` | `22` |
| `PairwiseMedianDist` | `0.2317` | `0.2142` |
| `AlleleDelta` | `0.0168` | `0.0137` |

解讀：

1. `GQ/QUAL` 對 TP 有輕度優勢，但不是巨幅分離。
2. rescued `TP` 的 `DP` 較高，而且 `AF` 反而比 rescued `FP` 略低，代表 `高 AF` 不是 TO 裡 TP 的保證。
3. `PairwiseMedianDist` 在 `5kHz TO` 的 TP 略高，和先前 `5kHz TO` 的方向一致。
4. 但整體差距沒有大到足以說「GQ 自己就把 TP/FP 完全分開」；真正讓 `FP` 沒有爆掉的主因仍是上游 candidate pool 已極度收斂。

#### error / label 線索

- rescued `TP/FP` 幾乎都已經是 `PASS`：
  - TP `97.39%`
  - FP `98.32%`
- `pon_hit` 在 rescued `TP/FP` 都是 `0`
- `VerificationClass` 上：
  - rescued `FP` 以 `Noise` 為主（`47.1%`）
  - rescued `TP` 的 `Weak/Strong` 比例較高

解讀：  
在 `5kHz TO`，一旦進入 eligible pool，`filter` 本身已經不是主分離器；較有解釋力的是 caller confidence 加上後段的 methylation / class annotation。

## 3.2 HCC1395 5kHz paired

`gq>=15` 下：

| 特徵中位數 | rescued TP | rescued FP |
| --- | ---: | ---: |
| `GQ` | `20` | `16` |
| `QUAL` | `18.47` | `0.00` |
| `DP` | `56` | `88` |
| `AF` | `0.5436` | `0.2063` |
| `AD_ref` | `0` | `63` |
| `AD_alt` | `30` | `16` |
| `alt_fraction` | `1.0` | `0.2727` |

解讀：

1. 這是四個 dataset 裡 caller-level 分離最清楚的一組。
2. rescued `TP` 常帶有：
   - 更高 `GQ`
   - 更高 `QUAL`
   - 更高 `AF`
   - 更強的 ALT 支持
3. rescued `FP` 常帶有大量 ref reads，像是 caller 邊界雜訊，而不是穩定的 somatic alt pattern。
4. 這也解釋了為什麼 paired 場景把門檻提高到 `gq>=20` 會更乾淨。

#### error 線索

- rescued `TP`：`PASS=69.8%`
- rescued `FP`：`LowQual=62.7%`

這說明 paired 5kHz 中，`LowQual` 仍保留了很強的 error-like 訊號。

## 3.3 HCC1395_DORADO paired

`gq>=15` 下：

| 特徵中位數 | rescued TP | rescued FP |
| --- | ---: | ---: |
| `GQ` | `20` | `16` |
| `QUAL` | `18.25` | `16.31` |
| `DP` | `65` | `66` |
| `AF` | `0.5981` | `0.7261` |
| `AD_alt` | `38` | `39` |
| `PairwiseMedianDist` | `0.1216` | `0.0961` |

解讀：

1. `GQ` 與 `QUAL` 仍偏向 TP，但不像 `5kHz paired` 那麼劇烈。
2. 這組最值得注意的是：rescued `FP` 常呈現極高 `AF`，甚至接近 `1.0`，不代表它們就比較可信。
3. 代表性 rescued FP 例子可見：
   - [chr2:107030503:G:A](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260314_gq_rescue_feature_audit/representative_rescued_examples.tsv)
   - [chr3:144834736:G:C](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260314_gq_rescue_feature_audit/representative_rescued_examples.tsv)
4. 這代表在 `DORADO paired`，`高 AF` 並不是 TP 專屬訊號；caller confidence 仍需要搭配 error context。

#### methylation / LOH proxy

- `Potential_LOH`
  - rescued TP：`36.1%`
  - rescued FP：`40.9%`
- `PairwiseMedianDist`
  - rescued TP 較高
  - rescued FP 較低

這支持先前的判讀：`DORADO paired` 的 pairwise 方向和 `5kHz TO` 不同，而且 `Potential_LOH` / `H`-flag / 高 `AF` 這類 proxy 背景在兩邊都常見。這裡的 proxy 只代表 haplotype-imbalance 或 LOH/CNV 線索，**不等於正式 LOH call**，因此不能拿來單獨當 rescue 主規則。

## 3.4 HCC1395_DORADO TO

`gq>=10` 下：

| 特徵中位數 | rescued TP | rescued FP |
| --- | ---: | ---: |
| `GQ` | `19` | `19` |
| `QUAL` | `0` | `0` |
| `DP` | `85.5` | `88` |
| `AF` | `0.3241` | `0.4432` |

| `AlleleDelta` | `0.0104` | `0.0136` |

這組是最重要的反例。

1. 一旦進入 `gq>=10` gate，`GQ` 本身幾乎不再分開 TP/FP。
2. rescued `FP` 反而更常是：

   - 高 `AD_alt`
   - 極端 ALT 主導
3. rescued `TP` 反而更常落在中等 `AF`、較低 pairwise、較高 `Potential_LOH` window 背景。

結論：  
`DORADO TO` 裡，低 FP 主要不是因為 `GQ` 進 gate 後還能精細分辨 TP/FP，而是因為 eligible FP pool 只有 `94` 筆，而且裡面真正被 `gq>=10` 放回的只剩 `11` 筆。

### 4. LOH / CNV 是否是主要原因

目前證據不支持把 `LOH/CNV` 當成 GQ rescue 成敗的主分離器。

#### 支持這個判斷的理由

1. `Potential_LOH` 在 `5kHz TO` 兩邊都高：
   - TP `59.3%`
   - FP `61.3%`
2. `DORADO paired` 也類似：
   - TP `36.1%`
   - FP `40.9%`
3. 只有 `DORADO TO` 顯示 TP 更常落在 `Potential_LOH`-positive / LOH-CNV proxy 背景：
   - TP `72.5%`
   - FP `45.5%`

因此最保守的結論是：

- `LOH/CNV proxy` 可以改變候選的背景分布；
- 但它目前更像 dataset-specific 的上下文，而不是跨樣本穩定的主分離器。

## 回答原始問題

### 為何 GQ 可以救回許多 TP 而不會產生太多 FP？

答案要分兩半：

1. **在 TO**
   - 主要原因是 caller 先把 `FP` 母體縮到幾乎只剩幾百筆 candidate。
   - `GQ` 再從這個小母體裡挑出一部分位點，所以看起來很乾淨。
   - 若直接對全域 call set 放寬 `GQ`，會把大量 `NonSomatic` 噪音一起放回來。

2. **在 paired**
   - `GQ` 本身真的還保留了 caller confidence 的排序能力。
   - rescued `TP` 通常有更高 `QUAL`、更合理的 ref/alt 支持結構。
   - rescued `FP` 則更像低品質或邊界雜訊。

### 被救回來的 TP 與 FP 是否有特徵差異？

有，但型態不完全一樣：

1. `5kHz paired`
   - 差異最清楚
   - TP 的 `GQ/QUAL/AF/AD_alt` 都更像穩定 somatic
2. `DORADO paired`
   - TP 仍較高 `GQ/QUAL`
   - FP 常呈現極端高 AF，不可把高 AF 誤當 TP
3. `5kHz TO`
   - `GQ/QUAL/DP` 對 TP 有輕度優勢
   - 但真正防止 FP 爆量的關鍵還是 candidate pool
4. `DORADO TO`
   - `GQ` 進 gate 後已不是主要分離器
   - TP/FP 差異改由 `AF / AD_alt / Pairwise / Potential_LOH` 背景補充說明

### 附近甲基差異、error、CNV/LOH 有沒有解釋力？

- **甲基差異**：有輔助解釋力，但不是跨樣本穩定主規則。
- **error flags**：paired 的 `LowQual` 仍有很強訊號；TO 一旦進 candidate pool，PON/NonSomatic 已大多清乾淨。
- **CNV/LOH**：目前只有 dataset-specific 背景效果，不能單獨當 GQ rescue 主因。

## 最終結論

最穩定的高層解讀是：

1. `GQ` 是有效的 rescue 工具，但**只在 caller 已經收斂好的 candidate pool 裡成立**。
2. `GQ` 對 paired 的直接區辨力較強，對 TO 則更像第二段排序器。
3. `LOH/CNV proxy` 與甲基特徵可以幫助解釋 rescued TP/FP 的差異，但目前都不足以取代 `caller-first`。
4. 因此現階段最合理的流程分工仍是：
   - 第一層：`caller-first`
   - 第二層：`GQ rescue`
   - 第三層：`methylation-support / annotation / artifact triage`

## 限制

1. `HCC1395 5kHz paired` 缺本輪完整 significance summary，因此 paired 5kHz 的甲基/LOH 解讀較弱。
2. `DORADO paired` 的 significance summary 只覆蓋可分析 subset，不是全母體。
3. TO 的 read-level 例子來自既有 representative diagnostics，不是專門為本輪 GQ gate 重跑。
