判斷：**可直接支援 AI Agent 操作與研究，但建議進行一輪「去舊語彙 + 入口收斂」整理，以降低誤判路徑與流程分岔。**

## 3. 對 AI Agent 的實際影響

1. **路徑分岔風險**：舊語彙與新語彙並存，Agent 可能採用非標準舊路徑寫入/引用。
2. **入口收斂已改善但仍可再精簡**：`CURRENT_FOCUS.md` 已改為現行分層，惟 scripts 端仍有歷史路徑語彙。
3. **腳本硬編碼歷史路徑**：部分 analysis/pipeline 腳本仍預設 `output/bip8_disk_output`，對跨專案重用與 Agent 自動化不友善。
4. **空目錄噪音**：增加 Agent 在「該放哪裡」的選擇成本與檢索雜訊。

## 4. 主要成因

1. 2026-02-28 重整後，活躍文件已收斂，但歷史文本與部分腳本尚未完全同步語彙。
2. 研究報告需保留歷史可追溯性，導致舊路徑大量存在於敘述內容。
3. 缺少「AI 專用單一入口手冊 + 一鍵健康檢查」的標準協議（本次已補上）。

## 5. 改善方案（建議順序）

### A. 立即可做（低風險）

1. 將 Agent 入口固定為：
   - `docs/references/manual/20260301_AI_Agent_快速操作手冊_01.md`
   - `scripts/analysis/check_ai_agent_readiness.sh`
2. 在新報告與新計畫禁止使用舊語彙：`experiments/outputs`、`docs/analysis/`、`output/bip8_disk_output`。
3. 每次重大整理後先跑 readiness check，再開始 Agent 批次任務。

### B. 短期整理（中風險）

1. 更新 `docs/CURRENT_FOCUS.md` 內容，使其與現行分層完全一致。
2. 將活躍腳本（`scripts/pipeline/config.sh`、`scripts/analysis/*`）改為：
   - 優先讀 `OUTPUT_ROOT` 環境變數
   - fallback 到 `output/`（symlink 入口）
3. 清理非必要空目錄，保留必要骨架即可。

### C. 中期治理（需你拍板）

1. 是否把 `check_ai_agent_readiness.sh` 納入 pre-run gate（例如 pipeline 啟動前必跑）？
2. 是否對 `docs/plans` 與 `docs/reports` 的活躍文件做一輪舊語彙替換（僅限非 archive/deep）？
3. 是否把 `scripts/analysis/*` 的硬編碼資料根路徑統一抽成單一設定檔？

## 6. 需要你決策

1. **Gate 強度**：readiness check 是建議執行，還是強制執行？
2. **清理範圍**：只修「活躍文件」還是包含 `ai_sessions` 歷史紀錄？
3. **腳本改造批次**：先改 pipeline（A），或先改 analysis 腳本（B），或兩者同時（C）。
