# InterSubMod 研究主線週報（2026-03-05 至 2026-03-10）

## 重點結論

本週的研究主線已明確從「混樣 purity / subsample 探索」重排為「純樣本優先、先做 paired，再做 tumor-only」。最重要的正向結果有三個：第一，`HCC1395 5kHz paired` 在新版正式 rerun 中，`InterSubMod` 已從 `LongPhase-S F1=0.8522` 提升到 `0.8532`，代表甲基與 phase 資訊在最 noisy 的主樣本上有實際增益；第二，`HCC1395 5kHz tumor-only` 的 candidate-specific 驗證已正式證明甲基資訊可以救回一批 borderline TP，例如 `gq>=10 + PairwiseMedianDist>=0.20` 可救回 `300 TP / 68 FP`、`F1 +0.004219`，而 `agreement_positive` 可達 `148 TP / 25 FP`，比單純 `Strong/Subclone` 更乾淨；第三，跨樣本驗證目前只支持「caller-first 穩定成立」，還不支持「methylation-support 穩定跨樣本成立」，因為相同規則在 `HCC1395_DORADO paired` 全部未能提升 F1。換句話說，本週最穩的研究結論是：`caller-first` 應作為第一層，`methylation-support` 應作為第二層，`artifact-veto` 應維持獨立的 FP triage 支線；甲基資訊不是無效，但現階段也還不是全域主規則。

## 2. 背景知識整理

### 2.1 InterSubMod 在這週的核心問題

InterSubMod 是一個把 read-level 甲基化（methylation）、phase（相位）與 somatic caller 結果整合起來的分析系統。這週的核心不是單純問「有沒有顯著甲基訊號」，而是進一步問：在 somatic calling 的邊緣位點中，甲基資訊能不能幫助判斷哪些是更可信的 TP（真陽性）、哪些是更像 artifact 的 FP（假陽性），而且這種效果是否能在不同資料型態下穩定成立。

### 2.2 本週涉及的三種研究場景

| 場景 | 中文解釋 | 在本週的角色 |
|---|---|---|
| `paired tumor-normal` | 配對腫瘤/正常樣本分析 | 目前最穩定的主驗證場景 |
| `tumor-only` | 只有腫瘤樣本的分析 | 問題更難，適合驗證 rescue / triage 是否真有價值 |
| `mixed purity / subsample` | tumor 與 normal 混和的低 purity 模擬 | 本週已降為補充研究，不再是主證據 |

### 2.3 本週反覆出現的三種方法分工

| 名稱 | 中文詞義 | 本週定義 |
|---|---|---|
| `caller-first` | 先由 caller 決定候選池 | 先用 `GQ / QUAL / candidate_eligible` 定義可救回的邊緣集合 |
| `methylation-support` | 甲基輔助支持 | 在 caller gate 之後，用 `PairwiseMedianDist`、`agreement_positive` 等做第二層支持 |
| `artifact-veto` | artifact 否決規則 | 用 `low VAF + high AlleleDelta + low CramersV`、`combined_artifact_veto` 做 FP triage，不直接拿來救 TP |

### 2.4 `label-first` 與 `cluster-first`

| 名稱 | 中文詞義 | 在本週的用途 |
|---|---|---|
| `label-first` | 依標籤驗證結構 | 看 HP / Allele 標籤是否真的對應到較強的甲基結構 |
| `cluster-first` | 依分群驗證標籤 | 看甲基聚類結果是否真的能被標籤解釋 |
| `agreement_positive` | 正向一致訊號 | `label_upgrade + consistent_strong + consistent_subclone`，代表 label 與 cluster 至少呈現合理正向一致或升級 |

### 2.5 `candidate-specific rescue`

本週的重要方法學修正，是不再拿 baseline kept-set 的 InterSubMod summary 硬去 join `lost_tp / removed_fp`，而是把 `caller_lost_tp` 與 `caller_removed_fp` 真正匯出成小型 VCF，再單獨跑 InterSubMod。這個修正讓 `HCC1395 5kHz TO` 的甲基 rescue 從原本錯誤的 `0/0 overlap` 變成正式可解讀的 candidate-specific 結果。

| 規則 | 類型 | TP rescued | FP reintroduced | F1 delta |
|---|---|---:|---:|---:|
| `qual>=10 or gq>=20` | caller-only | 491 | 118 | +0.006824 |

## 4. 主題式整合分析

### 4.1 這週真正完成的研究重排

這週之前，mixed purity / subsample 仍占了不少注意力；這週之後，主線已經非常清楚：

1. `HCC1395 5kHz paired` 是第一主實驗
2. `HCC1395_DORADO paired` 是第一交叉驗證
3. `HCC1395 5kHz TO` 是第一個更困難但可量測的 rescue 戰場
4. mixed purity / subsample 暫時後移，不作主證據

這個重排很重要，因為它把「是否能找到真有用的甲基特徵」從容易被組織差異混淆的題目，拉回到 paired 與 tumor-only 的實際決策問題。

### 4.2 `low VAF + high AlleleDelta` 的定位

本週持續確認這個特徵的重要性，但同時也把它的邊界講清楚：

| 問題 | 本週結論 |
|---|---|
| 它能不能當全域規則？ | 不能，目前只在 `HCC1395 5kHz` 明顯有效 |
| 它的用途是什麼？ | 更像 `artifact triage` 或 `ArtifactSuspect` 註記 |
| 它適不適合直接拿來救 TP？ | 不適合，因為它對 FP triage 有用，但用於 TP rescue 容易多丟 TP |

### 4.3 `PairwiseMedianDist`、`agreement_positive`、`hp_assign_rate`、`Quality_Score` 的意義

| 特徵 | 中文意義 | 在 `5kHz TO` 的方向 | 在 `DORADO paired` 的方向 | 目前定位 |
|---|---|---|---|---|
| `PairwiseMedianDist>=0.20` | read-level 甲基距離較高 | 正向 support，可救 `300 TP / 68 FP` | 負向，`10 TP / 36 FP` | 不能升級成跨樣本規則 |
| `agreement_positive` | label-first 與 cluster-first 呈現正向一致或升級 | 正向 support，`148 TP / 25 FP` | 負向，`36 TP / 72 FP` | 可作高品質 support 候選，但不泛化 |
| `hp_assign_rate>=0.99` | region 內 read 的 HP 可用率很高 | 不是主要訊號 | 在 DORADO paired 有微弱正增量 | 值得保留為 DORADO 類 support 候選 |
| `Quality_Score>=60` | 多層驗證後的整體信心分數 | 可用 support，但未超過 caller gate | 與 `hp_assign_rate` 組合後有小幅正增量 | 可作排序特徵，不宜單獨升級為正式規則 |

### 4.4 本週最合理的分工

根據這週所有主線證據，最合理的工作分工是：

1. **第一層：caller-first**
   - 先用 `GQ / QUAL / candidate_eligible` 定義可救回的邊緣集合
2. **第二層：methylation-support**
   - `PairwiseMedianDist>=0.20`
   - `agreement_positive`
   - 視樣本狀況補 `hp_assign_rate`、`Quality_Score`
3. **獨立旁路：artifact triage**
   - `low VAF + high AlleleDelta + low CramersV`
   - `combined_artifact_veto`

目前不應做的事也很清楚：

1. 不要把 `artifact-veto` 直接拿去做 TP rescue 主規則
2. 不要把 `Strong/Subclone` 直接當 hard keep
3. 不要把 `5kHz TO` 的甲基 support 直接升級成跨樣本規則

## 7. 目前尚缺與待補齊事項

### 7.1 研究內容仍缺

1. `HCC1395_DORADO TO candidate-specific InterSubMod`
   - 這是把結論從「5kHz TO 成立」升級成「跨平台 TO 也成立」的最關鍵一步
2. 更多 top TP / FP diagnostics
   - 尤其是 `agreement_positive` 與 `PairwiseMedianDist>=0.20` 真正救到的 TP/FP 子集
3. `pileup` 與 `full model` 的 TO 對照
   - 本週大多數 TO 結論都只對 `ClairS-TO pileup` 直接成立

### 7.2 方法學仍缺

1. `label-first / cluster-first` 的顯著性設計雖已可用，但仍需更多 sample / mode 驗證
2. `hp_assign_rate`、`Quality_Score`、`GlobalP` 是否應該升級成正式 support feature，還需要更多測試
3. `artifact-veto` 與 `TP rescue` 的邏輯邊界，雖然本週已講清楚，但尚未正式寫進主流程 annotation 層

### 7.3 文件與自動化仍缺

1. 研究文件 agent / skills 還沒有真實 eval prompts
2. prompt refinement 還沒有 changelog
3. 若未來要給其他人穩定使用，仍需要一個「週報輸出模板實例」作為參考

## 8. 下一步建議

1. 先做 `HCC1395_DORADO TO candidate-specific InterSubMod`，驗證 TO 下甲基 support 是否能跨平台成立。
2. 對 `5kHz TO` 中 `agreement_positive` 與 `PairwiseMedianDist>=0.20` 救回的 top TP / FP 做 diagnostics，確認這些 support 訊號究竟在 read-level 呈現哪些模式。
3. 把 `caller-first / methylation-support / artifact-triage` 寫成 annotation 層規則，而不是直接改成 hard filter / hard keep。
4. 對 `pileup` 與 `full model` 的 TO 輸出做最小對照，避免後續把不同 caller 路線混成同一結論。
5. 用這週剛落地的 agent / skills 產生下一份主題式證據鏈報告，驗證文件自動化是否足夠穩定。
