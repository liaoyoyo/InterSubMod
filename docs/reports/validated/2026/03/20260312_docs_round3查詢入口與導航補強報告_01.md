# docs round 3 查詢入口與導航補強報告

## 重點結論

round 1 與 round 2 主要解的是「類別混雜」與「邊界不清」，但到那個階段仍有一個明顯缺口：使用者雖然知道 `docs/` 大類目錄怎麼分，卻還是需要先知道精確檔名，才能找到 `research/` 與 `references/manual/` 內的真正入口。  
本輪不再搬檔，而是補齊 `research/`、`references/`、`references/manual/` 與 `methylation_methodology/` 的上層 `README`。結果是 `docs/` 現在已具備從總入口到主題入口、再到單一文檔的三層導航；結構驗證仍維持 `Name issues = 0`、`Metadata issues = 0`，剩餘 `Link issues = 11` 也仍只存在於 `docs/archive/deep/` 歷史快照，不是本輪新引入問題。

## 為什麼要做 round 3

### round 2 後仍存在的問題

1. `docs/research/` 沒有總入口
   - 知道 topic 名稱的人可直接進去
   - 不知道 topic 名稱的人仍需靠目錄樹或搜尋
2. `docs/references/` 沒有總入口
   - `manual/` 與 `external/` 已拆開
   - 但沒有更上層說明兩者差異
3. `docs/references/manual/` 缺 README
   - 手冊很多，但沒有依用途分類
4. `methylation_methodology/` 沒有 topic README
   - 目前主方法學只有一份藍圖文檔
   - 但缺少「為什麼這份是入口」的說明

### round 3 的目標

1. 讓 `docs/README.md` 能導到主題級入口，而不只是一串重要文件
2. 讓 `research/` 與 `references/` 都有清楚的上層邊界
3. 讓新使用者不需要先知道精確檔名，也能找到方法學主線與內部手冊

## 新增入口的設計邏輯

### 1. `docs/research/README.md`

這一層解決的是「研究主題如何總覽」。

固定寫清楚：

1. `research/` 的定位
2. 與 `plans/`、`experiments/`、`reports/` 的邊界
3. 目前有哪些 topic
4. 每個 topic 的入口檔

目前 topic 僅有兩個：

1. `methylation_methodology`
2. `methylation_f1_optimization`

### 2. `docs/research/methylation_methodology/README.md`

這一層解決的是「目前主方法學文檔只有一份，為什麼它是入口」。

固定寫清楚：

1. 主題定位
2. 主文檔
3. 與 plans / experiments / reports 的關係
4. 建議閱讀順序

### 3. `docs/references/README.md`

這一層解決的是「references 內部其實有兩種完全不同的資料」。

固定拆成：

1. `manual/`
   - 專案內部手冊、規格、設定檔
2. `external/`
   - 外部文獻、第三方指南、外部方法

### 4. `docs/references/manual/README.md`

這一層解決的是「manual 文件很多，但不知道先看哪一份」。

固定拆成：

1. 研究啟動
2. 文件 / Agent / Skills
3. PPT 與個人風格
4. `assets/` 的邊界與現有 JSON 設定檔
