## 2. 發現的瑕疵與問題（6 項）

### 瑕疵 1：5kHz TO 的 delta F1 在不同 context 中有微妙差異，未加說明

- Section 3.3 rescue 表：`qual>=10 or gq>=20` 給出 `+0.006824`
- Section 3.4 annotation 表：`caller_primary_only (gq>=10)` 給出 `+0.006754`
- GQ 系統驗證報告：`gq>=10` 給出 `+0.006943`

這三個數字看似描述同一件事（5kHz TO 的最佳 rescue），但其實是三種不同的評估框架：
1. `qual>=10 or gq>=20`（複合規則）vs `gq>=10`（單一規則）— 不同規則
2. candidate-specific pool 的 TP/FP 定義在 rescue 評估 vs annotation 評估中可能略有不同
3. GQ 驗證用的是整個 candidate pool，annotation layer 用的是 annotated subset

**影響**：讀者可能誤以為同一個 `gq>=10` 的效果在不同 section 不一致。建議在報告中加一段說明「不同評估框架的 delta F1 不直接可比」。

**嚴重度**：中（不影響結論方向，但影響可重複解讀性）

### 瑕疵 2：Section 3.3 表格缺少 DORADO TO 資料列

Section 3.3 的 candidate-specific rescue 表只列了 `5kHz TO` 和 `DORADO paired`，但 `DORADO TO` 的驗證報告已完成（20260311_HCC1395_DORADO_TO_candidate_specific甲基rescue驗證_01.md），其中有完整的 rescue 數據：

- `gq>=10`: 40 TP / 11 FP / +0.000540
- `gq>=10 + Quality>=60`: delta F1 vs gate = -0.000064
- `gq>=10 + Pairwise<=0.20`: delta F1 vs gate = -0.000142

這些數據在 Section 4.1 被間接提到（「DORADO TO: gq>=10, 有明顯甲基 support」），但沒有出現在 Section 3.3 的主表格中。

**影響**：讀者無法在同一張表看到完整的 2×2（5kHz/DORADO × paired/TO）rescue 矩陣。

**嚴重度**：中（資料完整性缺漏，不影響結論）

### 瑕疵 3：paired candidate-specific coverage 極低但未量化呈現

Section 7 提到「paired 的 candidate-specific methylation coverage ceiling 仍偏低」，但沒有給出具體數字。實際資料：

- 5kHz paired: lost_tp coverage = **11.41%**，removed_fp coverage = **10.20%**
- DORADO paired: lost_tp coverage = **8.29%**，removed_fp coverage = **19.66%**

相比之下：
- 5kHz TO: **87.32%** / **71.48%**
- DORADO TO: **100%** / **100%**

這個 coverage 差異（8~19% vs 87~100%）對結論的影響極大：**paired 甲基 rescue 無效的結論可能部分源自覆蓋率不足，而非甲基訊號本身無效**。週報的「paired 甲基無效不能直接解釋成 paired 一定沒有甲基價值」的 caveat 方向正確，但沒有量化支撐。

**影響**：讀者可能過度推論「paired 完全沒有甲基價值」。

**嚴重度**：高（影響結論的可信度邊界）

### 瑕疵 4：5kHz paired 的 F1 增益幅度描述可能誤導

Section 重點結論第 1 點：「InterSubMod F1=0.8532 已高於 LongPhase-S F1=0.8522，代表在最 noisy 的主樣本上，甲基與 phase 資訊整合確實能有實際增益」

這個 F1 差異是 +0.0010（萬分之十）。在 ~40K truth set 上：
- InterSubMod 比 LongPhase-S 少 2 個 TP（29752 vs 29754）
- InterSubMod 比 LongPhase-S 少 83 個 FP（544 vs 627）

因此增益主要來自 FP 削減而非 TP 救回。用「甲基與 phase 資訊整合確實能有實際增益」這個措辭可能暗示增益比實際更大。建議加上實際的 TP/FP 變化來定性這個增益的來源和規模。

**嚴重度**：低（方向正確，但缺乏幅度脈絡）

### 瑕疵 5：Section 4.2 的 PairwiseMedianDist 方向矛盾未充分強調

表格寫「5kHz TO 偏高 pairwise，DORADO TO 偏低 pairwise」，然後在「不該怎麼用」欄寫「不可升級成跨樣本全域規則」。

但報告沒有深入探討這個方向相反的含義：如果同一個特徵在不同 dataset 上的最佳方向相反，這代表的不只是「不能升級成全域規則」，而是 **PairwiseMedianDist 本身可能不是一個穩定的生物學訊號，而更像是 dataset-specific noise 的代理指標**。這個更深層的方法論問題值得討論。

**嚴重度**：中（影響方法學判讀深度）

### 瑕疵 6：Section 2 目標表的「完成度 100%」可能過於寬鬆

所有 6 個子目標都標示 100%，但：
- 「candidate-specific rescue」只在 4 個象限中的 3 個做了主表呈現（缺 DORADO TO 主表列）
- 「phase 2 benchmark」的 TO raw pileup/full 尚未做（只有 paired 的）
- 「annotation layer 回接」目前只到 policy evaluation，尚未接到 dashboard / round summary / candidate diagnostics

建議用更精確的完成度標示（如 90%），或在備註欄說明剩餘部分。

**嚴重度**：低（主要影響管理期望值）

## 3. 邏輯與推論驗證

### 3.1 核心結論鏈是否成立

報告的核心推論鏈：

```
caller-first 最穩定 → methylation-support 是第二層 → annotation/QC 是第三層
```

**驗證**：

| 推論環節 | 支撐證據 | 判定 |
|---------|---------|------|
| caller-first (GQ) 最穩定 | GQ>=15/20 在 4 個象限都是正增益或最佳 | ✅ 成立 |
| methylation-support 有訊號 | 5kHz TO 的 Quality/Pairwise/agreement 都有正 support | ✅ 成立 |
| methylation-support 不超過 caller | 所有 gq+甲基 組合都 <= gq-only | ✅ 成立 |
| annotation 應用而非 hard rule | 甲基方向不穩定、coverage 有限 | ✅ 合理 |

**結論**：核心推論鏈邏輯上成立，每一步都有數據支撐。

### 3.2 是否存在邏輯跳躍

1. **「raw caller 不適合直接取代 merged」** — 邏輯正確。raw pileup/full 確實有更高 recall 但 FP 暴增，F1 下降。但報告沒有討論一個合理的中間方案：是否可以用 raw 的額外 TP 作為 rescue candidate pool（類似 candidate-specific rescue 的做法）？這不算邏輯錯誤，但算是一個值得探討的方向。

2. **「TO 下甲基 support 成立但不超過 caller-only」** — 邏輯正確，但需注意：5kHz TO 的甲基 support 實際 TP/FP 比率（如 `Pairwise>=0.20`: 300/68 = 4.41:1）遠優於 caller-only 的 TP/FP 比率（`gq>=10`: 499/119 = 4.19:1）。甲基 support 的 precision 其實更高，只是 recall 較低。報告用 F1 delta 來判定「不超過」在純粹的 F1 意義上是對的，但如果目標是 high-precision rescue，甲基 support 可能有不同的價值。

3. **「hp_assign_rate 應降階為 phase/QC annotation」** — 邏輯正確。TO diagnostics 顯示 TP/FP 的 hp_assign_rate 都常達 1.0，因此無鑑別力。

### 3.3 因果關係與相關性的區分

報告在以下地方做得好：
- 沒有把 F1 小幅改善解讀成方法學突破
- 明確指出 PairwiseMedianDist 的方向依賴性
- 用「support」而非「rule」定位甲基特徵

報告可改進之處：
- 沒有明確討論 F1 delta 在 4~7 位小數的統計顯著性（是否可能是隨機波動？）

## 4. 方法論審查

### 4.1 benchmark 方法

- **Truth set**：使用 SEQC2 truth set（HCC1395），業界公認標準 ✅
- **F1 計算**：基於 TP/FP/FN 的標準定義 ✅
- **比較基準**：有明確的 baseline（ClairS → LongPhase → InterSubMod 三層） ✅

### 4.2 方法論風險

| 風險 | 說明 | 建議 |
|------|------|------|
| 單樣本偏差 | 所有數據都來自 HCC1395（5kHz/DORADO 是同一細胞系的不同定序平台）。沒有獨立細胞系驗證 | 優先補 COLO829 或 H1437 的 TO pipeline 驗證 |
| F1 delta 顯著性未檢驗 | 多數增益在第 4 位小數（+0.001 ~ +0.007），未做 bootstrap CI 或 permutation test | 對關鍵規則補做 bootstrap 95% CI |
| 多重比較問題 | 數十條規則在 4 個象限上測試，最佳規則可能有 overfitting 風險 | 保留一個 dataset 做 held-out 驗證，或用 Bonferroni/FDR 校正 |
| TO pileup-only 限制 | 所有 TO 結論目前只基於 pileup 模型，full model 未測 | 在 Section 7 已提及但無具體計畫 |
| Coverage ceiling 差異 | paired 的 candidate-specific coverage 極低（8~19%），可能系統性偏倚結論 | 如瑕疵 3 所述，需要量化呈現 |

### 4.3 研究設計評價

**優點**：
1. 四象限設計（5kHz/DORADO × paired/TO）是合理的交叉驗證框架
2. candidate-specific rescue 方法比 baseline kept-set join 更正確（避免了 CURRENT_FOCUS 提到的錯誤結論風險）
3. 從 hard rule → annotation layer 的策略轉向有充分的數據支持
4. 有明確的「不該怎麼用」欄位，避免過度推論

**可改進**：
1. 缺乏統計顯著性檢驗
2. 缺乏獨立樣本（不同細胞系）驗證
3. annotation layer 的實際輸出格式（VCF INFO? TSV column?）尚未定義

5. **PairwiseMedianDist 深入分析**：討論方向相反的根本原因（是 dataset noise 還是真實的甲基結構差異）
