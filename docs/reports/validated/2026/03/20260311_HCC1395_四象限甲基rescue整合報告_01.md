# HCC1395 四象限甲基 Rescue 整合報告

## 1. 破題結論

目前把 `HCC1395 5kHz / HCC1395_DORADO × paired / TO` 四個主 dataset 放到同一個可比框架後，可以收斂成 4 個穩定結論。

1. `caller-first` 仍是目前最穩定的主規則，尤其是 `GQ (Genotype Quality，基因型信心分數)`。
2. 甲基特徵不是全部負效果；`Quality_Score`、`PairwiseMedianDist`、`agreement_positive`、`hp_assign_rate` 在部分 dataset 對 baseline 有正向 rescue 訊號，但多半沒有超過同一個 caller gate。
3. `PairwiseMedianDist` 的方向具有明顯 dataset-dependence（資料集依賴）：`5kHz TO` 偏高 pairwise 為正向 support，`DORADO paired / TO` 偏低 pairwise 較合理，因此目前不能升級成跨樣本全域規則。
4. `5kHz TO` 的 read-level snapshot 用的是 `full tagged BAM`，`DORADO TO` 用的是 `candidate-window subset tagged BAM`；因此 TO 的 read-level 圖可以做方向比較，但**不能**把 coverage、alt fraction、hp_assign_rate 的絕對值拿來做跨 dataset 硬比較。

這代表在目前證據下，最合理的流程分工仍是：

- 第一層：`caller-first`
- 第二層：`methylation-support`
- 獨立旁路：`artifact triage`
- 補充註記：`annotation / QC`

## 3. 背景與這輪要回答的問題

這輪不是單做某個 dataset 的一個規則，而是要回答 3 個更高層的問題：

1. 在 `5kHz / DORADO × paired / TO` 四個主情境下，從 `ClairS / ClairS-TO -> LongPhase-S / LongPhase-TO -> InterSubMod` 各層級的改善或退化，是否能被放進同一個表格中解讀。
2. 現有甲基特徵到底是：
   - 主 rescue 規則
   - 第二層 support
   - 還是只適合當 annotation / QC
3. `5kHz TO` 與 `DORADO TO` 的 read-level snapshot 因為 BAM 母體不同，這個差異會不會讓我們誤判特徵方向。

這一輪採用的原則是：

- benchmark 層可以跨 dataset 比較
- candidate-specific rescue 可以比較方向與效果量，但要同時看 coverage
- read-level diagnostics 只能在同 scope 下做絕對值比較
- 沒有雙模型 benchmark 的情況，只能做 availability 與 phase 2 規劃，不能硬下 pileup/full model 結論

## 6. 特徵單獨效果、組合效果與目前定位

### 6.1 `GQ`

`GQ` 目前仍是最穩定的主規則來源，但最佳 threshold 不同：

| Dataset | `gq>=10` | `gq>=15` | `gq>=20` | 目前最合理解讀 |
| --- | --- | --- | --- | --- |
| `5kHz TO` | `499 TP / 119 FP`, `F1 +0.006943` | `365 / 71`, `+0.005233` | `143 / 38`, `+0.001966` | `gq>=10` 對 TO 明顯有效 |
| `5kHz paired` | `183 / 616`, `-0.004459` | `106 / 75`, `+0.000825` | `59 / 8`, `+0.000871` | paired 不支持把 `gq>=10` 當穩定 gate |
| `DORADO paired` | `173 / 344`, `-0.001401` | `97 / 88`, `+0.000502` | `51 / 7`, `+0.000749` | paired 仍以 `gq>=15/20` 較合理 |
| `DORADO TO` | `40 / 11`, `+0.000540` | `33 / 9`, `+0.000446` | `16 / 3`, `+0.000229` | TO 下 `gq>=10` 仍有正增益 |

因此：

- **TO 下**：`gq>=10` 可作第一層 gate
- **paired 下**：不能直接沿用 `gq>=10`

### 6.2 `Quality_Score`

`Quality_Score` 在 TO 下是正向 support，但不應當 hard keep。

| Dataset | 單獨規則 | 相對 baseline | 相對同一 gate |
| --- | --- | ---: | ---: |
| `5kHz TO` | `Quality_Score>=60` | `556 TP / 162 FP`, `F1 +0.007466` | `gq>=10 + Quality>=60` 相對 gate `-0.001391` |
| `DORADO TO` | `Quality_Score>=60` | `208 TP / 77 FP`, `F1 +0.002620` | `gq>=10 + Quality>=60` 相對 gate `-0.000064` |
| `5kHz paired` | `Quality_Score>=60` | `76 TP / 355 FP`, `F1 -0.003064` | 不支持 paired 主 rescue |
| `DORADO paired` | `Quality_Score>=60` | `73 TP / 170 FP`, `F1 -0.000899` | `gq>=10 + quality>=60 + hp_assign>=0.99` 只在特殊組合下微正 |

這說明：

- `Quality_Score` 在 TO 下有訊號
- 但固定 caller gate 後沒有超過 caller-only
- 因此最合理定位是 `soft support / ranking / annotation`

### 6.3 `PairwiseMedianDist`

`PairwiseMedianDist` 是目前最明顯 dataset-dependent 的甲基特徵。

| Dataset | 較合理方向 | 單獨規則結果 | 解讀 |
| --- | --- | --- | --- |
| `5kHz TO` | 偏高 pairwise | `>=0.20`: `408 TP / 132 FP`, `F1 +0.005374` | 高結構異質性較像 support |
| `DORADO TO` | 偏低 pairwise | `<=0.20`: `173 TP / 60 FP`, `F1 +0.002217` | 方向與 5kHz TO 相反 |
| `DORADO paired` | 偏低 pairwise | `<=0.20` 較 `>=0.20` 合理，但整體仍不超過 caller-only | paired 也支持低 pairwise 方向 |
| `5kHz paired` | 沒有穩定 support 方向 | 高低 pairwise 都沒有形成正向 rescue | paired 目前不能升級使用 |

因此：

- `PairwiseMedianDist` **不能**升級成跨樣本全域規則
- 目前最合理定位是 `dataset-aware annotation`

### 6.4 `agreement_positive` 與 `Strong/Subclone`

在 `5kHz TO`：

- `agreement_positive`: `213 TP / 62 FP`, `F1 +0.002877`
- `Strong/Subclone`: `208 TP / 60 FP`, `F1 +0.002814`
- 固定 `gq>=10` 後：
  - `gq>=10 + agreement_positive`: 相對 gate `-0.004780`
  - `gq>=10 + Strong/Subclone`: 相對 gate `-0.004809`

在 `DORADO TO`：

- `agreement_positive`: `59 TP / 27 FP`, `F1 +0.000698`
- `Strong/Subclone`: `88 TP / 30 FP`, `F1 +0.001134`
- 固定 `gq>=10` 後仍未超過 gate

因此這兩組特徵目前比較像：

- 提供一個較乾淨、可追溯的 support 子集
- 但還不能升級成主 rescue 規則

### 6.5 `hp_assign_rate`

`hp_assign_rate` 在 `DORADO paired / TO` 有微弱正訊號，但 read-level diagnostics 顯示它更接近 `phase/QC annotation`。

原因是：

- 高 `hp_assign_rate` 的 TP 和 FP 都很多
- 多個 FP 同時呈現 `hp_assign_rate=1.0 + 極端 haplotype skew + 高 alt fraction`

因此：

- `hp_assign_rate` 不適合作為 truth-discriminative 主 support
- 應降階為 `phase completeness / QC annotation`

### 6.6 `low VAF + high AlleleDelta (+ low CramersV)`

這組規則在目前證據下，最合理定位仍是 **後段 artifact triage**。

理由：

- 在 `5kHz TO` 當 rescue veto 時，對 `gq>=10` 沒有提供額外好處
- 在 `DORADO TO` 也沒有形成正向 rescue
- 在 `5kHz paired` 的主要價值仍是後段刪除 suspect FP，而不是提前找 TP

因此：

- 不應把這組特徵直接改成 TP rescue 主規則
- 但它仍值得保留在 artifact / suspect annotation

來源：

- [feature_overlap_focus.tsv](/bip8_disk/liaoyoyo2001/InterSubMod_out/output/research_rounds/20260311_hcc1395_cross_quadrant_matrix/feature_overlap_focus.tsv)

目前可以先記住兩件事：

1. `Pairwise` 與 `agreement_positive / StrongSubclone / Quality_Score / hp_assign_rate` 並不是完全重疊，表示它們確實包含部分正交訊號。
2. 但交集規則常把 TP 與 FP 一起縮掉，所以「多加條件」不一定更好；很多情況只是把 caller-only 的正增量再縮小。

因此後續如果要繼續暴力分析，方向應該是：

- 找真正正交、且 `a_only_tp / b_only_tp` 仍明顯存在的特徵組合
- 而不是單純把 support 特徵一直硬交集

## 8. TO snapshot scope 差異是否有差

答案是：**有差，但現在已可更精確地說明差在哪裡。**

### 8.1 現況

| Dataset | snapshot BAM | scope | 可做什麼 | 不能做什麼 |
| --- | --- | --- | --- | --- |
| `5kHz TO` | [tumor_tagged.bam](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260307_hcc1395_to_pilot_1/step03_longphase_to/tumor_tagged.bam) | full tagged BAM | 觀察 within-dataset 的 read 結構與 support/artifact 現象 | 不能直接拿來和 subset snapshot 做絕對值硬比較 |
| `DORADO TO` | [tumor_candidate_windows_tagged.bam](/home/liaoyoyo2001/InterSubMod_runs/output/research_rounds/20260311_hcc1395_dorado_to_candidate_rescue/step03_longphase_to/tumor_candidate_windows_tagged.bam) | candidate-window subset tagged BAM | 觀察 candidate 附近局部結構與 support/artifact 現象 | 不能和 full BAM snapshot 的 coverage / hp_assign 絕對值直接比較 |

### 8.2 後續 control 補充

`2026-03-12` 已補做 [TO snapshot scope same-scope control](/big8_disk/liaoyoyo2001/InterSubMod/docs/reports/validated/2026/03/20260312_TO_snapshot_scope_same_scope_control_01.md)：

- 對 `HCC1395 5kHz TO` 的相同 18 個代表性 region，比較 `full tagged BAM` 與 `candidate-window subset tagged BAM`
- 結果為 `18/18` region 完全一致
- `read_count`、`target_alt_fraction`、`na_hp_fraction`、`collapsed_hp_balance_delta` 等主要指標全部 `max_abs_delta = 0.0`

這代表：

- `subset` 技術本身在 same-dataset / same-region 控制下，沒有觀察到 snapshot 指標偏移
- `subset snapshot` 可安全用於 **同 dataset 內** 的 read-level ranking 與 diagnostics

### 8.3 意義

這會直接影響：

- `target_depth`
- `target_alt_fraction`
- `na_hp_fraction`
- `hp_assign_rate`
- `samtools depth / mpileup` 的 read 構成

因此現在應更精確地說：

- `5kHz TO` 與 `DORADO TO` 在 TO support / artifact 現象上有方向差異
- 但不能說某個 dataset 的 read-level support 「數值更高」或「HP 更乾淨」
- 這個限制的主因是 `dataset/platform` 與 coverage ceiling 差異，而不是 `subset` 萃取技術本身

## 10. 目前最合理的高層分工

### 第一層：caller-first

- 主特徵：`GQ`, `QUAL`, `FILTER`, TO 額外的 caller 標記
- 作用：定義可以討論 rescue 的邊緣集合

### 第二層：methylation-support

- 主特徵：`Quality_Score`, `agreement_positive`, 部分情境下的 `PairwiseMedianDist`
- 作用：support / ranking / annotation
- 限制：目前多半沒有超過同一 caller gate

### 獨立旁路：artifact triage

- 主特徵：`low VAF + high AlleleDelta (+ low CramersV)`
- 作用：後段 FP suspect / artifact 註記
- 限制：不適合作 TP rescue 主規則

### annotation / QC

- 主特徵：`hp_assign_rate`, `PairwiseMedianDist`, `NA HP fraction`, `haplotype skew`
- 作用：幫助理解 read-level 現象與 phasing 完整度

### Pool B FN closeout 對主線分工的補充

`2026-03-12` 已補做 [Pool B FN integration closeout](/big8_disk/liaoyoyo2001/InterSubMod/docs/reports/validated/2026/03/20260312_PoolB_FN_integration_closeout_01.md)，對高層分工的補充結論是：

- `Pool B FN = 840` 再次確認 caller-side rescue 空間真實存在
- 原始 caller-only 最佳規則為 `no_varcluster`（`428 TP / 390 FP`, `F1 +0.003391`）
- 最乾淨的 caller-side 規則為 `no_varcluster_and_gq15`（`115 TP / 45 FP`, `precision=71.9%`）
- 補跑甲基後最佳 combined 規則 `gq15_and_allele_delta_low` 雖為正增益（`+0.002702`），但仍低於原始 caller-only 最佳
- `Pool B` 中 `Strong/Subclone` 與高 `PairwiseMedianDist` 在 non-FN 反而更高，因此甲基不適合作為獨立主 rescue 規則
- `AlleleDelta` 在 `Pool B` 與 TO kept-set / artifact triage 的方向不同，因此不可跨母體全域化

這代表四象限主線中的高層分工不需要改寫，只需再明確補一句：

- `caller-first` 不只在 kept-set rescue 成立，在 `Pool B FN` 的 caller-side rescue 也再次成立

2. paired 下 `pileup_filter / full_alignment_filter / final output` 的直接 benchmark 對照。
3. 若空間與成本許可，補 `DORADO TO full baseline InterSubMod`。
4. 若未來要升級規則，先升 annotation，再考慮 hard rule。

---

## 12. 本輪結論

在現在的證據下，最保守且正確的結論是：

- **已成立**
  - `caller-first` 是四象限最穩定的主規則
  - `Pool B FN` closeout 再次支持 caller-side rescue 空間存在，且甲基只提供弱補強
  - 甲基特徵不是全部負效果
  - `Quality_Score` 在 TO 下可作 support / ranking
  - `PairwiseMedianDist` 與 `hp_assign_rate` 更適合作 annotation / QC，而不是全域 hard rule
  - `low VAF + high AlleleDelta` 適合作 artifact triage，不適合作 TP rescue 主規則

- **只在部分 dataset 成立**
  - `5kHz TO` 的高 pairwise support
  - `DORADO TO` / `DORADO paired` 的低 pairwise support

- **尚不能成立**
  - `PairwiseMedianDist` 的跨樣本全域固定方向
  - TO 的 pileup vs full model 差異結論
  - `DORADO TO` 的 full baseline InterSubMod 整體 benchmark 結論

這份整合報告的用途，是讓後續每次再做 brute-force feature sweep、pairwise/full model 比較、或 read-level diagnostics 時，都有一個固定的上位框架與可複查路徑可以承接。
