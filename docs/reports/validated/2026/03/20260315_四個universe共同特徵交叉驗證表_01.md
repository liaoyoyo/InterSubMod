# 四個 universe 共同特徵交叉驗證表

## 一句結論

這輪把 `final kept / old full / boundary / TO` 四個 universe 拉到同一張表後，最穩定的結論有三個：

1. `CramersV>=0.30` 是目前**唯一真正跨 universe 都維持 TP enrichment** 的共同特徵，但在 paired boundary 的 coverage 只有 `6.51%`，所以它適合當 `positive annotation tier`，還不夠當主規則。
2. `AlleleDelta>=0.30` 是目前**最穩定的跨 universe FP/artifact 特徵**；在 final kept、old full、paired boundary、TO analyzable subset 都偏向 `FP_enriched`，更適合 `artifact triage` 而不是 `TP rescue`。
3. `Subclone`、`Quality_Score`、`PairwiseMedianDist` 都受到 universe-selection effect 或 schema 限制影響，不能直接從單一 universe 的正面結果推成全域規則。

本輪新增可重跑腳本 [analyze_cross_universe_feature_validation.py](/big8_disk/liaoyoyo2001/InterSubMod/scripts/analysis/analyze_cross_universe_feature_validation.py)，輸出目錄在 [/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_cross_universe_feature_validation](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_cross_universe_feature_validation)。

## 1. 為什麼要做四個 universe 交叉驗證

前一輪已經出現一個核心張力：

1. provenance / pilot 分析在 `final kept` universe 看到 `Subclone` 與 `CramersV>0.3` 很乾淨，見 [20260315_甲基特異位點亞克隆整合分析_pilot_01.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/reports/validated/2026/03/20260315_甲基特異位點亞克隆整合分析_pilot_01.md)
2. 但我們主線研究框架在 `paired boundary` 與 `TO candidate-specific` universe 看的是 `support / rescue / triage` 問題，見 [20260315_甲基候選研究框架與觀察資產盤點_01.md](/big8_disk/liaoyoyo2001/InterSubMod/docs/reports/validated/2026/03/20260315_甲基候選研究框架與觀察資產盤點_01.md)

如果不把同一特徵放到同一張 cross-universe 表，就很容易把：

- `final selection 後很乾淨`

誤講成：

- `decision boundary 也有用`

這輪的目的，就是把這個邏輯斷點補齊。

## 2. 四個 universe 的定義與口徑

根據 [universe_summary.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_cross_universe_feature_validation/universe_summary.tsv)：

| Universe | TP | FP | analyzable TP | analyzable FP | analyzable coverage | 回答的問題 |
|---|---:|---:|---:|---:|---:|---|
| `final kept` | 29,740 | 627 | 29,740 | 627 | 100.00% | final selection 後哪些特徵像 biology annotation |
| `old full` | 30,476 | 4,822 | 30,476 | 4,822 | 100.00% | 舊 full output 中哪些特徵偏 TP / 偏 FP |
| `boundary` | 1,052 | 12,974 | 111 | 802 | 6.51% | paired caller boundary 是否有甲基 rescue / triage 價值 |
| `TO` | 773 | 298 | 675 | 213 | 82.91% | tumor-only caller-first 後哪些特徵可當 support |

最重要的口徑修正是：

1. `boundary` 不能用整張 paired `rescue_joined_features.tsv` 去算。
2. 真正的 paired boundary universe 只應該是：
   - `caller_lost_tp`
   - `caller_removed_fp`
3. `boundary` 與 `TO` 都要再拆成：
   - `full universe 母體`
   - `matched summary analyzable subset`
4. 原因是這兩張表對沒有 matched InterSubMod region export 的列做了 `0-padding`；如果不先拆開，就會把「沒有 summary」錯當成「feature=0」。

也因此，這輪每個特徵都同時記：

1. `precision`
2. `analyzable subset TP rate / FP rate`
3. `full universe TP capture / FP capture`
4. `coverage`

這是本輪最重要的方法學修正。

## 4. 驗證推論過程與概念

### 4.1 第一步：先問這個 universe 在回答什麼問題

1. `final kept`
   - 回答的是：最後留下來的位點裡，哪些特徵更像 biology / annotation
   - 不回答：caller decision boundary 能不能靠這個特徵救回 TP
2. `old full`
   - 回答的是：全體 paired full output 中，哪些特徵偏 TP 或偏 FP
   - 適合看全域 triage / annotation 傾向
3. `boundary`
   - 回答的是：paired caller 真正卡在邊界的位點，甲基到底有沒有實際 utility
4. `TO`
   - 回答的是：tumor-only caller-first 之後，甲基能不能提供第二層 support

所以，**同一特徵如果只在 final kept 很乾淨，不代表它能碰 boundary 問題。**

### 4.2 第二步：看方向，而不是只看 precision

本輪的主要方向判定，不是看「precision 高不高」，而是看：

- `analyzable TP hit rate`
- `analyzable FP hit rate`

也就是：

- 這個特徵在可評估子集內，到底是更常命中 TP，還是更常命中 FP

這樣可以避免 `final kept` 因為 baseline precision 本來就很高，而誤把「幾乎所有東西都很乾淨」講成「這個特徵特別有用」。

### 4.3 第三步：看 coverage，避免高精確低覆蓋被誤用

最典型的例子就是 `CramersV>=0.30`：

1. 在 `boundary` analyzable subset 中是 `5 TP / 2 FP`
2. precision `71.4%`
3. `TP_enriched` 沒錯
4. 但它只覆蓋整個 paired boundary full universe 的：
   - `5 / 1052 = 0.48%` TP
   - `2 / 12974 = 0.02%` FP

所以正確說法不是：

- `CramersV>=0.30` 可以解 paired boundary

而是：

- `CramersV>=0.30` 是一個穩定正向的 annotation tier，但 coverage 太低，不能單獨升級成主規則

### 4.4 第四步：如果方向翻轉，先假設 selection effect，而不是先假設 feature 失效

最明顯的是 `Subclone` 與 `PairwiseMedianDist`。

#### `Subclone`

1. `final kept`：`1402 TP / 10 FP`，看起來非常乾淨
2. `old full`：`1421 TP / 232 FP`，已不再特別純
3. `boundary`：`6 TP / 82 FP`，甚至偏向 FP
4. `TO`：`24 TP / 7 FP`，又回到中度正向

這種 pattern 不應該被講成：

- `Subclone 有時有用、有時沒用`

更精確的說法是：

- `Subclone` 主要是 `final-kept biology lens`
- 一進到 `paired caller boundary` 就失去 rescue utility
- 在 `TO` 裡保留少量 support/annotation 價值

也就是：**它的語義受 universe 影響很大。**

#### `PairwiseMedianDist`

1. `final kept` 中，`<=0.20` 比 `>=0.20` 更乾淨
2. `paired boundary` 中，反而是 `>=0.20` 比 `<=0.20` 好
3. `TO` 中，高低 pairwise 差距很小，但偏高仍略偏 support

這說明：

- `Pairwise` 不是單向規則
- 它高度依賴：
  - dataset
  - universe
  - selection stage

所以 Pairwise 只能做 `dataset-aware annotation/support`，不能做全域 threshold。

## 5. 逐特徵結論

### 5.1 `CramersV>=0.30`

這是目前最穩定的 cross-universe 正向特徵。

根據 [feature_consensus_summary.tsv](/big8_disk/liaoyoyo2001/InterSubMod_runs/output/big8_disk_output/research_rounds/20260315_cross_universe_feature_validation/feature_consensus_summary.tsv)：

1. `final kept`：`TP_enriched`
2. `old full`：`TP_enriched`
3. `boundary`：`TP_enriched`
4. `TO`：`TP_enriched`

但它的正確角色仍是：

- `positive annotation tier`

不是：

- 直接當 paired boundary rescue rule

原因是 paired boundary coverage 太低。

### 5.2 `AlleleDelta>=0.30`

這是目前最穩定的 `FP_enriched` 特徵。

1. `final kept`：`70 TP / 44 FP`
2. `old full`：`73 TP / 251 FP`
3. `boundary`：`0 TP / 13 FP`
4. `TO`：`2 TP / 1 FP`

雖然 `TO` 的數量很小，但整體方向仍一致：

- 高 `AlleleDelta` 更像 artifact / triage 線索

因此它最適合做：

- `artifact suspect`
- `FP triage`
- `Strong suspect decomposition`

而不是：

- `TP support`

### 5.3 `VerificationClass=Subclone`

`Subclone` 不是穩定的 rescue 特徵，而是很典型的 universe-sensitive feature。

1. 在 `final kept` 非常乾淨
2. 在 `old full` 幾乎只剩中性
3. 在 `paired boundary` 變成負向
4. 在 `TO` 只剩少量正向

所以 provenance 裡看到的：

- `Subclone FP 率很低`

不該被推成：

- `Subclone` 可以拿來做 paired caller boundary rescue

更合理的定位是：

- `subclone prioritization`
- `case-study seed`
- `biology lens`

### 5.4 `Quality_Score>=60`

這個特徵有兩個限制：

1. `old full` 不可用，因為舊 schema 沒有 `Quality_Score`
2. 在 `final kept` 幾乎接近 ubiquitous，高低本身不再是分離器

但在 `boundary` 與 `TO` analyzable subset 中，它都偏向正向 support：

1. `boundary`：`76 TP / 395 FP`
   - precision `16.1%`
   - 高於 paired boundary analyzable baseline `12.2%`
2. `TO`：`556 TP / 162 FP`
   - precision `77.4%`
   - 高於 TO analyzable baseline `76.0%`

所以 `Quality_Score` 的正確角色是：

- `caller-first` 後的 `soft support / ranking`

不是：

- 全域 biology marker
- 全域 hard filter

### 5.5 `PairwiseMedianDist`

這個特徵最能說明「不能只看單一 universe」。

1. `final kept` 偏向 `<=0.20` 較乾淨
2. `paired boundary` 偏向 `>=0.20` 較乾淨
3. `TO` 中 `>=0.20` 與 `<=0.20` 差距很小，僅輕微偏高 pairwise

所以 Pairwise 的最終定位應該是：

- `dataset-aware annotation`
- `support/ranking`

而不是：

- `所有 paired / TO 都通用的 threshold`

### 5.6 `Subclone+Significant` 與 `SuggestFilter`

這兩個是本輪特別保留的 restricted features，因為它們剛好代表兩種常見誤解。

#### `Subclone+Significant`

1. `final kept`：`21 TP / 0 FP`
2. `old full`：`22 TP / 0 FP`

這代表它很適合：

- `case-study seeds`
- `高信度 subclone 候選`

但由於 coverage 只有 `0.07%` 左右的 TP，它不應該被拿來當主流程規則。

#### `SuggestFilter=True`

1. `final kept`：`106 TP / 31 FP`
2. `old full`：`113 TP / 233 FP`

它比較像：

- `full-output artifact triage annotation`

而不是 boundary/TO 的 negative evidence。  
因為在 `boundary` / `TO` 這個欄位根本不可用，不能拿 `N/A` 當成「無效果」。

## 6. 最終角色分工

如果要把這輪結果收斂成可操作結論，最合理的角色分工如下：

1. `CramersV>=0.30`
   - `positive annotation tier`
   - `high-confidence biology hint`
2. `AlleleDelta>=0.30`
   - `artifact triage`
   - `FP suspect decomposition`
3. `VerificationClass=Subclone`
   - `subclone prioritization`
   - `biology lens`
   - 不是 paired boundary rescue
4. `Quality_Score>=60`
   - `caller-first` 後的 `soft support / ranking`
5. `PairwiseMedianDist`
   - `dataset-aware annotation`
   - 不升級成全域 threshold

## 7. 下一步

這輪最合理的後續不是再加更多門檻，而是做兩件事：

1. 在 round 2 把 `CramersV>=0.30` 與 `AlleleDelta>=0.30` 明確分成：
   - `positive annotation tier`
   - `artifact triage tier`
2. 對 `Quality_Score` 與 `PairwiseMedianDist` 只在：
   - `TO`
   - paired analyzable boundary subset
   做 dataset-aware rule sweep，不再嘗試把它們升成全域規則

一句話總結：

**跨 universe 後，真正穩定的不是「甲基整體有沒有用」，而是每個特徵的流程角色。**
