## 五、Pre-Existing Bug：隨機種子非確定性

### 問題

`StructureTest` 的 RNG 預設 seed=0，意味著用 `std::random_device` 產生隨機種子：

```cpp
// include/core/StructureTest.hpp:35
uint64_t seed = 0;

// src/core/StructureTest.cpp:17-21
if (config_.seed == 0) {
    std::random_device rd;
    rng_.seed(rd());  // 每次執行不同種子！
} else {
    rng_.seed(config_.seed);
}
```

**影響**：label PERMANOVA（HP/Allele）在每次執行時因不同隨機種子，導致 ~3/672（0.45%）的位點 VerificationClass 不同。這是 **pre-existing bug**，與 cluster PERMANOVA 啟用與否無關。

**修復方案**：在 `RegionProcessor.cpp` 中設定固定種子（如 `sig_config.structure_config.seed = 42`）。

## 九、全量測試補充（2026-03-23 第二輪）

### 9.1 Seed Bug 根因修正

**問題根因**（`init_analyzers()` 邏輯）：

```cpp
// src/core/SignificanceAnalyzer.cpp:18-32
void SignificanceAnalyzer::init_analyzers() {
    if (config_.seed != 0) {   // 只有頂層 seed ≠ 0 才傳播！
        config_.structure_config.seed = config_.seed + 2;
        config_.label_config.seed = config_.seed + 4;
        // ... 其他組件
    }
}
```

舊設定（`sig_config.structure_config.seed=42, sig_config.seed=0`）：
- `init_analyzers()` 不執行 seed 傳播
- `label_config.seed=0` → `random_device` → **label PERMANOVA 非確定性**
- `global_config.fisher_config.seed=0` → `random_device` → **PassedGating 非確定性**

新設定（`sig_config.seed=42`）：
- `init_analyzers()` 傳播所有種子
- `structure_config.seed=44`, `label_config.seed=46`, `global_config.seed=42`
- **所有組件 100% 確定性**

### 9.3 修正後辨別力（fixed seed=42）

| 染色體 | TP | FP | PassedGating TP | PassedGating FP | AUROC |
|--------|----|----|----------------|----------------|-------|
| chr19  | 672 | 96 | 45.8% | 34.4% | **0.650** |

**重要更正**：前次報告 chr19 AUROC=0.742 是因 global Fisher test 也使用 random seed，
固定後 AUROC=0.650（PassedGating subset 從 234→308 個，AUROC 稀釋）。

**可能原因**：
- chr19 含大量 imprinting loci（H19/IGF2/SNRPN）→ 強烈真實甲基化差異 → 高 F 值
- chr1+2+3 的 FP 也有真實甲基化結構（FP PassedGating 高達 36%）
