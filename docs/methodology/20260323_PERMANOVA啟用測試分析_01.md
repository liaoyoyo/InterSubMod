## 四、VerificationClass 影響

### 啟用 PERMANOVA 前後的 VerificationClass 一致性

| 比較 | 差異數 | 原因 |
|------|--------|------|
| PERMANOVA=true vs false | **4/672** | **非 PERMANOVA 直接影響** |
| PERMANOVA=false vs false（兩次） | **3/672** | label PERMANOVA 隨機種子 |

**結論：PERMANOVA=true 導致的 VerificationClass 差異為 4 個，其中 3 個是 pre-existing 的 label PERMANOVA 非確定性問題。真正由 cluster PERMANOVA 引發的差異最多 1 個。**

**`cluster_significant` 的定義（第 306-308 行）不使用 PERMANOVA**：
```cpp
bool cluster_significant = result.passed_gate &&
                           (result.global_alt.fisher_ffh.p_value <= 0.05 ||
                            result.global_hp.fisher_ffh.p_value <= 0.05);
```
即使啟用 PERMANOVA，VerificationClass 邏輯完全不改變。

## 五、Pre-Existing Bug：隨機種子非確定性

### 問題

`StructureTest` 的 RNG 預設 seed=0，意味著用 `std::random_device` 產生隨機種子：

```cpp
// include/core/StructureTest.hpp:35
uint64_t seed = 0;

// src/core/StructureTest.cpp:17-21
if (config_.seed == 0) {
    std::random_device rd;
    rng_.seed(rd());  // 每次執行不同種子！
} else {
    rng_.seed(config_.seed);
}
```

**影響**：label PERMANOVA（HP/Allele）在每次執行時因不同隨機種子，導致 ~3/672（0.45%）的位點 VerificationClass 不同。這是 **pre-existing bug**，與 cluster PERMANOVA 啟用與否無關。

**修復方案**：在 `RegionProcessor.cpp` 中設定固定種子（如 `sig_config.structure_config.seed = 42`）。
