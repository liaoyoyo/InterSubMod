單分子解析度的腫瘤亞群重建與甲基化關聯

從「哪些突變在同一條 read 上」
到「哪些演化分支的甲基不一樣」

兩個獨立的軟體、一條資料流。LongLineage 只做純遺傳的 read 連鎖與樹重建，把結果寫回 BAM；InterSubMod 讀那份 BAM，問甲基化的差異 跟哪個標籤軸有關。甲基不參與樹的推論 —— 否則用甲基推分支、再用分支 解釋甲基，就是循環論證。

① 問題

腫瘤不是一群相同的細胞

一顆腫瘤由多個帶不同突變的亞群（subclone）組成。要知道它們的演化關係， 關鍵問題是：兩個體細胞突變是在同一顆細胞裡，還是在不同亞群裡？

圖 1．為什麼要用長讀長。ONT read 常達數萬 bp，能同時跨過多個突變位點。 「A 與 B 出現在同一條 read 上」是單分子的直接觀察，不需要用族群頻率去推。 本專案的整條方法建立在這個觀察之上。
本專案要回答的三個問題，依序解決：
  1. 哪些突變彼此連鎖？ → 用 read 共現切出「該一起分析的位點群」
  2. 它們的發生順序是什麼？ → 在每個位點群上解最簡約的演化樹
  3. 不同分支的甲基化有沒有差？ → 事後把甲基疊上去 characterize
② 整體

兩個軟體、四個階段

圖 2．系統架構。左側 LongLineage 完全不碰甲基化，只用 read 共現與簡約原則建樹； 右側 InterSubMod 讀那份帶標籤的 BAM，把甲基化事後疊上去問關聯。兩者的交界是一份標準 BAM 檔， 所以任何一邊都可以單獨使用、單獨驗證、單獨替換。
③ LongLineage

三個步驟：切區域 → 建樹 → 標回 BAM

步驟 1：用 read 共現切出「該一起分析的位點群」

全基因組 35,332 個體細胞突變，若一起解是 NP-hard。先用 read 連鎖切成小塊：

圖 3．連鎖切區域。節點是突變位點，邊是「有幾條 read 同時定住兩端」。 連通分量就是一個分析單元。門檻不是拍腦袋定的：低於 3 條的連鎖無法與技術誤差區分。 儀表板內建 what-if 面板，可直接看門檻改成 1／2／5 各會多／少多少邊。

步驟 2：在每個位點群上解最簡約的演化樹

圖 4．從 read pattern 到樹。樹的節點是「突變狀態組合」，邊是「獲得某個突變」。 最簡約原則 = 每個突變只發生一次。三態必須分清楚：實測節點、補入節點、以及「所有邊都是推論」。 儀表板用實線／虛線／點線三種畫法，並在圖旁固定顯示圖例。

步驟 3：把樹上的位置寫回每條 read

樹解完後，每條 read 依它的 R/A/X pattern 對到樹上某個節點，寫成 BAM aux tag。 只覆蓋部分位點的 read（pattern 含 X）本來對不到單一節點 —— 取所有相容節點的最近共同祖先（LCA），就能斷言「它在這個節點或其後代」。

④ 交界

BAM 標籤契約 —— 兩個軟體的唯一介面

LongLineage 的輸出與 InterSubMod 的輸入，就是這一份標準 BAM。 原始的甲基化標記 MM/ML 完整保留， 所以同一份檔案既能看譜系、也能做甲基分析、也能直接進 IGV。

tag型別內容這是事實還是推論
lpZ觀察到的 pattern，如 ARX 事實 直接讀出來的
lvZ階層路徑，如 HP2-1-1；+ 後綴 = 此節點或其後代 推論 由樹推得
lsAU 唯一解 / M 同分並列 / P 只覆蓋部分 / A 拓撲未定 可信度 上一列那個推論有多硬
loZ突變獲得順序 pos>pos>pos 推論 ls=A 時不寫
lc／luZcomponent／block 的識別碼 索引
HPZ（字串）九態單倍型 1 2 1-1 2-1 3 由上游 sidecar 注入
MM／MLZ／B鹼基修飾（5mC/5hmC） 事實 原封不動保留
設計要點：把「事實」與「推論」分開存。 lp 是這條 read 上實際讀到什麼，lv 是據此推得的位置， ls 告訴你那個推論有多可靠。任何下游都能自己決定要不要信 —— 例如只用 ls=U 的 read 做嚴格分析，或放寬到 ls=U|M 換取樣本量。

在 IGV 裡怎麼看

輸出預設是單一座標排序的 BAM（逐染色體只是平行化的中間產物，跑完會自動合併）。 載入 IGV 後：

  1. Group alignments by → tag → 輸入 lv → 依譜系分組，看哪些 read 屬於同一分支
  2. 改成 ls → 把唯一解與部分覆蓋的 read 分開看
  3. 開啟 base modification 顯示 → 直接看每條 read 的甲基化
一個必須知道的細節：HP 是字串 HP:Z，不是 IGV 內建 haplotype 模式認的 HP:i 整數。 這是刻意的 —— 九態單倍型的 1-1／2-1／3 無法用整數表達。 所以要走「Group by tag」而非內建的 haplotype 模式。

⑦ 可信度

系統怎麼證明自己沒出錯

產出的每一份 HTML 都附一份自檢報告，內含 12 條機械計算的守恆等式。 不是敘述性的「已檢查」，而是可以重算的等式：

#等式實測
C4有樹 + 無樹 = 全部 region，且無樹者可完全歸因 9,130 + 2,460 = 11,590 ✅
C5每棵代表樹滿足 |V| − 1 = |E|（樹的定義） 9,130 棵，違反 0 ✅
C11LCA 前後的 receipt 是乾淨的 A/B 10 欄相同，3 欄不同 ✅
C12每個 block 的位點都由通過門檻的邊連通 11,590 / 11,590 ✅
C10沒有任何軸的顯著率逼近 100%（雙重使用偵測） 甲基自身分群 100.0% ❌
唯一不成立的 C10 是真的問題，不是誤判。 系統偵測到「甲基自身分群」軸的顯著率是 20,903/20,904，追查後確認是雙重使用。 該軸已在三處隔離：表格標紅籤、結論句排除、全基因組軌道不含它。 C10 是泛用偵測 —— 任何軸只要 n≥100 且顯著率 ≥99% 都會被抓，不是針對這一個寫死的。

方法本身的界線（引用結果前必讀）

樹的節點 ≠ subclone

節點是由 read 共現的簡約解推得的「突變狀態」。稱它為已確認的 subclone 需要 single-cell 或 multi-region 的獨立證據，本管線沒有。

read 比例 ≠ 細胞比例（CCF）

本樣本共現區 94% 是拷貝數異常區，read 豐度受拷貝數影響，不可當細胞比例讀。

甲基覆蓋 81.6% 且非隨機

缺的位點是被 ISM 自己的覆蓋度／CpG 密度 gate 濾掉的，與這兩個因子相關。 任何「拓撲 × 甲基」的結論都必須聲明母體。

k ≥ 7 的區域沒有樹

153 個區域的 solver 主動放棄（資源上限），標成「定不出來」而非給不可靠的答案。 那些區域的圖只能用等位 pattern 分組。

目前是單樣本。 7 個樣本都有拓撲層，但 lineage 標籤與甲基分析只有 HCC1395。 架構是多樣本的 —— 跨樣本比較區塊會明確標示「從缺」，補齊資料後重跑即自動填入，不需改程式。
