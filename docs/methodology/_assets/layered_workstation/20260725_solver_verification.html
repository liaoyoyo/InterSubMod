L1 · 重點邏輯

瓶頸不是問題太難，是預算設太緊、又把「突變數多」誤判成「結構複雜」

  • 決定性ABSTAIN 的成因單一且明確。 全部 10,717 個的 reason 都是 SEARCH_NODE_LIMIT_REACHED， 卡在 maximum_search_nodes=1000。但實測 B&B 常需要數千至數百萬節點才收斂 —— 1,000 這個預算太緊，而 DP 路徑根本不受它限制。
  • 決定性調高上限行不通，必須改結構。 鏈長 m=8 用暴力枚舉需 C(254,7)≈1.2×10¹³ 個候選（估 ~85 天），但真值只是閉合式 m!，O(1) 可得。
  • 重要「鏈填充」不是結構複雜度。 popcount-m 的終端必然需要 m−1 個祖先，那只是突變距離、零推論內容，卻把 cap 額度佔滿。
  • 重要求 h* 該用 DP 而非 B&B。 10,295 個 unit（96.1%）由 DP certify，實測比 B&B 快 20–1000×。
  • 背景k 上限不能移除，但可重新定義。 硬上限綁在 active loci（真正有變異的位點）而非區域 sSNV 數；稀疏區 k=64 仍是 0.05 ms。
