# 顯著分析各步驟有效性確認

## 核心發現（重要）

ISM 的顯著分析有幾個關鍵架構事實，需要用戶確認理解：

### 事實 1：VerificationClass 未參與最終 VCF 過濾

**最終過濾邏輯位置**：`scripts/pipeline/steps/03_filter_analysis.py:158-200`

```python
def should_filter_variant(row, vcf_features=None, rule_config=None):
    allele_delta = abs(float(row.get("AlleleDelta", 0)))
    cramers_v = float(row.get("CramersV", 0))
    vaf = ...  # from VCF

    core_trigger = (allele_delta > threshold AND vaf < threshold)
    # VerificationClass、Significant 完全未使用！
```

**含義**：ISM 計算出 Strong/Weak/Subclone/Noise，但最終決策僅依賴 AlleleDelta + VAF (+ CramersV)。`VerificationClass` 是「參考指標」，不是「決策指標」。

### 事實 2：Cluster PERMANOVA 刻意停用

`src/core/RegionProcessor.cpp:1146`：
```cpp
sig_config.enable_permanova = false;  // 刻意停用
```

`significance.json` 的 `cluster_structure` 區塊永遠是空值（F=0, valid=false）。

### 事實 3：`Significant`（TSV）≠ `label_significant`

- `VerificationClass` = 由 `label_significant` × `cluster_significant` 決定（2×2 矩陣）
- `Significant`（TSV column）= `passed_gating AND global_p≤0.05 AND CramersV≥0.1 AND reads≥20`
- 兩者獨立計算，不一定一致

### 事實 4：VerificationClass 決策矩陣

```
                cluster_significant=True    cluster_significant=False
label_sig=True:  → Strong                  → Weak
label_sig=False: → Subclone                → Noise
```

其中：
- `cluster_significant` = `passed_gate` AND (global_alt_p ≤ 0.05 OR global_hp_p ≤ 0.05)
- `label_significant` = label-first HP/Allele PERMANOVA 或 LocalTest 的結果

## 問題診斷

### 問題 A：Label HP PERMANOVA 貢獻幾乎為零

70-97% 失效率 + AUROC=0.515 → HP PERMANOVA 對最終分類幾乎沒有貢獻。

**根本原因**：TO mode 的 haplotagging 品質有限。HP PERMANOVA 設計假設大多數 reads 有 HP tag，但實際上只有少數。

### 問題 B：VerificationClass 與最終 F1 脫鉤

`VerificationClass` 計算複雜但未連接到 VCF FILTER 決策。最終 F1 delta ≈ 0 可能因為：
1. 最終過濾器（`03_filter_analysis.py`）使用 AlleleDelta+VAF，與 ISM 的 VerificationClass 無關
2. ISM 的加分/扣分邏輯沒有直接影響 calling 結果

### 問題 C：Cluster PERMANOVA 停用後遺留了空欄位

`cluster_structure` 在 significance.json 中永遠是空值，但還是被計算和輸出。

## 修改選項

### 方案 A：確認架構意圖，補充文件
- 確認「VerificationClass 作為參考，不參與 FILTER」是否為設計意圖
- 補充架構文件說明各個步驟的用途
- 不改程式碼
- **F1 影響**：0

### 方案 B：將 VerificationClass 連接到最終過濾邏輯
- 修改 `03_filter_analysis.py`，讓 Strong/Weak/Subclone 影響過濾決策
- 例如：Noise 且 AlleleDelta < 0.2 → 過濾掉
- **風險**：需仔細評估 Noise TP 的數量（46.6% TP 被標為 Noise，不能全過濾）
- **F1 影響**：需測試，可能 ±0.001~±0.005

### 方案 C：改進 LabelAllelePermanovaF 連接到最終判決
- 將 `LabelAllelePermanovaF`（AUROC=0.569）作為輔助 FILTER 條件
- 例如：AlleleF ≥ 10 → 免於被過濾（救回一些 TP）
- **修改位置**：`03_filter_analysis.py` 或 ISM 主程式
- **F1 影響**：可能 +0.001~+0.005

### 方案 D：移除/停用 cluster PERMANOVA 的無用輸出
- 移除 `cluster_structure` 區塊的輸出（或標記為 deprecated）
- 節省 I/O 資源和混淆
- **F1 影響**：0（純清理）
