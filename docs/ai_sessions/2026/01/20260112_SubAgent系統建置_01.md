## 對話背景

用戶希望根據專案中的各種工作流程，建立專門處理不同任務的自動化系統，包括資料收集、程式規劃、程式撰寫、測試驗證、版本控制等角色。

## 關鍵決策

| 決策 | 原因 | 影響 |
|------|------|------|
| 採用方案 B：7 個 Agent + 1 個 Skill | 保持細緻分工，簡單任務用 Skill 處理更輕量 | 平衡了功能完整性和易用性 |
| 所有 Agent 使用 `model: inherit` | 繼承主對話的模型設定，保持一致性 | 避免頻繁切換模型 |
| 合併 Deploying + GitOps 為 release Agent | 發布流程整合更合理 | 減少 Agent 數量，提高效率 |
| 將 Reporting 轉為 /report Skill | 報告撰寫較簡單，不需獨立 Agent | 更輕量的調用方式 |
| 使用 PubMed MCP 優先搜尋生醫文獻 | 專案屬於生物資訊領域 | 搜尋結果更相關 |
| 建立 .env 檔案存放 API Key | 安全性考量，避免金鑰洩露 | 需在 .gitignore 排除 |

## Hooks 配置

| Hook 類型 | 觸發條件 | 動作 |
|-----------|----------|------|
| PreToolUse | 危險命令 (rm -rf, git reset --hard) | 顯示警告 |
| PostToolUse | 編輯 C++ 檔案 | 提醒編譯和測試 |
| PostToolUse | git commit | 提醒確認測試和文檔 |
| SubagentStop | 子代理完成 | 提醒檢查輸出 |
| Stop | 會話結束 | 提醒撰寫執行報告 |

### MCP 與 Claude Code 權限的關係

**重要發現**：MCP 服務器**不受** Claude Code 權限規則限制。

- MCP 是獨立的 Python 腳本，直接由系統執行
- 它可以自由讀取 `.env` 檔案
- Claude Code 的 `deny` 規則只影響 Claude 自己的 Read/Write 操作
