# v18 探索性 Read 過嚴拒絕

## 結果

- Reviewer A/B 均成功以全檔、非空、無 error 的 `Read` 讀完七個指定
  trust-chain source。
- A 另以 `offset/limit` 讀取一個非必要分析檔；舊 parser 以
  `Claude required Read was not an unbounded whole-file request` 拒絕。
- B 另嘗試讀取尚未建立、理應不存在的 v5 authority，取得 error；
  舊 parser 以 `Claude required Read did not return successful nonempty content`
  拒絕。
- 兩者皆產生一次、成功且 input/result 一致的 `StructuredOutput`，
  但 consumer 未發布 attestation；review signer private keys 保持 mode `0400`。

## 修正契約

1. 七個必要路徑各自至少要有一次只含 `file_path`、成功、非空的全檔 Read。
2. 非必要探索 Read 可使用 offset/limit 或取得 error；它不計入
   `required_read_paths`，也不能替代必要 Read。
3. 所有 tool use/result 仍須配對，StructuredOutput 仍須恰好一次、
   payload 綁定且成功非空。
4. regression 同時涵蓋 optional bounded/error Read、missing result、
   unexpected result、StructuredOutput zero/duplicate/mismatch/error。
