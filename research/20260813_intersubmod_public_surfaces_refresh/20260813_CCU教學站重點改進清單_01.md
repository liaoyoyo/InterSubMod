## 4. 仍待處理（16）：可執行改善規格

> 本節的 P0/P1 是 **下一輪執行優先級**，不是改寫 finding ID 內原始 `OLD-P1` 嚴重度。每項都同時定義原問題、失當原因、資料／模型／統計補件、最低修文與可觀察驗收。

### P0-01 — `OLD-P1-SR2C`

- **原問題**：`site/sr2c.html:56-72,220-249,3412-3447,3506` 顯示 `64.89%`，但沒有可追溯來源、numerator、denominator、unit/grain 或計算式；另有殘留 cell/cellular wording。
- **為何不合理**：精確百分比會被讀成可重算結果，但目前 authority 只允許重算 `63,506 / 71,955 = 88.2579%`。這不能直接取代 `64.89%`，因為兩者可能不是同一 estimand；它只證明現有已知分母無法支持 `64.89%`。
- **必要資料**：原始 artifact、numerator、denominator、unit/grain、納入排除條件、資料版本、SHA-256、產生日期與 validator 身分。
- **必要演算法／模型**：將該百分比綁到具名 derivation script；明示它是 unit/family/molecule/site/sample 哪一層的 ratio，並移除 cell-level promotion。
- **必要統計**：列 point estimate 的精確算式；若為抽樣估計，再列 uncertainty/CI 與 missingness。若找不到原始分子與分母，統計處置就是刪除精確值。
- **最低修文**：`「64.89%」目前無可追溯 numerator/denominator，故暫不報告；本頁只保留 molecular-state feasibility ceiling，不將其解讀為 cell proportion。`
- **驗收條件**：`rg -n '64\.89%'` 在 source/generated/live 皆為 0；唯一例外是同一畫面直接連到 receipt，且重跑版本化命令可得到完全相同的 numerator、denominator 與百分比。`cell/cellular` 也不得再描述現行 output。

### P0-02 — `DELTA-NEW-011`

- **原問題**：`site/sr2c.html:3275-3276` 由 `δ=1%`、`n=60` 直接給出 detection lower bound `0.07`。
- **為何不合理**：樣本數本身不決定偵測下限；沒有 detector/test statistic、null/alternative、α、target power、one/two-sided、multiple-testing policy 與 dispersion model，`0.07` 無法被解讀或重算。
- **必要資料**：每個 unit 的 n 分布、background/error observations、state competition、缺失與 overdispersion 資料；固定輸入快照與 SHA。
- **必要演算法／模型**：明定 detector、test statistic、H0/H1、decision rule、abstention、one/two-sided 與多重比較集合；用版本化 script 產生 power curve。
- **必要統計**：預先指定 α、target power（例如 80%/90%，實際值須由研究設計決定）、multiplicity correction、binomial/beta-binomial 或其他 dispersion model，並以 simulation/analytic power 交叉驗證。
- **最低修文**：`n=60 與 δ=1% 只構成示意設定；0.07 尚未經 detector、α 與 power 校準，不是已驗證 detection limit。` 若頁面無空間呈現設定，直接移除 `0.07`。
- **驗收條件**：要嘛 source/generated/live 完全沒有把 `0.07` 稱為 detection bound；要嘛版本化 script 可在指定 detector、α、power、sidedness、correction 與 dispersion 下重算 `0.07`，並輸出 power table/curve 與 failure cases。

### P0-03 — `DELTA-NEW-010`

- **原問題**：`site/sr2c.html:2812` 把 H2009 的 observed maximum `k=12` 寫成 `19×` 成本的原因。
- **為何不合理**：現有證據只有「H2009 觀察到 max k=12」與較高成本，沒有 per-dataset k-support histogram，也沒有排除 coverage、unit count、candidate-state count、search nodes、I/O、硬體或 commit 差異；相關不能升格為原因。
- **必要資料**：各 dataset 的 k histogram；逐 unit wall/CPU time、peak RSS、read coverage、unit count、candidate count、search nodes、I/O bytes；固定 commit、binary SHA、hardware、thread count 與 cache 狀態；`19×` 的明確 reference denominator。
- **必要演算法／模型**：建立 profiler 與 matched-subsampling/controlled-ablation 流程；至少能固定 coverage、unit count、hardware 與 I/O，再只改變 k-support/tail。
- **必要統計**：報告 `log(runtime)` 或適當 outcome 對 k、coverage、unit count、candidate states、I/O 的多變量 effect estimate、uncertainty 與 diagnostics；若要用「cause」，還需受控 ablation 或清楚的 identification argument，不能只用 cross-dataset correlation。
- **最低修文**：`H2009 在目前 snapshot 觀察到最大 k=12；較高 k 的尾端與較高成本相容，但是否造成所稱 19× 差異尚未經受控 profile 驗證。`
- **驗收條件**：`19×` 的 numerator/denominator、硬體、commit 與 profile 可重跑；同時提供 controlled/matched analysis 與 confound-adjusted effect。若只有描述性相關，頁面只能寫「hypothesis/association」，不得寫「原因／導致」。

### P0-04 — `DELTA-NEW-009`

- **原問題**：`site/sr2c.html:1642` 用 LOH 會「quietly wrong」「will be wrong and look normal」等必然語氣。
- **為何不合理**：未模型化 allele loss 的確是高風險 failure mode，但目前沒有 allele-specific CN/LOH truth、error rate、confusion matrix 或 calibrated failure probability，不能宣稱所有 LOH 情境必然且無聲地錯。
- **必要資料**：allele-specific CN/LOH truth、purity strata、simulated loss scenarios、已知 phase/marker anchors、正常與 LOH 對照樣本。
- **必要演算法／模型**：加入 `LOSS_UNMODELLED` 狀態、CN/LOH precheck、out-of-scope flag 與 abstention route；不得硬輸出看似正常的 topology。
- **必要統計**：依 LOH/CN/purity strata 報 confusion、abstention、failure rate、calibration 與 uncertainty；模擬需涵蓋 loss、subclonal CN、mapping/phase error。
- **最低修文**：`未納入 allele-specific CN/LOH 時，模型可能系統性誤表達 molecular topology；偵測到或無法排除 loss 時標記 LOSS_UNMODELLED 並 abstain。`
- **驗收條件**：全文不再有無條件的「必然錯／quietly wrong」；所有 LOH/CN 情境先被 flag 或 abstain。只有在 truth benchmark 後，才可用有分母與 CI 的定量 failure claim。

### P0-05 — `DELTA-NEW-007`

- **原問題**：`site/sr2c.html:853-894` 把 pairwise four-gamete compatibility 說成可唯一決定 tree、完全不需 search，並把四格俱全單因歸咎 error/mis-tag。
