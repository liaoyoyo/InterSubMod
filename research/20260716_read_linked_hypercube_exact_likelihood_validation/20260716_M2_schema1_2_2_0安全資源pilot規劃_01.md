1. **site load 可證明是最大**：154 個 VCF-indexed tasks 中，27,127 為最大，略高於 HCC1395 chr6 的 27,099。

## 5. 放行門檻

### 5.1 科學 / receipt hard gates

| 層 | PASS 條件 | 失敗時 |
|---|---|---|
| Extraction identity | schema `1.2.0`；external receipt checksum PASS；manifest / extractor hash 與執行當次一致 | 不可 ranking；保留目錄作診斷，新 version 重跑 |
| Alignment funnel | `all_pass=true`；flag + MAPQ funnel 守恆；eligible alignment / molecule IDs unique | NO-GO |
| Sidecar join | eligible alignments 100% exact joined；missing=0；conflict=0 | NO-GO |
| PS partition | PS_HP1 / PS_HP2 的 exact-known-PS × thresholds 1/2/3/5 各自 site conservation PASS；不同 PS 不共享 support | NO-GO |
| Ranking identity | schema `2.0.0`；upstream receipt / ranker hash / parameters / output hashes 全一致 | NO-GO |
| Candidate correctness | 只有 globally minimum compatible vertex sets 可進入 likelihood；任何 incomplete / k>12 不得被稱為 exact winner | NO-GO |
| Optimizer | 所有被宣稱的 candidate fit 為 globally KKT-certified；global LL gap ≤1e-8；simplex residual ≤1e-12；非收斂 fit 不得成 winner | NO-GO |

### 5.2 資源 hard / probe gates（單 task）

| 指標 | GO | PROBE | NO-GO / 停止 |
|---|---:|---:|---:|
| Extraction wall | ≤4 h | >4–8 h | 8 h timeout |
| Ranking bootstrap=0 wall | ≤4 h | >4–8 h | 8 h timeout |
| 任一 process peak RSS | ≤4 GiB | >4–8 GiB | >8 GiB；不開 full workers |
| k≤12 exact-eligible enumeration incomplete rate | ≤1% 且全為 abstain | >1–5% 且全為 abstain | >5%，或任一 incomplete 被宣稱 winner |
| exact-limit coverage | k≤12 占需 inference units ≥90% | 80–90% | <80%（結果過度 local-only） |
| optimizer globally certified candidate fits | 100% | — | <100%，除非全部 fail closed 且先重新改法 |
| refinement iterations | p99 ≤100、max ≤1,000 | 任一超過 | 超過且 task wall 逼近 timeout |

`k>12` 被明確標記 local-only / abstain 不是數學錯誤；上表的 coverage gate 衡量「全量產出有多少可用結論」，而不是把 k>12 改稱為 exact。

### 5.3 現有 solver-tail 觀測缺口

schema 2.0 的 unit / candidate table 有 `candidate_generation_status`、`refinement_iterations`、KKT gap、candidate count，但**沒有 per-unit candidate-generation / likelihood-fit elapsed seconds**。所以現在能稽核「哪些 unit 不完整 / 超 cap / 未收斂」，但不能正確報 solver wall-time p95 / p99。

在 154-task full release 前應新增且 receipt 匯總：

- `candidate_generation_elapsed_seconds`；
- `candidate_fit_elapsed_seconds`；
- per-task p50 / p95 / p99 / max 與超過 30 s MILP limit 的 unit 數。

在此前，只能用 task wall + status tail 作中信心操作 gate，不得宣稱「solver p99 已通過」。

## 6. 154-task 外推公式

### 6.1 已知 proxy 總量與 pilot 比值

| Proxy | 154-task 總量 | DORADO chr6 pilot | 總量 / pilot |
|---|---:|---:|---:|
| VCF index records | 469,849 | 27,127 | **17.3203** |
| BAM-size-weighted VCF records† | — | — | **19.2918** |
| 舊 family units | 118,234 | 910 | **129.9275** |
| 舊 T>1 units | 43,953 | 298 | **147.4933** |
| 舊 PS read exposures | 9,484,622 | 53,935 | **175.8528** |

†公式為 `sum_i[S_i × (BAM_size_dataset_i / BAM_size_pilot)] / S_pilot`；它仍是 proxy，不是 chr coverage 實測。

定義：

- `D_E`, `D_R`：pilot extraction / bootstrap0 ranking 輸出 bytes；
- `W_E`, `W_R`：pilot extraction / bootstrap0 ranking wall hours；
- `A`：啟動 full 前 `/big7_disk` available bytes；
- full runner 先固定 `workers=2`，並用 1.20 當 I/O / scheduling 保守係數。

**Point estimate**：

```text
D_full_point = 19.2918 × D_E + 147.4933 × D_R
W_full_point_workers2 = 1.20 × (19.2918 × W_E + 147.4933 × W_R) / 2
```

**Conservative resource envelope**：

```text
D_full_upper = 1.25 × 175.8528 × (D_E + D_R)
W_full_upper_workers2 = 1.20 × 175.8528 × (W_E + W_R) / 2
```

這不是 confidence interval；它是用三種現有 proxy 做的操作 envelope。第一批 8–16 tasks 完成後，必須改用實測 `molecule_sparse_rows`、primary units、candidate fits 重拟，不可一路沿用單 pilot proxy。

若完成推薦的 **dual pilot**，則改用更合理的分工外推：DORADO chr6 估 extraction，H2009 chr2 估 ranking。H2009 chr2 的舊 family-unit 總量比值為 `118,234 / 2,133 = 55.4308`，舊 T>1 比值為 `43,953 / 919 = 47.8270`。

```text
D_full_dual_point = 19.2918 × D_E,DORADO_chr6
                  + 55.4308 × D_R,H2009_chr2

W_full_dual_point_workers2 = 1.20 × (
    19.2918 × W_E,DORADO_chr6
  + 55.4308 × W_R,H2009_chr2
) / 2

D_full_dual_upper = 1.25 × (
    175.8528 × D_E,DORADO_chr6
  + 55.4308 × D_R,H2009_chr2
)
```

dual formula 仍要把兩個 pilot 本身的 extraction + ranking outputs 加入當前 disk usage，並在首批 8–16 tasks 後改用實測率。

### 6.2 full release 的 disk / wall gate

只有同時成立才啟動 154 tasks：

```text
D_full_upper <= 0.50 × A
A - D_full_upper >= 300 GiB
W_full_point_workers2 <= 168 hours
```

規劃當時 `A ≈ 717 GiB`，但必須當場重量；以該舊值示意，full 輸出 budget 上限是 `min(358.5, 417) = 358.5 GiB`。這個數字不可被當成未來的固定配額。

### 6.3 首批量後的再校正

full runner 不應一次放開到 154 個並行。以 workers=2 開始，每完成 8–16 tasks 重算：

```text
estimated_remaining_disk = sum_over_remaining_tasks(
    median_bytes_per_sparse_row × estimated_sparse_rows
  + median_bytes_per_primary_unit × estimated_primary_units
  + median_bytes_per_candidate_fit × estimated_candidate_fits
)

estimated_remaining_wall = observed_sum_worker_seconds / completed_tasks
                           × remaining_tasks / active_workers
```

同時以 completed-task receipt 的 p95，而不是只用 mean，用來抓 H2009 chr2 類的 solver tail。

## 7. 放行結論

- **現在 verdict：PROBE / WAIT**：有資源衝突 job，不執行；不 bypass gate。
- **只能選一個 release pilot 時**：HCC1395_DORADO chr6；它能合理 gate extraction / PS routing，但 solver-tail 信心只能標中等。
- **推薦方案：dual pilot**：先 HCC1395_DORADO chr6，再 H2009 chr2。前者是 site / PS stress，後者是舊 family-unit / T>1 / capped-group tail；兩者都通過後才對 154-task full run 有足夠的操作信心。
- **HCC1954 chr22 的正確角色**：可以先當 schema 1.2 low-cost smoke，但舊 schema 1.0 結果（16m00.77s、93,444 KB RSS、2.0 MB output）不能代表新 exact-PS / rank2 成本，也不能單獨放行 full run。
- **DORADO chr6 通過後**：仍要把 H2009 chr2 排在首批，因為它是舊資料的 ranking-tail 高風險點。
- **最終 full GO**：不只看 exit=0；必須同時通過 receipt identity / conservation / exact-abstain contract、RSS / disk / wall 外推與 solver-tail usefulness gate。
