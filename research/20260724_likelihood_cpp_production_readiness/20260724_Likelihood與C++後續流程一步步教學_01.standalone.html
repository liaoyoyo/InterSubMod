00 / map first

Likelihood 不是直接「看 VAF 選一棵樹」

它問的是：在一份候選狀態清單下，能否用合理的狀態比例與讀序錯誤率，解釋實際看到的全部 molecule patterns？

Mathematically defined

結構先限定候選；likelihood 再比較候選。兩者不可混成任意加權總分。

Read 編碼

每條 molecule 在 k 個 sSNV 上變成 R/A/X pattern。

候選狀態

minimum-extra solver 提供完整候選 vertex sets。

Emission

用每個固定 R/A call 的 BQ 算 match／flip 機率。

Fit π

在每個候選內估計最能解釋 reads 的 state mixture。

比較 LL

全部候選完成且 optimizer certified 後，才判唯一或並列。

01 / observation language

先把每條 read 寫成同一種語言

假設區域內有三個 sSNV。每一列不是一個 clone，而是一條 molecule read 對三個位置所提供的觀察。

三個位置上的 read-pattern 教學例子
Pattern視覺能確定什麼不能確定什麼
RRA RRA 三個位置都有固定 R/A call。 仍只是這條 molecule 的狀態，不是整個腫瘤 clone。
AAA AAA 同一條 molecule 同時帶三個 ALT。 不直接告訴我們三個突變的先後順序。
RAX RAX 前兩點固定；第三點沒有資訊。 不能把 X 當 REF，也不能任意補成 ALT。

Implemented Partial read 不會展開成多個獨立世界。

RAX 的概念補值是 RAR 或 RAA；solver只建立「候選至少要包含一個相容狀態」的聯合 group constraint。Likelihood 中，X 的 emission 乘數為1。

為什麼不把所有 X 補完後逐一建樹？

若一條 pattern 有 u 個 X，概念補值數是 2^u；多條 reads 若做笛卡兒積會變成 2^(Σuᵢ)。那會同時造成計算爆炸與重複計數。正確做法是保留每條 symbolic group，聯合求一個可同時覆蓋所有 groups 的候選。

02 / error-aware emission

BQ 決定「不一致」要罰多重

高品質 call 若與候選狀態相反，比低品質 call 更難被解釋為測序錯誤。

e = 10−BQ/10　·　match = (1−e)/(1−2e/3)　·　flip = (e/3)/(1−2e/3) 現行實作使用對稱 substitution model，並條件化在觀察鹼基屬於 REF／ALT；因此 flip 不是直接等於 e。

拖動 BQ，看 match／flip 如何改變

這只是單一固定 R/A call 的 emission；一條 read 的機率會把所有已觀察位置相乘。

X 的處理

03 / latent proportions

π 是讓候選最好解釋資料的狀態比例

一個候選狀態集合 V 可能包含多個 mutation states。程式在所有非負、總和為1的 π 中，尋找讓 reads 整體機率最大的組合。

LL(V) = maxπ Σr nr log [ Σv∈V πv P(r | v, BQr) ] r 是一種 read-pattern＋BQ group；nᵣ 是它出現的 molecule 數；v 是候選內的一個 mutation state。

名稱要精確：首頁用「哪棵樹」方便理解，但這一步實際評分的是候選 mutation-state vertex set V；相同 V 的不同 parent edges 得到完全相同的 likelihood。

Constraint

πᵥ ≥ 0

任何狀態的權重都不能是負值。

Constraint

Σπᵥ = 1

所有狀態權重總和必須等於1。

Interpretation

latent mixture

是固定候選下maximum-likelihood latent-state weight估計，不是硬分配每條read，也不是EM responsibility的條件期望。

Not clone fraction

不可直接叫 clone 比例

CN、purity、sampling與狀態不可辨識都可能使π偏離cellular clone fraction。

為什麼不再加一次 VAF？

同一批 reads 的 ALT／REF 次數已經進入 nᵣ 與 likelihood。再把 VAF 加成另一個 score，會把同一份 allele-count evidence 算兩次。

05 / identifiability boundary

狀態清單唯一，不代表 parent edge 唯一

Snapshot reads決定一個 state 出現時，通常不會記錄它是從哪個 parent state 演化而來。相同 vertex set 的不同 parent choices具有完全相同的 emission與likelihood。

Edge non-identifiable 兩圖的 states完全相同，所以read likelihood完全相同。

可以報告「winning vertex set唯一，但parent edge不唯一」；不能硬選紅色edge。要再縮小edge，需CN/CCF、跨區一致性、時間序列或其他獨立方向證據。

06 / resource guard ≠ scientific bound

max_sets=256 沒有「最多256棵樹」的數學保證

256 是materialized candidate數的工程上限。它不是由 k、統計顯著性、clone biology或候選family大小推導，也不能取代總wall-time與memory限制。

Critical distinction

cap單獨不保證程式準時結束；搭配deadline等控制後，才可保證回報成功或ABSTAIN。

State space

k=8 → 2⁸=256 states

這是超立方體「節點」上限，不是候選vertex sets或directed trees的上限。

Candidate family

候選可遠大於256

候選是節點組合與順序。單一terminal含6個未定序突變時，就有 6! = 720 個同樣最短的順序。

那256應該改成多少才「合理」？

沒有一個固定數字能由數學保證適合所有區域。合理做法是把 cap 明確定義為硬體／時間預算，例如「每unit最多N個materialized sets、M GiB、D秒」；先做family count或lower bound。現行enumerator只有在 F<cap 且下一解已證明INFEASIBLE時才自然完成；若剛好 F=cap，仍需外部completion certificate，否則保守標incomplete。

因此256可以暫時保留為保守預設，但必須與per-unit總deadline、memory cap、checkpoint及ABSTAIN一起出現。

10 / direct answers

三個問題的直接答案

Question 1

限制上限後能跑完嗎？

cap單獨不能保證。還需per-unit／global wall-time、memory cap、checkpoint及fail-closed receipt；這些齊備後，才能保證整批回報成功或ABSTAIN。

Question 2

256有數學推論嗎？

沒有候選數≤256的數學保證。256是可調資源預算；2^8=256 states不能推成256 trees。

Question 3

July資料夠嗎？

資料種類足夠，production contract尚不足。需big8重抽或正式big7↔big8 authority，再補adapter與solver。

Question 4

C++現在能出正式結果嗎？

尚不能。現在可快算W／partition；candidate、likelihood、directed topology仍待實作與parity gate。

建議先完成「可安全跑完全資料、硬區域明確ABSTAIN」的C++ hybrid backend，再追求提高可解coverage；不要用提高max_sets掩蓋family爆炸。
