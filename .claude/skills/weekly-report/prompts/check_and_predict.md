# check_and_predict.md — W5+W6 → C3 prompt（合併版）

## 使用時機

C2 分類+排序確認後，AI 同時做：
- W5：邏輯紅旗檢查（過度宣稱 / 流水帳 / 教授視角缺）
- W6：教授問答預測（5-7 個追問 + 預備回答）

合併為一個 checkpoint C3，因兩階段互為依據（紅旗修正後才能準確預測追問）。

## 觸發前置條件

- C2 分類+排序完成
- W3+W4 internal state 已存

## AI 自動處理

### W5 三類紅旗掃描

對 PPT 桶 + 講稿桶素材：

**過度宣稱**：
- 描述含「證實」「確認」「解決」但標籤為 [O]/[I] → 紅旗
- 描述含「全部」「完全」但 sample_count < total → 紅旗
- 描述含「顯著」但無 p-value/CI → 紅旗

**流水帳**：
- PPT 桶 > 5 筆無因果連接詞（因為/所以/由於）→ 紅旗
- 同層級 ≥ 5 個 bullet 平列 → 建議改為 grouped narrative

**教授視角缺**：
- 母稿無 §17 教授追問段（必補）
- §16 下週計畫不接續本週發現 → 紅旗
- 求協助型主線無 §5 候選 trade-off → 紅旗

### W6 教授追問預測

依主線類型載入 5-7 個追問（→ `templates/{type}_focus.md` 「教授可能追問」段）。
每個追問 AI 自動起草「預備回答」1 段。

## AskUserQuestion 模板

```yaml
question: "邏輯紅旗 N 個 + 教授追問預測 M 個。如何處置？"
header: "C3 邏輯+追問"
multiSelect: false
options:
  - label: "採納 AI 修正建議"
    description: "AI 已逐項提出改寫，用戶接受後寫回 C2 結果。"
  - label: "個別修改（指出哪幾項）"
    description: "用戶列「紅旗 X 是誤判 / 追問 Y 改成 Z」之類的指令。"
  - label: "補追問（教授有特殊偏好）"
    description: "用戶補述教授個人偏好（如：他每次必問 baseline）。AI 加入追問清單。"
  - label: "跳過某些紅旗（接受風險）"
    description: "明知是過度宣稱但無法降級（如教授看法不同）→ 標 [USER_OVERRIDE] 留檔。"
```

## 輸出格式

```markdown
### W5 紅旗清單

| # | 類型 | 觸發句 | AI 改寫建議 |
|:-:|------|-------|----------|
| 1 | 過度宣稱 | 「證實 X」（[O]）| 改「初步觀察 X，需 N 樣本驗證」 |
| 2 | 流水帳 | PPT 7 筆無連接詞 | 重組為 3 個 narrative 群 |
| 3 | 教授視角缺 | 無 §17 | 強制補（見 W6 結果）|

### W6 教授追問預測

| # | 追問 | 預備回答 |
|:-:|------|---------|
| 1 | 「為什麼是這個方法？」 | 回顧 Phase 1A 三方向比對表 + ΔF1 對比 |
| 2 | 「跨樣本一致嗎？」 | 7/7 樣本 ΔF1 表 + bootstrap CI |
| 3 | ... | ... |
| 5-7 | 主線類型對應追問 | 各對應 evidence |
```

## 用戶處置流程

| 用戶選擇 | AI 行動 |
|---------|---------|
| 採納 | 紅旗逐項修正 + 追問寫進 §17 → 進 W7 |
| 個別修改 | 等用戶指令 → 修改 → 顯示 → 確認 |
| 補追問 | 接收用戶補述 → 加入追問清單 → 起草回答 |
| 跳過 | 紅旗保留但標 [USER_OVERRIDE] → 進 W7 |

## fast-track 模式

C3 為**非必停** checkpoint。fast-track 下：
- AI 自動修正所有紅旗 + 自動產追問清單
- 30 秒倒數，用戶可中斷
- 不暫停 AskUserQuestion

## 與其他階段的關聯

- 上游：依賴 C2 分類+排序
- 下游：W7 母稿產出時，紅旗修正後的描述語氣 + §17 追問段直接寫入
