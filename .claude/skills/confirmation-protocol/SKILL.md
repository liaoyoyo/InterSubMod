# 確認時機協議（Confirmation Protocol）

## 執行模式切換

用戶可隨時在兩種模式間切換：

| 模式 | 觸發詞 | 行為 |
|------|--------|------|
| **互動模式** (預設) | `互動模式`、`interactive` | 在 Gate 和 Review 暫停點暫停等待用戶確認 |
| **全自動模式** | `全自動`、`auto`、`自動跑到底` | 跳過所有 Review 暫停點，只在 Hard Gate 停止。完成後輸出完整報告 |

**切換範圍**：模式切換只在當前對話有效。新對話預設為互動模式。

**全自動模式規則**：
- Review 暫停點 → 自動通過，使用最合理的預設選項
- FYI 暫停點 → 靜默跳過
- **Hard Gate 仍然暫停**：不可逆的高風險操作（刪除檔案、C++ 修改 commit、研究方向關閉判定）
- 完成後輸出「自動執行報告」：列出所有自動做的決策、跳過的確認點、最終結果

## 暫停點分類

| 暫停類型 | 互動模式 | 全自動模式 | 說明 |
|----------|---------|-----------|------|
| **Hard Gate** | 暫停 | **暫停** | 不可逆操作，任何模式都必須確認 |
| **Gate** | 暫停 | 自動通過 | 重要決策點，全自動下使用預設 |
| **Review** | 暫停 | 自動通過 | 中間產出展示 |
| **FYI** | 顯示 | 靜默 | 低風險通知 |

## 自主推進 vs 暫停的動態判斷（2026-04-17 新增）

**目的**：在 Opus 4.7 的自主性提升下，避免因過嚴規則造成低價值頻繁暫停，同時保留不可逆操作的安全網。

### 三維度定義

#### 影響度（Impact）

| 等級 | 操作定義 |
|------|---------|
| **低** | 可逆（git 可 revert）、局部（單檔案/單函數）、<10 min 可重做 |
| **中** | 多檔案改動、需重跑 benchmark（10min-1h）、影響單一樣本結論 |
| **高** | 跨模組重構、影響多樣本結論、研究方向判定、>1h 不可快速還原 |

#### 信心度（Confidence）

| 等級 | 操作定義 |
|------|---------|
| **高** | 有先例（evidence_ledger 或 memory）、單一合理解讀、規格完整 |
| **中** | 2-3 種合理解讀但偏向明確、部分先例可參考 |
| **低** | ≥3 種解讀、無先例、規格缺關鍵參數（資料集/閾值/方法） |

#### 可逆性 override（絕對暫停清單）

以下操作**不論影響度/信心度為何，一律 🔴 立即暫停**：

- 刪除/搬移任何檔案（含自動產出的 output/，需用戶確認後才可 rm）
- C++ 原始碼 commit（對應既有 Hard Gate hook）
- 研究方向 NO-GO 判定（寫入 evidence_ledger verdict=NO-GO）
- 覆寫 evidence_ledger / MEMORY.md 的既有記錄（append 不在此列）
- 推送至遠端（git push / PR 建立）

**長時間計算（>10 min）有條件例外**：
- 用戶**當輪明示**啟動（「跑全量」「平行 7 樣本」「benchmark 這個」）→ 🟢 一行告知直接執行
- 用戶未明示、模型自判需長計算 → 🔴 仍需暫停確認
- 判斷依據：當輪 user message 是否出現明確的「啟動」或「跑」動詞指向該計算

### 完整暫停判斷矩陣

| 影響度 ＼ 信心度 | 高信心 | 中信心 | 低信心 |
|----------------|--------|--------|--------|
| **低** | 🟢 一行告知後繼續 | 🟡 列假設後繼續 | 🟠 節點暫停報告 |
| **中** | 🟡 列假設後繼續 | 🟠 節點暫停報告 | 🔴 立即暫停 |
| **高** | 🟠 節點暫停報告 | 🔴 立即暫停 | 🔴 立即暫停 |

### 對應到現有暫停級別

```
🔴 立即暫停   → Hard Gate（不可逆）或 Gate（可逆但高影響）
🟠 節點暫停   → Review（完成階段性產出後暫停）
🟡 列假設繼續 → 內化為自主行為，artifact 中記錄假設
🟢 一行告知   → FYI 級別，主動輸出一行決策軌跡
```

### 決策流程（每個決策點依序檢查）

```
1. 這是不可逆操作嗎？
   ├─ 是 → 🔴 立即暫停（Hard Gate）
   └─ 否 → 進入 2

2. 評估影響度（低/中/高）
3. 評估信心度（高/中/低）
4. 查矩陣 → 得出級別

5. 依級別行動：
   🟢 → 輸出一行決策 + 繼續執行
   🟡 → 列出 2-3 個假設選擇 + 繼續執行第一步
   🟠 → 完成當前節點 + 暫停報告給用戶
   🔴 → 立即停下報告 + 等用戶確認
```

### 「一行告知」格式與範例

**格式**：`[決策]（影響: 低/中/高, 信心: 低/中/高, 理由: 一句）`

**範例 1（🟢 低影響+高信心）**：
```
以 within-group OLS 殘差化 AF（影響: 低, 信心: 高, 理由: O12 已驗證 pooled OLS 產生 collider bias）
```

**範例 2（🟡 低影響+中信心）**：
```
假設：
  (a) 用 NHD 距離 — 對稱；與前輪一致
  (b) 用 Jaccard — 不對稱但更符合甲基化生物意義
選 (a)（影響: 低, 信心: 中, 理由: 與 O9 baseline 對齊，可直接比較）
```

**範例 3（🟠 中影響+中信心，節點暫停）**：
```
已完成：修改 Bernoulli 距離正規化至 [0,1] 區間
結果：HCC1395-5kHz delta_F1 = +0.0008（邊緣改善）
下一步候選：
  (a) 擴散至 COLO829 / H2009 驗證
  (b) 回退，嘗試 L2 metric 正規化
暫停待用戶決定方向（影響: 中, 信心: 中）
```

### 跨場景快速查表

| 典型場景 | 典型影響 | 典型信心 | 預設級別 |
|---------|---------|---------|---------|
| 加圖表標註 / 改 matplotlib 參數 | 低 | 高 | 🟢 |
| 選擇統計方法且有先例 | 低 | 高 | 🟢 |
| 改單一 Python 分析腳本邏輯 | 低 | 中 | 🟡 |
| 新增 Python 特徵欄位 | 中 | 高 | 🟡 |
| 微調 C++ 閾值（已有 baseline） | 中 | 中 | 🟠 |
| 新增距離度量算法 | 中 | 中 | 🟠 |
| 決定是否 escalate 至 full benchmark | 高 | 高 | 🟠 |
| 判定研究方向 NO-GO | 高 | — | 🔴（不可逆） |
| 刪除 output/ 下任何檔案 | — | — | 🔴（不可逆） |
| C++ 原始碼 commit | — | — | 🔴（不可逆） |
| 啟動 >10min 計算（用戶明示） | — | — | 🟢（當輪明示例外） |
| 啟動 >10min 計算（模型自判） | — | — | 🔴（未明示） |

### 與既有權限邊界的關係

- **「AI 自主權限邊界」** 定義「什麼操作在全自動模式下可自主」
- **「暫停判斷矩陣」** 定義「自主時是否需告知/節點暫停」
- 兩者互補：先問「能不能自主」，再問「自主時怎麼溝通」

## 各場景暫停類型

| 場景 | 暫停類型 | 全自動時的預設行為 |
|------|---------|-------------------|
| 刪除/搬移檔案 | Hard Gate | — (必停) |
| 研究方向 NO-GO 判定 | Hard Gate | — (必停) |
| C++ 修改 commit 前 | Hard Gate | — (必停) |
| 假說選取 | Gate | 選最高優先級假說 |
| 測試計劃確認 | Gate | 使用建議方案 |
| benchmark 結果出爐 | Review | 自動記錄 + 判定下一步 |
| 觀察結果分析完成 | Review | 自動生成假說 |
| 週報草稿完成 | Review | 自動產出 |
| PPTX Storyboard 審查 | Review | 自動使用預設故事弧結構 |
| Python 分析執行 | FYI | 靜默 |
| git commit | FYI | 靜默 |
| 記憶更新 | FYI | 靜默 |

## AI 自主權限邊界

**可自主決定（不需暫停）**：
- 選擇分析腳本和統計方法（但需記錄選擇理由）
- 圖表格式和排版
- Git commit 內容
- 檔案命名和目錄組織
- 中間數據格式

**需暫停（Gate 或以上）**：
- 研究方向選擇和假說確認
- C++ 程式碼修改
- 結論判定（positive / negative / NO-GO）
- 刪除或搬移任何檔案
- 超過 5 分鐘的長時間計算前

## Opus 4.7 Subagent 觸發規則（2026-04-17）

Opus 4.7 預設**少 spawn subagent、少 tool call、優先單回合 reasoning**。本協議對齊此行為：

### 預設行為（不需用戶明指）

- **單檔案修改 / 局部邏輯調整** → 模型直接處理，**不 spawn subagent**
- **廣泛代碼搜尋（≤3 查詢）** → 直接用 Grep/Glob，不呼叫 Explore agent
- **單樣本測試** → 直接執行，不呼叫 parallel-benchmark

### 必須明寫觸發條件才啟用的 subagent

| 情境 | 必寫的觸發語 | 對應 agent |
|------|------------|-----------|
| 跨樣本平行 benchmark | 「平行驗證 HCC1395_5kHz / COLO829 / H2009」 | `parallel-benchmark` |
| 開放式程式碼探索（>3 查詢） | 「深度探索 XXX 的實作鏈」 | `Explore` 或 `general-purpose` |
| PR / 大型修改審查 | 「code review 這次 commit」 | `pr-review-toolkit:code-reviewer` |
| 獨立第二意見 | 「獨立審查 / 第二意見」 | `feature-dev:code-reviewer` |
| 深度 methodology 分析 | 「啟動 methodology-audit」 | `methodology-reviewer` |

### FYI：`/cpp-change` Step 4.5 的 code-reviewer 呼叫

屬於「結構性必要」的 agent 呼叫（非 4.7 預設行為可覆蓋），仍須執行，不因 4.7 自我審查能力提升而跳過。理由：獨立 context 的審查可抓出模型本身的盲點。
