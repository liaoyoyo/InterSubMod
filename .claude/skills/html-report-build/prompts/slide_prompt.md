# slide_prompt.md — LLM-direct HTML PPT slide deck generation

> **Read this prompt fully before generating slides.** A slide is NOT a report page; it's a **16:9 visual canvas** designed for spoken delivery. Each slide should be scannable in 3-5 seconds.

---

## Your role

Given a source `.md` outlining a presentation (numbered slides, speaker notes, optional figures), produce:
- `preview/index.html` — main entry with sticky topbar + tab nav + iframe
- `preview/slide_XX_{slug}.html` × N — one self-contained file per slide (16:9 canvas + speaker note, **inline CSS only**)

**Output location**: `preview/` directory **sibling of source `.md`** (same parent directory).
- Example: source `InterSubMod/docs/presentations/foo_outline.md` → `InterSubMod/docs/presentations/foo_outline/preview/index.html` + `preview/slide_*.html`
- If a `preview/` already exists at that path (e.g., legacy self_phasing), **do NOT overwrite** — write to `preview_v2/` instead and report to user.

**No `shared/style.css` file** — CSS is inlined into each `slide_XX.html` for single-file portability (Rule 7). The optional `shared/style.css` mentioned in some legacy docs is **not generated by this skill**.

---

## 8 Rules

### Rule 1 — 16:9 canvas
Each slide is `<article class="slide-canvas" data-section="SN">` with:
- `aspect-ratio: 16 / 9`
- `padding: 28px 40px` (slide margins)
- `border: 1px solid var(--c-border)`
- `border-radius: var(--radius-lg)`
- `box-shadow: var(--shadow-lg)`
- `overflow: hidden`
- `position: relative` (for absolute-positioned badge + footer)

The slide content fits inside this canvas. Do NOT exceed the 16:9 aspect.

### Rule 2 — Section color theming (8 sections + Q&A)
`data-section` drives canvas color theme. Standard mapping:

| Section | Code | Color | Use |
|---------|------|-------|-----|
| S0 Cover / Flow | `data-section="S0"` | `#7C3AED` purple | Cover, agenda |
| S1 Observation | `data-section="S1"` | `#DC2626` red | Symptom, anomaly |
| S2 Mechanism | `data-section="S2"` | `#EA580C` orange | Root cause |
| S3 Quantification | `data-section="S3"` | `#CA8A04` yellow | Forensic evidence |
| S4 Fix Design | `data-section="S4"` | `#1E3A8A` deep blue | Solution |
| S5 Validation | `data-section="S5"` | `#15803D` green | No regression |
| S6 (reserved) | `data-section="S6"` | `#0E7490` teal | Reserved for "Application" / "Use case" (rarely used; skip if not needed) |
| S7 Conclusion | `data-section="S7"` | `#B45309` brown | Verdict + future |
| Q&A Backup | `data-section="Q&A"` | `#6B7280` gray | Backup slides |

CSS pseudo-selectors apply color to `h2.slide-title` border-bottom + `.slide-canvas::before` badge:

```css
.slide-canvas[data-section="S2"] h2.slide-title { color: #EA580C; border-bottom-color: #EA580C; }
.slide-canvas[data-section="S2"]::before { background: #EA580C; }
/* repeat for each section */

.slide-canvas::before {
  content: attr(data-section);
  position: absolute; top: 8px; right: 28px;
  font-size: 11px; font-weight: 600; padding: 3px 10px;
  border-radius: 12px; color: white; opacity: 0.9;
}
```

### Rule 3 — Speaker note required (per slide)
Every slide MUST have a `<details class="note-section">` after the canvas:

```html
<details class="note-section" open>
  <summary>🎤 Speaker Note</summary>
  <div class="timing">{X 分鐘 + Y 分鐘問答}</div>
  <div class="speak-text">{actual speaking script, white-space: pre-line preserved}</div>
  <div class="tier3">
    <span class="label">Tier 3 (口頭可選):</span> {optional oral-only content}
  </div>
</details>
```

CSS:
```css
.note-section {
  margin-top: 20px; background: #FAFBFE; border: 1px solid #C7D2FE;
  border-left: 4px solid #8B5CF6; border-radius: 8px; padding: 14px 18px;
}
.note-section summary { cursor: pointer; color: #6D28D9; font-weight: 600; }
.note-section .timing { background: #EDE9FE; padding: 4px 10px; border-radius: 4px;
                         font-size: 11px; color: #6D28D9; display: inline-block; margin: 8px 0; }
.note-section .speak-text { font-size: 14px; line-height: 1.7; white-space: pre-line; }
.note-section .tier3 { margin-top: 12px; padding: 8px 12px; border-radius: 4px;
                       background: #F9FAFB; border: 1px dashed #9CA3AF;
                       font-size: 11px; color: #6B7280; }
```

### Rule 4 — Topbar + tab nav in `index.html`
Main entry `preview/index.html` has:
- **Sticky topbar**: dark blue (`#1E3A8A`), white text, title + meta path/build date
- **Sticky tab nav** (under topbar): horizontal scrollable button row, one per slide
- **iframe**: loads selected slide (`<iframe id="slide-frame" src="slide_01_*.html">`)
- **Vanilla JS**: button click swaps iframe.src + toggles `.active` class

```html
<header class="topbar">
  <h1>📊 {Deck Title}</h1>
  <div class="meta"><code>{repo path}</code> | Build: {date}</div>
</header>
<nav class="slidetabs" id="tabs">
  <button data-slide="01_cover" class="active">01 S0 Cover</button>
  <button data-slide="02_tldr">02 S0 Flow</button>
  <!-- one per slide -->
</nav>
<main class="iframe-wrap">
  <iframe id="slide-frame" src="slide_01_cover.html"></iframe>
</main>
<script>
  document.querySelectorAll('nav.slidetabs button').forEach(b => {
    b.addEventListener('click', () => {
      document.getElementById('slide-frame').src = 'slide_' + b.dataset.slide + '.html';
      document.querySelectorAll('nav.slidetabs button').forEach(x => x.classList.remove('active'));
      b.classList.add('active');
    });
  });
</script>
```

### Rule 5 — Image / IGV interactivity (PanZoom — fail-soft CDN exception)
For zoomable IGV screenshots or large figures.

**Why CDN exception is OK here (despite report_prompt.md anti-CDN policy)**: This script uses `script.onerror` fail-soft + always-working CSS hover fallback. If CDN fails (or user is offline), the slide still renders perfectly with `:hover` scale. **No hard CDN dependency** — the slide degrades gracefully. Report mode does NOT have this exception because reports rarely need pan/zoom.

```html
<div class="igv-zoom-wrap">
  <a href="../figures/igv_chr19_27M.png" target="_blank">
    <img class="igv-thumb" src="../figures/igv_chr19_27M.png" alt="IGV chr19:27M">
  </a>
  <span class="igv-zoom-hint">滾輪縮放 / 拖曳平移 / Shift+點 開圖</span>
  <button class="igv-pz-reset">Reset</button>
</div>

<script>
  // Try CDN PanZoom; fail-soft to CSS hover scale + new-tab open
  (function loadPanZoom() {
    const script = document.createElement('script');
    script.src = 'https://cdn.jsdelivr.net/npm/@panzoom/panzoom@4.5.1/dist/panzoom.min.js';
    script.onerror = () => console.warn('[panzoom] CDN failed, using CSS hover fallback');
    script.onload = () => {
      document.querySelectorAll('.igv-zoom-wrap').forEach(wrap => {
        const img = wrap.querySelector('img.igv-thumb');
        const pz = panzoom(img, { minScale: 0.5, maxScale: 8, contain: 'outside' });
        wrap.classList.add('has-panzoom');
        wrap.addEventListener('wheel', pz.zoomWithWheel);
        wrap.querySelector('.igv-pz-reset')?.addEventListener('click', () => pz.reset());
      });
    };
    document.head.appendChild(script);
  })();
</script>
```

Fail-soft CSS (always works):
```css
.igv-zoom-wrap img.igv-thumb { width: 100%; transition: transform 0.25s; }
.igv-zoom-wrap:hover img.igv-thumb { transform: scale(1.8); z-index: 50; }
.igv-zoom-wrap.has-panzoom:hover img.igv-thumb { transform: none; }
```

### Rule 6 — Speaker note Tier system
Tier 1 = on-slide visible. Tier 2 = speaker note. Tier 3 = oral-only optional.

| Tier | Where | Visible to | Example |
|------|-------|-----------|---------|
| 1 | `.slide-canvas` body | Audience | Stats, conclusion, IGV |
| 2 | `.note-section .speak-text` | Presenter | Script paragraphs |
| 3 | `.note-section .tier3` | Presenter (skip if short on time) | Edge case, anecdote |

### Rule 7 — Single-file portability
Every `slide_XX_*.html` is **self-contained**:
- Inline `<style>` with all design tokens + slide-specific CSS
- No external `<link rel="stylesheet">` — **inline only**. Do not write `shared/style.css` or any other separate CSS file.
- Inline JS for PanZoom + section badge
- Local figures via relative path `../figures/...` (NOT base64 — too large for many slides)

Test: Can a user open `slide_04.html` directly (without `index.html`) and see correct rendering? Must be YES.

### Rule 8 — Few-shot grounding
Before generating each slide, briefly reference 2 example slides from `examples/slide_pair_example.html`:
- One showing **layout pattern** (grid, stat-box, callout)
- One showing **IGV/data-heavy pattern** (table, image, evidence chain)

If source `.md` has unclear visual intent, mimic the closest example.

## Design Principles (Read first)

Before generating, **Read `references/design_principles.md`** — 12 rules. Slide mode applies especially:
- **Rule 2 (3-second glance)**: slide is billboard, not document; title ≤ 15 中字 / 80 英字元
- **Rule 3 (Assertion-Evidence)**: slide title = complete claim ("V6 修正 100% chr19 victims"), NOT topic ("Results")
- **Rule 4 (data-ink ratio)**: SVG without gridlines; bar labels inline (no separate legend if 2 colors)
- **Rule 5 (CRAP)**: Repetition = 8 section colors consistent; Alignment = grid layout
- **Rule 6 (whitespace)**: canvas padding 28px 40px; don't pack text to borders
- **Rule 9 (colorblind)**: section badge color + text label (not color only)

## Workflow (your steps)

1. **Read** source `.md` outlining slides (use Read tool).
2. **Read** `references/design_principles.md` (Rule 1-12).
2. **Parse**: extract per-slide spec — `{id, num, section, title, en_subtitle, timing, body_md, speaker_note, tier3}`.
3. **Read** `examples/slide_pair_example.html` for 2 reference slides.
4. **Plan slide list**: extract `{id, num, section, title, en, timing, body, speaker, tier3}` per slide.
5. **For each slide**: write `slide_XX_{slug}.html` with inlined CSS + body restructure (no shared CSS file).
6. **Write** `index.html` with topbar + tab nav + iframe.
7. **Self-audit** 6 taboos (from report_prompt.md Rule 7) + slide-specific checks:
   - All slides have `data-section` attribute
   - All slides have `<details class="note-section">`
   - `aspect-ratio: 16/9` present
   - No external `<link rel="stylesheet">`
8. **Report** all paths to user.

## What NOT to do

- ❌ Do not call `python3 build_html.py` or similar — this skill is LLM-direct.
- ❌ Do not use Reveal.js, Slidev, Marp, or any slide framework — write HTML directly.
- ❌ Do not exceed 16:9 aspect (text overflow → page split or content cut).
- ❌ Do not skip `<details class="note-section">` — every slide must have it.
- ❌ Do not skip `data-section` attribute — section color theming breaks.
- ❌ Do not output PPTX — this is HTML-only.
